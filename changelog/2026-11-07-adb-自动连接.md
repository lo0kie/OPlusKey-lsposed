# 启停连带检查、停用态收口与自动找设备

> 上一笔提交（`76d6c0a`）之后的一轮改动。

## 新增

### 新增：「独立设置」—— 每一档都能自己决定公共项

- 「按键绑定」页与「组合键编辑」页的顶栏，⋮ 左边各多一颗设置键，进的是**同一个页面**、**同一张卡**。
- 顶上那颗总开关「使用独立设置」默认关 = 跟随公共设置；打开后接口 / 振动 / 振动强度 /
  执行提示 / 提示文案全部改用这一档自己的值（不做逐项开关）。
- 从关拨到开的那一刻**先继承公共那份**：否则看到的是出厂默认（振动关、强度中、提示关），
  与公共页不一致，读起来像「开了没生效」。
- 页面只认 `SettingsTarget`（在改谁），单键与组合共用 `OwnSettings` 契约与 `Config` 上那五个
  `xxxFor` 取值出口 —— 执行侧不再有「组合走全局」的分支。
- 改的是一组组合时，这一页多出「组合按键设置」一节：**无操作时执行按键命令**（这一组自己一份，
  `ComboKey.passthrough`，没设过跟随公共）与**按键之间的等待**（这一项仍是全局：
  按下第一颗键时还不知道会组成哪一组，等多久只能有一份，副标题写明「所有组合共用」）。

### 重构：组合键不再处处分叉

- 长按设置卡：`LongRepeatCard` 与 `ComboLongCard` 合成一张，参数走 `LongPressParams`、
  改动走 `LongPressEdit`，卡片里没有「是单键还是组合」的分支。
- 组合编辑页不再手写一份骨架，直接用 `BindingList`（场景入口 / 设置卡 / 网格 / 命令网格 / 焦点圈
  全是同一份实现）。
- 系统场景入口：说明、闸门、灰着那句话收进 `scenarioEntry(target)`；进场景页收进
  `openBranchesFor(target)`（「为谁编、编哪一档」由 target 给）。
- 「松手执行额外动作」的写入：两个函数合成一个，走 `withLongPress`。

### 新增：`tools/adb-find.sh` —— 不知道 IP 也能把设备连上

- 三条路，从便宜到贵：**缓存**（`build/.adb-last`，上一次连成的 `host:port`，0.4 秒）→
  **mDNS**（`adb mdns services` 里的 `_adb-tls-connect._tcp`，无线调试端口变了也找得到）→
  **扫本机 /24**（默认只试 5555，给 `adb tcpip 5555` 那套兜底）。
- 扫描先做 **TCP 端口探测**再 `adb connect`：直接对 254 个地址挨个 connect 要三分钟
  （连不上时每条都要等超时），而探测对关闭端口是立刻回 RST 的。
- `--export` 打印 `export ANDROID_SERIAL=…`，可以 `eval "$(bash tools/adb-find.sh --export)"`
  接进 `tools/device-state.py` 那套链路。

修的三个坑（都在本机真跑出来的）：

- **中文 Windows 的 `ipconfig` 是 CP936**：直接 `awk/grep` 会被当成二进制、一行都读不到 ——
  先 `iconv -f CP936` 转一道。
- **取第一条 `IPv4` 会拿到 169.254.x 的 APIPA 地址**（虚拟网卡 / 没拿到 DHCP 时它最先出现），
  于是去扫一个空网段、白扫三分钟。判据改成「有默认网关且不是 169.254」。
- **`awk` 的 `END` 又打了一遍**：`ip` 变量带着真地址进 END，`prefix` 变成两行，拼出来的
  每个目标都是废的。去掉 END、只在块结束时打一次。

本机实测：删掉缓存、`adb disconnect` 之后跑一次，17 秒找到并连上；再跑一次走缓存 0.45 秒。

### 新增：开机就把宿主进程拉起来

- 模块的执行侧全在宿主进程里，那个进程平时由 ROM 的 exsystem 服务绑上来，实测要等开机后 ~15s，
  期间按侧键什么都不发生。
- 注入侧（system_server）启动后按固定间隔向宿主发 `startService`，把它提前拉起来；
  40s 没成功就放弃、等 ROM 自己去绑，失败原因进日志。发的是宿主自己的按键服务，
  与宿主侧「防冻结」那一手是同一个服务。

### 新增：编辑态顶栏的「全选」

- 「按键功能」页编辑态在「完成」左边多一颗「全选」：一次勾满按键与组合两列，再按一下收回
  （收回那一档文案换成「取消全选」）。

## 修复

### 修复：独立设置与「三档同一事件」写了却读不回

- `KeyConfig` 那一对 `fieldValues()` / `ofFields()` 只补了写的一半：新加的七个字段进了广播与
  落盘，却没有对应的读回 ⇒ 内存里永远是默认值。表现是「配置文件里有 `use_own_settings: true`，
  界面上也保存成功，按下去照旧走公共设置」。
- 同一批还漏了 `same_event` —— 它是「三档同一事件开了不生效」的另一半原因（前一半是它没进
  按键广播列）。

### 修复：停用快捷键之后，按其它自定义键会把模块页面拉起来

- 注入侧不变：停用的键（含内置侧键）一律原样放行，照走系统事件。
- 宿主侧那条场景派发改按「这一下有没有被模块认领」判：认领过就吞（这一下归模块），没认领就放行
  （这是停用键的原生动作载体）。原先按「侧键自己的开关」判，于是停用侧键之后每一次按键都放行
  一次，页面被反复拉起。
- 「认领」与那条派发的先后是竞态的：没认领时**先扣住 150ms 再看一眼**，期间补到认领就丢掉，
  仍没有才补投原生动作。

### 修复：组合按键列表行尾的启停态显示反了

- 停用的那一档画成「已停用 + 箭头」，启用的不画标记。

### 修复：开关行置灰后点一下没有任何反应

- 置灰那一档在整行之上盖一层只吃点击的透明层，点哪儿都会说清为什么不能改。

## 修改

### 修改：那一页的名字改回「按键设置」

- 它装的仍是公共那份（接口 / 振动 / 提示 / 组合键）；覆盖值那页叫「独立设置」，两页不再抢同一个名字。

### 修改：独立设置那几句文案去掉指代

- 「下面这几项用自己这份」→「接口、振动、提示分别设置」；关闭态同理写全对象。
- 「无操作时执行按键命令」的两句子标题只留后果（「两颗键各执行自己的绑定」/「什么都不做」），
  前提由标题说一次。
- 独立设置页的副标题：组合改用成员键名（`「侧键」×「电量 +」`），不再显示内部 id `cmb1`。

### 修复：「三档同一事件」开关一直没生效

- 那一位原先挂在全局字段表里，却既不在全局广播列、也不在按键广播列 ⇒ 注入侧永远读到默认的 false。
  改成每颗键一位之后进了按键字段表，判定侧才拿得到。

### 修复：配置被整份判成读不懂

- `same_event` 从全局段挪回键段时漏抬 `ConfigCodec.VERSION`（29 → 30）：当前版本的 md5 是「按新 DTO
  重新编码」算的，不抬号就会拿新 DTO 去校旧文件，每一份已有配置当场读不出来。
- 这一轮又加了两批字段（按键级覆盖、`ComboKey.passthrough`），版本一并抬到 32。
