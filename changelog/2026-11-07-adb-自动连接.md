# 局域网里自动找设备并连上

> 上一笔提交（`76d6c0a`）之后的一小笔：纯工具，不动模块代码。

## 新增

### 新增：`tools/adb-find.sh` —— 不知道 IP 也能把设备连上

- 三条路，从便宜到贵：**缓存**（`build/.adb-last`，上一次连成的 `host:port`，0.4 秒）→
  **mDNS**（`adb mdns services` 里的 `_adb-tls-connect._tcp`，无线调试端口变了也找得到）→
  **扫本机 /24**（默认只试 5555，给 `adb tcpip 5555` 那套兜底）。
- 扫描先做 **TCP 端口探测**再 `adb connect`：直接对 254 个地址挨个 connect 要三分钟
  （连不上时每条都要等超时），而探测对关闭端口是立刻回 RST 的。
- `--export` 会打印 `export ANDROID_SERIAL=…`，可以 `eval "$(bash tools/adb-find.sh --export)"`
  接进 `tools/device-state.py` 那套链路。

### 修的三个坑（都在本机真跑出来的）

- **中文 Windows 的 `ipconfig` 是 CP936**：直接 `awk/grep` 会被当成二进制、一行都读不到 ——
  先 `iconv -f CP936` 转一道。
- **取第一条 `IPv4` 会拿到 169.254.x 的 APIPA 地址**（虚拟网卡 / 没拿到 DHCP 时它是**最先**出现的
  那条），于是脚本去扫一个空网段，白扫三分钟。判据改成「有默认网关且不是 169.254」。
- **`awk` 的 `END` 又打了一遍**：`ip` 变量带着真地址进 END，`prefix` 于是变成两行，
  拼出来的每个目标都是废的（扫描一条都连不上）。去掉 END、只在块结束时打一次。

## 怎么用

```bash
bash tools/adb-find.sh                     # 找出来就连上
eval "$(bash tools/adb-find.sh --export)"   # 顺手设好 ANDROID_SERIAL
```

手机那侧两种开法：**无线调试**（Android 11+，配合 `ADB_MDNS_AUTO_CONNECT='*'` 连脚本都不用跑），
或者先用 USB 执行一次 `adb tcpip 5555`（端口固定，IP 变了靠这个脚本扫出来）。

## 验证

- 本机实测：删掉缓存、`adb disconnect` 之后跑一次 —— 17 秒找到 `192.168.0.102:5555` 并连上；
  再跑一次走缓存 0.45 秒。
- 真机 `PLK110`（`3B15BR005FN00000`），手机 `192.168.0.102` / 电脑 `192.168.0.103`，同一 /24。
