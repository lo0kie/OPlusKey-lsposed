# 长按卡置灰分档、滑杆手动输入、选择应用顶栏改位置

> 上一笔提交（`11061c3`）之后这一轮的改动。提交里那份 `2026-11-06-选择应用显示开关联合筛选.md` 不再改。
>
> 「灵感语音」那一档的最终形态以本文为准：那一份里写的「拆成两个平级动作」不再作数。

## 修复与调整

### 修复：长按动作是多条命令 / 灵感语音时，整张长按设置卡全灰

- 「多条命令不支持连续触发」「灵感语音不支持连续触发」这两条原因原先被当成**整卡**闸门，于是时序两行（松手才触发 / 松手后再执行）与「长按延迟」一起被连坐 —— 而它们跟连不连发没有关系。
- 现在置灰分两层：整页级的原因（主开关关 / 链路没通 / 配置只读）灰整张卡；「动作自己不支持连发」只灰「连续触发」那一族（开关 + 振动 + 间隔），副标题仍写清为什么。
- 真机上撞到的正是最常用的那种配法：长按 = 开始灵感语音、松手 = 结束灵感语音 —— 整张卡全灰，刚配好的松手那一行点都点不了。

### 修改：长按延迟上限 1000ms → 2000ms

- 「长按延迟」滑杆拨到尽头也只能到 1 秒，想「按住两秒才算长按」调不出来；手改配置写的更大值还会被 `ConfigFields` 的钳制压回 1000（上限与滑杆必须是同一个数，`KeyConfig.MAX_LONG_PRESS_MS` 一处）。
- 上限只参与「排长按那一枪」，不影响判定正确性：越长越不容易误判成长按，代价是长按动作要等更久。
- 单键与组合键共用这一档（都走 `ConfigFields.F_LONG_PRESS_MS` 的钳制）。
- 注入侧仍按自己的编译期上下限钳制广播里的值：装完之后 **>1000ms 的值要重启手机才在判定侧生效**（宿主侧与界面立刻按 2000 算）。

### 新增：所有滑杆行点一下都能手动输入

- **整行可点**：点滑杆行的任何一处（行首图标那一格、标题 / 摘要、行内边距、行尾那个当前值）都弹出输入窗 —— 按下反馈、波纹与触觉走行自己的点击，与页面其余行同一条口径。滑杆在这些档上像素不够分（长按延迟 200–2000 一档 50ms、36 档挤在一根轨道上），想落在「恰好 1250」几乎不可能；页面缩放那种要精确到 5% 的一样。
- **点轨道那一下不算**：那条「点轨道跳值」的手势会把抬手消费掉，于是外层那次点击不会成立 —— 否则点轨道会同时「跳到那个值」与「弹窗」。拖动本来就不经过这两条路（移动超过阈值，点击自己就取消了）。
- 小窗**复用全项目那一个**（`NameDialog` 多收一个 `range`）：标题与行首图标取原行，同一张卡里并着两根滑杆时（长按那一档）分得出弹的是哪一根。
- 数值那一档三件事与名字那一档不同：只收半角数字（位数按上限算）、标题行尾那格小字改成显示**取值区间**（打字时占位被盖住也一直看得见范围）、越界时「确定」按禁用色画且按不动。
- 打进来的数**先吸到档位上**（`SliderSpec.snap`，与拖动 / 点轨道同一套刻度）：打 260 落到 250。不吸的话配置里会存进「不在档位上」的值，滑块夹在两档之间 —— 看着就像 step 失效了（只有手动输入这一路要补，另外两路本来就落在刻度上）。
- 刻度的算法从两处收成一处（`snapToStep`）：`tapSliderToSeek` 的「位置 → 值」与这次的「输入 → 档位」共用它，区间不整除时不会各算一格。
- 落盘仍走滑杆那条 `onCommit`：钳制、写盘失败拨回、判据日志都在同一处，手动输入不另开一条路。
- 行尾那格小字的样式抽成 `TitleSmallText`（字数统计 `n/24`、条数 `n` 与这次的取值区间共用一份）。

### 修改：「选择应用」页那一行小字挪到大标题下面，并写清「要做什么 + 做给谁」

- 原来挂在大标题**右边**（尾随标题），写的是「已选择: 微信」—— 这一趟到底要普通打开、还是小窗起、还是挑了个界面 / 快捷方式，从那一行看不出来，只能靠行尾一枚小窗图标猜一半。
- 现在挪到**大标题下面**（库的 `subtitle` 槽位，走 `PageHeader.subtitleBelow`），文案按**将要写下去的形态**拼：

    | 这一趟               | 那一行                                                   |
    | -------------------- | -------------------------------------------------------- |
    | 普通打开             | `打开应用: 微信`                                         |
    | 挑的是某个界面       | `打开应用: 微信 - LauncherUI`                            |
    | 挑的是快捷方式       | `打开应用: 微信 - 扫一扫`                                |
    | 开着「以小窗口打开」 | `以小窗打开应用: 微信` / `以小窗打开应用: 微信 - 扫一扫` |
    | 「结束应用」那一趟   | `结束应用: 微信`                                         |

- 前半句**只分「怎么开」**（打开应用 / 以小窗打开应用），不跟类型：组件与快捷方式已经把「具体是哪一个」写在后半句的 `-` 后缀里，前面再说一遍「打开快捷方式」就是同一句话说两次。
- 组件 / 快捷方式在应用名后面再用 `-` 接一句「具体是哪一个」：快捷方式取挑的那一行的名字（老配置里可能是 token 末尾的 `|名字`），组件取类名最后一段（系统给的界面标题要那一页的清单才有，这一层拿不到）。
- 判据分两层：**草稿（刚挑完还没提交的那一条）优先**，没有草稿才读当前绑定的动作 —— 后者是「现在绑着什么」，前者才是「这一趟将要绑成什么」；两档互斥地算，不会出现「当前绑的是快捷方式、这趟刚挑了个应用」被念成「打开快捷方式」。
- 行尾那枚「小窗起」图标随之撤掉：文案已经写清起法，再挂一枚就是同一件事说两遍（「停用」那枚仍留着，它在别的页）。
- 这一行连同它的判据搬进 `ui/screen/apppicker/PickerHeaderText.kt`（`PageTopBar` 已贴着函数数上限）；顺带删掉 `selectedLabel`（只是 `appNameOf` 的别名，说明与后者的类注释同一份）。
- 前半句跟着收口：`APP_PICKER_OPEN_FORMAT` / `APP_PICKER_OPEN_WINDOW_FORMAT`（`打开%s`）换成 `APP_PICKER_OPEN_APP` / `APP_PICKER_OPEN_WINDOW_APP`（`打开应用` / `以小窗打开应用`），三个 `APP_PICKER_KIND_*` 一起删掉 —— 类型不再参与前半句的拼接。

### 修改：「以小窗口打开」从 ⋮ 菜单摘出来，做成顶栏右侧第二颗键

- 用户口径：「打开应用的以小窗打开摘出来，做成第二个 header 右侧菜单」。
- 现在顶栏右侧是**两颗**：左边那颗是「以小窗口打开」的开关（画中画字形），右边仍是 ⋮
  （`AppPickerMenu`，两圆键之间 8dp）。
- 为什么该出来：它决定的是「这一趟往哪个动作上写」（`window:` 还是 `app:`），挑应用之前就得定下来，
  藏在菜单里等于每次多按一下；而 ⋮ 里剩的那两项是**列表怎么显示**，与它不是一件事。
- 开关的两态只靠字形颜色分（开着走 `primary`，关着走顶栏按钮常规内容色，`COLOR_TRANSITION_SPEC` 过渡）——
  顶栏圆键没有「选中」那一档底纹，加一档要动公共组件，代价比收益大（与「按键功能」页那颗编辑键同一个做法）。
- 出现规矩不变：只认应用本身的那几趟（条件执行挑应用、结束应用）**不出现**（那几趟不读 `window:`）；
  ⋮ 那两行仍只在「打开」那一趟出现，两行都不剩时连按钮一起摘 —— 所以结束那一趟顶栏右侧一颗都没有。
- 顺手改掉几处跟着变的说法（`AppPickerState.smallWindow`、`PageIcons.SmallWindow`、`PageTopBar`、
  `AppPicker` 的注释）：它们原来都把这一项称作「菜单里的那一项」。

### 修改：应用列表的行尾图标只分两档 —— 选中给实心圆勾，其余给右箭头

- 那一格原来随选中态换四档字形：没选中 = 右箭头、选中整个应用 = 勾、选中某个界面 = 一块屏、选中快捷方式 = 表格 + 箭头。
- 现在只剩两档：**选中那一行 = 实心圆勾**（与按键列表的选中态同一颗），其余行 = 右箭头。
    - 类型（应用 / 组件 / 快捷方式）已经由顶栏那行小字说清，行尾不再兼这一职；
    - 这一页的行是「挑一个」，勾比箭头更直接地说「就是它」。
- 那一格**恒占位**（两档都是 24dp）：原来「没选中不画、选中才画」时宽度从 0 跳到 24dp —— 库按行尾实际宽度算中间那列，长包名会当场折行（真机表现是「勾一出现，两个标题一起上移」）。
- `RowState.iconFor` 与它专用的 `appOnly` 字段一并删掉；「选择界面」那一页（`ActivityPickerList`）的圆圈 / 勾**保持原样** —— 那里是单选组，圈的是「选了哪一个」，不是重复类型。

### 新增：菜单行支持子标题，「打开应用 / 结束应用」两行写出绑的是哪个应用

- 菜单行组件（`MenuEntry.Row`）补上 `summary`，走库里的 `DropdownItem.summary`：标题下面一行 `body2` 小字，库自己管行数（带子标题时标题最多 2 行、小字最多 2 行，超了省略号），行高是 `heightIn(min = …)`，两行会自然长高，字不会被裁。
- 用法收在「应用控制」那一层菜单：选中「打开应用」或「结束应用」之后再打开这层菜单，那一行的标题下面写出**当前绑的是哪个应用**（`微信` / `微信: 扫一扫`）—— 两行都只写应用名时，隔着两层菜单看不出自己绑的是哪一个。
- 「当前绑的是哪个应用」与网格里「应用控制」格的小字**同一份实现**：原来那段（`BindingGrids.kt` 里的 `rememberBoundAppLabel`）搬进 `ui/AppNaming.kt` 改名 `boundAppName`，两处共用一套优先级与缓存；查询仍在 IO 上跑，小字晚一帧出现，不在首帧卡 binder。
- 子标题只出现在**被选中那一行**（`modeEntries` 里按 `ActionCatalog.isBound` 判）：绑的是「打开应用」时「结束应用」那行不出小字，否则读起来像是它也绑了那个应用。
- 顺带把「进场滚到选中那一行」的矩形改成**按实测行高**取（`rememberMenuRowBringIntoView`）：原来写死单行 32dp，带子标题的行更高，拿 32dp 去请求会让选中行下半截留在视口外。量的是行首图标格的父节点（库里那层内层 `Row`），量到再请求。

### 修改：子标题字号降一档（14sp → 13sp），系统开关 / 灵感语音也接上子标题

- **字号**：库给子标题写死的是 `body2`（14sp），与行标题 `body1`（16sp）只差 2sp，两行摞在一起像两个标题。菜单这一层改用 `footnote1`（13sp），读起来才是「注解」。
    - 库没有给子标题的样式口，于是补丁 `0011-dropdown-summary-style`：`DropdownItem` 多一位 `summaryStyle: TextStyle? = null`（`null` = 上游的 `body2`，不传就与官方一致）。补丁产物版本 `1.1.0-subtitle11` → `subtitle12`，`patches/coui/build-patched.sh`、`app/build.gradle.kts`、`gradle.lockfile`、`gradle/verification-metadata.xml` 四份一起吃（`bash tools/relock.sh`），旧产物从 `patches/repo` 删掉。
- **接上另两族菜单**：子标题原来只给「应用控制」那两行（绑的是哪个应用），现在入口格那一层的每一行都按「当前绑的是哪一档」给：
    - 系统开关（Wi‑Fi / 蓝牙…）→ `切换` / `打开` / `关闭`（问 `ActionCatalog.stateMenu` + 按**动作**那一侧读的 `switchStateLabel`）；
    - 灵感语音 → `开始灵感语音` / `结束灵感语音`（那一行自己还带一层，取到最里面那一档——只写「灵感语音」看不出是开还是停）。
    - 判据仍是「只有被选中那一行显示」：绑的是「打开免打扰」时别的行不出小字。
- `modeEntries` 的 `selectedSummary` 从「一个字符串」改成「每行自己算的函数」——三种入口各问各的：应用控制要异步查名字，另两族是纯查表。

- **第一版这里写错了**：系统开关那几行最初走的是 `ActionCatalog.boundModeOf`，而它查的是「这一**格**点开的那一层」（`MODE_MENUS` 那张入口格表）—— 开关行（`setting:wifi`）根本不在那张表里，于是永远返回 `null`，真机上就是「系统开关选中时没有小字」。现在改成直接问那一行自己的三档（`stateMenu`），状态从动作那一侧读（`switchStateLabel`），老写法（`oplus:no_disturb`）也认。

### 新增：抽屉里的候选行也接上小字，与网格同一句

- 「添加命令 / 换一步」抽屉里那一列候选行（`CardRow.Item`）接上了 `summary`：标题下面那行小字写**当前绑的是什么**，与网格里那一格完全同一句。
- 为此把网格原来那支 `builtInSubtitle`（在 `BindingGrids.kt` 里、私有的）搬到 `ui/model/TileSubtitle.kt` 成 `tileSubtitle(spec, current, boundMode, appLabel)`：两处摆的是同一张清单（`ActionCatalog.GROUPS`），同一个「系统开关」在两处写成两句话的话，用户看到的就是两套说法。判据只留一份，界面两侧各填自己那个槽（网格 `ActionTile.subtitle`、抽屉 `CardRow.Item.summary`）。
- 抽屉比网格多认一格：`ActionCatalog.APP_TILE`（「选择应用」那一行）与「应用控制」同一档，小字写 `打开应用: 微信` / `结束应用: 微信`。
- 应用名一次查好递进去（`StepSheetCtx.boundApp`，仍走 `boundAppName` 那条 IO + 缓存的路）：抽屉一列四十多行，按行判就要按行查。
- 单行 / 两行的行高差由 `CardRow` 自己撑（库那条行本来就是按内容高），不额外定高。

### 修改：「松手动作」那一行的系统开关 / 灵感语音 / 锁屏快捷改成「取值」的写法

- 原来那一行与步骤行共用 `stepTitle`，写出来是**动词在前**的一条命令名（`关闭:手电筒`）；读到「松手动作」这四个字下面时，等于把「做什么」说了两遍，还得先翻到冒号后面才知道是哪个开关。
- 现在这两族换成**取值**的语序（用户口径）：`手电筒 - 关闭` / `Wi-Fi - 打开` / `免打扰 - 切换` / `灵感语音 - 开始` / `灵感语音 - 结束`。连接符用 `-`（与「选择应用」页那一行、网格小字同一套），不是冒号。
- 锁屏快捷那一档（相机 / 计算器）用**冒号**接：`锁屏快捷: 相机`。它后半截是**名字**而不是状态，读法与 `打开应用:微信` 同一族；而且不带前缀只写「相机」会被读成「打开相机」—— 它其实只在**锁屏**上出现。
- 判据（`ui/model/CommandText.kt` 的 `releaseActionTitle`）：系统开关走 `Action.Setting` + `switchStateLabel`（状态词与网格小字、菜单子标题同一处），名字取 `SystemSwitches.titleOfId`；灵感语音按 `ActionCatalog.modeMenu(VOICE_TILE)` 那两档的位置取「开始 / 结束」；锁屏快捷按 `modeMenu(KEYGUARD_TILE)` 里命中哪一档取名字。
- 其余动作**照旧**走 `stepTitle`（`打开应用:微信` 那些本来就是「动作:对象」，不该反过来）。步骤行与执行提示也不动 —— 那两处读的是「执行了什么事」。
- 新增四条字典：`common.name_state_format`（`%s - %s`）、`common.start`、`common.stop`、`common.prefix_name_format`（`%s: %s`）（中英两份都补）。

### 修改：网格与抽屉的「一行怎么显示」收成一份（`ActionRowView`）

- 两处摆的是同一张清单（`ActionCatalog.GROUPS`），但渲染是两套代码：网格走 `BuiltInTile`、抽屉走 `stepSheetRow`。每加一条展示规则都得写两遍，漏一遍就成「同一个系统开关在两处长不一样」—— 先后踩过三次：行首字形、行尾箭头、小字。
- 现在规则只有一份：`ui/model/ActionRowView.kt` 的 `actionRowView(spec, current, appLabel)` 给出 `title / icon / subtitle / selected / trailing`，网格与抽屉各自只把它塞进自己的槽（`ActionTile` / `CardRow.Item`）。以后加规则只改这一处，从结构上不会再走形。
- 顺带修掉最后一处不一致：抽屉里「选择应用」那行以前只画格子自己的字形，现在与网格「应用控制」格同一套 —— 绑成结束 / 快捷方式 / 某个界面就画对应的那颗（判据里带 `selected`：当前绑的是「结束应用」时这一行不是它，不会画错）。
- `BindingGrids` 里那份 `appTileIcon` 搬进 `ActionRowView`（改名 `boundAppIcon`）；`tileIcon` / `tileSubtitle` 现在只在那一处调，网格与抽屉都不再各拼一半。

### 修改：菜单子标题补到「系统场景」、条件取值与主题

- 「系统场景」那一行（按键绑定页与组合键编辑页的 ⋮ 菜单）子标题写这一档的条数：没有 → 「没有添加系统场景」，有 → 「有 N 个系统场景」（只数启用中的，与页面里那条横幅同一判据）。
- 条件一级菜单里，**选中那一行**的子标题写这一条现在的取值（`打开` / `22:00-07:00`）；空条件不出小字，其余行也不出 —— 写了会被读成「也选了」。「前台应用」那一档写**个数**（`已选择 3 个应用`）：那一档能选好几个应用，名字顿号连起来比标题还长。
- 条件表里「前台应用」那一行**不限制行数**（其余条件照旧单行）：那一行正是用来核对挑了哪几个应用的，单行省略等于把答案裁掉。
- 「命令」那一行也不限行：`打开应用: 微信 - LauncherUI` 这种一长串同样会被单行省略裁掉半截。
- 主题菜单里「跟随系统 (Monet)」拆成标题「跟随系统」+ 子标题「Monet」：两档标题本来就该一样，差别只在用不用壁纸取色。
- 「打开应用 / 结束应用」两行补行尾右箭头：点下去是另一张页面，与其余「选了就是结论」的行分开。

### 修改：网格与抽屉改成**完全同源**（清单、文案、图标、小字、二层菜单全一样）

- 原来抽屉用的是 `STEP_GROUPS`，它在 `GROUPS` 上多做了一处替换：`appctl:`（应用控制）**就地换成** `app:`（选择应用）。于是同一个入口两处不同名（「应用控制」/「选择应用」）、层级也不同（网格点开有「打开 / 结束」两层，抽屉直接进挑应用页），而且**「结束应用」根本做不成一步**。
- 现在两处共用同一张表：`STEP_GROUPS` / `BRANCH_GROUPS` 只剔「无操作」（那是「能不能当一步」的语义），不再替换条目。抽屉里那一行现在也叫「应用控制」，行首字形、小字、选中态、点开后的两层菜单与网格一模一样（都是 `ActionRowView` + `modeEntries`）。
- 随之打开的一条能力：**「结束应用」可以是一步了** —— 抽屉里点「应用控制 → 结束应用」进同一张挑应用页（`AppPickerState.stopApp` 那一档），落盘成 `proc:stop:包名`。为此 `StepPickerPage` 多一档 `AppStop`，`openForStep` / `openForBranch` 各多一个 `stop` 参数，`openAppPickerForStep` / `openAppPickerForBranch` 透传；写回仍走原来那条 `writeToken`，没有新落盘路径。
- 「无操作」仍然只在**系统场景**那张表里（`BRANCH_GROUPS`），步骤里不列 —— 一步不能是空动作。

### 新增：「最终文案」`actionFinalTitle` —— 入口格带上格子名

- 形如 `系统开关: WIFI - 打开`、`响铃状态: 静音`、`小布 AI: 结束灵感语音`：**格子名 + 最里面那一档 + 状态词**。应用 / 界面 / 快捷方式 / 结束应用 / 亮度 / 音量**不加前缀** —— 它们自己的名字已经说清「做什么 + 哪一个」（`打开应用:微信`、`增加 15%`），再套一层只会把一句话切成两截冒号。
- 两处用它，都是「一眼看出这是哪一格里的哪一档」：
    - **系统场景**那几行规则的动作格（`ui/screen/command/CommandBranches`，原来是 `系统开关 - WIFI`，看不出打开还是关闭）；
    - **执行时提示**里的 `$action`（`host/action/ActionNotice`）：用户口径「执行时提示也用这个文案」，于是提示长成 `侧键 - 单击 → 系统开关: WIFI - 打开`。
- 实现只在 core 一份（`ActionLabels.kt`），界面侧另有一个 `(String) -> String` 名字回调的包装（`ui/model/CommandText.actionFinalTitle`），与 `stepTitle` 共用同一份「Action → 目标字符串」的映射。
- `tools/audit-arch.py` 的判据跟着改：界面里的调用点从 3 处变为 6 处（执行时提示 / 步骤行 / 绑定回执 / 系统场景 / 界面侧包装两处），并新增一条**实现处 = 2**（`actionTitle` + `actionFinalTitle`）的硬判据 —— 多一份实现就红。

### 修复：媒体控制的「播放/暂停」一行被当成入口 —— 多点一层选择器、还和「播放」一起亮

- 两个症状同一个根：**取值格的首行与格子自己共用同一串 token**。`MEDIA_MODES` 的第一行（「播放/暂停」）token 就是 `MEDIA_TILE`（`keyevent:85`），而 `MODE_MENUS` 里 `MEDIA_TILE` 又指向 `MEDIA_MODES` 这张表 —— 于是「这一行有没有下一层」被误判成「有」，可它指回的是**它自己所在的这一层**。响铃状态的首行（`RINGER_CYCLE`，token 也是 `RINGER_TILE`）同理。
- **症状一：多余的选择器。** `ModeMenuPopups` 第二层的分派原来写的是 `modeMenu(picked.token) != null` ⇒ 点「播放/暂停」先收菜单、再起一格单选弹窗，里面列的又是同样那五条（用户口径「点播放/暂停时会弹出来」）。
- **症状二：同时选中两行。** `isBound` 里那条「还有一层的行」的展开（原本是给灵感语音写的：绑「开始」或「结束」都算那一行绑上）把**兄弟**当成了**子档** —— 绑「播放」时逐行问下来，「播放/暂停」那一行也命中，于是两行一起打勾。
- 判据拆开，各问各的：
    - 新增 `ActionCatalog.hasDeeperLevel(spec)`：**那张表里没有一行与它同 token** ⇒ 它才是标记行（灵感语音），表里那几行才是它的子档。`ModeMenuPopups` 第二层分派改用它。
    - `isBound` 的展开加同一道闸：**只有一条都没剔掉**时才往下展开；剔掉了就说明这一行本身就是表里的一行，落到常规判据按整串比，与其余叶子同一把尺子。
- **`isEntryTile` / `popsSelector` 一个字都没改**：它们问的是「这一**格**点开有没有菜单」，对取值格正该为真 —— 换成 `hasDeeperLevel` 会让点「媒体控制」那一格直接写 `keyevent:85`、不再弹那层菜单。层级不同，判据就该不同（`popsSelector` 的 KDoc 补了这条区别，`hasDeeperLevel` 的 KDoc 写了反方向的那一半）。
- 顺带修正的三处：
    - 响铃状态那一层的「循环」行**以前一次都没打上勾**（它自己的 token 与格子相同，展开后只剩三个兄弟，没有一条能与 `keyevent:164` 相等）——现在绑「循环」就勾「循环」；
    - 网格「媒体控制」那一格的小字、以及最终文案（`媒体控制 - 播放`）以前会写成「播放/暂停」（`boundModeOf` 取到的是表的第一行），现在取到真正绑的那一档；
    - 点「循环」同样不再弹那张多余的选择器。

### 修复：一块里「添加场景」（加一条**条件**）插进来的那一行是生硬插入

- 症状：一条规则里点「添加场景」再加一条条件时，那一行条件没有进场动画 —— 满高直接出现（用户口径「列表里面，一块里多条件添加时…是生硬插入的」）。加**整条规则**那条路一直是有动画的，所以第一次我改错了地方（见本节末尾的更正）。
- 根因在共享的那一层：`CardList` 记行的进出场状态用的是 `remember(index)` —— **只认位次**。条件行是**追加**在条件表末尾的，于是新行落到的那个位次原本属于「动作那一行」，`remember` 把那份状态原样交了出来：它 `currentState = true`（动作行一直在场），新行于是先以满高出现一帧、再被 `targetState = false` 拉去收缩、下一帧又展开回来 —— 读起来就是「啪」地插进去、还闪一下。
- 修法：给 `CardRow.Item` 加一位 **`rowKey`（这一行在列表里的身份，`null` = 照旧按位次）**，`CardList` 改成 `remember(index, row.identity())`。条件行的身份就是**那条条件本身**（`BranchCondition` 是 data class，结构相等，改内容才换身份），占位行「未选择场景」不给身份 —— 它被第一条真条件顶掉时正好换一份新状态，所以**第一条条件也能从 0 高展开**。
- 这一位只在需要时给：其余 `CardList` 调用点都不传，`identity()` 返回 `null`，`remember(index, null)` 与原来的 `remember(index)` 逐帧等价。
- 改某一条条件的内容（亮屏 → 锁屏）会换身份 ⇒ 换一份新状态，但那份从 `visible`（此时为 `true`）起步，所以**不播动画**，不会闪。
- **更正**：上一版我误以为是「整条规则」那条路，把 `addBranchRule` 里「第一条不播行进场」的 `NO_FRESH_ROW` 特判去掉、又给空态↔表格那层按方向拆了转场 —— 那两处已原样回滚（`BRANCH_BODY_TRANSFORM` 与 `addBranchRule` 的 `first` 判断都回来了）。用户说的不是那条路。

### 修复：一块里的**第一条**条件不是「插入」，是占位行原地换内容

- 症状（用户口径）：点右上角「添加」出一条空场景 → 点「未选择场景」随便选一档 → 那行瞬间消失、高度塌掉，然后选中的场景再滑进来。这一下应当只是**透明度替换**。
- 根因：`applyBranchCondition` 的「追加一条」分支**不区分原来有没有条件**，一律设 `menus.freshCond`。于是「占位行 → 第一条真条件」也被当成「往表里插了一行」，走出「先不可见一帧、再展开」那一套（`RuleBlock` 的 `freshShown`）。
- 修法三处：
    1. **只有原来确实有条件时才设 `freshCond`**（`old.conditions.isNotEmpty()`）：条件表本来是空的，这一下就不是插入 —— 占位行原地换内容，那一行根本不该收起来。第二条起才是真的插入，照旧从 0 高展开。
    2. 占位行与「这块唯一那条条件」**共用同一个 `rowKey`**（`CONDITION_PLACEHOLDER_KEY`）：位置、高度都没变，接着用同一份行状态，连子组合都不重建。
    3. `ItemText` 的标题改成 **`Crossfade`（`COLOR_FADE_SPEC`）**：行首那颗字形本来就在交叉淡（`cardRowStartAction` 里那层），文字硬切就成了「图标在淡、字在跳」。两种内容同字号同边距，交叉期间行高不变 —— 这就是「透明度替换」。同一处也顺手覆盖了动作格「无操作 → 具体命令」这类原地换内容。
- 现在这三条路各按各的性质播：占位 → 首条 = 淡换内容（不动高度）；第二条起 = 从 0 高展开插入；整条规则的第一条 = 空态与表格那层交叉淡入（见上一节回滚）。

### 修改：应用那一族的「哪一个」只有一套写法（网格小字 / 菜单子标题 / 选择应用页页头 / 场景动作格 / 执行提示）

- 症状（用户口径）：重新从网格里点进「选择应用」页，页头子标题只剩应用名；网格里那一格的小字也只有应用名。绑的是某个界面 / 快捷方式时，界面上根本看不出绑的是哪一个。

- 现在只有一个拼法：`core/ActionLabels.appTargetLabel(appName, detail)` —— 应用名 + `-` + 具体是哪一个；具体那一段的**来源顺序也只有一处**（`ui/AppNaming.appTargetLabelOf`）：这一趟刚挑的名字（页头用）→ `Config.appNames` → 老写法 `|名字` → 组件的类名尾段。快捷方式没有最后一档（`包名/id` 里的 id 是给系统看的）。
- 五处共用：
    - 网格「应用控制」格的小字：**只有应用名**（`微信`）—— 前缀与细节都不要（用户口径「只要应用名，不用打开应用和细节之类的」）。这一格只有一格宽，前缀一占名字就只剩一半；而「打开 / 结束」行首那颗字形已经说了（与菜单那两行同一对 `player-play` / `player-stop`），再写一遍是说两次；
    - 点开那层菜单「打开应用 / 结束应用」两行的子标题：`微信 - 扫一扫`（行标题已经写了动词，剩下的就是「哪一个」，而且菜单行宽）；
    - 「选择应用」页页头那行小字：`打开应用: 微信 - 扫一扫`；
    - 系统场景里动作那一格：同页头；
    - 执行时提示：同页头（宿主进程那边按同一套顺序取名字，实现在 `host/action/ActionNotice`）。
- 「要不要带细节」成了 `boundAppName(current, withDetail)` 的**显式参数**（没有默认值）：格子 / 抽屉那一行传 `false`、菜单传 `true` —— 两处摆的仍是同一张清单、同一个取值，只在详细度上分开，省得哪天又各写一套。

- **格子里不再按组件 / 快捷方式换字形**（用户口径）：绑定只分「打开族 / 结束」两档，分别画菜单里那两颗（`player-play` / `player-stop`）。以前按「界面」「快捷方式」各画一颗，同一个格子绑了不同东西时长得像另一个动作，而「具体是哪一个」本来就有下面那行小字在说。随之删掉 `PageIcons.ShortcutMark` / `PageIcons.ActivityScreen`（只剩那处用过，留着就是死常量）。

### 修改：所有命令文案收成一条范式 —— **父动作名: 子动作名 - 状态**

- 起因（用户口径）：要求全应用复核「命令的文案是不是都是 `父动作名: 子动作名 - 状态`，比如 `系统开关: NFC - 切换`」。复核下来**并不统一**：`actionTitle`（步骤行 / 命令卡摘要 / 绑定回执）里开关写成「打开:Wi-Fi」、导航只写「主屏幕」、亮度写成「亮度增加 15%」、变量写成「「计数」+= 1」；只有 `actionFinalTitle`（执行提示 / 场景动作格）那一支带父名。同一个动作在两处一句话两个样子。
- 做法：把两个函数**合成一份**（删 `actionFinalTitle`，`actionTitle` 是唯一实现），所有「念一个动作」的地方（步骤行 / 命令卡摘要 / 执行提示 / 系统场景格 / 绑定回执）逐字一致：

| 动作                     | 文案                                 |
| ------------------------ | ------------------------------------ |
| `setting:wifi:on`        | `系统开关: Wi-Fi - 打开`             |
| `keyevent:3`（主屏幕）   | `系统导航: 主屏幕`                   |
| `keyevent:164`（循环）   | `响铃状态: 循环`                     |
| `oplus:voice_memory`     | `小布 AI: 灵感语音 - 开始`           |
| `app:微信/…`             | `应用控制: 打开应用 - 微信 - 扫一扫` |
| `proc:stop:微信`         | `应用控制: 结束应用 - 微信`          |
| `bright:+15`             | `屏幕亮度: 增加 15%`                 |
| `volume:+10`             | `音量: 增加 10%`                     |
| `setvar:计数+=1`         | `自定义变量: 「计数」+= 1`           |

- **应用控制那一族**：`应用控制: <动词> - <目标>`（`打开应用` / `以小窗打开应用` / `结束应用`），拼法只有 core 的 `appControlTitle` 一处。「选择应用」页页头也用同一句 —— 页头大标题只说动词，子标题说目标。
- **目标那一段**（`appTargetLabel`）：`应用名[ - 小窗][ - 组件名/快捷方式名]`。小窗那一档要标出来，否则同一个应用的两条绑定在列表里长得一样。
- 网格 / 抽屉的小字**只写应用名**（`微信`）：那一行只有一格宽（用户口径「格子子标题只写应用名就行，太长了放不下」）；打开还是结束由行首那颗字形说。菜单里那两行的子标题写 `微信 - 小窗 - 扫一扫`（行标题已经写了动词），「选择应用」页页头同这一句。
- 退休的文案键（中英两份 + `Strings` 常量一起删）：`common.open_app_format`、`common.open_mini_window_format`、`common.open_shortcut_format`、`common.stop_process_format`、`common.brightness_format`、`common.volume_format`、`common.turn_on/off/toggle_setting_format`、`app_picker.target_format`、`app_picker.target_detail_format`、`app_picker.open_app`、`catalog.voice_memory_start`、`catalog.voice_memory_stop`；新增 `common.window_tag`（`小窗` / “Mini window”）。整句骨架只剩 `common.prefix_name_format`（`%s: %s`）与 `common.name_state_format`（`%s - %s`）。

  宿主那套 `Toast` 实例复用 / 1.5 秒同句去重 / `Handler` 全部删掉 —— 注入侧本来就有 1 秒同句去重，
  两份账留一份就够。
- `ActionRunner.requestSystemToast` 搬成同包顶层函数，`runShell` 的 `onTip` 也改调它：**全模块只有一个
  提示出口**，以后再加提示不会又绕回本地 `Toast`。
- 注入侧不用重启：`ACTION_TOAST` 的收方一直都在，这次只是把发话人多了两处。

### 修改：动词只剩「打开应用 / 结束应用」，「小窗」只进目标的括号

- 用户口径：「怎么最终文案还是以小窗打开，不是精简了吗」。上一版 `ActionWindow` 走的是
  `以小窗打开应用 - 微信(小窗)` —— 动词与括号各说了一遍小窗。
- 现在 `actionTitle` 里应用那一族只有两个动词：**打开应用** / **结束应用**；小窗是
  **目标的一层注记**（`微信(小窗)`），由目标回调拼（`appTargetLabel` 的 `window`）。
- 于是：`应用控制: 打开应用 - 微信(小窗)`、菜单子标题 `微信(小窗 扫一扫)`、
  选择应用页页头同它、步骤行 `应用控制: 打开应用 - 微信(小窗)`。
- `app_picker.open_window_app`（「以小窗打开应用」）这条文案随之退休（中英两份 + 常量）。

### 修复：系统场景那格多出一层括号（`应用(小窗 组件)(小窗)`）

- 根因是**两处都在拼括号**：`CommandBranches` 用 `appTargetLabelOf` 拼出 `微信(小窗 扫一扫)`，
  而 `stepTitle` 的名字回调 `appTargetName` 又按动作类型补了一次「(小窗)」—— 两层套在一起。
- 修法：给 `CommandText` 加 `stepTitleWithTarget(token, target)` —— 目标那一段**整段由调用方给**，
  里面不再有「名字回调」这一层。系统场景那一格改用它，并把「从动作到目标」这一小段收成
  `appTargetLabelOf(action)` 重载（`AppNaming`）—— 判「哪个字段是目标、哪一个算小窗」的判据
  因此只有一处，调用点不会漏。
- 分工钉死：**拼括号的只有一处** —— 用 `stepTitle`（纯名字回调）时由 `appTargetName` 拼；
  用 `stepTitleWithTarget`（完整目标）时由调用方拼。两种写法不再叠加。

### 复核：四处文案的样式对照（网格小字 / 菜单 / 执行提示 / 系统场景）

四处各有入口函数，**全部由「格名 / 动词 + 档位 + 状态」这一套派生**，只是详细度按「这一处有多宽、
上下文够不够」分三档：

| 动作 | 网格小字 | 菜单（行标题 / 选中行子标题） | 执行提示 = 系统场景 |
|---|---|---|---|
| 打开应用 | `微信` | `打开应用` / `微信(小窗 扫一扫)` | `应用控制: 打开应用 - 微信(小窗 扫一扫)` |
| 结束应用 | `微信` | `结束应用` / `微信` | `应用控制: 结束应用 - 微信` |
| 系统开关 | `WIFI - 打开` | `WIFI` / `打开` | `系统开关: WIFI - 打开` |
| 系统导航 | `主屏幕` | `主屏幕` / — | `系统导航: 主屏幕` |
| 响铃状态 | `静音` | `静音` / — | `响铃状态: 静音` |
| 媒体控制 | `播放` | `播放` / — | `媒体控制: 播放` |
| 灵感语音 | `开始` | `灵感语音` / `开始` | `小布 AI: 灵感语音 - 开始` |
| 屏幕亮度 | `增加 15%` | `增加` / — | `屏幕亮度: 增加 15%` |
| 音量 | `增加 10%` | `增加` / — | `音量: 增加 10%` |
| 自定义变量 | `「计数」+= 1` | —（点它弹变量窗） | `自定义变量: 「计数」+= 1` |
| 截屏 / 录屏 / 自定义命令 | —（顶层格没有「值」） | — | `截屏` / 命令名 |

- **为什么网格小字最短**：一格宽，父名由格子的标题说（「系统开关」「应用控制」），状态 / 具体那一段
  只在菜单与最终文案里写。这是用户逐条点出来的（「格子子标题只写应用名」「太长放不下」）。
- **为什么菜单的行标题就是「档位」**：一级菜单那层有 `Section` 标题写着父格名（`系统开关` /
  `媒体控制`），二级那层每行写取值；选中那一行的**子标题**才是「现状」（状态 / 目标）。
- 执行提示与系统场景**逐字相同**（同一个 `actionTitle`）：`父动作名: 子动作名 - 状态` ——
  这是这一轮的范式，也是审计脚本里 `实现处 = 1` 那条判据守的东西。
- 一处**刻意**的差异：网格「应用控制」小字不写「打开 / 结束」，靠行首那颗 `player-play` /
  `player-stop` 分开（用户口径）；菜单两行的行标题写出来了。
- 一处**值得留意**：网格「小布 AI」格的小字只有 `开始` / `结束`（用户口径「格子和菜单只写开始和结束」），
  单看这一格读不出是灵感语音 —— 若觉得别扭，改成 `灵感语音 - 开始` 只动 `tileSubtitle` 的 else 分支。

### 修改：图标不再自己拼 —— 应用控制换 `category` 一族

- 结论：**只有音量 / 亮度还拼**（底图 + 右下角角标），录屏与应用控制都不拼了。
- 走过的三步（留个记录，别再绕回去）：
  1. 录屏三档 + 应用控制两档都照音量那套自己拼（`ScreenRecordStart/Stop/Toggle`、
     `AppControlOpen/Stop`，角标 `Play` / `Stop` / `Swap`）。真机口径「效果太差了，缺角裁切呢，
     小图标也变形了」—— 这两族的底图上，最好认的那一笔**正好长在要留给角标的右下角**
     （摄像机的镜头、一叠方块的第四块），让位之后底图就不像原来的东西了。
  2. 录屏先退出：三态与音量那种「同一类东西的三个档位」不是一回事（见下一节）。
  3. 应用控制也不画了（用户口径「别画了」）：直接用图标库的 `category` / `category-plus` /
     `category-minus` —— 同一族的底子、角上换符号，一叠方块少一块反而读不出是「应用」。
- 落下的映射：`Glyph.AppControl → category`、`Glyph.AppOpen → category-plus`、
  `Glyph.StopApp → category-minus`（菜单两行与网格里那一格是同一对，`PageIcons.AppOpen` /
  `AppStop` 也指过去）。
- 删掉的：`DrawnIcons` 里的 `AppControlTile` / `AppOpen` / `AppStop` / `appGrid`；`Badge` 缩回
  `Plus / Minus / Gear` 三档（连同 `PLAY_*` / `STOP_*` / `SWAP_*` 那些常量与那一支 `hypot` 墨迹半径）。
- 摄像机底图（`DrawnIcons.ScreenRecordTile`）留下，但**整颗在 24 格里居中**（纵向 6~17.5）：
  第一版压在 4~15.5，与旁边的音量 / 应用控制摆在一列里明显偏高。

### 修改：录屏变成「一个动作 + 弹窗选三态」，行尾不再挂选择器

- 用户口径：「用 dialog 选择器，网格 / 菜单里视为一个动作，点击弹 dialog 选，行尾不用 selector」。
- 网格里那一格、抽屉里那一行都还是**一格 / 一行**「录屏」；点它**不再弹一层菜单**，直接起三行单选弹窗
  （开始 / 结束 / 切换，当前绑的那档打勾）。
- 判据进模型：`ActionCatalog.stateChoices(token)`（名单 `STATE_ONLY_TILES`，此刻只有录屏）。
  同一个名单还决定另外两件事，所以只能有一份：
  - `popsSelector` 对它返回 `false` —— 行尾那颗「点了还有一层清单」的选择器字形不再画（改画取值格的勾选框）；
  - 文案没有父动作可写（见下一节）。
- 三档不再各带字形（`SCREEN_RECORD_MODES` 里删掉 `glyph`，`Glyph.ScreenRecordStart/Stop/Toggle` 一并删除）：
  弹窗是纯文字行，给一条用不上的字形只会让下一个人以为菜单层还在画图标。

### 修改：文案范式补一条 —— **没有父动作时用 `动作 - 状态`**

- 范式仍是 `父动作名: 子动作名 - 状态`，但那要求「上面真有一个父动作」。录屏的三档不是它下面的东西，
  是同一条命令的三种状态，硬套冒号两边会写成同一件事（`录屏: 开始`）。
- 现在：`录屏 - 开始` / `录屏 - 结束` / `录屏 - 切换`（`ActionLabels.nameState`，
  `%s - %s` 仍走字典 `common.name_state_format`，与主句里的横杠同一个来源）。
- 判据只有一处：`ActionCatalog.stateChoices(格子的 token) != null`。四处（步骤行 / 命令卡摘要 /
  执行提示 / 系统场景格）都走同一个 `actionTitle`，所以四处逐字一致。

### 修改：系统场景里「场景」与「命令」之间改用加深带

- 条件执行那一块卡片里，动作行（「做什么」）与上面那几行条件（「什么情况下」）之间换成一条**加深带**（与浮层菜单组间那条同一档、同两个 alpha），不再是一条细线。
- 卡片行组件 `CardRow.Item` 补了 `dividerBefore`（默认 `false` = 细线），目前只有这一处用到。

### 修改：系统场景里「打开应用」也能挑组件 / 快捷方式 / 小窗

- 条件命中后那一支动作的「打开应用」，原来只认应用本身（点一行就选中、没有二级页、也没有小窗），与网格里那份不是一回事。
- 现在与网格同一套：点一行进「选择界面」挑具体组件或快捷方式，菜单里的「以小窗口打开」也在。
- 只认应用本身的仍是两处：「前台应用」**条件**本身（只存包名），以及「结束应用」。

### 修复：从「应用组件」页不选直接返回，抽屉还会弹出来

- 进过二级页（应用组件 / 选择界面）再返回，等于「看过了、决定不选」—— 回到命令页不再把步骤抽屉支起来。
- 没进过二级页（在选择应用页直接返回）仍按原样恢复抽屉：那是「还没挑」。条件执行页那一趟同一口径。
- 点了确认（落盘）之后回来源页也不再弹：那笔「回来支抽屉」的账改成**写盘之前**清 —— 写盘那一路会当场退页，来源页读到它时已经晚了一帧，真机上就是「确认了、抽屉照样弹出来」。
- 根因还有一半：进挑应用页时抽屉**根本没关**（只是被压在下层页面底下），回来时它自然还在。现在压页前先收起抽屉，回来开不开只由那笔账决定 —— 挑成了账已清，就不开。

### 修改：录屏改成三态（开始 / 结束 / 切换）

- 「小布 AI」那一格里的「录屏」仍是一行，点它弹一层选择器：**开始 / 结束 / 切换**，当前绑的那一档打勾。
- 三档都是独立取值：`oplus:screen_record_start`（只起、不当开关）、`oplus:screen_record_stop`（只发停止广播）、`oplus:screen_record`（原来的切换）。
- 升级不受影响：以前绑的那一档就是「切换」，取值没动。
- **录音仍是单档**：ROM 那一条透明界面本身就是「进去就起 / 停」，没有独立的开始 / 结束事件（取证见 `docs/device-findings.md` 17.5），拆不出来。
