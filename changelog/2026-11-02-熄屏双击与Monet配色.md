# 熄屏双击、Monet 配色与卡片换档收口

### 修：熄屏下双击判不出来

- 熄屏抬手之后设备立刻进深睡，双击窗口那一枪不到点 ⇒ 熄屏这一按只剩单击。现在排窗口时若屏幕是黑的，先要一段**带超时**的唤醒锁把 CPU 顶住，窗口走完再自己放。
- 代价写明：**熄屏单击要晚一个双击窗口**（`doubleClickMs`）才执行。此前那一档是「熄屏抬手当场判单击」，为的是熄屏即时响应，但它把双击整档废掉了 —— 双击不能没有，改走顶醒 CPU。
- 唤醒锁带超时、不主动放（漏放一次就是 CPU 再也不睡，多醒几百毫秒是这一档付得起的代价），且不计引用数，超时那一次就是真释放。
- 取不到 `PowerManager` 时静默降级成「熄屏这一按判不出双击」，按键本身不受影响 —— 判定侧不为了顶醒 CPU 把异常抛回输入线程。
- 唤醒锁由装配方注入（借 `SystemContext` 取服务），判定器仍然不碰 Context。

### 加：界面颜色多一档「跟随系统 (Monet)」

- 「更多 → 外观 → 界面颜色」在「跟随系统」下面加一档：深浅同样跟系统走，底子整套换成系统那套配色 —— 底色、卡片、文本、分隔线全跟着壁纸取色。
- 其余三档的底子仍是库那套，强调色只换主色那一族，不会把底色也染成系统色。
- 配置新增取值 `monet`；认不出的写法照旧落回「跟随系统」。

### 改：「强调色」第一档改成跟随系统取色

- 菜单第一档从「蓝色」变成「默认」：种子取系统强调色（`android.R.color.system_accent1_500`），换壁纸 / 换系统配色这一档跟着变；原来那个蓝另立一档「蓝色」（`blue`）。
- **没选过强调色的人，升级后强调色会变成系统那个色**；想留原来那个蓝，去「强调色」里选「蓝色」。
- Android 12 以下取不到这组资源，落回原来那个蓝。

### 改：配色菜单行首的色块改成 2×2 四格

- 原来一块实心方块，现在四个小方块拼成一大块 —— 同一个色的四档透明度（100% / 55% / 30% / 12%），读起来是「这一套色的色板」，而不是四块互不相干的色。
- 六档共用同一个形状，颜色仍逐行给；原来那颗「调色盘」图标改名，现在只给「界面颜色」那一行用。

### 修：卡片里行的进出场会互相顶一下

- 行序（首 / 中 / 末那一档内缩与圆角）原来只按「此刻画得出来的行」算：退场行一藏就让位，还在收缩的行先被顶下去；进场行算得太晚，它自己先在低一档的位置出现、长完再弹回原位。
- 判据改成「退场要播完才让位、进场从第一帧就算在场」，两个方向换档都是净零 —— 多出来 / 少掉的那一档落在卡片边上。
- 已经彻底藏好、但这一帧还挂在组合里的行取「中间」那一档，不再去争首 / 末的内缩。

### 改：菜单里小标题的上下留白放宽

- 从 6dp 加到 10dp：小标题是分组的分界，上下松一点，组与组之间才看得出「这是另一段」。

### 改：换一步时那一行就地换字

- 命令步骤里「换一步」（同长度、只有一个位置对不上）不再播退场 / 入场 —— 原来是旧行收缩、新行展开，看着像「这一行先变矮又长回来」。
- 多出 / 少掉一行、或顺序变了（上移下移）仍走差分，那些要的是进 / 出场与位移动画。

### 改：文案与注释

- 补齐中英文案：「强调色 → 默认」「界面颜色 → 跟随系统 (Monet)」。
- 「界面颜色」菜单、色板清单与卡片列表的类注释跟着现状改口径（档数、种子怎么取）。

### 加：屏幕状态多一档「熄屏」

- 「条件执行 → 屏幕状态」在亮屏 / 锁屏之外加一档**熄屏**：屏幕灭着时成立。**锁屏算熄屏的一种** —— 锁屏那一刻熄屏一定也成立（锁屏上亮着的那一屏同样是「现在用不了」），所以这两档**不互斥**。
- 于是三种状态分别是：亮着没锁 ⇒ 只有亮屏；亮着但锁着 ⇒ 亮屏 + 熄屏 + 锁屏；灭屏 ⇒ 熄屏（锁着的话再加锁屏）。
- 读不到屏幕状态时按「判不出」处理（与其余条件同一条契约），熄屏不成立。

### 改：锁屏那一档换了个字形

- 原来用那颗普通的锁，与「这颗键被停用」那颗是同一颗 —— 摆在一起读成「这一档被禁用了」。锁屏改用带锁的方块，熄屏用手机打叉、亮屏用手机本体，三档各一颗。

### 修：命令列表超过两条时卡片叠在一起

- 两条命令正好一行，看不出问题；三条起第二行直接盖在第一行上。原因是那段网格被塞进了交叉过渡的内容位 —— 那里是**叠放式**的，所有子项都摆在左上角。现在网格自己套一层竖排，多行才按行往下排。

### 改：去掉单条命令下面那行「am / cmd 等命令需 root」

- 已经有「以 root 执行」这个显式开关（开只走 su、关只走 sh），这行提示在替用户判断「哪条命令需要 root」，与实际行为对不上，删掉。中英文案与那个键一并撤掉。

### 改：系统场景的「确认」只在有改动时出现

- 右下角那颗不再恒亮：没改过就没有要写回去的东西，一颗常驻按钮只会让人以为「不点它就白改了」。改完自动滑出去（存盘后草稿重载、改动归零）。

### 改：系统场景换手势不再拦，退出只看当前这一档

- 顶栏那条手势带点一下就换，不再被「先确定或放弃这一档的改动」拦下 —— 换档本来就是「把草稿整份换成那一档」，当前这档没保存的改动跟着丢掉，丢掉的那几条留一条 W 日志。
- 退出这一页仍然会问一句，但判据只是**当前这一档**改没改（草稿只装当前这一档，换过档就是干净的），别的档一概不管。
- 撤掉那句「先确定或放弃这一档的改动，再换手势」的文案与键。

### 改：系统场景保存完留在原页

- 点「确认」写盘成功不再退页，只报一句「已保存系统场景」（中英各一条）；写盘失败仍在原地。
- 那颗按钮从「什么都不改也退页」那一支里出来 —— 没改动时它根本不出现，这一支已是死路。

### 加：系统场景页顶栏那行写键名

- 「条件执行」页顶栏的尾随小标题写**在编哪一颗键**（`「快捷键」`；组合键那一档写 `「侧键」+「电量 +」`）。这一页从「按键绑定」的某颗键进来，进来之后整页没有别处提过是哪一颗。
- 哪一档手势不写在这一行：它由顶栏下那条手势带说，两边各说一半，也就不跟大标题抢宽度。表尾注脚与空态那句仍写「键名 - 手势」，两处共用同一个键名取法。

### 改：系统场景换成三页横滑，滑块跟手

- 单击 / 双击 / 长按不再是「同一张表换一份草稿」，而是**三页并排**：与「按键绑定」同一套分页器，横滑换档、顶栏那条带子的滑块按浮点页码实时跟着手指走（点带子则是翻页动画）。
- 组合键那一趟只有两页（短按 / 长按）—— 双击在组合上没有定义，摆一页写进去也永远不会命中的表比少一页更糟。页数与带子标签读同一处，不会对不上。
- 从「按键绑定」的某一档、或从某组组合键进来时，直接停在**那一档**（进页时把分页器拨过去）。

### 改：三档各一份草稿

- 三页同时在场，共用一个草稿对象会把邻页没保存的东西冲掉 —— 现在一档一份，各编各的表、各播各的行动画、各记各的滚动位置。
- FAB、退出那一问、保存、顶栏「添加」都只看**当前这一页**那份：别的档改没改不参与（退出仍然只问当前这一档）。
- 菜单与三个确认窗改成收「这一页那份草稿」再动它，不再回头去取「当前」那一份 —— 滑到一半点在邻页上也改不到别人的表。
- 草稿层的「在编哪组组合键」提到页面级那一份（三档共用同一个来源），出栈时三份草稿与它一起清。
- 「这一页在编谁」（键名 / 组合键、有哪几档、当前那份草稿）拆到 `BranchOwner.kt`，顶栏、FAB、退出判据与页内注脚共用同一处。
