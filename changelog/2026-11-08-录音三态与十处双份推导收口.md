# 录音三态、文案工厂，与十处「同一句话两份推导」收口

这一批四件事：

1. **功能**：录音拆成三档、「结束」只停不误停、「切换」按真实状态翻面；「前台转小窗」从父子动作改成两态选择器。
2. **修 UI**：长按「额外动作」那一行不再有「未设置」；系统开关三档共用一颗种类字形；亮度 / 音量文案改回「父: 子 - 状态」；格子行尾指示缩小一档。
3. **修 bug**：独立设置里拨一项会把总开关带跑；绑了小窗之后系统开关格冒出一行小字。
4. **重构**：文案收成一个工厂；十处「同一句话在两地各写一遍」各收成一处置（改一处漏一处的后果都不编译报错）。

---

## 新增：录音变成一格三档

- 网格与「添加命令」里「录音」还是**一格**，点它弹三行单选：切换 / 开始 / 结束（与录屏同一个弹窗）。
- 老配置里那条 `oplus:recording` 仍是「切换」，绑定不用改；新两档是 `oplus:recording_start` / `oplus:recording_stop`。
- 行尾不挂选择器字形；格子里那行小字与步骤行按「录音 - 开始」念（与录屏同一套范式）。

## 新增：「结束」只停，「开始」不会误停

- 「结束」只停，不弹录音页；**没在录音时什么都不做** —— 对录音机发一次「没有采集的停止」，它会当场弹出一张录音流体云（真机上撞到过）。
- 「开始」撞上正在录的那一次什么都不做 —— 否则那条入口会把在录的停掉；查不到状态时也不发，报一次「没执行成功」。
- 两档都走录音机自己导出的控制接口（它没有停止录音的广播）。

## 修改：录音的「切换」按真实状态翻面

- 原来那一下完全交给录音机自己判断（它的判据里还夹着「录音页在不在前台」）；现在在录就停、没在录才起。
- 问不到状态时退回原来的行为（那条入口本身就是开关）。

## 修改：长按「额外动作」那一行只认动作本身，不再有「未设置」这一档

- 这一行的取值不再滤掉「无操作」：`Action.None` 就是它的默认值，不是「还没配」。原先滤掉之后
  界面多出一个「未设置（松手不做事）」状态 —— 与「无操作」是同一个意思却两种说法，
  还得为它单独准备一颗图标（那颗起初借的是网格里「系统按键」的，两处长得一样，
  而那一格绑的是一组按键动作，读起来像这一行在控制系统按键）。
- 于是这一行**所有状态都有图标**，且图标就是那个动作自己的（`actionIcon(token)`，
  与网格里对应那一格同源）：无操作是 `ban`、应用控制是应用类、自定义命令是终端。
  `LongPressSpec.releaseIcon` / `releaseLabel` 随之改成非空 —— 卡片不必再为「没值」留兜底。
- 一并删掉死掉的文案 `binding.long_press_release_empty` / `Strings.BINDING_LONG_PRESS_RELEASE_EMPTY`
  与两份 locales 里对应的条目：它只服务刚才那个「未设置」状态。
- 副标题也走**标题格式**（用户口径「子标题走标题格式」）：有父动作写 `父动作: 子动作 - 状态`
  （`系统开关: WIFI - 打开`、`快捷功能: 手电筒 - 关闭`），没有父动作写 `动作 - 状态`
  （`录屏 - 开始`）。那就直接是步骤行那一份，不再为这一行另立语序 ——
  原来「系统开关 / 灵感语音」两族被改成 `东西 - 状态`（`手电筒 - 关闭`），理由是父格名是分类、
  写不下也不该写；但同一个动作在别处叫「快捷功能: 手电筒 - 关闭」、到这里少一截，反而认不出是哪一格。

## 修改：系统开关的三档共用一颗「种类」字形

- 原先把**状态**也画进图标：明确「打开」换 `toggle-right`、明确「关闭」换 `toggle-left`，
  只有「切换」那一档留开关自己的字形。于是同一个开关的三档长成三种不同的东西，看着像三个动作。
- 现在一律按**开关种类**取字形，三档共用一颗；是开是关由行首那句「打开蓝牙」「关闭蓝牙」说。
  这一族本来就没有自己的字形，它们只是某条开关的三种取值（用户口径：「它们不是没有图标吗」）。
- `ToggleLeft` / `ToggleRight` 两处 import 随之删掉。
- 这一族后来还收成了 `SwitchKind` 枚举（见下面「图标：开关种类」），漏配字形从「掉 Dots」变成编译错误。

## 修改：「前台转小窗」改成两态选择器，不再是父子动作

- 原来它是**入口格 + 二级菜单**：网格里一格「前台转小窗」，点开再列「展开 / 收起」两行，
  文案写成 `前台转小窗: 展开`。
- 现在与录屏 / 录音同一档（`ActionCatalog.STATE_ONLY_TILES`）：格子本身就是那个动作，
  点它直接弹两行单选弹窗，文案写成 `前台转小窗 - 展开`，行尾也不再挂选择器字形。
  两档只是同一个动作的两种状态，中间再夹一层只写着「前台转小窗」的小标题等于把同一句说两遍。

## 修改：音量与亮度的文案改回「父: 子 - 状态」

- 这两族的数值是**状态**，不再编进子动作里：`音量: 增加 - 10%`、`屏幕亮度: 设置为 - 50%`。
  网格小字、百分比弹窗那一行、步骤行与执行提示仍是同一句（`增加 - 10%`）。
- 它们因此与系统开关走同一条标准支路（父格 → 档位 → 状态），六条专用文案
  `catalog.brightness_*_of` / `catalog.volume_*_of` 与两处拼装函数随之删掉。

## 修复：独立设置只在**第一次**打开时抄公共值，之后用自己的

- 原先每一趟「关 → 开」都把公共设置那五项重抄一遍（判据是「当前开关是关着的」）。
  于是用户把独立设置调成自己想要的样子、关掉总开关、过一阵又打开 —— 那套值被**悄悄扔掉**，
  换回公共设置。读起来像「我的设置没保存」。
- 现在每一档带一位 `OwnSettingsSeeded`：**第一次**打开总开关时抄一次公共值并置位，
  之后开关怎么拨都不再读公共那份。判据从「当前开关关着」换成「没播过种」。
- 播种这件事仍然必须有：这一档从来没配过时，五项是各自的代码默认值（振动关着、强度中档、
  提示关着、模板是默认那句），与公共那份往往不同 —— 打开开关却看到一片不一样的旧默认值，
  读起来是「开了没生效」。
- 落盘：`ConfigFields.F_OWN_SETTINGS_SEEDED` + `KeyConfig` / `ComboKey` 各一位 +
  `KeyDto` / `ComboDto` 各一个可空字段（老文件缺它 ⇒ `false` ⇒ 第一次打开会播，与新装一致）。
- 这一位**不进 `KEY_FIELDS`**（广播字段清单）：注入侧和执行侧都不读它，它只服务界面
  「要不要抄一遍」。为此在 `ConfigFields` 的文件头补了这条例外 —— 否则下一个人照「加字段要
  改几处」那四步做，会顺手把它塞进广播。
- 判据日志多一位：`own_settings 提交：field=… 提交值=… 现存=… 已播种=… 写入=…`。
  下次再报「又被覆盖了」，看一眼 `已播种` 就知道是没写上还是判据又错了。

## 修复：卡片把「配置读不出来」报成「已关闭」，且执行侧主开关对不上时不说话

真机反馈：「设置生效异常了，但首页卡片没显示异常状态，点击的提示条也走默认文案」。

两处判据各缺一档，症状合起来就是「看起来一切正常」：

- **卡片为什么说「已关闭」**：`HomeActivationCard` 的状态分支第一档是 `!masterOn -> Disabled`，
  而 `masterOn` 读的是 `configState.config.global.enabled` —— 配置读不懂时那份是 `Config.DEFAULT`，
  主开关读出来就是 `false`。于是「文件读不懂」被说成「你自己关的」。
  `Disabled` 还是**无色相**的那一档（不是红色），用户不会去查。
  现在 `facts.readOnly -> Inactive` 排在它前面：读不到配置时说不清用户关没关，报异常比报「已关闭」诚实，
  具体原因由 `blockedReason()` 给（读不懂 / 旧宿主，下一步不一样）。
- **提示条为什么走默认文案**：`ready` 的判据是
  `hostUp && respondOk && configSideOk && !hostConfigBroken`，**不含 `hostEnabled`**；
  而「运行状态」里「设置生效」那一行的 `ok` 含它。两者不同源，于是存在一档：
  执行侧读到的主开关是关的、你这边开着 —— `ready` 说正常、`blockedReason()` 落空
  （于是 `?: MODULE_UNAVAILABLE_HINT` 那句「页面还没就绪，重进本页试试」，而重进不好使）、
  「运行状态」却红着。
  这一档有两条来路：**开机还没解锁**（`opluskey_config.conf` 在 credential-encrypted 存储里，
  解锁前宿主按 `Config.DEFAULT` 报上来）、以及配置刚写完而宿主那次读早于写盘
  （`configPending` 那道宽限只管注入侧）。
- 收法：`LinkFacts.hostSwitchMissing = !hostEnabled && !masterOff` 一位，三处同源 ——
  `ready` 加它（整页闸与卡片随之）、`blockedReason()` 加一档（文案复用「设置未同步，重进本页即可」，
  对用户来说都是「另一侧手上不是这一份」）。`masterOff` 为真时不算，那是用户自己关的。
- 顺手把这条单向关系写成 `blockedReason()` 的 KDoc：**`ready == false` ⟹ 这里一定给得出话**
  （反过来不成立 —— 主开关不进总闸，否则它锁死自己）。这就是加档时的检查表：
  往 `ready` 里加一项，必须在这里加一档，否则又是「整页灰着、卡片报异常、却说不清为什么」。

## 修复：配置坏了旁边就有一份好的，却从来不去试

- `ModuleFiles.read` 走 `AtomicFile.openRead()`，而它**只在主文件缺失时**回落到备份；
  主文件在、内容坏了（写到一半被杀 / 手改错几个字节 / 记事本存成别的编码），它照样把坏内容交回来
  ⇒ `Load.Unreadable` ⇒ 页面进只读。用户的选择只有「清空配置」，把绑定、开关、变量一起丢掉。
- 第一版想复用 `AtomicFile` 自己那份备份，装到机器上一看：**目录里根本没有 `.bak`**。
  现代 `AtomicFile.finishWrite` 是 `sync` → 关流 → 删掉遗留的 `.bak` → `.new` 改名成 base，
  中间不再留旧的一版；`.bak` 只在「写盘途中被杀、下次 `openRead()` 发现」这条老路径上存在。
  也就是说：备份不是没找到，是**从来没人写过**。于是改为自己写。
- 现在 `ConfigStore.write()` 在落盘前先 `snapshotModuleFile()` 把当前主文件复制成 `.prev`。
  名字**不能叫 `.bak`** —— `AtomicFile.openRead()` 一见到 `.bak` 就认定「上次没写完」，
  会删掉主文件把它顶上去 ⇒ 每读一次就回滚一版。`.prev` 它不认，是纯给 `ConfigStore` 看的。
- `Load` 多一档 `Recovered`：主文件解析失败时再试 `.prev`，读得懂就用它。
  页面**照常可写** —— 用户随便改一处，`write` 把这份写回去，主文件当场修好，下次不再恢复。
- `.prev` 也读不懂（连坏两次）时仍走 `Unreadable`：页面只读、绝不拿默认值顶上去。
- 读的那一层**不做写**：宿主按键路径每秒进来好几次，在那里改盘是不可预期的 IO 与权限问题。
- 「恢复回来的比最后一次成功写入**旧一个版本**」这件事要说出来，否则用户只会发现
  「我配过的那一项不见了」而毫无线索：`ConfigState.configRecovered` → `LinkNotice.ConfigRecovered`
  → 提示条一句「配置已从备份恢复；最近的改动可能丢了，改一次即可」。
  它排在 `noticeReason()` 最前 —— 与链路自检无关，而且比「跑着旧包」更该先说。
- 三处消费点跟着补：宿主自检日志（`SideKeyGestureHooks`，这条日志是「某一项改动不见了」的唯一线索）、
  `ConfigStore.read()` 的只读方入口（Recovered 与 Ok 同义）。
- `PageLoadSnapshot` 的三个配置结论（内容 / 只读 / 恢复）收成 `ConfigRead` 一个类型：
  加第三位时它顶到了 detekt 的 `LongParameterList`，而这三项本来也是一起用的。
- `snapshotModuleFile` / `readModuleFileBackup` 是顶层函数而不是 `ModuleFiles` 的成员：
  加上这两个后它顶到类级 `TooManyFunctions`（11/11）。`delete()` 的清理列表跟着加上 `.prev`，
  否则「重置模块」之后还会剩一份能恢复回来的旧配置。
- `slots()` 也把 `.conf.prev` 认成一种合法形态。它只收 `(.conf|.conf.bak|.conf.new)` 三种时，
  「主文件不在、只剩一份 `.prev`」（上一次写入没落地）这个槽会**从这个模块的槽列表里消失** ——
  槽号随即被 `nextSlot` 复用给另一份新配置，随后那份 `.prev` 要么被新槽的 `delete` 带走，
  要么留下来，等新槽哪天读不懂时被当成「它的上一版」恢复回来（内容完全是别人的）。
  这与文件里早就写明的那条不变式是同一条：**只在磁盘上留下痕迹的槽，也算槽号被占着**。

## 修复：配置怎么还是坏的 —— 加字段没抬 `ConfigCodec.VERSION`

- 上面那条 `.prev` 恢复装上机器后，配置**照样读不出来**。取出设备上那份
  `/data/user_de/0/com.oplus.gesture/files/opluskey_config.conf`：11824 字节、魔数正确、
  正文完好，就是被判「读不懂」。
- 根因不在文件，在 `ConfigCodec`：这一轮给 `KeyDto` / `ComboDto` 各加了
  `own_settings_seeded`（独立设置那五项被公共值播过种没有），**却没抬 `VERSION`**（还是 33）。
  `version == VERSION` 那一支的校验方式是「拿当前 DTO 把正文重新编码一遍、比 md5」——
  多一个字段就多一个键，重编码的字节与旧文件必然不同 ⇒ 每一份已有配置当场全部判死。
- 抬到 34 之后正常读出（日志里键与组合键都在，没有「读不懂」那一行）。
- 这已经是**第三次**同类事故，所以在枚举注释里把三次现场都记下来，
  并把那条规矩写成一句能照着做的话：**加字段与抬版本是同一次提交里的两件事**，
  只做前一件，代价是所有存量配置下一次读取全部失败 —— 而失败现场看起来像「文件坏了」，
  排查方向会被带偏到文件系统 / 权限 / 编码上去。
- 顺带把「备份恢复」也在日志里说清：日志是「某一项不见了」的唯一线索，恢复这件事必须留痕。

## 修改：灵感语音的「开始 / 结束」改按落在哪一格判

- 原先按菜单**行号**判（`index == 0`）—— 行序一动就会说反。改按「这个动作落在哪一格」判。
- 顺带删掉死代码：`settingTitle`（输出与标准支路逐字相同）、`SystemSwitches.find` / `titleOfId`。

## 修改：网格格子行尾那颗指示图标缩小一档

- 24dp → 20dp：格子只有一格宽，行尾那颗是**提示**（点了还有一层 / 选没选），不是内容 ——
  与行首那颗（22dp）同高时抢标题的横向空间。
- 三种指示器（选择器字形 / 右箭头 / 选中框）仍是同一尺寸，格子里的内容不会跟着挪。
- 通用的行尾尺寸（`ROW_END_ICON_SIZE` 24dp）不动：首页、选择应用、关于页那些行的可用宽度
  比两列的格子宽得多，这一档只属于网格。

## 修复：绑了「前台转小窗 - 展开」之后，系统开关格也冒出一行小字

- 格子小字里「系统开关」那一支只判了「这一格是不是系统开关」，**没判当前动作落在哪一格**，
  然后直接取动作的详情 —— 而那个函数只看动作、不看格，别的格绑了什么它就念什么。
  于是选了「展开」的小窗，系统开关格下面也挂上「展开」。
- 加一条判据：`modeHitOf(current)?.tile?.token == SWITCH_TILE` 才写。与亮度 / 音量 /
  变量那几支的 `as?` 是同一个意思（「先确认这个动作属于这一格」），只是开关这一族的动作
  得靠 `modeHitOf` 才认得出归属。

## 修复：独立设置里拨「执行时提示」，「使用独立设置」那颗自己又关回去

- 现象（真机）：打开「使用独立设置」→ 再点「执行时提示」→ 顶上那颗总开关自己弹回关闭。
  连点会来回翻。
- 根因：卡片把**整份** `OwnSettingsValues` 交回来，而那份值是**渲染这一帧时**从 `owner` 读的。
  写盘 → 重组之间只要错开一步，交回来的就是上一帧的整份值（含旧的 `useOwnSettings=false`），
  于是写回时把总开关一起抹平。日志里能同时看到 `values.useOwn=false` 与 `现存.useOwn=true`。
- 改法：写回**按字段合并** —— 卡片在提交时说明这次改的是哪一项（`OwnField`），
  页面用 `ownerIn(configState.config.value)` 现取的那一份作底，只覆盖被点的那一格
  （`OwnSettingsValues.withField`）。别的项有多旧都不再影响结果。
  `OwnSettingsCard.onWrite` 因此多一位 `OwnField`；`commonRows` / `strengthRow` / `toastRows`
  的 `edit` 也带上它。
- 顺带修掉一处同源问题：「是不是刚从关拨到开」的判据原先用 composable 捕获的 `owner`，
  值过期时抄公共设置那一段会漏掉或重复；现在改用现取的那一份。
- 留了一条 W 级判据日志：`own_settings 提交：field=… 提交值=… 现存=… 写入=…`，
  下次这类「某一项被别的行带跑」的问题看一眼日志就能定位。
- `OwnField` / `OwnSettingsValues` / `values()` 随之从 `OwnSettingsCard.kt` 搬到
  `OwnSettingsValues.kt`：那支卡片已经顶到 detekt 的文件级函数数上限，而这两样东西也不是界面
  —— 「按字段合并」的规则只有一份，卡片与页面都用它。

## 修复：`appPickerSelectedPkg()` —— 死代码 + 第二份（错的）包名拆分

- `SettingsPage` 里有个 `appPickerSelectedPkg() = appPickerSelectedTarget()?.substringBefore('/')`：

## 重构：「一个动作怎么念」收成一个工厂 + 两个出口

- 原先这句话有**四个拼装函数**和**五个对外包装**：`builtInTitle`（父: 子 - 状态）、
  `ModeHit.detail`（子 - 状态）、`appControlTitle`（动词 + 目标）、`varSetTitle`（表达式），
  外面再包出 `actionTitle` / `actionDetail` / `stepTitle` / `stepTitleWithTarget` /
  `releaseActionTitle`，调用点各挑一个。同一个动作因此能出三种句子 ——
  「改一处漏一处」都是从这儿长出来的（长按那一行的语序、系统开关格冒小字都是）。
- 现在只有 `core/model/CommandTitle.kt` 一处：一个 `private join` 拼句子，两个**按显示位置命名**的
  出口 —— `forSentence`（执行提示 / 步骤行 / 命令卡 / 场景格 / 长按「额外动作」那一行）、
  `forTile`（网格与抽屉里那一格的小字）。调 `join` 的权限收在类里，谁碰不到。
- **「额外动作」那一行走 `forSentence`**：它上面那行标题写的是「额外动作」四个字，
  不是某个格子的名字 —— 省掉父名之后 `WIFI - 打开` 读不出是哪一格的东西。
  这一处只动了调用点。原先为它留的 `forValueRow` 出口（省父名、留名字）在改成完整文案之后
  零调用点，一并删掉 —— 留着会让「几个出口」名不副实，下一个人还会以为「那半句是标准写法」。
- **出口按位置命名，不按裁剪命名**：叫 `full` / `bare` / `nameOnly` 等于把「我这儿该要哪半句」
  推给每个调用点 —— 四处重复里有三处就是判错的。按位置命名后，调用点只说「我在哪儿显示」，
  挑错半句在设计上就没有位置。
- `forTile` 比 `forSentence` **省一档**：「格子本身即动作」的那几格（录屏 / 录音 / 前台转小窗）
  只写状态（`展开`），不写名字 —— 那一格的标题就是那个动作，小字再写
  `前台转小窗 - 展开` 等于把标题抄一遍。判据是 `TitleSegments.nameIsTheTile`
  （由内置那一支在「这格有状态档位」时置位），不在调用点各判一次。
  真机反馈：「前台转小窗」那一格的小字原本就是「前台转小窗」。
- **「无操作」的空串从工厂里挪走**：`forSentence` 原先带一句
  `if (action is Action.None) return ""` —— 那是「提示这个位置不弹」的规矩，不是「这个动作怎么念」。
  塞进工厂的代价有两个：长按那一行只好自己再特判一次（顺手把 `ActionCatalog.label` 的调用点
  变成 2），而同一个动作在「提示」与「步骤行」两处念出两种结果（回执那边还得拿 `ifBlank` 兜）。
  现在这句话在 `GestureExec.noticeIfNeeded` 里（那函数本来就有 `if (what.isEmpty()) return`，
  只多一行 `if (!action.isBound) return`）：工厂只念句子，提示自己决定弹不弹。长按那一行的特判
  随之删掉，`None` 直接念成「无操作」—— 这一行本来就要看见这四个字。
- `CommandTitle.of(parent, name, state)`：材料已经齐了、手上没有 `Action` 的那几处
  （「选择应用」页顶栏）也走同一个 `join`。原先 `appControlTitle` 自己用 `prefixName` +
  分隔符键拼了一遍，与契约那一份并存 —— 旁路一旦留下，下一个人就会照着抄。
- 分隔符**只有一处**：`%s - %s` 由 `link()` 逐段折叠、`%s: %s` 由 `join` 套一层。
  清单里那段「中间层用横杠连起来」也走 `link`，不再各写一次 `joinToString(" - ")`。
- `commandTitleOf` **不写 `else`**：`Action` 是 sealed，逐个列全。写成 `else -> builtInTitle` 的话，
  「新增一族忘了登记」会静默降级成内置文案、不报错；现在新增动作子类会当场编译失败并点名那一支。
- **四种形态不落成四个类**：父类看「父名」与「状态」两个 null 就推得出来
  （单一功能 / 父子 / 父子+状态 / 单一+状态）。形态是**推出来的，不是登记出来的** ——
  加一档动作不会因为忘标类型而写错句子。
- 材料只有三段：父名、名字、状态。父名与名字从清单取，状态由开关/百分比那两支给；
  只有「应用目标」与「变量表达式」这两段不在清单里（token 里没有名字，只有调用方查得到），
  所以它们各有一条 segments。一共四个常量，**不是五个子类** —— 按「状态从哪来」分族时发现
  三个族的另外两个方法逐字相同，留成空壳子类只会多出维护面。
- 句子**每次调用现拼**（不构造时拼好）：字典是运行时切的，构造期拼会把文案冻在当时那门语言上。
  两个出口都是无状态对象，也不需要按 token 建缓存。
- 调用点同步收口：宿主执行提示、`stepTitle` / `stepTitleWithTarget`、长按「额外动作」那一行、
  绑定回执、`ActionCatalog.label` 的变量那一支都走 `commandTitleOf(...).forSentence`；
  格子小字的六支分支压成三支（应用格用应用名，其余格先判「动作是否真落在这一格」再问 `forTile`）。

## 重构：八处业务规则各收成一处置

形状都一样：同一条业务规则在两个地方各写了一遍，改一处漏一处的后果**都不编译报错**。
下面每一节的收益都是同样的三类之一 —— 不会出两种行为、改的时候只改一处、加了东西会红。

（连同上面那个文案工厂、以及「修复：`appPickerSelectedPkg()`」那一处，这一批一共十处。）

### 键码归不归模块 → `KeyId.claimsBuiltin`

- 原先两处各推一遍「这个码是不是模块自己认领的」：动作解析（`CLAIMED_CODES`，把
  `KeyId.builtins` 摊平成一张常量表）与注入前复核（现写 `builtins.any { code in it.acceptedKeyCodes }`）。
- 漂移后果两个方向都很难看：漏改解析侧 ⇒ `keyevent:<自己的码>` 拦不住，注入出去在
  `system_server` 里每 ~100ms 一轮自持循环；漏改复核侧 ⇒ 用户自己收的键被误拦。
- 现在唯一判据是 `KeyId.claimsBuiltin(code)`（companion 上，含侧键那一族的 780/781/782），
  两处都问它。`CLAIMED_CODES` 删掉。**不含**自定义键的码 —— 那些只存在于配置里，
  `core` 拿不到，调用点自己叠 `Config.keyForCode`（这一半的差别是正当的）。

### 应用名 / 目标名的优先级 → `core/model/AppName`

- 界面 `ui/AppNaming.appNameOf` 与宿主 `host/action/ActionNotice` 各有一条优先级链，
  顺序**相反**：界面把「落盘时记下的名字」摆在 `PackageManager` 前面（理由「冷启动清单还没回来」），
  宿主摆在后面（理由「现查更准」）。两个理由都成立，但不可能同时成立 —— 同一个应用
  在界面上叫旧名、在提示里叫新名。
- 界面那条「冷启动」的理由其实不成立：查名字走的是 `PackageManager` 的同步查询，
  与「清单有没有回来」无关。第 2 档真正有用的是**应用已卸载**那一档（PM 查不到，配置里还记着）。
- 现在顺序只在 `core/model/AppName.kt`：**现查系统 → 落盘那份 → 老配置 `|名字` → 包名**。
  两个 `inline` 函数（`resolveAppName` / `resolveTargetName`）定顺序，两侧只回答
  「这一档你取到什么」—— 与 `CommandTitle` 同构：材料由调用方给，顺序由 core 定。
- 顺带把「查不到」与「名字恰好是包名」分开：新增 `appLabelOrNull` / `pmLabel` 给 `null`，
  否则下面三档永远走不到（应用卸载之后界面上只剩包名，而配置里明明记着它从前叫什么）。

### 有没有绑定 → `Action.isBound`

- `!is Action.None` / `== Action.None` / `is Action.None` 原先散在 24 处（`Config.boundClicks`、
  `GesturePlan`、`GestureExec` 七处、`GestureDetector`、界面几处…）。跟这条判据走的行为很多
  （振动、记「最后一次动作」、进执行计划、提示弹不弹、组合键透传），它们必须同时成立 ——
  一半按「绑了」处理、一半按「没绑」处理，表现是「振动了但没执行」这种没人看得懂的样子。
- 收成 `Action.isBound`。不叫 `isEmpty`：`isBarePrefix` 说的是「写法不完整」（坏配置），
  与「什么都没绑」（正当配置）是两件事。
- `when` 里的 `is Action.None ->` 保留（结构分派，不是判「有没有绑」）：`CommandTitle` 与
  `ActionRunner` 各一处。

### 点这一格会发生什么 → `ActionCatalog.clickKind`

- 界面各处自己判：网格判「有没有档位菜单」画选择器、菜单行判两个 token 画箭头、
  抽屉那套又判一次 —— 同一格因此长出了**两种指示**：「应用控制」在网格里画选择器
  （它弹原地菜单，对的），在抽屉里画右箭头（说它跳页，错的）。
- 现在 `ActionCatalog.clickKind(spec)` 回答「点下去干什么」：`DIRECT` / `MENU` / `STATE` /
  `PERCENT` / `SWITCH` / `PAGE_APP` / `PAGE_VARS`。界面只 `when` 它。
- `PAGE` 拆成 `PAGE_APP` / `PAGE_VARS` 是必须的：合成一个的话，界面还得回去判 token 才知道
  跳哪一页（网格点击那一处原先正是这么干的）——「UI 只 when 它」就不成立。
- 「是不是入口格」改为从 `clickKind` 派生；原先那个「行尾画选择器」的判据零调用点后删掉。

### 条件表取动作 → `pickAction`

- 单键的 `actionFor` 与组合键的 `resolve` 原先逐字相同：
  `rules.firstOrNull { it.appliesTo(gesture, matches) }?.action ?: actionOf(gesture)`。
  注释给的理由是「合并得先让两个类共一个父类型」——**那个理由不成立**：要的只是
  「一张表 + 一个兜底动作」，抽成顶层函数就够（两个类确实没有别的共同字段）。
- 现在 `core/model/StateRule.kt` 的 `pickAction(rules, gesture, fallback, matches)` 是唯一实现，
  两个类各一行转调。
- 为什么这句必须只有一份：条件分支的错**只在真机上看得见**（某个系统开关打开时本该走另一条），
  而两份实现里只要有一份判据差一点（一处先判 `enabled`、一处没判），就只会在那天现形、不报错。

### 语言档 → `applyLanguage`

- `I18n.currentLanguage = AppLanguage.fromCode(config.global.language)` 原先在三个地方各写一遍：
  设置页写盘出口（`ui/ConfigWrite`）、界面读盘之后（`ui/PageLoad`）、宿主每次执行前
  （`host/GestureExec.syncLanguage`）。三处都必须有（不同进程 / 不同时机），但**写法**不该有三份。
- 收成 `core/i18n/I18n.kt` 的 `applyLanguage(code)`，三处转调。
- 忘调的表现是「配置本身是对的，界面还是旧语言」—— 用户看到文案不跟着切，而盘上明明写着 English。

### 图标：`Spec.glyph` 改必填

- 原先「这一格画什么」有两个入口：清单里 25 处 `Glyph.` 与界面 `actionIcon(token)` 的 33 支
  token 分支。`Spec.glyph` 可空，空着就按 token 猜 —— 加一条动作漏了图标**不报错**，
  只掉到 `Dots`（看着像「这条本来就没配图标」）。
- 现在 `Spec.glyph` 的类型是 `ActionCatalog.GlyphSource`，**必填**：

    ```kotlin
    sealed interface GlyphSource {
        data class ByCommand(val kind: CommandKind, val steps: Int, val root: Boolean)
        data class BySwitchKind(val id: String)
    }
    enum class Glyph : GlyphSource { ... }   // 枚举的每个取值 = 一支固定字形
    ```

    为什么不是直接 `Glyph`：两类条目的字形由**别的字段**决定（自定义命令看 `kind/steps/root`、
    系统开关看种类 id），塞进枚举会逼出 `Glyph.Command` 这种占位值 —— 占位值一出现，
    「必填」就退化成「随便填一个能编译的值」。
    为什么 `Glyph` 自己就是实现：清单里那 25 处 `glyph = Glyph.X` 不用套一层包装。

- `specIcon` 改成对 `GlyphSource` 做 `when`，**不再按 token 猜**。`actionIcon` 退回兜底位置：
  只服务「没有 Spec 可言」的 token（步骤行、执行提示、手写配置），那 33 支精确分支保留 ——
  步骤里存的是 token 本身，可能指向一个清单里挑不到的动作。
- 补齐 71 条 `Spec` 的字形（`Glyph` 枚举从 25 项扩到 55 项），编译器逐个点名，一个没漏。
  三态弹窗那几行（录屏 / 录音）原先「不带字形，因为弹窗是纯文字行」——
  现在给「那个动作自己的字形」，将来弹窗要画图标不必回来改。
- 顺带把「只有 token、为回执文案造一个假 Spec」那处改成走 `pickToken` —— 它本来就是
  「清单外的 token」那一条路，回执文案也更准（`打开应用:微信`）。给 `pickToken` 补了
  `appName` 参数（挑应用要一并记名字，原路径有这个功能，别丢了）。

### 图标：开关种类 → `SwitchKind` 枚举

- 原先加一条系统开关要动**两处**：`SystemSwitches.ITEMS` 加一行、界面上那张
  `Map<String, () -> ImageVector>` 加一支。漏了字形**不报错**，只是掉成 `Dots`。
- 种类 id 本身也散着：`SettingSwitch` 里有 `id == "rotation" || id == "nfc"` 这种裸字面量，
  `SystemSwitches` 里又有一组 `ID_*` 常量（和 `ITEMS` 里的 `settingToken("bt")` 是两份）。
- 现在 `SwitchKind` 枚举是唯一真源（13 项，每项一个 id）：
  · `ITEMS` 的条目改成 `Item(SwitchKind.BT, 字典键, "蓝牙")`，`token` 由 `kind.id` 推；
  · `ID_*` 常量删掉，`SettingSwitch` 里 8 处（含两处裸字面量）改成 `SwitchKind.X.id`；
  · 界面那张表改成对枚举做 `when`，**没有 `else`**。
- 收益是**编译期**的，实测过：往 `SwitchKind` 加一个不配字形的值，编译当场报
  `'when' expression must be exhaustive. Add the 'TEMP_PROBE' branch`。
  这正是原先那张 map 给不了的东西 —— 缺键只能静默兜底。
- `when` 的每个分支是**表达式**，仍然「读一颗建一颗」：原先用 lambda 是为了避免整表预建
  （冷启动后第一次进页那笔掉帧），换成 `when` 后这个取舍不变。
- 表本身从 `ActionIcons.kt` 拆到 `ui/model/SwitchKindIcons.kt`：那个文件已经顶到 detekt 的
  文件级函数数上限，而这一族与「按 `Spec.glyph` 翻译」那套本来就是两件事。

## 判据：`tools/audit-arch.py`

这一轮的重点是**把「约束」改成会红在实处的东西**。

- 原先第 3 组数的是 `actionTitle(` / `actionFinalTitle(` / `fun actionTitle(` —— 这三个名字随重构
  一起没了，于是脚本报「界面调用点 0 / = 4」「实现处 0 / = 1」：它会红，但红的原因是
  **脚本还在认旧名字**，不是又长出一份实现。一条改名字就会失效的判据不算约束。
- 换成数**结构**、不数名字：数格式键在哪儿被读、数拼装函数有几个、数清单名被谁喊。
- 之后每收一处就补一条，都实测过会红（临时探针造违规 → 报未达标 → 删掉回绿）。

| 判据                                               | 值  | 规则                                           |
| -------------------------------------------------- | --- | ---------------------------------------------- |
| 拼句子的格式键（工厂之外）                         | 0   | `= 0（旁路手拼分隔符）`                        |
| 拼装函数（core）                                   | 1   | `= 1（唯一拼装）`                              |
| `ActionCatalog.label` 的直接调用                   | 1   | `= 1（只有工厂取清单名）`                      |
| 键码归属就地推（builtins 上跑遍历）                | 0   | `= 0（用 KeyId.claimsBuiltin）`                |
| 「有没有绑定」就地取反（`!is` / `== Action.None`） | 0   | `= 0（用 action.isBound）`                     |
| 老 `\|名字` 后缀在优先级链之外被读                 | 0   | `= 0（走 resolveAppName / resolveTargetName）` |
| `clickKind` 的界面调用点                           | 4   | `≥ 3（网格格子 / 抽屉行 / 菜单行）`            |
| 开关种类 id 裸字面量比较                           | 0   | `= 0（用 SwitchKind.X.id）`                    |

几条经验：

- **正向计数**也有用（`clickKind` 要求 ≥ 3）：界面都在问它，才说明没有第二份判断。
- **会红在合法写法上的判据只能添噪音**。试过一条「`actionIcon(canonicalToken(...))` = 0」，
  命中的是步骤行那条兜底路径（那里 token 本来就不是 Spec，走兜底是对的）—— 撤掉，
  理由写在脚本里防止下一个人再加。
- 能交给编译器的就交给编译器：`Spec.glyph` 必填、`SwitchKind` 的 `when` 穷尽，
  「漏了不报错」这两件事已经不存在，不需要 grep 再守一遍。
- 给脚本加了 `count_excluding()`：`Strings.kt` 里那两个格式键是**定义**，不算旁路 ——
  判据要卡的是第二份实现，不是第一份。
- 判据表按显示宽度补空格（中文字符算两列），否则整表串行。

现在 14 条，全绿、`--strict` exit 0。

## 顺带清掉的过期注释

重构之后有 10 处注释指向已删的函数（`Strings.kt` 两处格式键说明、`ActionNotice`、`CommandText`、

### 修改：首页大卡片的提示段出现 / 消失带高度过渡

- 原先两条提示都没有时 `ActivationTips` 直接 `return`，卡片高度是硬切的；现在走统一那一档显隐
  （`VISIBILITY_ENTER` / `VISIBILITY_EXIT`：淡入 + 纵向展开），与网格小字、首页那行
  「点按卡片即可开启」同一套规格。
- `MutableTransitionState` 起手取当前值：翻 tab / 从子页回来不会把这一段重播一遍展开。

### 修改：「重置模块」把模块落过的盘全部回出厂

- 命令表仍写一份空表（不是「不管它」）：文件删了但**内存里那份**还在，界面与执行侧会继续看见旧命令。
- 确认窗文案改成把范围说全；死文案 `toast.config_clear_vars_failed` 随之删掉。
- 「重置配置」（更多选项 → 切换配置）不动，仍是只重建当前那一份。

## 修复：导入配置覆盖「默认」之后，默认那份变成「未命名」

- 现象：导入配置时选「盖到默认配置」，盖完之后列表里那一行从「默认配置」变成**「未命名」**，
  而且它还能被改名、被删除（默认本该两样都不许）。
- 根因在 `ConfigProfiles.importInto`：它把被覆盖那份的**名字**与**位次**原样搬了过来，
  却给 **`profile_id`** 铸了一个新的：

  ```kotlin
  config.copy(profileId = newProfileId(), profileName = target.profileName, …)
  ```

  而「是不是默认」判的是 id（`Item.isDefault = id == DEFAULT_PROFILE_ID`）。
  id 一换，它就不再是默认；名字本来又是空串 —— 于是落到 `Item.displayName` 的
  `name.isBlank()` 那一档，显示成「未命名」。它同时失去了「不许改名 / 不许删除」那两条约束。
  讽刺的是那个函数的 KDoc 一直写着「身份仍是默认（DEFAULT_PROFILE_ID）」，是代码没照做。
- 收法：**身份三位一次搬完**，做成 `Config.withIdentityOf(profile)` 一处推导，
  `importInto` 与 `resetCurrentProfile`（重置也有同一个毛病：只搬名字与位次、把 id 抹成空串）都转调它。
  覆盖 = 换内容，不换「这份配置是谁」。
- 顺带把「默认」的判据从 `id` **改回形态**（名字空 + 位次 0）。这不是放宽，是让它与自己的文档
  对齐：位次 0 是**只留给默认**的（`nextSlot` 给普通配置的永远是 ≥ 1），所以「名字空 + 位次 0」
  本身就足以认定默认；原先那条多出来的 `profile_id 为空` 恰好把这次受害的数据放跑了
  （id 非空、名字空、位次 0 ⇒ 两个判据都不认它是默认）。
- 这一改**顺手修好了已经坏掉的数据**：受害那份下次读入时由 `assignProfileIds` 按形态认回
  `DEFAULT_PROFILE_ID`，列表里重新显示「默认配置」，改名 / 删除重新被拦住。不需要迁移、不丢内容。
- `assignProfileIds` 的三条规则跟着重写：**默认按形态认领**（不管文件里写的是哪个 id）→
  其余照用文件里的 id → 撞了退槽位 id。撞车那条保留：真机上出现过两份都「名字空 + 位次 0」的数据，
  id 必须唯一，否则菜单里两行分不出谁是谁。

### 修复：系统开关 / 响铃状态 / 媒体控制三格点下去不再弹菜单

- 现象：这三格的行尾画成勾选框（checked / unchecked），点下去直接绑上首行那个取值 —— 二级菜单
  根本不开。
- 根因在 `ActionCatalog.clickKind` 的两条判据，都不适用于**格子**：
  · `stateMenu(token)` 排在前面，而它只看前缀 —— 格子那串标记 token `setting:` 被它当成
    「某个开关的三档」（剥出空 id 照样给三档），于是系统开关被判成 `SWITCH`；
  · `hasDeeperLevel(spec)` 是为「媒体控制 / 响铃状态的首行与格子共用同一串 token」设的自指闸，
    拿它判**格子**恒为 false，于是这两格被判成 `DIRECT`（点一下就落盘）。
- 改法：格子那一档改用 `modeMenu(spec.token) != null`（「这一格」的定义），`stateMenu` 让到它后面
  —— 三格都回到 `MENU`：行尾是选择器、点开弹二级菜单。菜单行（`setting:wifi`）仍落到 `SWITCH`。

## 功能：「打开应用」可以套原版那层启动转场（命令级，与小窗互斥）

- 新增动作写法 **`app:a:<目标>`** —— `a` 是 animation，紧跟在 `app:` 之后，与快捷方式那一档
  的 `appshortcut:w:` 同一个位置。它不换前缀（像 `window:` 那样）而是**加一个标记位**：
  目标是同一串 `包名[/Activity]`，解析、命名、图标、同一性判据全都要复用，拆成两个前缀就得让
  「取目标」的推导在两处各写一份。
- 执行那一侧**把这次启动整个转交回宿主自己那条链路**（`OriginalLaunch`）：反射调
  `remote.transition.d#m(context, intent, 2, false)` —— 原版三个入口最终都落到它，选动画实现、
  配 COE 扫光、建 animator、`startActivityAsUser` 全在里面。转交之后调用方 `return`，
  不再自己起一次（否则两个任务）。
- **为什么是「转交」而不是「复刻」**：先按文档 §2.4 / §5 把原版那套包裹（`0x10200000` 标志、
  `key_position` / `android_action_key_launch_type` 两个 extra、`ActivityOptions`
  的 `setLaunchDisplayId(0)` + `setSplashScreenStyle(0)`）补上试过一版 —— 日志里包裹确实带上了，
  **观感完全没变**，系统不按那几个 extra 挑过渡；又试了手动调 `d#l` 播扫光 ——
  字节码显示 `COESysEffect.playAnim` 全 APK 只有一个调用点（`ActivityTransitionAnimator$a#w`），
  而 `w` 是**远端动画的 `onAnimationStart`**，没有 `RemoteAnimationAdapter` 就永远不会被调到
  ⇒ 那一版只是「配置了特效但没人播」。两条都删了。
- **文档 §9 的结论在真机上不成立**：它判定 `callback.a()` 与 `z` 都是常量 false、adapter 恒 `null`、
  整条链路是死代码。把模块总闸关掉让侧键走原生行为，系统日志里会出现
  `RemoteTransitionInfo { … debugName = SpruceLauncher }` 与
  `Delegate animation for (#47) to RemoteTransition { … SpruceLauncher }` ——
  这个名字全 APK 只有 `d$a.a()` 一处写，而它只在 `adapter != null` 时才被调到。
  静态分析读的是常量分支，运行时的实际取值不是它算的那个。**结论：那条链路是活的，能用就别复刻。**
  （复刻也确实做不到：`IRemoteAnimationRunner` 是隐藏 AIDL，本工程没有框架 stub 依赖，编不过。）
- 只对**主用户**转交：`d#m` 用 `UserHandle.CURRENT`，没有 userId 入口，分身目标（`999@包名`）
  交给它会被起进主用户 —— 那一档仍走我们自己的 `AppLaunchAsUser`（没有原版动画）。
  反射拿不到 / 调用抛异常 ⇒ 返回 `false`，调用方照旧自己起。**不留延时兜底**：
  那要在「前台判定」与「原版已起但还没到前台」之间猜，猜错就是开两个任务。
- **与小窗互斥**：小窗那一档走 ColorOS 自己的配方（`MiniWindowLauncher`），塞不进原版这条链路，
  同一格装不下两种起法。界面侧是双向的 —— 顶栏那颗「以小窗口打开」拨开会关掉这一项，
  ⋮ 里这一行拨开会关掉小窗；进页重算时（`resetSmallWindowForPicker`）也保证两个最多一个为真
  （老配置里可能两个标记都写着）。
- 入口在**「选择应用」页 ⋮ 菜单**（用户口径：这是命令级设置，不是全局偏好），与
  「显示系统应用 / 显示失效应用」用一条加深带断开 —— 那两行管列表怎么显示，这一行管**写成哪个动作**。
  只会在写 `app:` 的那几趟出现（`appOnly` 那两趟写的是包名与 `proc:stop:`）。
- 名字与命令文本跟着认这一档：目标是 `微信(原版动画)`，与 `微信(小窗)` 同一个括号位置
  （`appTargetLabel` 多收一位）；它**不加**格子右上那枚小窗标记 —— 那是「窗口形态」的记号，
  这一档说的是「这一次启动套不套转场」。
- 配置层**没有加字段**，所以 `ConfigCodec.VERSION` 不用动（抬号那条规矩只管 DTO 多出键的情况）。

### 修改：公共项取值收成一个出口

- `Config` 上五个逐字同构的 `xxxFor(owner)`（`colorOsApiFor` / `vibrateFor` /
  `vibrateStrengthFor` / `toastOnRunFor` / `toastTemplateFor`）收成一个
  `effectiveFor(owner): OwnSettings`：规则只有一条「独立设置开着就看自己那份，否则看公共」，
  调用点直接读字段（`config.effectiveFor(keyConfig).vibrate`），不必再记「该问哪个方法」。
- `GlobalConfig` 因此实现 `OwnSettings`（`useOwnSettings` 恒真 —— 它自己就是公共那份），
  于是「公共」与「某一档自己的设置」能当成同一种东西返回。
- `haptic` / `noticeIfNeeded` 里同一个 owner 的两次解析合成一次。

## 修改：「选择应用」页拨过打开方式，退出时也按草稿问一句

- 「以小窗口打开」和「使用原版动画」都是**绑定的一部分**：拨完再挑应用、按右下角确认才落盘。
  以前只判「二级页点确认过一条」（`picker.draft != null`），于是拨了开关却没挑应用就退出去时
  一声不响地丢掉 —— 用户以为改过了，实际一个字节都没写。
- 判据扩成 `picker.draft != null || picker.windowTogglesChanged`，两处消费点（`goBack` 与
  `wouldConsumeBack`）本来就是同一条，跟着一起生效。
- 「拨过」按**进页那一刻的基线**算：基线在 `resetSmallWindowForPicker` 里记（进页重算完顺手记一笔），
  「结束应用」那一趟不重算，所以在 `openAppPickerForStopApp` 里也记一次 ——
  否则会拿上一趟的基线比，把「什么都没拨」判成「拨过」。
- 那张确认窗**不为这一档另写文案**：正文要嵌「哪一条」，只拨开关时没有目标可念，
  于是这一档**不带正文**（同一张窗、同一个标题与同一颗「放弃」），与「草稿未确认」共用一份。
