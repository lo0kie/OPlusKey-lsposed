# 拿掉「同一事件立即执行」，独立设置页补齐置灰与入口

> 上一笔提交（`e24cc3d`）之后的一轮改动。

## 移除

### 移除：「三个内置手势同事件时立即执行」

- 整个功能拿掉，不留开关：`KeyConfig.sameEvent`、`Config.sameEventNow`、
  `KeyConfig.sameEventAction`、字段表里 `F_SAME_EVENT` 与 `SAME_EVENT_EXTRA`、
  按键广播列里的那一项、判定侧「按下即执行」那一支、执行侧的三档兜底一并删除。
- 判定侧顺带清掉 `GestureDetector` 里的 `sameEventFired` 与它在 `onKeyUp` / `reset` 中的处理。
- 界面侧三处置灰与解释也一起走：`BindingSettings` 里那行开关与其滑杆闸门、
  `InstantSingleCard` 的置灰与 hint、`LongRepeatCard`、`BindingTarget.sameEventBlocked`
  （抽象与两处实现、场景入口的闸门）、`KeyParamsWrite.setSameEvent`、
  `PageIcons.Immediate` 这一颗图标、中英两份 locales 里的四条文案。
- 配置版本抬到 33：`KeyDto.same_event` 与 `GlobalDto.same_event` 都不再写出，老文件里残留的
  那两个键按未知键忽略（`version < VERSION` 走「不校验 md5」那一支）。
- 三档恢复成各按自己的时序判：单击要等双击窗口、长按要过阈值 —— 也就是这一档出现之前的行为。
- `tools/config-shape.txt` 基线随之刷新（version=33，78 字段）。

## 修复

### 修复：独立设置页置灰之后点了不说话

- 总开关「使用独立设置」没开时，接口 / 振动 / 提示 / 提示文案那四行点一下都会说
  「先打开「使用独立设置」」（新增 `Strings.KEY_SETTINGS_NEED_OWN`）。
- 判据分两层：整页闸门（主开关 / 链路 / 只读）关着时 `ownHint` 给 `null`，仍用整页那句；
  整页没事、只是这一档的总开关没开时才说上面那句 —— 两句话说的是两件事，不能混用。

### 修复：组合的独立主开关没闸住「组合按键设置」那一节

- 「无操作时执行按键命令」与「按键之间的等待」现在跟着「使用独立设置」一起灰：
  `ComboOwnCard` 新增 `ownOn` 参数，`rowsEnabled = enabled && ownOn`，
  `disabledHint` 同样走上面那两句。
- 执行侧取值同步改：`Config.comboPassthroughFor` 总开关关着 ⇒ 一律用公共那份
  （`global.comboPassthrough`），否则界面灰着、实际照旧按这一档自己的 `passthrough` 走。
- `ComboKey.passthrough` 仍是 `null` = 跟随公共，与总开关是两层：总开关管「这份值算不算数」，
  `null` 管「没设过时取哪一份」。

### 修复：组合键编辑页没有那颗「自定义命令」FAB

- 「按键绑定」页顶到列表底部会浮出那颗「自定义命令」，组合编辑页没有。
- `BindingFab` 由 `private` 改 `internal`，两页共用同一颗、同一个落点
  （`rememberFabVisibleOnScroll(scrolls[pager.currentPage])`）；`ComboEditScreen` 外面包一层 `Box`。
- 那一页有、这一页没有时，「按键与组合键功能完全一样」在界面上是句假话。

### 修复：状态异常时首页状态卡仍显示「已激活」，且提示是模板句

- 判据不同源：状态卡原先只看 `LinkFacts.respondOk`（注入侧回了包 + 接管点挂上），而整页总闸
  用的是 `LinkFacts.ready`（再多两段：设置送到且指纹对得上、执行侧那份配置读得懂）。
  中间任一段断掉时，页面整片灰、大卡片却绿着说「已激活」——「状态异常，可大卡片一切正常」。
  现在 `ActivationState.Active` 判 `facts.ready`，与 `pageWritable()` / `linkReady` 同一个出口。
- 未激活那一句不再固定写「系统侧未接管按键」：那句只在「注入侧没回包」时成立，其余几档
  （设置没送到 / 执行侧读不懂 / 跑着旧包）都被它答成同一句，把人指去勾作用域。
  改成取 `blockedReason()` —— 它的每一档都写着下一步做什么（重进本页 / 重启服务 / 重启手机 /
  去 LSPosed 勾作用域）。`ActivationState.detail` 因此收一个 `reason` 参数，`null` 时才退回那句旧的。
- 下半段那条提示不再拼「{段名}异常」：`statusTipText()` 里 `linkChecks()` 那一段拿掉了，
  只留「能用、但跑着旧包」那两档（系统侧 / 宿主侧）。真故障归大字下面那句 ——
  同一条原因在同一块卡里说两遍（一份具体、一份模板），读起来像两个问题。
  两处都出同一句时（`restartNeeded` 那条）下半段自动去重（`takeIf { it != reason }`）。
- `ActivationBody` / `ActivationHead` 的参数收成 `ActivationExtras`（原因 + 新版本 + 那句提醒）：
  加一位参数就会顶到 detekt 的 `LongParameterList`，而这三项本来就是同一件事。

### 修复：所有滑杆行灰着被点一下都落回整页那句

- 根因是一条**通道缺口**，不是某一行写错了：滑杆行几乎全是 `CardRow.Custom`（灰不灰由
  `SliderSpec.enabled` 定，行本身没有 `enabled` / `disabledHint` 这两位），于是 `CardList` 那条
  「行自己带一句原因」的链根本走不到它们 —— 灰着点一下一律落到页面那条，而页面那条答的是
  「这一页为什么改不了」（主开关 / 链路 / 只读），不是「这一行为什么改不了」。
- 通道开在 `SliderSpec.disabledHint` 上，投递收在 `SliderRow` 那一处（新的 `SliderRowBody` 只留本体）：
  所有滑杆自动获得这条通道，调用点只答「这一行为什么灰」。判据与 `CardRow.Item` / `Switch` 同源
  —— **只有灰着**才换，`null` 时不覆盖。
- 接上行级原因的地方：
  - 独立设置页的「振动强度」（「先打开「使用独立设置」」）；
  - 组合「按键之间的等待」（`ComboWindowRow` 新增 `disabledHint`，独立设置页那一头传同一句；
    公共页那一头仍是 `null`，因为那边 `enabled` 就是整页闸门）；
  - 长按卡的「触发间隔」（`gates.repeatBlocked` —— 与上面两行同一句，之前只有开关行说了）；
  - 长按卡的「长按延迟」：原来拿**副标题**顶替原因，现在改走新通道，副标题恢复「多久算长按」。
- 其余几根（公共页振动强度、双击延迟、组合等待窗口的公共入口、页面缩放的）`enabled` 直接来自
  整页闸门，`disabledHint` 留 `null` —— 与同页其它行同一条口径，不各说一套。
- 命令页「命令间隔时长」那一根不动：它外面已经整块包了 `DisabledHint("编辑中，先点右下角完成")`，
  滑杆给的 `null` 会沿用外层那句。

## 修改

### 修改：「使用独立设置」的图标换成与主开关同一颗

- 原来是齿轮（`PageIcons.SettingsCog`），换成 `PageIcons.MasterSwitch` —— 与首页「启用按键绑定」
  同一颗（拨到右的开关）。两者是一回事：这一个开关决定下面那一组算不算数。

## 顺带

- `Config` 上函数变多，给 `data class Config` 加 `@Suppress("TooManyFunctions")` 并写明理由
  （那一批 `xxxFor` 取值出口是刻意的单口，拆出去反而散）。
- `OwnSettingsCard` 拆成 `ownSettingRows` + `toastRows` 压行数；`pageTitle` 是纯映射表，
  复杂度高是分支多而不是逻辑绕，加 `@Suppress("CyclomaticComplexMethod")` 并写明。
- `GestureExec` 抽出 `resolveAction` / `announceOnce` 降复杂度；功能移除后 `resolveAction`
  只剩「场景让位 + 取绑定」两件事，`config` 参数一并去掉。
- 三处 i18n 兜底字面量落后于字典（`GeneralComboCard`、`BindingSettings`、`BindingTarget`），
  已同步为字典值；`check-i18n-fallbacks` 复跑 696 处调用、0 处不一致。
- **`BindingTarget` 从 `ui.screen.binding` 挪到 `ui`**：它是「这一档往哪儿写」的页面模型，
  被 `ui` 根（`ScenarioEntryRow`）与两个具体的屏共用 —— 留在 `screen.binding` 里就成了
  「共用件反向依赖具体屏」，耦合审计那一条越界一直在（`audit-coupling.py` 的白名单是空集，
  按 `docs/decoupling.md` 七 只许缩短、不许把既成事实抄进去）。搬迁只动包声明与 import，
  逻辑一字未改；`openBranchesFor` 跟着过去，调用点补一行 import。
- **detekt 基线对账**：`config/detekt/baseline.xml` 落后于代码 —— 上一版提交时 `:app` 还有
  13 条没被基线兜住（`gate` 因此红着），这一轮减到 11 条。按「历史存量由基线兜」的口径，
  用 `:app:detektBaseline` + `:core:detektBaseline` 各生成一份再与旧基线取并集
  （两个模块共用同一个文件，单独跑任一个都会把另一个的条目盖掉）：130 条 = 旧 119 + 补记 11，
  新增的 11 条逐条核过，全是既有代码的复杂度 / 长度 / 参数个数，没有混进新问题。
