# 长按收掉与性能收口

### 改：手势页网格与已保存命令卡不再接长按

- 手势页里自定义命令那一格：长按不再进编辑页，「已选中时再点一次」是唯一入口；
- 「自定义命令」页的已保存命令卡：长按不再弹菜单，只从右上角那颗「更多」进（测试 / 编辑 / 删除）；
- 两处都不再有「长按那一下额外振一次」——它们现在只剩轻点一个手势；
- 内置动作那几张网格本来就只接轻点，这下整页的手势口径一致了；
- detekt 基线里那三条按完整签名匹配的条目跟着对齐（`onLongClick` 那一段从 ID 里去掉），条目总数不变。

### 改：性能收口（四条热路径）

- 文字光学修正：同一种字号在整个进程里只量一次（原先列表里每滚出一行就排一次版、建一次
  `Typeface`）；
- 按键认领：键码 → 键的那两张表改成建一次、之后每次按键一次 `HashMap` 查找（原先每个按键都要
  线性扫一遍全集，认领路径与原始码路径各扫一遍）；
- 组合键判定：参与组合的键集合改成收到配置时算一次（原先每次按下都要扫一遍组合表）；
  一个组合都没配时直接返回，不再每次按键分配一个空列表；
- 已保存命令卡：选中 / 取消选中那 200ms 里只有标题那一行重组（原先整张卡连同摘要、每一步
  都跟着每帧重组一遍）。

### 新：小标题可以点着跳页

- `SectionTitle` 的可点从「只能开菜单」扩成两档：开菜单（行尾一颗 `chevron-down`，开合时转）
  与跳转（行尾一颗右箭头，恒不动）。两档合成 `SectionTitleClick` 一个类型（`Menu` / `Jump`）；
- 手势页「已保存的命令」那个标题接上了跳转：点标题进「自定义命令」页；
- 它与标题下面那行「去创建自定义命令」**不是一个去处**：那个会先清空表单（新增的入口），
  这里只跳页，表单里正编着的那份草稿原样留着；
- 另外三处「已保存的命令」标题仍是纯标题：命令页那一处是本页自己；组合键编辑页跳走会丢正在编
  的内容；添加命令抽屉跳走等于把这一趟加步骤的路断了。

### 新：「自定义命令」页最右多一个「命令列表」页签

- 页签从两档变三档：单条命令 / 多条命令 / 命令列表；
- 「已保存的命令」那一片原来挂在两张表单页的页尾、每页只列自己那一类（翻到哪页只看得到一半），
  现在是独立一页，两类混着按保存顺序排；
- 点开一条（或它菜单里的「编辑」）会**跳回它所属那一类的表单页**并滚回顶部 —— 停在列表页
  等于「点开了一条，眼前什么都没变」；
- 停在「命令列表」这一页时不显示右下角那颗「保存」（这一页没有表单），进这一页也会收掉
  步骤排序态（它只属于「多条」那张表单）。

### 改：手势页「已保存的命令」标题在没有命令时不接点击

- 一条命令都没有时，那一格已经是「去创建自定义命令」的入口，标题再点一下是同一个去处 ——
  两个入口摆在同一条标题下面反而让人以为标题是另一件事；
- 有命令之后标题才成为入口，落点是**命令列表**那一格（不是上次停着的表单页）：点这条标题的
  意思是「去管命令库」，留在列表看得出来全部命令。

### 改：命令列表按单条 / 多条分成两段

- 页面上半段「单条命令」、下半段「多条命令」，各一条小标题；空的那一段整段不画，
  一条命令都没有时给整页一句空状态；
- 顺带把行高摆正了：单条卡是半个正方形、多条卡是正方形，混排时一行按高的那一档算，
  单条卡会空出半张 —— 分段之后每段只有一种类型。

### 改：小标题被点时振一下

- 走页面那条通用通道（`LocalTick`），与能点的行、开关同一份判据；不在组件里另起一套振动。

### 改：命令列表那一页的「重置」始终置灰

- 那一页没有表单，重置没有宾语；灰着点一下只说结论：「这一页没有表单」
  （新字典键 `command.reset_list_page`），不再补一句「切到单条或多条再重置」。

### 改：命令列表一条命令都没有时，空态整页居中

- 与「选择应用」「条件执行」那两块整页空态同一个处理：高度按可视区算（减掉顶栏、分页带与页底
  留白），在那一块里正中；
- 空态**仍留在滚动内容里** —— 挪出滚动容器就没有越界回弹了，整块跟着内容一起拖、一起弹。
- 有命令时仍按单条 / 多条分两段，段与段各一条小标题。

### 改：从「单条命令」切到「多条命令」时，步骤列表不再重新展开

- 根因是**读错了那一份表单**：步骤卡读的是 `draft.steps`（「当前 `draft.kind` 那一份」的快捷方式），
  而 `draft.kind` 由分页器**单向同步**、翻页期间晚一帧 —— 从「单条」翻过来的那一帧读到的是
  单条那份**空表**，`sync([])` 把展示行全标退场并清空 `rows`，下一帧读到真步骤时只能整表新建
  ⇒ 整张表从头展开一遍。从「命令列表」过来不会有这一帧（那时 `kind` 已经是多条），
  所以那条路一直看着正常；
- 现在这一页只认**多条那一份**（`serialForm`）：步骤的读 / 增 / 删 / 移动，以及「命令间隔时长」
  那条滑杆，都不再跟 `draft.kind` 的镜像走；
- 另加两道保险：次序与对象都没变时 `sync` 不重写展示层（避免一次「空表」让整表被重建）；
  这支组合进来的第一帧把入场动画置空，之后新增 / 删除仍走原来的展开 / 收起。

### 改：命令页右下角那颗 FAB 不再滑入滑出

- 它的显隐跟着**当前这一页的表单内容**走，翻 tab 会让它进 / 出一次；
- 现在这一页的显隐直接生效、不做过渡（`PageCornerFab` 多一个 `animate` 参数，
  「选择应用」那颗仍是原来的滑入滑出）。

### 改：「重置」只清当前这一页的表单

- 两页的表单各自独立（见 `CommandForm`），在「单条」页点重置不该把「多条」页写了一半的步骤
  一起清掉 —— 那时候另一页的内容根本不在屏幕上；
- 列表页菜单里那条「再点一次编辑＝重置」按**那条命令所属的类型**取表单（新增 `CommandDraft.formOf`），
  不看当前停在哪一页。

### 改：点开一条命令时不再「瞬变 + 再滚一段」

- 原先先把分页器瞬移到表单页、再播一段滚回顶部的动画，看着像「内容猛地换成另一份、然后自己又动一下」；
- 现在先把目标页瞬时滚回顶部（此刻它还在屏幕外，看不见），再让那一页滑进来 ——
  一次过渡，落定即是一屏完整的表单。
### 删：命令页那条没人调的底部工具条

- `CommandActions` / `FloatingActions` / `ToolbarSpec` / `ToolbarButtons` / `toolbarFrostModifier`
  全仓零调用点（保存早已是右下角那颗 FAB），整段删掉；
- 它专用的四个常量一并删：`COMMAND_TOOLBAR_BOTTOM` / `TOOLBAR_ICON_SIZE` / `TOOLBAR_EDGE_GAP` /
  `TOOLBAR_SHADOW_ALPHA`；
- `commandToolbarVisible` 更名 `commandDraftHasContent`，名字不再指着已撤掉的底栏；
- detekt 基线里那两条按它的签名记的条目跟着删（117 条）。

### 删：另外两处零引用

- `ui/SectionColumn.kt` 的 `SectionColumn` 与 `SECTION_GAP` 零引用（同文件的 `spacedItems` 还在用），
  删完按内容更名为 `ui/SpacedItems.kt`；
- `conditionTitle` / `conditionTitleOf` / `VALUE_TITLES` / `ValueTitle` 零引用，整族删掉；
  条件文案只剩 `conditionRowTitle` 一个出口，两处提到旧名的注释一并改写。

### 删：字典里 8 个没人用的键

- `COMBO_MEMBERS` / `COMBO_UNBOUND` / `COMMAND_NAME` / `COMMAND_BRANCH_NEED` /
  `PROFILE_DELETE_TITLE` / `PROFILE_DELETED` / `TOAST_CONFIG_IMPORTED` / `KEY_WATCH_ADD`；

### 改：耦合审计补上「共用件不许依赖具体屏」

  脚本一直没落，`component/` 并入 `ui/` 之后等于没人执行）；
- `IconInput`（`InputSpec` / `IconInputView` / `moveCaretToEnd` / `InputLeadingIcon`）从
  `ui/screen/command/` 搬回 `ui/`：它同时服务命令页两处与「起个名字」弹窗，那条反向 import 正是新判据抓到的。

### 改：文档基线按今天重测

- `docs/decoupling.md` 零节的实测值全部重测，并写清它是唯一口径来源、正文的历史快照不回填；

- 屏目录数、单文件最大行数、`Strings` 键数、`ui/state/LinkCheck`、`SettingsPageView` 等过期指针一并修正；
- `docs/architecture-refactor.md` 的共用件目录与迁移映射表标成历史记录，不再当作现状索引。

### 改：状态色与状态字形的过渡收拢到同一条曲线

- `BindingTile` 那三处颜色过渡（标题与图标、行尾弱化色、行尾指示字形）原先没给 `animationSpec`，
  走的是 Material 默认的 300ms `FastOutSlowIn`，而同一格的焦点圈走的是 200ms 减速档 ——
  注释写着「同一组参数」，实际是两条曲线；三处都补上 `COLOR_TRANSITION_SPEC`；
- 「更多选项」菜单里行首图标那一处同样补上；
- 新增 `COLOR_FADE_SPEC`（同一条曲线的浮点版，与颜色共用同一个时长常量），
  替掉命令抽屉里手写的那份 `tween<Float>(200, …)`；
- 绑定网格取值格的行尾方框由「硬切字形」改成 `Crossfade`（`COLOR_FADE_SPEC`）：
  选没选是状态、形状插不了值，于是与旁边那片底色同一条曲线淡过去，两种字形同尺寸不挤宽度。

### 改：动作清单三张按 token 记忆的表（空间换时间）

- `ActionCatalog` 新增 `actionOf(token)`，把 `Action.parse` 的结果按 token 记下来；
  `stepTitle`、`systemSettingIcon`、步骤抽屉里「当前这一步是哪个动作」三处改走它 ——
  这三处都在「每次重组 / 每行每帧」的位置上，原先每走一遍就切一次前缀、造一次对象；
- `modeHitOf` 也记忆了：原先每次要扫一遍 `ALL`（四十余项），再对每个入口格扫一遍它那层菜单行；
  现在命中的进一份表、明确不命中的进另一份（不记「没命中」的话 `cmd:` 那类 token 每次都重扫）；
- `switchStates` 同样按 token 记忆：它原先每次要新造 1~3 个 `Spec`（data class，名字还要过一次 i18n），
  而调它的 `stateMenu` 在入口格菜单与网格小字上被反复问到；
- 三张表的键集合都只由 token 决定，随「清单 + 用户建过多少命令」封顶，不随运行时间增长，
  所以不需要 LRU —— 与既有的 `canonicalToken` 同一口径，并发下允许重复算一次、结果相同。

### 改：构建号抬到 1.3.0

- `ModuleInfo.BUILD_ID` 更新为 `2026-10-28-0001` —— 它是「换了包但 system_server 里还是旧的」那条判据的尺子，
  每次出包都要手动抬，不抬就量不出两次构建的差别。
