### 提示条与弹窗收口

> 这一批只动**界面观感**与**导入导出**那条链路；接线、配置格式与全量审查见
> `2026-10-19-多按键接线与全量审查.md`。

#### 提示条加一圈描边

用户口径「提示条加一个边框」。胶囊是**半透明磨砂**底，落在同色内容上时边界会糊掉
（暗色下最明显，看着像「一块模糊的空气」），描一道就把边界收住：

- 宽度 `1.dp`、颜色取 `SnackbarDefaults.snackbarColors().contentColor` 的 **12%**
  —— 深浅两套主题下它都正好是「比底色明显、又不抢文字」的那一支，不必再对一套颜色；
- 第一版用 `DividerDefaults.DividerColor`，真机反馈「太亮了」，于是直接换色、
  不做按比例缩 alpha 那套换算（用户口径「换个颜色就行，不用搞那么复杂」）；
- 位置在 `background` **之后**（画在底色上）、`clip` **之前**：`Modifier.border` 的描边
  居中于节点边界，先 `clip` 会把外半圈裁掉、视觉只剩半宽。

#### 换句不再做宽度动画（文字溢出）

用户口径「提示条的动画现在是文字先变化，在动画未完成前文字会溢出」。

- 根因：`animateContentSize` 只动**这一颗节点报给外层的尺寸**，而文字是**立刻**按新内容
  布局的 —— 换句变长时胶囊还在从旧宽度往新宽度长，文字已经占满目标宽度，那几十毫秒里
  挂在胶囊边界之外（`clip` 只能切掉它，看着就是「字被切了」）。两者做不到同步：
  文字没法等宽度长完；
- 中间试过一版**直接去掉宽度动画**（同帧就位），溢出没了但过渡也没了（用户口径
  「提示条的宽度过渡没了」）；
- 现在改成**换句三段**：文字淡出（35ms）→ 换内容，胶囊在这个不可见的窗口里把宽度过渡完
  （`animateContentSize` 120ms）→ 文字淡入（35ms）。「文字与宽度不同步」仍然存在，
  但发生在一个看不见的窗口里；
- 时长是按「别慢半拍」定的：第一版 70 + 180 + 70 = 320ms，真机上换句明显迟滞（用户口径
  「文字动画太慢了」）。现在 190ms，且淡入只等宽度过渡的**尾巴**
  （`delay(HINT_RESIZE_MS - HINT_TEXT_FADE_MS)`）—— 与最后那一截重叠，
  不然「等都等完了文字才出来」会有一拍发条感；
- 只给**文字**那一层套 alpha（`graphicsLayer`），磨砂 / 底色 / 描边全程不动 ——
  `AnimatedContent` / `Crossfade` 那条老结论不变：它们裁容器框（阴影四周被切平）、
  且给整棵子树套 alpha（磨砂那层也在里面，换句时糊会消失）。

#### root 授权到底要给谁（实测）

用户反馈「提示这条命令要 root，但它已经 root 了」，随后又提出「管理器里只给手势体感不够，
还要给 shell 授权」。真机对照测了一遍，结论是**后半句不成立**：

| 谁在跑命令                            | uid   | su 可用 | 结果                                                         |
| ------------------------------------- | ----- | ------- | ------------------------------------------------------------ |
| 模块（宿主 `com.oplus.gesture` 进程） | 10277 | ✅      | `shell:id -u > /data/local/tmp/…` 写出 `0`，属主 `root:root` |
| `adb shell`                           | 2000  | ❌      | `su: inaccessible or not found`（`which su` 无输出）         |

- 在 root 管理器里**撤掉 shell 那条授权**之后（`adb shell su` 立刻不可见），模块照样
  `shell 命令已在后台启动（走的是 su）` 并把 `am start -n com.android.settings/.Settings` 跑成功
  —— 两条授权互不影响，**模块只要宿主那一条**；
- 所以「还要给 shell 授权」只在**终端调试**场景下成立（你 `adb shell su` 会被拒），
  写进用户提示会让人多开一个不必要的口子；
- 文案因此保持原样：「权限不够：root 要授给「手势体感」（`com.oplus.gesture`），不是本模块」。
  中途按用户口径加过「和 shell 都授权」，实测后已改回 —— KDoc 里留了这段对照数据，
  免得以后再把它加回去。

#### 失败时把 shell 输出尾部记进日志（release 也能看）

用户拿到的反馈是「提示这条命令要 root，但它已经 root 了」，问 release 版日志能不能定位。

- 能定位到「**A 还是 B**」，看这两行（都是 `w` 级，release 里在）：
    - `shell 解释器定为 su` / `shell 解释器定为 sh`；
    - `用 su 起进程失败（…），试下一个`。
      定为 `sh` ⇒ 模块**没拿到 su**（`SHELL_NO_ROOT`，文案会点明要授给宿主包
      `com.oplus.gesture` 而不是模块包）；定为 `su` 仍报权限 ⇒ 是命令**自己的输出**里有
      `Permission Denial`（`SHELL_NO_PERMISSION`），两件事完全不同；
- 但**看不出命令到底为什么失败**：逐行的 `sh: …` 是 `d` 级，release 里被
  `VERBOSE_LOG=false` 编译期消除，日志里只剩「命令没跑成功」这一句结论；
- 改法：`ShellRunner` 在读输出时顺手保留**尾部 12 行**（`SHELL_TAIL_LINES`），
  **只在失败路径**（非 0 退出码 / 超时）以 `w` 回放一遍。失败是低频路径，一次不刷屏；
  正常退出一个字都不多打；
- 尾部内容**不脱敏**：它已经是命令自己的输出（`Intent { cmp=… }` / `Error type 3` 就是判据），
  命令本体在别处已经过 `redactCommand`；
- `Permission Denial` 的判定仍是**逐行匹配**（`DENIED_HINTS`），不靠这条尾巴
  —— 那句后面跟着十几行 `at android.…` 栈帧，一裁就没了。

#### 选择界面崩溃：重复的列表 key

真机在贴吧的「应用组件」页崩了 `:ui` 进程（`Process: com.oplus.gesture.ui`）：

```
java.lang.IllegalArgumentException: Key "com.baidu.tieba/com.baidu.wallet.paysdk.ui.AuthorizeSignActivity"
was already used. If you are using LazyColumn/Row please make sure you provide a unique key.
```

- 根因：`loadActivities` 把 `getPackageInfo(…, GET_ACTIVITIES)` 的 `activities` 直接映射成清单，
  而**同一个类可能被报出多条**（声明 / 合并成重复条目）；列表那边是 `items(key = { it.target })`，
  key 一重复 Compose 就在测量期抛异常，整页连带进程一起没 —— 这也是为什么栈里全是
  `LazyListMeasure` / `fling` 那一串，看不出是 key 的问题；
- 改法：`loadActivities` 返回前 `distinctBy { it.target }`。既修崩溃，也顺带保证用户不会看到
  两条一模一样的界面；
- 一级「选择应用」页同一处也补了一道（`(apps + clones).distinctBy { it.target }`）：主清单与
  分身理论上不会撞（分身带 `999@` 前缀），但两条来源合成之后补一道比赌它不撞便宜；
- 这是**既有问题**，不是这批改动引入的 —— 只是这批把滚动条加上了、用户在那页停留得更久、
  真滚到了那条重复项。

#### 提示胶囊的圆角改成 squircle

用户口径「用 coui-squircle 画消息条的圆角」。

- COUI 的圆角全是超椭圆（卡片 / 按钮 / 弹窗 / 顶栏），一个正圆角的胶囊混进去，四角会显得
  比周围更尖 —— 提示条正好压在卡片和工具栏上，对比最明显；
- 库给的是三支 `Modifier`（`squircleBackground` / `squircleClip` / `squircleBorder`，
  都在 `io.github.suqi8.coui.kmp:squircle`，1.1.0），但这个胶囊需要**同一个形状**贯穿五处：
  阴影（`dropShadow`）、磨砂离屏（`frosted`）、底色、描边、裁内容 —— 前两者只收 `Shape`；
- 所以加了一个 `SquircleShape : Shape`，`createOutline` 里用库的 `addSquircleRect`
  （`Path` 扩展，签名 `(width, height, cornerRadius, extension, squircleEnabled)`）生成路径，
  返回 `Outline.Generic`。形状定义仍然只有库那一份，不自己写贝塞尔；
- 调用点只换了一行：`RoundedCornerShape(HINT_CAPSULE_RADIUS)` → `SquircleShape(…)`。
  半径仍是 `SnackbarDefaults.SingleLineCornerRadius` 那一档，与库的提示同一颗圆角；
- **换完角看起来变小了**，原因在库里的钳制：
  `radius = (cornerRadius × extension).coerceAtMost(min(宽, 高) / 2)`。提示条只有一行字，
  高度那一半（约 18dp）比 24dp × 1.2819 = 30.8dp 小 ⇒ 半径被压到 18dp；而原来的
  `RoundedCornerShape(24dp)` 同样被钳到 18dp —— **两者半径一样，只是超椭圆的角部更平**，
  看着就「方」一点。往大传没有用（钳死在上限），只能让胶囊长高；
- 于是上下各加 2dp（`HINT_TALLER_BY`），上限从 18 抬到 20dp。代价是胶囊略胖。
- 顺带修了一处：那个 `Box` 没给 `contentAlignment`，默认是 `TopStart`，胶囊比一行字高时
  **文字顶在上沿**（用户反馈「文字没有垂直居中」）。改成 `Alignment.Center`。

#### 两个选择页加滚动条；「Activity」页改名「应用组件」

用户口径「加到选择应用和 activity 里，activity 的主标题改成应用组件」。

- 两页各贴一条 COUI 的 `VerticalScrollBar`（`io.github.suqi8.coui.kmp.basic`，
  走 `rememberScrollBarAdapter(LazyListState)`）：它自带淡出、拖动加宽与更宽的触达区，
  不滚动时自己收起来，显隐不用我们管；
- 起画位置取**此刻的顶栏 + 搜索带**：这两截是叠在列表之上的固定浮层，滚动条从窗口顶边
  画起会被它们盖住一截，看着像「凭空从中间冒出来」。
  第一版取的是 `collapsedHeaderHeight`（折叠到底那一档，为的是不读滚动态、不逐帧重组），
  真机上滚条顶部被展开的顶栏压住一截（用户口径「滚动条被 header 挡住了」）——
  进页时顶栏是展开的，两者差着一整截。改成 `currentHeaderHeight` 之后跟着折叠走；
  代价是这一层跟着顶栏逐帧重组，但它本来就随滚动每帧更新（adapter 读的就是列表位移），
  重组的是一个 thumb、不是列表；
- 抽成 `PickerScrollBar`（`AppPickerList.kt` 里，两页共用）：几何只写一份，顺带把两个调用点
  的组合函数从 `LongMethod` 上限边上拉回来；
- 「应用组件」页的 `ActivityRows` 里，列表内容抽成 `LazyListScope.activityRows(...)`：
  它要放 `Box` + 滚动条，整段留着就顶到 60 行上限。`ActivityRow` 因此不再是 `SettingsPage`
  的扩展（一个函数只能有一个显式接收者）—— 触觉改由调用方 `rememberTick()` 取好、按参数传；
  顶栏那一段高度也收成 `@Composable () -> Dp` 传进去，订阅才落在 `item` 里、不放大到整页；
- 标题：`ACTIVITY_PICKER_TITLE` 从「Activity」改成「应用组件」（en: App components）。
  小节标题（「快捷方式」旁边那一节）仍叫 `Activity` —— 它是与快捷方式并列的分类，没跟着改。

#### 按键菜单：自定义键之间也用通用细线

用户口径「菜单里自定义按键之间的分隔线用通用的细线」。

- 库对相邻两行会自动画一条，但那条左端从 `PopupItemDividerMarginStartWithIcon` 起 ——
  行首有图标时**让开图标那一格**、只从文字下面开始，与别处穿图标区的细线不是同一支笔；
- 改法：`keyMenuEntries` 在每两颗键之间显式插 `MenuEntry.RowLine`（即 `PopupRowDivider`，
  左端取 `DropdownDefaults.InsideHorizontalPadding`）。显式放一条之后，那段的自动细线不再画；
- 「键清单 → 添加按键」那条原本就是这么写的，现在这一组内部也统一了。

#### 命令详细必须以支持的格式开头

用户口径「去掉支持的命令格式的默认为 shell 和 cmd:，同时对命令详细限制，必须以支持的格式开头」。

- 删掉「支持的命令格式」卡的第一行「默认为 shell 命令」—— 这条默认不再成立；
- `Action.parse` 的兜底从 `Shell(text)` 改成 `None` + 一行 `w` 日志：认不出前缀的写法
  **不执行**。宁可不跑，也不把一段不知道是什么的字符串交给 shell；
  这里兜的是手改配置文件 / 老版本存下来的裸写法（新写的在界面上就存不进去）；
- 新增 `Action.hasSupportedFormat(raw)`：判据就是 `parse` 认的那几样（几个精确比较的字面量
  加各条 `xxx:` 前缀）。`commandPayloadReady()` 用它当保存闸门 —— 没带格式的正文，
  「保存」是灰的；
- 「命令详细」那一栏同时出红字说明原因（`command_format_required`），
  否则用户只看到按钮灰着、不知道为什么；
- ⚠️ 往 `parse` 里加新前缀时，记得同步 `Action.PREFIXES` —— 两处漂移会让新格式
  「能执行但存不进去」；
- `cmd:` 那一行**保留**：它是「调用另一条单条命令」的唯一写法，删掉会让所有已存的引用失效。

#### 两条提示不再同时出现（结构性收口）

用户反馈过两次：「关闭主开关会出现两个提示条」「导入配置又出现了两个提示条」。
两次的成因是同一个 —— `HostLinkState` 里那两份状态各自独立：

- `statusHint`（常驻结论）：说明「现在能不能用」，不会自己走；
- `actionHint`（操作回执）：说明「刚才那一下的结果」，两秒多自己消失。

任何让「结论改变」的动作（关总闸 → 主开关关着；导入 → 配置整份换掉，结论跟着重算）都会让常驻那条
立刻出现，同时调用点又发了一条回执 —— 底部就是两层胶囊。

**收口放在显示层**（`PageSnackbars`），而不是逐个调用点判断「会不会撞上另一条」：

- 回执在场时，常驻那条**不参与组合**（包在 `if (actionText == null)` 里），回执消失后它自己回来；
- **不是**「传 `null` 让它走退场」：那样常驻条的退场（130ms）会和回执的进场（150ms）重叠，
  真机上看到的就是「两条同时在、靠上那条迅速消失」（用户口径，第三次反馈）；
- 判据只有一条：回执比结论更该被看到 —— 它是用户刚动手的答复，而且很快就走；
- `HintSlot` 相应改成收 `String?` 而不是 `HintState`（这一层只关心「这行现在显示什么」），
  并且 `last` 的初值取当前文本 —— 整行被移出组合再回来时，第一帧就该是那句话，不空一帧。

关总闸那次还多做了一步，**两档回执不一样**（用户口径「关闭主开关会出现两个提示条」→
「开启主开关也提示」）：

- **关**：`setKeyEnabled` 不发回执（只 `write`）。常驻那条「按键绑定已关闭」本身就是回执，
  再叠一条就是两层胶囊；原来回执里那句有用的后果说明已经并进常驻文案
  （`status.key_disabled` →「按键绑定已关闭，**侧键交还系统**」，en 同步）；
- **开**：要发。这时常驻那条是**收掉**，界面上一个字的反馈都没有，用户会以为「点了没反应」
  —— 回执「已启用按键绑定」正好补上这一格；
- `toast.binding_off` 随之无用，`Strings` 常量与两份语言包里的键一并删掉（各 325 键、完全对齐）；
  `toast.binding_on` 保留，就是给「开」这一档（以及「免责声明确认 → 启用」那条路）用的。

#### 导入导出适配自定义按键

用户口径「导入导出配置适配一下自定义按键」。`ConfigBundle` 导出 / 导入都会把 `keys` 里
每一颗键的 `enabled` 一律写成 `false`（那条规则本是「主开关与已确认不随文件走」），
但它只该管**侧键**：

- `enabled` 对两类键含义不同：侧键的它是**用户的决定**（首页总闸）；自定义键没有独立开关
  —— 它就是「这颗键能不能用」的闸门（收集时 `withCustomKey` 置 true，绑定页整片置灰
  判的也是它）；
- 照旧写 `false` 的后果：导出的配置**再导回来**，用户收的每一颗自定义键都是关着的、
  绑定页整片灰，而界面上**没有任何开关**能把它们打开；
- 改法：新增 `Config.withShareableKeys()` —— 侧键写关、自定义键**一律写开**，导出与导入
  两侧共用同一处。强制开而不是「保持原值」：文件可能被手改过，原值是 `false` 的话导进来
  就是一堆看得见、用不了的键；
- 顺带覆盖老文件：旧版导出的包里自定义键是 `false`，新版导入时会被这条规则纠正。

#### 导入保留本机「主开关」与「已确认免责协议」

用户口径先后两条：「如果已经是确认免责协议就不需要再清除这个状态了」「导入配置还是把主开关给关了」。

- 文件里那几位仍然一律写「关 / 未确认」（`ConfigBundle`：不该让别人的文件替这台机器做决定，
  也不该让人靠导入绕开「启用之前先确认」）；
- 但**本机此刻的状态**没必要因为一次导入被抹掉 —— 用户早就在这台机器上开过、确认过了。
  `ConfigTransfer.applyImportedConfig` 在写盘前把这几样换回本机此刻的值：
  主开关（`KeyId.PLUS` 的 `enabled`）与两位「已确认」；
- 自定义键相反：它们没有独立开关，`ConfigBundle.withShareableKeys()` 已统一置开；
- 导入成功的提示相应改回一句「已导入配置」（原来那句「主开关保持关闭」不再成立）。

#### 提示条文字「偏上」—— 按像素量完再对

用户口径「B, 我怎么感觉提示条的文字没有垂直居中」→「全部切，我感觉消息条文字还是偏上」→
「现在消息条常驻的，你直接量一下像素」。

- 上一轮已经加了 `contentAlignment = Alignment.Center`，文字在**行盒**层面确实是居中的；
  这次不靠感觉，拿真机截图（1272×2772 @ 560dpi ⇒ 3.5 px/dp）逐行扫亮度量：
  胶囊外沿 2460~2603（144px = 41.1dp），墨迹 2503~2557，**墨迹质心 2526.7 vs 胶囊中心 2531.5**
  —— 偏上 **4.8px = 1.37dp**（去掉那个全角逗号、只看中文墨迹主体，偏 5.5px）；
- 根因不是布局：`Center` 居中的是行盒（ascent + descent），而中文墨迹不占 baseline 下面那段
  降部（整句话里只有「，」伸下去几个像素）—— 行盒居中了，墨迹自然偏上；
- 改法：只给**文字那一层**加 `offset(y = 1.5.dp)`（`HINT_TEXT_OPTICAL_DROP`，5.25px），
  不动胶囊高度 —— 加高会连带把 squircle 的半径上限抬起来（见上一节的 `HINT_TALLER_BY`）。

#### 全仓动画曲线统一到 COUI

用户口径「项目里所有的动画曲线用的是COUI里的吗」→「全部切」。

- 之前混着用：Material 的 `LinearOutSlowInEasing` / `FastOutLinearInEasing`、两条手写
  `CubicBezierEasing`、以及不写 `easing` 时那两条默认曲线（`FastOutSlowInEasing` 等）；
  与 COUI 控件摆在同一页时，同一次点击触发的两段动画节奏对不上；
- 现在只有**两条档**，全部来自 `io.github.suqi8.coui.kmp.anim`：进 / 涨用 `DecelerateEasing()`
  （`1-(1-t)²`）、出 / 缩用 `AccelerateEasing()`（`t²`）。改到的位置：
  `PageMotion.kt`（显隐 / 贴边滑入滑出 / 步骤行 / 颜色过渡）、`Visibility.kt`（只淡入淡出那一档）、
  `SavedCommands.kt`（单条 / 多条翻页的淡入淡出 + 尺寸过渡）、`PageSnackbar.kt`（换句淡入淡出、
  宽度过渡、进出场）、`IconInput.kt`（错误提示淡入淡出）；
- 整页转场那条也从手写的 `CubicBezierEasing(0.2f, 0f, 0f, 1f)` 换成库公开的
  `NavProgrammaticEasing`（`response = 0.8 / damping = 0.95` 的弹簧阶跃烘焙成的 Easing，
  库把它公开出来就是给自定义 `NavSettleSpec.Tween` 复用的），**时长仍是我们真机拟合的 350ms**；
- 有一处是**照抄**而不是 import：错误提示原来那条 `(0.33, 0, 0.67, 1)` 就是库 `InputView` 里的
  `CouiEase`，但它是 `private`，拿不到；既然拿不到同一个常量，就改用 `anim` 包公开的
  `SinOutEasing`（淡入淡出这个幅度，两条肉眼看不出）。

#### 全项目「文字偏上」普查 + 一处算法收口

用户口径「看一下全项目还有哪里有文字偏上的问题，看看能不能全局修复一下」。

**成因**（与提示条那一节同源）：行盒高度 = `ascent + descent`，汉字墨迹基本只占 baseline
以上那段 —— 基线下面那截 descent 是留给西文降部（g / p / y）的，中文用不上。于是
`Alignment.Center` 居中住的是**行盒**、不是墨迹，墨迹永远高出一档。

**第一版按 0.1em 一条比例通吃，被真机打回**：用户口径「tag里的文字偏下了」。量下来
种类标签（11sp `footnote2`、Regular）多沉了 **2.5px = 0.71dp**。两次实测放一起才看清：

| 实测点 | 字号 / 字重 | 墨迹偏上 | 换成 em |
| --- | --- | --- | --- |
| 提示条胶囊 | 14sp / Medium | 4.8px = 1.37dp | **0.098em** |
| 种类标签 | 11sp / Regular | 1.3px = 0.37dp | **0.034em** |

差三倍：中文字体按字重**换的是另一个字体文件**，两个文件 hhea 里的 descent 本来就不是一个值。
所以 `opticalTextCenter(fontSize, fontWeight)` 按字重分两档（≥ Medium 用 0.1em、其余 0.035em），
**字重必须跟着传**；只传字号的调用点一律改掉（`DonorCell` 那种直接吃整份 `TextStyle`）。

**这套算法本身**收在 `ui/TextOptics.kt`，用 `offset { }` 只改绘制、不改测量。原先散在三处的
魔法数（`TILE_TEXT_OPTICAL_SHIFT` / 提示条自己那份 `HINT_TEXT_OPTICAL_DROP` / 手写的
`.offset(y = 1.5.dp)`）全部改成调它；字号或字重换了不用再回头改常量。

**动了的地方**（都是「文字在可见边界里居中」或「文字与图标同行」这两类）：

| 位置 | 情形 | 沉多少 |
| --- | --- | --- |
| 底部提示条胶囊 | 胶囊边界 + 居中 | 1.4dp（Medium） |
| 绑定网格格：标题 / 副标题 | 52dp 卡片边界 | 1.4dp / 0.45dp |
| 捐赠表格单元格 | 表格线围出的格子 | 按 `style` 自带字重（表头 Bold、数据行 Regular） |
| 「支持的命令格式」每行 | 定高 32dp、两条分隔线之间 | 0.45dp |
| 命令卡标题（类型图标 + 名字） | 图标与文字同行 | 1.6dp（Medium，**只在单行时**：两行时那块字上下各占一半，整体已经平了） |
| 命令卡摘要里带小图标的每一步 | 图标与文字同行 | 0.45dp |
| 「选择应用」行的大标题 | 与标签并排 | 1.6dp（Medium） |
| `AppKindTag` 那枚种类标签 | 胶囊上下各只有 1dp 内边距 | 0.39dp（Regular） |

**标签这一处多一笔**：把字沉正之后，胶囊**自己**比旁边 16sp 标题的墨迹中线高 3px（实测
2021 vs 2018），于是补了 `APP_KIND_TAG_SINK = 0.85dp` 把胶囊整体让下来。装完再量：
胶囊 720~772（中心 746）、墨迹 728~763（中心 745.5，上留白 8 / 下留白 9）、标题墨迹中心 745.5
—— 三者对齐，残余偏差 0.5px。

**没动的地方**（以及为什么）：

- `CommandSteps` 的步骤行、「选择应用」列表行里的第二行（包名）：列顶对齐，没有边界可比，
  挪了只破坏行距；
- 正常段落 / 多行文字：眼睛读的是基线，行盒偏不偏看不出，这一档不该动。

#### 底部提示：两份状态改成「谁最近变了显示谁」

用户口径「消息不是全局单例吗，切换消息会立即生效，我现在点振动反馈再点主开关，主开关的提示条会
等振动反馈的消息条消失再显示，而且是从靠上的位置瞬回的」。

前一轮的规则是「回执在场时，常驻那条整个**不组合**」（治的是「两层胶囊叠在底部」），这条规则
带出两个毛病，正是用户看到的：

- **要等**：主开关一关，「现在能不能用」已经变了，可只要回执还挂着（它自己的 2 秒没到点），
  常驻结论根本没进组合 —— 得等回执走完才敢露脸；
- **瞬回**：回执到点后要走 130ms 退场，退场期间**仍占着一行高**，此时常驻结论插进
  `Column` 的第一格 ⇒ 先出现在靠上的位置，等退场结束才「瞬回」底边。

改法：底部**只留一个位置**（`HintSlot` 只有一个），两份状态比「谁的话更新」：

| 时刻 | 显示谁 |
| --- | --- |
| 回执刚来 | 回执（常驻那条让位） |
| 主开关 / 运行状态刚变 | **常驻结论立刻顶掉还在计时的回执**（用户要的「立即生效」） |
| 回执到点自己走 | 落回常驻那条 |

三种切换都发生在**同一个节点**里（换的只是字符串，走 `HintCapsule` 那套三段换句），
没有第二个节点占位，也就不再有位移。

**「谁更新」的号必须全局发**（`HintState.stamp`）：一开始给两份状态各发各的号，结果
「先点振动反馈、再点主开关」两边各变一次、都是 1，平手判成回执赢 —— 症状跟没改一样。
改成 `HintStamp.issue()` 一个计数器发号后序号才有大小关系。同一句话重发不换号
（配置重载 / 重复点同一行不该把刚弹出来的回执顶掉）。

### 审计修复：静默做错的九处

#### 成功回执只在「都成」时发

- 「清空配置」「重置当前按键」「选动作」「删除按键」「重命名按键」「命令改名」六处：
  落盘成功、但广播没发出去时不再补一句「已完成」—— 那句会把写盘侧的「已保存，但通知注入侧
  失败，退出重进」顶掉（底部只有一行回执），用户看到的是「已完成」而注入侧仍按旧配置吞键；
- 判据从 `!= Failed` 收紧到 `== Ok`；「绑定挪没挪成」那类返回值仍按「有没有落盘」给，
  广播失败时文件与本地状态都已是新值，不算失败。

#### 「选择界面」：清单没到不许写、快捷方式身份不能丢

- 右下角那颗确认键改成**清单到了才出现**：第一版从第一帧就常驻，列表还在查时按一下会把
  「绑的是哪个界面 / 快捷方式」写成整个应用；
- 默认选中把**快捷方式身份**（`shortcutId`）一起递下去（草稿优先，其次当前绑定）：
  少了它，写回走 `app:包名`，一条能用的快捷方式绑定被改成永远解析不了的 token；
- 清单已经查到「这一项真不在了」时不带身份（交给原来的「退回自动」），不替不存在的 id 拼 token。

#### 分身的三处判错

- 「选择应用」：分身行「能不能打开」改成真判一次（取该用户的 `PackageManager`），
  不再写死 `true` —— 「隐藏失效应用」与确认键的闸原先都判不到分身；判不出来时仍按能开算，
  免得把好端端的分身滤掉；
- 「选择界面」：拿不到分身的 `PackageManager` 时不再静默退回主用户（那会列出并写入分身
  根本没有的界面），改为返回「没读出来」；整段补一层异常保护（兄弟路径本来就是这么做的）；
- 小窗：分身解析不到入口时不再去主用户的 PM 问「这个包还在不在」，不再把已安装的分身
  报成「可能已卸载」。

#### 链路自检两端对齐

- 注入侧也改成「**问满所有轮都没答**才把结论清成未加载」：原先每轮没回音就清，
  某轮 AMS 忙一下首页就整片置灰（用户报的「换 ROM 后整页一直是灰的，退出去再进来才好」）；
  两侧现在同一套判据，单轮漏答不算数。

#### 其它

- `keyevent:` 拒绝模块自己认领的侧键码（735 / 780 / 781 / 782）：那几个码被拦截器认领，
  注入出去会在 system_server 里自己触发自己（每 ~100ms 一轮）；其余码照旧放行；
- 国际化字典：解析失败也记一次尝试，损坏的字典不再每次取文案都重开 APK 的 zip、重打一条 W；
- 四处判据行从 `d` 提到 `w`（进「选择界面」看的是哪个应用、平台没有 `onBackPressed`、
  状态栏遮罩的两处跳过）；`ConfigStore` 那条「文件在但读不出来」仍留 `d` —— 它每条按键都读一遍。

- 顺带删掉零引用的 `ROOT_FIELDS`，`Field` 的参数从 3 个降到 2 个。

#### `KeyId` 上那三个「按键码反查」删掉

- `fromId` / `fromKeyCode` / `fromAnyKeyCode` 零引用（只在注释里出现），但它们只认内置键 ——
  谁照着注释用一次，自定义键就会静默落空；统一走 `Config.keyForId` / `keyIdOf` / `keyForCode` / `keyForRawCode`；
- 类注释与 `Config` / `Framework` / `GestureReceiver` 里指向它们的注释一并改掉。

### 审计修复：六条功能项与供应链

#### 反射兜底不再瞎挑重载

- `Reflect.method` 最后那段「名字 + 参数个数」的兜底从 `firstOrNull` 改成**唯一命中才返回**：
  多个候选时返回 null 并打一条 `w` —— 原先按反射返回顺序挑一个，挑错的后果是 `invoke` 抛异常，
  而日志看起来像「这个方法不存在」。

#### 起 / 停 / 退路四条路共用一份 extras

- `AppLauncher` 删掉只保 `Int`、其余转字符串的那份拷贝，四条路统一走保类型的 `putExtrasOf`：
  同一个能力走哪条路，服务端读到的类型不该变（`longPressEventType=false` 变成 `"false"` 是语义变了）。

#### 结果回调沿类链补挂

- 新增 `ui/hook/FileResultHook`：弹选择器前沿宿主 Activity 的类链找**第一处**声明并单独挂钩 ——
  宿主在自己的类里覆盖 `onActivityResult` 且不调 `super` 时，原先那一次回调直接断掉
  （界面上「选完了没反应」，日志里一条都没有）；
- 挂上之后返回 null、`super` 不会被调用，平台那份 hook 不会重复触发；同一个类只挂一次。

#### 生命周期三处

- 换页时先 `dispose` 上一页（原先只在关页那一路收，新实例先建、老实例后销毁时旧页面永远没人收）；
- 首帧诊断监听加「3 秒到点自摘」：页面一直不画时 `onDraw` 永远不来，监听会永久挂在宿主 ViewTreeObserver 上；
- 关页时释放 `FallbackOwners`（`ViewModelStore` 不再等下一次换页）。

#### 未知写法不再「静默」吃掉

- `Action.parse` 的兜底日志写明后果（下次保存会归一成 `none`）；不在模型里原样保留是**有意的** ——
  那要新增动作类型、属动作契约变更（AGENTS.md 一、4）；
- `docs/implementation.md` 补「已知限制」一节，把这条与自定义键的 `enabled` 语义写进去。

#### 供应链

- `gradle/verification-metadata.xml`（623 个组件，SHA-256）随仓库提交：依赖被换过会当场失败；
- wrapper 补 `distributionSha256Sum`（Gradle 9.3.1）；
- 两个 workflow 的 `uses:` 全部钉到 commit SHA（tag 可被挪，SHA 不行），注释里留原 tag；
- `patches/repo` 的产物补 `.sha256`，`build-patched.sh` 版本改写后**重新生成**而不是删掉了事；
  新增 `tools/verify-patches.sh` 并挂进 CI —— 补丁 aar 是 CI 直接解析的二进制，没有校验和时被换掉也看不出来。

### 禁用态的点击提示按真实原因说

- 「按键绑定」页里被置灰的控件，点一下原先一律回「页面还没就绪，重进本页试试」——
  页面的 provider 是 `blockedReason() ?: 页面还没就绪`，而「这一颗键被停用」不属于整页总闸
  （总闸是通的），于是落到最后那个兜底，把人引去重进页面，而真正要做的是到 ⋮ 菜单里把键启用回来；
- 新增 `disabledClickReason()` 一处判据：整页总闸（`blockedReason`）→ **当前编辑的自定义键被停用**
  （「「X」已停用，可在 ⋮ 菜单里启用」）→ 兜底改成中性的「这一项现在不可用」，
  不再冒用「页面还没就绪」；
- 页面级 `LocalDisabledClick` 与浮层菜单里那几行禁用项共用这一处（菜单行自己带了更具体的原因时仍优先）。

### 总闸与逐键拆开，按键菜单：停用的键带标记

- 「侧键停用」与「关掉主开关」原是同一个字段（`keys.plus.enabled`），于是 ⋮ 菜单里停用侧键
  等于关模块：整页变灰、横幅报「按键绑定已关闭」、再开还要过免责声明。现在拆成两层：
  **模块总闸** `GlobalConfig.enabled`（首页「启用按键绑定」那一行，要过免责声明）与
  **这一颗键** `KeyConfig.enabled`（⋮ 菜单那一行，每颗键都有，含侧键）；
- 判定侧只有一处判据 `ConfigChannel.enabledOf(id) = 总闸 && 这一颗键`；宿主侧那三处同样两级相与
  （`SideKeyGestureHooks` 的场景派发、`GestureReceiver` 的执行与松手）。报活的 `enabled` 改报总闸；
- 广播：总闸用新的 `module_enabled`（`GlobalConfig` 那一段、不带前缀），逐键的 `enabled` 不再兼任总闸；
- 老配置迁移：文件里没有 `global.enabled` 时，总闸取旧的 `keys.plus.enabled`、侧键这一颗写成开着
  —— 否则升级后打开总闸会是「开了没反应」。`KeyConfig.defaultFor` 也随之改为「内置键默认开、
  自定义键默认关」（「装上不改变行为」现在由总闸默认关来保证）；
- 导出 / 导入：只关总闸，每颗键一律写开（与原先对自定义键的处理同一条理由）；
- 菜单里停用的那颗键，名字后面挂一枚 `pointer-cancel` 图标（`MenuEntry.Row.stateIcon`）。用图标
  而不是文字：库那一槽（`hint`）只有 40dp，14sp 的三个汉字 42dp 会被截成「已…」（真机验过），
  11sp 放得下但小得不像话，而且还得为它多一条翻译；
- `setCustomKeyEnabled` 改名 `setKeyEnabledFromMenu`（不再只管自定义键）；首页那个写总闸的
  入口改名 `setModuleEnabled`；`disabledClickReason()` 对**任何**一颗键都给「可在 ⋮ 菜单里启用」。

### 修：加字段没抬格式版本 ⇒ 全量「配置读取失败」

- 给 `GlobalDto` 加 `enabled`（模块总闸）时**漏了抬 `ConfigCodec.VERSION`**：当前版本的 `md5` 是
  「按当前 DTO 重新编码」算的，多一个字段就对不上 ⇒ 所有 v3 文件当场被判「读不懂」，
  页面顶着「配置读取失败」、整页只读；
- `VERSION` 3 → 4；v3 文件按「版本更老、不校验 md5」那条读进来，迁移规则照旧（总闸取旧的
  `keys.plus.enabled`、侧键这一颗写成开着），下一次写盘自然升级成 v4；
- `ConfigDto` 类注释补一条「加 / 挪字段必须同时抬 VERSION」——这个坑踩过两次（v2→v3 搬单击延迟），
  两次的症状一模一样：不改一行数据，却让所有老文件一夜之间读不出来。

### 修：冷启动时那条常驻提示「闪一下就没」

- 首页那条常驻提示的判据是 `blockedReason()`，而冷启动那几帧 `hostServiceUp` / `injectStatus`
  都还是空的 —— 它必然判出「后台服务未运行」；等宿主报活广播一到，原因变 null、提示又被收走，
  观感就是一条消息条闪一下消失；
- 弹之前先等 `BLOCK_HINT_SETTLE_MS`（600ms）：这段挂起会随原因变化被取消，所以**只要它自己
  在这段时间里通了，这条提示根本不出现**。真故障只是晚 600ms 报，不影响任何闸门
  （页面该灰还是立刻灰）；
- 顺带：原因没变时不重弹（`show` 会重发一个 stamp，提示条要重播一次进场动画）。

### 「按键绑定」页的尾随标题也标停用

- 顶栏大标题右边那行（`pageSubtitle`，现在这一组叫什么）在**当前这颗键停用**时补一枚
  `pointer-cancel`，走的是同一个 `trailingSubtitleIcon` 槽位（原先只有「选择应用」页的
  「小窗起」用它）；
- 不标的话，这一页整片灰只能从「模块关了 / 链路没通 / 只是这颗键不接管」三档里猜，
  而真实原因就在 ⋮ 菜单那一行上（同一个字形，见 `MenuEntry.Row.stateIcon`）。

### 修：顶栏「小窗起」错标 + 命名窗键盘反复拉起

- 「选择应用」页没选应用时那一行是「还未选择应用」，尾随图标槽里的小窗图标照样画着，
  读起来像「这个还没选的应用会用小窗打开」——判据抽成 `appPickerChosenTarget()`，
  小窗图标只在**真选中了**才标（那行文字与图标现在同一个判据）；
- 「添加按键 → 命名」这条路上键盘会被反复拉起又消失，两处一起改：
  · **两个弹窗窗口不再叠**：听到键之后命名窗不再立刻开，而是等收集窗的收场回调
    （`onDismissFinished`，兜底 600ms）到了才 `show` —— 平台在窗口销毁时会把键盘一起带走，
    叠着就意味着「刚聚焦就被收走」；
  · `FocusOnShow` 改成**只抢一次**：`isWindowFocused` 翻一次它就重新 `requestFocus()` 一遍，
    ROM 收键盘 / 宿主抢一下都会让它翻 ⇒ 输入框反复「刚拿到又丢」，也就是键盘反复被拉起。
    抢到过就不再抢，真丢了焦点用户点一下输入框即可；
  · `AddKeyDialog` 的 `focusReady` 参数随之删除（不再需要「晚一点抢焦点」）；`addKey` 收掉
    `code` 的空判断与回执，让 `CollectKeyDialog` 留在圈复杂度阈值之内。

### 修：顶栏尾随图标与文字中线不齐（改补丁）

- 尾随标题那个图标是**我们自己的补丁**加的（`patches/coui/0004`），原先按行盒 `CenterVertically`
  对齐；而 COUI 的行高样式（`LineHeightStyle(alignment = Top, trim = None)`）让汉字墨迹落在行盒
  中线**之上** —— 图标反而显得偏低；
- 真机 3x 实测（「音量 +」那一行）：文字墨迹中线 425.3px、图标 430.5px ⇒ 偏低 5px ≈ 1.7dp。
  补丁里给图标加 `TrailingSubtitleIconLift = 1.75.dp` 的 `offset(y = -…)`；收缩是整块
  `graphicsLayer` 缩放，抬升跟着一起缩，折叠态关系不变；
- 复测：图标墨迹 402..447（中线 424.5），文字 403..447（中线 425.3）—— 差 0.8px，已在一像素内；
- 顺带修 `build-patched.sh` 的一处顺序错：校验和原先在 `sed -i` 改 `.module` / `.pom` **之前**生成，
  `tools/verify-patches.sh` 每次都会报这两份对不上，现在挪到最末尾统一算；
- `gradle/verification-metadata.xml` 里 `coui-ui-android` 的 aar / module 校验和跟着更新。

### 修：网格禁用时尾随图标还带着选中色

- 取值格的尾随勾选框按 `entryIndicatorColor` 上色，原先禁用分两档：选中的那一格用
  `disabledPrimary`（带主题色的灰蓝），其余用 `disabledSecondaryVariant` ——
  整片网格都灰了，只有绑着动作的那一格还「亮着选中的味道」，读起来像它还选中着；
- 改成**禁用时不分选中**，一律 `disabledSecondaryVariant`。勾选框的**形状**还在
  （哪一格绑了什么依然看得出来），只是不再用主题色喊；可用那两档（`primary` /
  `onSurfaceVariantActions`）不变。

### 禁用态被点：由补丁库递出「为什么」，菜单行也接了

- 上一版在控件外面包一层透明点击面（`DisabledExplainer`），一页套七八处、结构难看，而且
  菜单行根本包不上（`DropdownItem` 是库的数据类，禁用时连点击都不派发）；
- 补丁 `patches/coui/0008-disabled-click-explains.patch` 开两条口子：
  · `LocalDisabledClick` —— `BasicComponent` / `IconButton` / 可交互 `Card` 在
    `enabled = false` 时挂一层**无涟漪、不动按下态**的点击，把事件交给使用方；
  · `DropdownItem.onDisabledClick` —— 菜单行逐行给原因（「最多三颗按键」「侧键不能改名」这种
    是**这一行自己**的限制，不能拿页面那句顶替）；
- 禁用行的指针处理分两位：`enabled` 只管**外观与按下态**（禁用行不闪高亮），
  `disabledClickable` 只管**抬手要不要派发**；并且**只吃「点一下」的抬手**（超过触摸阈值算滚动，
  不碰）—— 第一版无条件吞抬手，菜单滚到一半松手会被判成取消、直接停住；
- 菜单行点完**不收菜单**（用户口径），只弹提示；`PageMenuPopup` 里那层「透明吃事件层」随之删除
  —— 它会把这次点击吃掉，且外面套 `Box` 会让库收不到点击（行宽也跟着错）；
- 页面侧只在 `PageContent` 根上 provide 一个 `LocalDisabledClick`（`blockedReason() ?: 模块不可用`），
  步骤的上移 / 下移与「添加命令」行各自就地覆盖一小段说自己的原因；
- 版本 `1.1.0-subtitle7` → `subtitle11`，`patches/repo` 里只留当前这一份，
  `gradle/verification-metadata.xml` 同步；
- `build-patched.sh` 的复位从 `git checkout -- .` 改成 `git reset --hard HEAD` —— 前者从**索引**
  恢复，索引里留着上一次打过的补丁时，重放必然报「补丁打不上」。

### 杂项收口

- 「这颗键停用了」的标记换成 `cancel`（圆圈 + 叉）：菜单行尾与「按键绑定」页顶栏尾随**同一颗字形**；
- 「自定义命令」那一行（还没有命令时的 `+`）在禁用时不跟着压暗 —— `startAction` 槽位库不上色，
  补 `rememberRowIconColor(enabled)`；
- 「添加命令」的**二级**浮层补上 `maxHeight = STEP_PICKER_MAX_HEIGHT`：原先按内容自然高度长，
  条数一多顶出屏幕且滚不动，现在与一级同高、超出由列表自己滚；
- 提示条：Android Toast 全部换成 COUI `Snackbar`（两摞：常驻结论 + 操作回执），
  命令执行失败与「收集按键」弹窗里的拒绝理由两处**刻意不换**（前者模块不在前台、
  后者被弹窗压着，改成写在弹窗正文里）。
