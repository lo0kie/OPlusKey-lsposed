# 自定义变量

### 新：自定义变量

- 变量页有自己的一份配置（`opluskey_vars.conf`），不受主页总开关管；两个入口都进它：
  首页「其他」卡那一行，以及「变量操作」页空态里那句「去新建变量」；
- 页里一列变量，一颗一行（名称 + 「当前值 · 类型」），行首那颗字形**按类型给**（文本 `abc` /
  数字 `123` / 布尔开关）—— 光看名字看不出它是哪一档；
- 点一颗**进「变量操作」页的管理模式**（不是一个抽屉）：在那里改它的当前值，也可以删掉它；
- 新建在**顶栏右上角**（那一页唯一的加法入口）：名称、类型、初始值三块，各带一句小标题；
  右下角不留 FAB —— 这一页只有一列变量，那颗实心圆会一直压着最后一行的右侧；
- 类型在菜单里选，三档各有自己的图标（文本 `abc` / 数字 `123` / 布尔开关）；建完之后类型不许改；
- 页内那句小标题是「自定义变量列表」：顶栏已经写着「自定义变量」，页内再原样重复一遍等于白占一行；
- 一颗变量都没有时铺一整屏空态（排版走通用那份 `Feedback`，字形与「已保存的命令」为空时同一张脸）：
  在可见区里居中，同时因为占满一屏，拖着照样能越界回弹；文案指向顶栏那颗「+」；
- 填错的地方当场标红（名称只能用字母 / 数字 / 下划线且不以数字开头，初始值必须符合所选类型）；
  名称或初始值没填对时标题行右端那颗提交键是灰的。

### 改：弹窗里的键盘不再「关了又自己弹起来」

- 输入弹窗那颗「焦点 / 键盘守卫」（`IconInput` 的 `ImeGuard`）原先观察 2 秒：这段时间里只要
  「聚焦着但键盘没了」就补叫一次。于是**键盘打开时按返回**（只收键盘、弹窗还开着）会被它当成
  「被 ROM 抢收」再叫回来，表现成键盘关了又弹起；
- 窗口收到 **800ms**（真机上「按电源键 → 弹窗弹出 → 键盘被 ROM 收走」发生在 0.3s 上下，留一倍半
  余量），并且**只补一次**：补完就收手，不再盯着补；
- 补叫还多一道前置：这次弹窗里键盘**先露过**才补。没露过就补等于在开窗那一刻先叫一遍，
  真正要被补的那一下（0.3s 后抢收）反而没人接。

### 新：变量跟着配置走

- 一份配置 = 主配置 + 命令库 + **变量表**：切换时三者一起换（`core/config/ProfileVars`），
  槽号同一套 —— `opluskey_config.conf` / `opluskey_commands.conf` / `opluskey_vars.conf`，
  第 2 份就是 `-2` 那一列；
- 不跟着走的话，切过去那套绑定里写着「计数 += 1」，改的却是上一套的计数 —— 看着像「配置没切干净」；
- 新建空白配置落一份**空**变量表（与「空白 = 空命令库」同一口径）：不落的话目标槽空着会被当成
  老配置，新配置一上来就继承了上一套的计数；
- 删除配置时连它的变量表一起删（留着就是谁也认不出的孤儿槽，而槽号不回收）；
- 老配置（只有 `config-N` / `commands-N`）没有自己的变量表：第一次切过去按「记住切走前的样子」
  处理 —— 当前这份存过去、当前不动，于是切走再切回来计数原样还在，不会因为升级被清空；
- 改值 / 增删 / **换配置**都让两页的变量清单重读一遍（`ui/state/VarListSignal` 一位记号，
  两页的 `LaunchedEffect` 都跟着它）：只让「记得那一页」刷新的话，另一页还挂着上一份配置的变量。

### 改：那格「自定义变量」点开进页，不再当场列两层

- 「自定义变量」那一格（绑定页与组合键编辑页同一张网格）点开从「当场列两层抽屉」改成
  **进「变量操作」页**：原来那套「一个面板换内容、标题跟着换成变量名」的编排整段删掉；
- 那一格的行尾改成**右箭头**（网格里 `ActionTile` 与命令步骤抽屉里那一行两处都改）：
  它现在确实是「进另一页」，与「打开应用」那格同一个指示；网格里其余行尾（入口格的选择器字形、
  取值格的方框 / 勾）一律没动；
- 命令的步骤抽屉里那一格也留着，点它进同一页（**不**把它落成一步：`vars:` 落下去只会写出一个
  `Action.parse` 认不出的废串）；挑完回来落成 `setvar:` 的一步；
- 步骤抽屉原先「最后一组逐颗列变量、点一颗再开一层」那一组撤掉了：同一个目录在两处摆两遍，
  只留一条入口，抽屉也少一层窗口；
- 绑上之后那一格的小字写的是**哪一步**（`「计数」+= 1`），不再只重复格名；
- 绑上之后的回执是「已绑定 「计数」+= 1」，不再套两层「」。

### 新：首页也能进变量页，命令里能对变量动手

- 首页「其他」卡里紧贴「自定义命令」下多一行「自定义变量」（另一个入口是变量操作页空态里那句）；
- 命令的步骤抽屉「快捷功能」那一组有一行「自定义变量」，点它进「变量操作」页挑一步；
- 选完**落成命令里的一步** `setvar:…`；
- 这一步在步骤行上显示成人话（`「计数」+= 1` / `「开关」取反`），行首是变量字形，
  不再是一串 `setvar:` 原文。

### 改：变量表单的三块与那颗按钮

- 名称那一格的行首图标与「自定义命令」页的「名称」同一颗（`label-important`）；
- 初始值那一格的行首图标换成一面旗（`flag`，读作「起点」）：原先借用变量自己的字形，与列表页
  每行行首那颗一模一样，抽屉里看就成了「又是一行变量」；
- 提交键从表单末尾那一整颗按钮挪到标题行**右端**（右上角），并且收成一颗**图标按钮**（对勾）：
  抽屉只有一个动作时，它与弹出层里的确定键同一个位置，图标又省掉一行字的宽度；
- 那颗对勾在「名称 / 初始值还没填对」时灰着并压暗，**点一下会说清是哪一条**（「请输入名称」/
  「只能用字母 / 数字 / 下划线…」/「这个值不符合所选类型」）—— 只灰不给原因，用户只会反复点；
- 标题行那两颗圆键收成一个组件（`SheetAction`）：触达区、图标边长、可用 / 破坏性 / **禁用压暗**
  三档配色、以及「灰着点一下说什么」全在组件里，调用点只给字形与一句原因；
- 布尔那一档的初始值不再是输入框，改成与「类型」同样的「一行当前值 + 一层菜单」，菜单里是
  `True` / `False`：布尔只认 `true` / `false`，让用户手打那两个小写英文词、打错了才知道不行；
- 换类型时已经写了一半的初始值按新档归一，归一不了就落到新档的空值（布尔落到 `false`）；
- 类型与布尔值那两行的行尾改成**选择器**字形（`selector`）而不是右箭头：箭头读作「点进去还有一层」，
  而这两行点开的都是一层菜单，与全项目那一套口径对齐；
- 抽屉里的小标题比页面里收一档：抽屉自己已经给过一层左右内边距，小标题再吃库默认那 32dp 就落到
  48dp，比它管着的卡片行文字右移一档 —— 收一档之后与行文字落在同一条线上。

### 改：抽屉统一走一个壳

- 步骤选择抽屉、新建变量抽屉两份骨架合成一个 `PageSheet`：面板底色、内边距、
  高度上限、高度过渡、滚动与越界回弹、返回登记与「跟手返回」全部下沉，调用点只递标题与内容；
- 两个抽屉的最高高度统一到 480dp（原先 460 / 480 各写一个，谁也没比谁更对）；
- 新建变量抽屉收起时不再硬切：`show` 原样交给壳，退场那一段动画回来了；「关掉再开是空表单」
  改由 `show` 作 `remember` 的键；
- 抽屉里的小标题**两处一起**收成同一档（`SHEET_TITLE_MARGIN`）—— 之前只改了变量那一处，
  命令页那个抽屉还是库默认，两个抽屉的标题不在同一条线上；
- 变量抽屉里的卡片补上「暗色下比面板亮一档」那一档色：原先漏了，暗色下卡片是半透明的，
  会透出底下的页面。
- 抽屉标题行右端那两颗圆键（新建 / 删除）取与顶栏同一档触达区 —— 不给的话库默认 48dp，
  摆在标题行里比标题还高一截。

### 改：组合键筛选菜单

- 「筛选按键」那句小标题挪到菜单最顶上（原先是夹在「全部」与按键列表之间）；
- 「全部」那一行的行首图标换成 `select-all`，并与下面按键列表之间加一条更深的分隔；
- 筛选之后的列表标题里，按键名用对角方框框起来，与绑定页里按键名的写法一致。

### 改：编辑步骤列表时「重置」不给按

- 命令页在编辑步骤列表（排序 / 增删步骤）期间，顶栏那颗「重置」置灰，点一下说明「排序中不能重置」——
  那一状态下页里别的控件本来就都禁用，只有这颗还留着会把人连改了一半的顺序一起清掉。

### 改：布尔的两种写法收进一处常量

- 存盘写法 `true` / `false` 现在由 `VarType` 提供（`TEXT_TRUE` / `TEXT_FALSE`），归一、
  取反、「算不算真」与新建表单共用同一份，不再各写各的字面量。

### 截图注入的结果码判反了，日志因此一直静默

- `injectInputEvent` 返回的是 `InputEventInjectionResult`：`0` = 成功、`1` = 失败、`-1` = 无权限。
  原实现把 `0` 当失败、`1` 当成功 —— 于是**真正失败的那一次（返回 1）一行日志都不打**，
  表现成「请注入侧注入」之后什么都没有；
- 顺带修掉注入模式：原来传 `1`（`WAIT_FOR_RESULT`，等「分发到目标窗口」），
  `input keyevent` 用的是 `2`（`WAIT_FOR_FINISH`）。截图这类被 policy 吞掉的事件没有窗口消费，
  用 `WAIT_FOR_RESULT` 必然拿到 FAILED。

### 截图加一条不依赖按键注入的兜底

- 真机日志（PLG110）：注入的 `keyCode=120` 确实进了 policy 的 `interceptKeyBeforeQueueing`、
  我们这边也认出「合成事件」并放行了两次（DOWN / UP），可屏幕就是不截；
- 注入的按键**没有**补 `FLAG_FROM_SYSTEM`：`input keyevent` 注入的 flags 本来就是 0、在绝大多数
  机器上都能截，加了反而与那条已验过的路不一致；
- 新增 `inject/ScreenshotViaHelper`：反射调系统的 `com.android.internal.util.ScreenshotHelper`
  （系统自己截图用的那条），**先试它、没成再走注入**；第一次调用把它的构造器与全部
  `takeScreenshot` 签名打进日志，签名对不上时一眼能看出来，不必再让用户抓一次；
- 回调那一行是这条路过没过的最终判据：发起成功但没有回调 = 系统那边没截。
- **PLG110 上实测跑通**：`takeScreenshot` 是 **3 参** `(int, Handler, Consumer<Uri>)`（AOSP 14 那份
  5 参在这台机器上不存在），`type` 传 `1` 有效；日志里「已发起（type=1）」之后截图正常出图，
  也不再走注入。签名与常量表都在第一次调用时打进日志，换 ROM 时照着对。

### 「快捷功能」加一格「屏幕翻译」

- 就是系统侧边栏那一项：起 `com.coloros.translate` 的前台服务
  （`oplus.intent.action.GLOBAL_TRANSLATION` + `extra_from_package`），屏上出翻译胶囊；
- 落点与配方照抄侧边栏（反编译 `GlobalTranslationTool.handle()` 逐字核过），权限宿主已有，
  不用绕 system_server；真机验过悬浮窗确实出来；
- 它不是开关：退出走它自己胶囊上那颗关闭，宿主不代停（会话状态在它手里）。

### 改：场景块那颗「更多」的右缩进与振动

- 行尾那颗「更多」与「多条命令」那颗「命令列表」的「更多」落在**同一位置**（字形右边缘都在
  页边 − 22dp）：这一行的标题本来就在页面内边距里面，再补 `endPadding`（或 `flushEnd`）都会
  把它往左推 10dp；
- 它原先**点了不振动** —— 小标题行尾这颗是唯一没走通用振动通道的控件，与旁边那颗可点标题
  同一行两种手感。现在与可点标题 / 卡片行走同一份判据（`LocalTick`）。

### 改：组合键编辑页的「已保存的命令」标题可点

- 与「按键绑定」页同一份判据（`SavedCommandsTitle`，两页共用）：有命令时点标题进「命令列表」
  那一格管命令库，草稿原样留着；
- 一条命令都没有时**不接点击**（那一格里已经是「去创建自定义命令」，同一趟去处不摆两个入口）。

### 改：抽屉里入口格的图标跟当前档位给

- 「响铃状态」这类入口格那一行，行首字形与网格那一格**同一判据**（`ActionCatalog.boundModeOf`）：
  绑的是哪一档就给哪一档的字形，不再一个看大类字形、一个看档位字形。

### 改：场景块里条件行的图标跟着取值给

- 条件那一行的行首字形原先只按**种类**给，同一类的不同状态长得一模一样（亮屏与锁屏都是那块屏、
  WiFi 开与关都是那个 WiFi、飞行模式开与关都是那架飞机），一列条件扫下来只剩文字能分；
- 现在按**取值**给（与取值菜单同一份 `conditionChoiceIcon`）：锁屏是锁头、亮屏是那块屏，
  开 / 关各一颗，方向是旋转箭头 —— 扫一眼就知道这一行在说什么；
- 未配完的那一条（只选了种类 / 刚插进来的空条件）仍按种类给：那时还没有取值可看。

### 改：场景图标分成「类别」与「状态」两族，不再撞字形

- 一级菜单（选哪一类）与两态取值原先撞在一起：屏幕状态那颗屏 = 「亮屏」那颗屏、充电那节电池 =
  「充电中」、WiFi / 蓝牙 / 移动数据 / 飞行模式那几颗也都是各自「开」的那一颗 —— 两级看下来
  像同一张图标表；
- 现在一级一律给**类别**记号、取值那几档给**状态**记号，两族不共用一个字形：屏幕 → 亮度、
  充电 → 插头、耳机 → 带麦的 `headset`、WiFi → 路由器、飞行模式 → 带航线的飞机；
  蓝牙「开」→ `bluetooth-connected`、移动数据「开」→ 满格 `cell-signal-5`；
- 屏幕方向那两档换成一对方向箭头（竖 / 横）：原先竖屏用「一块屏」、横屏用旋转箭头，
  前者与「亮屏」撞、后者与类别那颗撞。

### 页面骨架与行尾图标收成公共件

- 新增 `ui/PageScaffold.kt` 的 `PageScrollColumn`：十个整页滚动页面原先逐字重复同一条修饰符链
  （`fillMaxSize → nestedScroll → overScrollVertical → verticalScroll → padding(bottom)`），
  而这条链的**顺序**有三条非写不可的理由（顶栏折叠、越界回弹、页底留白），十份拷贝里写反一份
  只在真机上看得出。现在顺序只有一处，各页只传「哪个滚动行为、哪个滚动状态」；
- `RowEndIcon` 从「关于」页搬进 `ui/CardRow.kt`（行尾槽本来就是它的）：原来有三份实现
  （`RowEndIcon` / `CommandBranchParts.SelectorGlyph` / 首页与变量页各写一遍的内联 `Icon`），
  三份只差字形、尺寸与颜色一模一样 —— 现在 13 处调用共用一支；
- `asSystem`（以 system_server 身份执行）从 `StatusBarBridge` / `VoiceAssistBridge` 的两份
  private 拷贝收成 `bridge/BinderIdentity.kt` 一份：`clearCallingIdentity` 之后必须还原，
  这条纪律原来只写在两份各自的注释里；
- `ScreenshotViaHelper.take` 拆出 `resolve`（找类 / 找构造器 / 找方法），让「发起 + 收尾」与
  「准备」分开，顺带过掉 detekt 的 `ReturnCount`。

### 改：点一颗变量改成居中弹窗，不再滑进一整页

- 「自定义变量」页点一行弹的是**居中弹窗**（标题是变量名），不再压一整页；
- 窗里的行按类型与用途给：数字多「加一 / 减一」，布尔在命令那一趟多「取反」；
  「恢复初始值」只在命令那一趟出现，「删除」只在首页那一趟出现；
- 「编辑 / 设为…」要填值、删除要确认，都是关掉本窗再弹下一层 —— 换层等前一窗退场播完，
  两层窗不叠着开（叠着开就是键盘刚叫起来又被收走）；
- 删掉一颗不再另说一句：那一行当场从列表里消失，比一条提示更直接；
- 「自定义变量列表」每行的副标题改成「当前值 - 类型」：与操作区小标题、条件页同一个分隔写法。

### 改：弹窗收成一个通用壳，全项目只留磨砂那一档

- 新增 `PickerActionDialog`（`ui/PagePicker.kt`）：与单选选择器同一套行（通栏纯文字、行间细线），
  区别只在这几行说的是「做哪件事」而不是「选哪一个」—— 没有对勾、点一行就办；
- 「自定义变量」页那张操作弹窗改用它，自己只出「有哪几条动作、点了做什么」，不再自带图标与副标题；
- `FrostedDialog` 删掉 `blurred` 参数：单选 / 多选选择器不再走库那块不透明面板，
  全项目弹窗只剩磨砂一档 —— 同一页里一半糊一半不透明，读起来像两个应用的控件；
- 弹窗收起时只翻「弹没弹」那一位，**冲着谁**留着：面板还在淡出，标题与行得留着，
  否则会先塌成一条空壳再淡出。

### 改：变量只剩一个页面，操作都在点一颗时弹的那张窗里

- 变量只有**一个页面**：「自定义变量」列表页。两个入口都进它：首页「其他」卡那一行，
  以及命令里引用（绑定网格那一格、命令步骤抽屉那一行、条件分支那条动作）；
- 在这一页点一颗变量 → 弹居中窗，操作都在窗里；**不再有「列表下面再起一块操作区」**——
  「变量操作」页（`Screen.VAR_OPS` / `VarOpsScreen` / `VarOpsRows` / `VarOpsState`）整个删掉；
- 窗里的行按类型给（选择器那一套：通栏纯文字、行间细线）；
- 两个入口的差别只有两处：第一行是「编辑」（管数据）还是「设为…」（挑一步），
  以及「删除」只在管数据那一趟出现；
- 点下去的落点不同：管数据那一趟**当场改值 / 删除**（走 `VariableStore.apply`，与执行侧同一条）；
  挑一步那一趟**落成一步**写回命令 / 绑定 / 分支，然后退回原来那一页；
- 这一趟是哪一种由入口在进页前写进 `VarManageState.enter`，页面与窗都只读它。

### 改：布尔变量改值不再给输入框

- 布尔只有两个取值，输入框只会让人手打 `true` / `false`、打错了才说一句「这个值不符合所选类型」——
  改成 True / False 两行让人挑，当前值那行打勾；
- 文本 / 数字仍是输入框。

### 改：新建表单换序、名字放宽、删前反查引用

- 新建变量抽屉里「初始值」挪到「类型」前面（名称 → 初始值 → 类型）；
- 变量名的约束放宽：不再只认 ASCII 标识符，中文、数字开头都可以 —— 只挡真正会坏事的字符
  （空白与 `= + - ! $ : { }`，它们在 `setvar:<名字><符号><值>` 与 `${名字}` 里是语法本身）；
- 删一颗变量前**反查引用**（`core/model/VariableRefs`）：把绑定、条件分支、整份命令库里的
  `setvar:<名字>…` 与 `${名字}` 都扫一遍；还有人在用时**不让删**，确认窗里写清有几处、按钮灰着；
- 命令库读不懂时按「有引用」处理 —— 那种情况下一律拦着，宁可不让删也不留空引用；
- 管数据那一趟（首页进来）不再给「取反」与「恢复初始值」：那是拿来绑的一步动作，归命令里那一趟。
