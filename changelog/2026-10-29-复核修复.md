# 复核报告逐条修复（2026-10-29）

对那份 P1 / P2 / P3 报告逐条核过代码后，成立的都改掉了。下面按「毛病的那一类」分组，
每组只写**改成了什么**（为什么写在代码注释里）。

## 一、变量落盘：三态里的 null 不再被当成空表

- `VariableStore.decode`：文件里缺 `vars` 段现在按**读不懂**处理（打 W、返回 `null`）——
  以前返回「空表 + Ok」，`update` 那套「读不懂一个字都不写」被从构造上绕过，下一次 `setvar`
  把空表写回去，用户攒的变量无声消失。
- 页面不再自己拼整表再 `save`：新增 `VariableStore.add` / `remove`（读 → 改表 → 写），
  「自定义变量」页与删除那一趟都走它们。页面手里那份是**进页快照**，而执行侧的 `setvar:`
  是现读盘的 —— 拿快照整表写回会把「页面开着时按侧键改的值」整表退回去。
- 变量页把「读不懂」与「还没有变量」分开：列表不再把 `Unreadable` 折成空表（那份空表是写路径的
  输入），空态换成一句「变量表读不出来，先别在这里新建」。
- `update` 加两层串行：同进程 `@Synchronized` + 跨进程文件锁（`.lock`，拿不到时不阻塞、只记日志）。

## 二、解析：`VarOp.split` 按位置认符号

`setvar:msg=hi!` 里那个 `!` 在 `=` 后面，是**值的一部分**。以前按符号种类先试 `!`，
名字被切成 `msg=hi` ⇒ 判非法 ⇒ 存下去的动作读回来不是同一个，按那一下什么都不做。
现在取**出现位置最靠前**的那个符号。

## 三、多配置：切换与删除的原子性

- `ConfigProfiles.switchTo` / `ProfileCommands.swap`：第一步成功、第二步失败时**把目标槽还原**。
  以前目标那份配置被旧当前覆盖之后就永久没了，日志还写着「不动」。
- `ConfigProfiles.delete`：**读不出来也要能删**。坏文件删不掉 + `isFull` 按槽位算 ⇒
  「新建 / 导入」永久灰、界面里没有自救入口。
- `ConfigProfiles.list` 把读不出来的那一份列出来（`broken`，危险色，点了弹删除确认）——
  看得见才删得掉。
- `isFull` 与 `nextSlot` 用**同一把尺子**（槽位数）；导入查重名只扫配置槽（不再拿命令库 /
  变量表去 `readOf`，那每次都刷一条「读不懂」的 W）。
- `ConfigProfileActions` 用上 `write()` 的三态：写失败不再无条件报「已切换 / 已重命名 / 已新建」，
  删除那条在切换没落盘时**不再继续删**（那一槽里还是退路配置本身）。

## 四、死分支判定：只有真互补的档才能推「恒成立」

新增 `ConditionKind.exhaustive`，只有读 `Settings.Global` 的那四个开关（Wi-Fi / 蓝牙 / 移动数据 /
飞行模式）为 true。屏幕（熄屏且没锁屏时两档都不成立）、充电 / 耳机 / 媒体 / 响铃（服务读不到时
都不成立）、方向（`ORIENTATION_UNDEFINED`）都不算 —— 「凑齐」不再当成「恒成立」，
保存那道闸因此不会拒绝一条本来合法的规则。

## 五、界面与链路

- 命令抽屉关闭时**三样一起复位**（搜索词 / 二级菜单那一格 / 它的锚点）：以前只清搜索词，
  系统返回收掉抽屉之后二级菜单仍挂着，随手选一档就把一步静默加进草稿末尾。
- 系统返回**只收最上面一层**浮窗（新增 `PageOverlays.closeTop`）：以前一次收光，
  从「两层叠着」的位置按返回像跳了两级。页面离开那条仍走 `closeAll`。
- `onHostReentered` 清栈改用 `discardAfterExit`，与另两条离栈路径同一时机（以前就地清，
  表单会先变空白再滑走）。
- `CardList` 的行序按**此刻画得出来的行**算：`visible = false` 的行不再占位置
  （以前卡片末行藏起来时，上面那行被画成 Middle，少掉 Tail 的内缩与圆角）。
- `EmphasisText` 的分段与对齐方式无关：左对齐的长正文不再被压成一整块。
- `ConditionValueText` 每一档都显式列「正面那一档」，认不出的取值**显示原值**（空串显示「未设置」）：
  以前一律兜成「亮屏 / 响铃」，界面说「配好了」而执行侧永不成立。
- `donors()` 只在真读到才缓存：读不到不再把空名单永久缓存。
- 分身（`999@`）那一档的排位表键改成 `包名/类名`，与主档和查表那处同一个写法。
- `defaultPickOf` 先按快捷方式 id 找、再按 target 找：同一 target 下的快捷方式不再被当成应用本身。
- 界面页搜索时不再列「自动」那一行（下标账跟着同一判据）。
- 收集按键收到 `keyCode <= 0` 时留一行日志 + 一句提示（那是「广播里没带按键码」，不是一颗键）。
- 绑定网格的方向键 / 确认键：音量亮度弹窗开着时也交出按键（以前只判入口格菜单）。
- `MiniWindowLauncher`：分身不走 freeform（那条路用主用户 Context，会起错人）。
- 导出配置：只读态改为从盘上读（以前用页面那份默认值，导出一份「默认配置」还报成功）。
- `PageViewTree` 的 owner 记账按「三个里有一个是我们写的」判（以前只看 lifecycle，
  宿主只缺另两件时新页会复用一个已 release 的 store）。

## 六、闸门与文档

- CI 的架构判据加 `--strict`（本地实测全部达标、exit 0），与 AGENTS 的承诺对齐。
- detekt 现在扫**所有变体源集**（`src/*/java/**`），不再只看 `src/main/java`。
  这一改当场翻出 5 条存量问题，都修掉了（不是塞基线）：
  `BindingGrids` 多一个纯转发函数、`LevelDialog` 超长 + 文件名与顶层声明不符、
  `actionTitle` 圈复杂度 18、`isSelected` 五个 return、`ConfigProfiles` / `VariableStore` 函数数超限。
- `config/detekt/baseline.xml` 删掉指向已删除 `TileMenuPopup.kt` 的死条目。
- **根 `build.gradle.kts` 进格式闸**：它原先不在 `spotlessCheck` 里 —— `subprojects { }` 那份
  `kotlinGradle { target("*.gradle.kts") }` 只覆盖两个子模块，最该被管的那份构建脚本一条格式判据
  都不吃。现在根项目自己 `apply(plugin = "com.diffplug.spotless")` 并配同一套规则，`gate` 里
  也多一道 `spotlessCheck`。
  开闸时翻出的是**规则与文件类型不合**、不是写法问题：`.kts` 的语法树把所有顶层语句包在脚本
  自己的 block 里，于是任何顶层 KDoc 都被 `standard:kdoc` 判成「KDoc 不许出现在 block 内」。
  所以给脚本档单独一份规则 `ktlintRulesForScripts`（在共用那份之上只关 `standard:kdoc`），
  源码那一档照旧。
- `tools/audit-coupling.py` / `check-i18n-fallbacks.py`：源码目录不存在**直接失败**
  （以前静默跳过 ⇒ 「0 个文件、审计通过」），后者补扫变体源集。
- `verify-apk.sh` 与 `ci.yml` 的 `|| true` 改回 0 / 1 / 2 分开判（grep 出错不再被吞成空结果）。
- 「两档区分度」不再只在签名轮跑：脚本缺哪一档就只跳过那一档，PR 轮也能拦住「debug 里冒出
  封存资产」这类。
- `publish.yml` 的 `contents` 降成 `read`；`dependabot.yml` 的锁文件说明改成事实
  （dependabot 不跑 Gradle，每个自动升级 PR 都要人工补锁文件）；`device-state.py` 的键名修正
  （`pm_path`，「路径对的但 system 没注入」那条结论以前永不输出）。
- 文档：`device-findings` 删掉「不得引入 androidx / Compose」那条不存在的红线、
  给 `RemotePreferences` 那段加「已证死」批注、修重号（二十六 / 二十七 / 二十九…）、
  机型与版本对齐（PLK110 / ColorOS 17）；`implementation` 补 `releaseLog` 档位、
  等 CI 改「一直等」、版本基线更新到 1.3.0 / 8、锁文件改成两份；
  `zoom-window` 的三个旧路径；`debug-channel` 与 `ProbeChannel` 的来源校验函数位置；
  `AGENTS` 的交叉引用。
