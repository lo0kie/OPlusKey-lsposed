# 截图改由注入侧代注入

### 修：截图按下去没反应

- 「截图」不再由宿主自己注入 `KEYCODE_SYSRQ`：宿主注入的那一下 `injectInputEvent` 返回成功，
  而 ColorOS 不处理，表现是「日志里有『截图：注入…』一行、屏幕没反应」；
- 也不走 `su` 跑 `service call color_screenshot` —— 内置动作不该为了截张图去要 root
  （弹一次授权、慢半拍，没 root 的机器上直接不可用）；
- 改成**请注入侧代注入**：宿主发一条 `ACTION_INJECT_KEY`（带键码），注入侧在 `system_server`
  里用 `InputManager.injectInputEvent` 注入 —— 那个身份就是系统本身，与 `input keyevent` 同级；
- 「小布识屏」那条别名仍是原生调用（`startForegroundService`）；「截图」不再是 shell 别名，
  多条命令里它与普通步骤一样可合并。

### 改：图标改成「读一颗建一颗」，冷启动后首次进「按键绑定」页不再卡一下

- 原来页面级有一张一次性建好的图标表：`derivedStateOf` 把整条动作队列（内置动作 + 各层菜单的取值
  + 命令库，一百五十多项）全建成 `ImageVector`，第一次有人读时就在组合期全建一遍 ——
  一屏其实只画得出二三十格，剩下那一百多颗是白建的，冷启动后第一次进「按键绑定」页那一下
  轻微掉帧就是这一笔；
- 改成按需：`tileIcon(spec)` 读一颗建一颗、带进程内缓存（键是 `Spec`，同一格在哪处露面都是同一颗）；
  网格、格子里那行小字、「添加命令」浮层、入口格菜单四处都改成它；
- 那张整表与拼它的 `ActionCatalog.queue` 一起删掉（唯一调用方就是那张表）；
- 「图标表缺项」那条兜底分支与它的 W 日志也一并去掉 —— 现在要什么建什么，不存在缺项。

### 改：「条件执行」页那一行「在编哪一档」挪到大标题下面

- 原来挂在大标题右边（尾随标题），而它写的是键名 + 手势（`「侧键」-单击`），比别的页那行小标题
  长得多，跟「条件执行」这个标题抢宽度；
- 改成占大标题**下面**那一行（首页放模块版本的那个槽位），一行放得下；
- 尾随标题那一侧因此空着 —— 这一页本来也没有别的要写在右边的东西。

### 改：「重启服务」也先问一句

- 原来 `⋮` 菜单里点一下就执行：它会**杀掉设置页进程**再让宿主把页面拉回来（页面闪一下重开），
  正在编辑、没保存的内容跟着丢 —— 与「清空配置」同一档代价，点一下就走太轻；
- 改成先弹一张确认窗（标题「重启服务」、正文只提醒一句「未保存的内容会丢」、动作「重启」），
  确认之后才走原来的流程；
- 那一位置放在页面状态里（与「清空配置」同一处），窗由首页那份菜单画。

### 改：注入侧注入的写法对齐 `input`

- 注入模式从 `INJECT_INPUT_EVENT_MODE_ASYNC`（0）换成 `INJECT_INPUT_EVENT_MODE_WAIT_FOR_FINISH`（1）——
  真机上 `adb shell input keyevent 120` 能截出图，而它用的就是这个模式（宿主那份用的是 0）；
- 注入挪到**独立线程**：`WAIT_FOR_FINISH` 会等事件被处理完，而调用点是 `system_server` 主线程，
  在主线程上等一次截图链路等于把整机挂住一下。

### 修：注入侧拿 InputManager 拿了空

- 真机日志：宿主把请求发到了注入侧，注入侧却报「`InputManager.getInstance()` 拿不到实例」——
  这条 ROM 上那个静态入口返回 null，于是整条注入静默失效；
- 改成按**新 → 旧**依次试多个入口：`InputManager.getInstance()` → `InputManagerGlobal.getInstance()`
  （Android 14 起静态方法搬到了这里）→ `LocalServices.getService(InputManager)` →
  `InputManager()` 的无参构造；第一个拿到的记住不再重取，全拿不到才记一行「这条路走不通」；
- 每次走哪个入口都记一行日志 —— 下次再出问题，一眼能看出断在哪一条。

### 改：界面上「条件执行 / 条件」统一改名「场景判断 / 场景」

- 页面标题、⋮ 菜单那一项、卡片小标题、两块菜单、清空 / 删除确认窗、各类提示，中文一律换掉：
  「条件执行」→「场景判断」、「条件」→「场景」（例：「未选择场景」「场景 1」「当前场景恒成立」）；
- 只动**用户看得见的字**：字典 19 条 + 代码里的中文兜底 35 处（含日志主语）；
  代码注释、`docs/` 里的说法保持原样（那是维护者的术语，与界面文案不是一回事）；
- 英文文案未动（`condition` / `Conditional execution` 在英文里本来就是准确说法）。

### 改：「场景」换了记号，菜单行那颗统一

- 新增「场景」的记号 `adjustments`（一组可调的情境设定）：卡片里「未选择场景」那一行用它 ——
  原来借用的是 `arrows-split`（岔路），而岔路说的是「按它走哪一支」，不是「在什么情境下」；
- `arrows-split` 留在规则表本身：空态与表尾那几处注脚；
- 组合键编辑页那行「场景判断」的菜单图标原来用 `arrows-split`、按键菜单用的是 `git-fork`，
  两处同名的一项长得不一样 —— 统一成 `git-fork`。

### 改：标题改叫「系统场景」，菜单行首换成场景那颗

- 页面标题、按键 `⋮` 菜单里那一项、组合键编辑页那一项，中文都从「场景判断」改成「系统场景」
  （与宿主服务里那套「系统场景派发」的说法对齐）；
- 菜单行首那颗从 `git-fork` 换成 `adjustments`（与卡片里「未选择场景」同一颗）—— 同一件事在两处
  用同一颗字；`git-fork` 那份单独的定义随之删掉。

### 新：配置可以有多份

- **入口全在「更多选项 → 配置 → 切换配置」那一层菜单里**：上半是配置列表（当前那份打勾、
  副标题写当前那份的名字，与「语言」那一行同一个形状），底部压一条加深带，接新建 / 重命名 / 删除；
- 「删除」不再开二级菜单：它删的就是**当前那份** —— 先换「默认」那份上来（两份内容互换），
  再把原来那份连同它的命令库删掉，删完提示「已删除「X」，切到「默认」」；
  当前是「默认」那份时这一行是灰的，点一下说「默认那份不许删除」（那就没有地方可以退回去了）。
- 首页 `⋮` 恢复原样（默认界面 / 重启服务 / 导出日志 / 清空配置），配置相关的一项都不留 ——
  它是「对整机动手」的地方，配置管理属于「更多选项」里那张配置卡；
- 当前生效的永远是最初那个槽（宿主按键路径上读的就是它），所以切换 = **两份内容互换**，
  执行侧一行没改；名字存在配置自己里头（`profile_name`，配置版本 14 → 15），交换之后不会错位；
- 「默认」那份（名字为空、升级时落在原位置的那份）**不许改名、不许删**：删了就没地方回去了；
  当前那份也不许删。两道闸：选择器里不列，业务层也拒；
- 槽号只增不回收，新的一份永远排在最末 —— 顺序因此恒等于创建顺序，不随切换跳动。

### 改：每份配置带上自己的命令库

- 主配置里绑定的是 `cmd:<名字>` 这种**引用**，命令正文在命令库里。库只有一份的话，切配置只换了
  引用、没换被引用的东西 —— 界面上按钮好好的，按下去不执行；
- 于是「一份配置」= `opluskey_config-N.conf` + `opluskey_commands-N.conf`：切换对调两份配置、
  复制带上命令库、删除连它那份命令库一起删；
- 老配置没有 `commands-N`：第一次切走时把当前那份命令库存进那个空槽（等于记住切走前的样子），
  当前那份不动；切回来时还是原样，什么都不丢。

### 改：「导出配置」可以先选一份

- 点那一行先弹一列配置的菜单（列出全部、当前那份打勾），选完再走系统的「保存到」；
- 只有一份时这层菜单里也只有一行，仍然照常弹 —— 配置列表永远是同一形状（与「切换配置」共用
  同一个行表构造，两处只差「点了之后干什么」）；
- 导出的包是那一份**连同它自己的命令库** —— 与「切到那份时机器上跑的东西」一致。

### 改：导入插到最末，不覆盖当前那份

- 导入不再写进当前生效那份，而是**存成新的一份、排在最末**：当前那份一个字节都不动，
  所以不可能出现「导错了、原来的也没了」；
- 因此也不用再在「配置写失败 / 命令库写失败」之间做回滚：两段都写进同一个新槽，
  任一步失败就把这一槽清干净（一起成、或一起不动）；
- 名字取文件里那份的 `profile_name`，没有就叫「导入配置」；提示改成「已导入为「X」」，
  要生效从菜单里切过去；
- 命令名去重（同名只留最后一条）这条闸照过 —— 它原来在「写命令库」那个出口上，
  导入现在不经过那个出口了，得自己再过一遍。

### 改：「新建配置」先起名、确认后直接切过去

- 点「新建配置」先弹一个命名窗（起点「配置 N」，N 是现在有几份的下一个号）：取消就什么都不做，
  一个字节都不写；
- 确认后把**当前那份**复制成新的一份、插在最末，然后**直接切到它** —— 用户刚给它起了名字就是要用它；
  原来是建完留在原地，卡片上还写着「当前：原来那份」，看着像没建成；
- 命名窗与「添加按键 / 重命名按键 / 重命名配置」是同一个 `NameDialog`（只差标题与确认之后干什么）。

### 新：「重命名配置」

- 位置在「切换配置」那层菜单的底部（新建下面一行）：一个输入框，改的是**当前那份**的名字；
- 「默认」那份不给改（它的名字空着才认得出），那一行是灰的，点一下会说「默认那份不许改名」；
- 名字存在配置自己里头（`profile_name`），落盘走通用写入通道 —— 页面状态、配置广播、重问注入侧
  一样不少；名字没变就什么都不做（不落盘，也不报「已重命名」）。

### 改：「填一个名字」的弹窗合成一个

- 「添加按键」与「重命名按键」本来就是同一个窗（只差一句标题），配置改名又要第三个 ——
  三处合成 `NameDialog`（`ui/PageNameDialog.kt`）：标题、输入框标签由调用方给，
  正文（输入框 + 取消 / 确定）只有一份；
- 长度上限、「确定」什么时候是灰的，也跟着只有一处。

### 新：自定义变量（底层能力，界面上暂无入口）

- 变量有**类型**：`string` / `number` / `boolean`。新建时选一次，之后**不许改** —— 类型是身份不是内容，
  要换就删掉重建。强类型的落点：每次写值都按类型归一（NUMBER 只认十进制数字、BOOLEAN 认真假与
  `1/0`、`on/off`、`yes/no`），归一不了就**拒收**，不悄悄转成别的类型；
- **初始值必填**（开机重置要有地方回），新建时也按类型归一一次；
- **持久化**：单独一份 `opluskey_vars.conf`（与主配置 / 命令库同一层外皮），值一变就原子写盘。
  不跟配置档走 —— 变量是运行期状态（计数器 / 标志位），切换配置不动它；
- **重启后重置**：文件里记一个开机指纹（`ProcClock.bootWall()`，与「六之三」同一处判据），宿主进程
  起来时比一次；变了就把带 `resetOnBoot` 的那几颗拉回初始值。同一次开机里反复起进程是幂等的；
- **命令里怎么用**：
  - 引用写 `${名字}`（shell 命令 / 应用目标 / 广播 action / `cmd:` 名字里都认），**执行前**展开；
    认不出的名字原样留着，不静默换空串；
  - 修改写一条动作 `setvar:<名字><符号><值>`：`=` 赋值、`+=` 相加（STRING 则拼接）、`-=` 相减、
    `!` 取反（只有 BOOLEAN，后面不跟值）。右边可以写 `${其它变量}`，所以「拿另一个变量算」不需要
    额外的表达式语法；
  - 变量**必须先存在**：命令不能顺手造一个出来（否则「类型不许改」在运行时就被绕过去了）；
- 与 `setting:` 同一类：`setvar:` 的载荷（名字 / 符号）认不出就按「不支持」处理，不落 shell 兜底；
- 那份文件读不出来时**一个字节都不写**（与主配置同一条纪律：不许按默认值写回）；
- 主配置版本**不动**（变量在自己那份文件里，`VAR_VERSION = 1`），没有迁移；
- 界面入口按口径「先不加入口」：现在只能手写文件建变量，`Variable.create()` 是将来「新建变量」
  那个窗唯一的落点。

### 改：列表顺序固定、「默认」永远在最上面、除默认外最多三份

- 排序改用**位次**（配置自己存 `profile_order`，0 固定留给「默认」）：切换是两份内容互换、
  内容会在槽之间搬家，按槽号排的话刚切过去的那份会从第 3 行跳到第 1 行 —— 现在切换前后
  列表一模一样，只有打勾的那一行变；
- 老配置没有位次（升级时都是 0）：三级兜底「是不是默认 → 位次 → 槽号」，行为与升级前一致；
- 新建 / 导入取「现有最大位次 + 1」，所以新的一份总排在最末；
- 除「默认」之外**最多三份**，按**槽位数**计（不按「能读出来的内容」：某份文件坏了读不出来时，
  那个槽仍然占着位置）；
- 到顶之后两道入口一起灰掉并给同一句「最多三份配置」：「新建配置」在切换菜单底部、「导入配置」
  在配置卡里 —— 导入不再让人选完文件才被告知满额；
- 配置版本 15 → 16（多一个 `profile_order`）。

### 改：「删除配置」先问一句

- 删掉一整份配置（连同它自己的命令库）不可恢复，与「删除命令」「清空配置」同一档：
  改成先弹确认窗（正文点名是哪一份），确认之后才走「先换默认上来、再删掉它」。

### 改：新写的注释与提示里不留「那份」

- 「那份」要回头看上一句才知道指谁，本会话新写的注释统一换成具体说法
  （当前配置 / 目标配置 / 退路配置 / 原来的命令库）；
- 界面文案同步：「默认那份不许改名」→「默认配置不许改名」、
  「切换失败：那份读不出来」→「切换失败：这一份读不出来」、「默认那份不许删除」→「默认配置不许删除」。

### 新：「组合按键设置」里可以调「按键之间的等待」

- 组合键判定里那个「两颗键的 DOWN 相差多少算同时按」的窗口原来是写死的 80ms，现在可调
  （20 / 80 / 300 下限·出厂·上限，10ms 一档），放在「组合按键页 → 组合按键设置」那一卡的第二行；
- 代价是真实的，副标题里写明「调大会让参与组合的按键多等这么久」：**参与组合的键**按下去之后
  会先压一个窗口（等第二颗键会不会来），这期间它自己的单击 / 长按都还没开始判；
- 不参与任何组合的键**一点不受影响** —— 判定器对它们直接回「与组合无关」，立刻照旧判单键；
- 实现：`ComboDetector.onDown` 从「是 / 否」改成三态（归组合 / 先等一个窗口 / 与组合无关），
  压着的那一按记在 `HeldPresses`（`inject/input/`，只管「到点补发」这一笔账，拦在单键判定器前面）；
  抬手时立刻补发（组合已经不可能成立，不必白等），组合成立时把压着的丢掉（否则一次按压执行两个动作）；
- 这一位要注入侧读，所以走**广播**（`ConfigFields.F_COMBO_WINDOW_MS`），配置版本 16 → 17。
  **装完要重启手机**（注入侧在 system_server 里，只随开机加载）。
