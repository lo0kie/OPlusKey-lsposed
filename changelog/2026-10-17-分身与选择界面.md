### 使用 ColorOS 接口开关持久化与动作分流

  内容整块高出一截，等页面读完配置那次重组才落回原位
- 判据改成「必须是负数」：首帧按展开高算，卡片顶边不再先高约 30dp 再复位
- 两个选择页「滚到已绑定那一行」也改成先等一帧再读折叠量（读到 0 等于没折，
  目标行会被压在展开的顶栏底下）

- 「设置生效」的判据在写完到注入侧回包之间必然不成立（两边指纹还没对上，实测十几毫秒），
  那一小段被当成「没送到」⇒ 整页控件打灰再亮回来、底部提示被换掉再换回来
- 自己刚写下去的那一份记成「在途」，宽限期（2 秒）内不判未同步；回包对上就提前结束，
  一直等不到则在宽限期满时按真实结论判

### 顶栏高度改成实测，首帧不再「先高一眼」

- 顶栏自己上报高度（`onSizeChanged` → 页面级 `BandHeight`，与三条固定带同一条通道），
  页内容顶上那个占位读实测值 —— 不再按库的展开高常量推（两者实测差 17dp）
- 整页第一帧先不画（alpha 0，底色与页面同值）：顶栏高度在同一帧里量不出来，
  先按兜底值排上再落回就是「闪一下」；等它量到再露，150ms 兜底防不画
- 一并覆盖所有页面（门开在页面骨架上，不是各屏各写一遍）

### 顶栏让位的三处结构错误

- 顶部让位不再叠加折叠位移：以前顶栏每折一点占位就矮一点，内容跟着一起上移
  （「内容区和 header 一起滚」）；退回上一页时那笔残留还会把内容缩到 header 底下
- 顶栏高度通道改成**每页一份**（CompositionLocal）：转场期间两页同时在组合，
  共用一份会互相覆盖 —— 这是「从别的页回首页内容跑到 header 下面」的直接原因
- 顶栏上报高度时扣掉固定带：带子高度各页自己已经加过一次，有带子的页面之前让了两次
- 每页首帧先不画内容，等本页顶栏量到高度再露（150ms 兜底），消掉「先高一眼再落回」

### 顶栏高度只剩一把尺子

- 折叠高也改成实测口径（实测展开高 − 库给的折叠量）：两个选择页定位时不再按库常量算，

### 松手结束（灵感语音）

- 线格式多一条 `phase=release`（`ModuleWire.PHASE_RELEASE`）：**松手不是手势**，它是独立的
  一条信号 —— 宿主按 (键, phase) 去重、按 phase 映射手势，混进 `long` 那三档里两边都会串
- 判定侧在「这一按结束」时报它（抬手，或 `FLAG_CANCELED` 取消；`GestureDetector.finish`），
  **只有真判过长按的那一次**才报 —— 短按 / 双击不报，否则每次按键都多一条广播
- 执行侧收到后发结束：同一条 `DataCollectService`，`longPressEventType=2`（真机实测：采集用的
  FGS 类型退回去、卡片收掉）。落点表新增 `BuiltIn.stopExtras` —— 「这一档有没有结束形态」由
  表说，执行侧不猜
- 收尾按 `ActionRunner.voiceMemoryOn` 判（我们起没起过那一段），不按配置判：3 秒连按窗口里
  第二次的起采集是被挡掉的，那一下松手若照样发结束，掐断的是**上一段**正在录的
- 灵感语音不再排「长按连续触发」：它连的是麦克风，重复拨等于把正在录的那一段掐掉重来
  （判据 `KeyConfig.longIsVoiceMemory`，与执行侧收尾同一个口径）

  不更新的话换包后那条「需重启」永远判不出来

### CI 没有签名文件时配置期就崩

- `beta` 档无条件取 `signingConfigs.getByName("release")`，而那一份只在有 `keystore.properties`
  时才建得出来 —— 没配密钥的 CI 连 `gate` 都跑不起来，报的是与真因无关的
  `SigningConfig with name 'release' not found`
- 两档共用一份回落：没有发布签名就用 debug 签名，真正会拦下的仍是封存层那条「缺签名」

### CI 产物名停在上一版

- 文件名与 Actions artifact 原来按 `BUILD_ID` 命名，而那是源码里的手写常量 —— 忘了更新时
  产物叫 `oplus-key-beta-2026-10-15-0001`，看不出是哪个版本
- 改成按 `versionName`（`oplus-key-0.2.0-beta.apk` 这一档），`BUILD_ID` 只留在 Release 正文里

### 打开应用：名字单独存，不再拼进目标

- 目标的写法回到纯身份：`999@包名/类名`、`999@包名/快捷方式id`（`AppTarget.format` 去掉了
  第三个参数）。名字是**显示信息**，不是目标的一部分
- 名字进配置里单开的一段 `app_names`（`Config.appNames`，键 = `AppTarget.identity`）：
  `ConfigCodec` 单独读写、**空表不写**（从没绑过应用的人，文件与从前逐字相同）；
  不进 `ConfigFields` 字段表、没有 `*_EXTRA` —— 执行侧不需要它，别每次按键都广播一遍
- 落盘时机：与绑定**同一次写盘**（`pick(spec, g, appName)`）—— 分两次写会多一次广播，
  而中间那一下读到的配置只有新绑定、没有名字，顶栏会当场闪一下包名
- 名字怎么来的收在一处（`appNameOf`）：存下的 → 老配置 token 里的 `|名字` → 现查 → 包名；
  网格小字、顶栏「已选择」、命令步骤名、执行时提示全走它
- 老配置**照读**：`AppTarget.label` 只剩「读旧数据」这一个用途，`Action.App` 的 token
  原样保留 `|名字`；重新挑一次就迁进 `app_names`（`AppShortcut` 那档重新落盘时名字会换回应用名，
  因为旧名字只存在于 token 里）

### 「选完快捷方式 / 界面，再进来显示的是包名」

- 顶栏「已选择」原来按 `AppTarget.same` 在本次清单里找名字 —— 那个比法**连 `/类名` 一起比**，
  绑了具体界面 / 快捷方式时清单里那一行只是纯包名，永远匹配不上 ⇒ 落到包名兜底
- 现查那一路也有两处同样的病：`appLabelOf(target.substringBefore('/'))` 对分身会拿着
  `999@包名` 去查（必然查不到，原样显示成包名）；命令步骤名那条也是这么切的
- 现在名字随绑定落盘，不进清单也能显示；现查那一步统一按 `AppTarget.pkg` 剥前缀、
  按分身补槽号（`appNameOf`）

### 模块说明里的入口路径

- LSPosed 管理器里那句「模块入口：设置 - 快捷键」改成「系统设置 - 快捷键」（英文同步）

### 撤掉机型锁

- 任何机型、任何系统版本都照常注入：按键接管 / 手势劫持 / 设置页替换全套，不再按适配清单跳过
- 清单外的组合只在「更多选项」里那一行提示（「未在适配清单里，可能不可用」/「未验证过这一版系统，
  可能不可用」），首页那条常驻提示与整页禁用都不再吃它
- `ENFORCE_DEVICE_GATE` 与那两条提示文案一并删掉

### 去掉 beta 档

- 只留 `debug` / `release` 两档；`beta` 的源集、构建类型、CI 步骤与产物全部删掉
- 预发布仍然只靠 Release 上的「预发布」标记区分，发的是同一个 release 包
- `tools/check_variants.py` 跟着改成两档

### 网格与小窗的文案

- 小窗那两档的标题改回「展开的小窗 / 收起的小窗」（菜单行与网格格子共用这两条）

### 二级菜单顶上写父标题

- 入口格弹出的那一层菜单（响铃状态 / 媒体控制 / 系统导航 / 系统按键）与「添加命令」浮层的二级，
  第一行都改成小标题（库的 `DropdownHeaderItem`），写的是**父标题** —— 一级菜单里那一行的标题
- 两处共用同一个构造入口 `modeEntries(parentTitle, …)`：格子侧传 `spec.label`，命令页传 `subTile.label`；
  二级浮层会把一级压暗，没有这行小标题时只看得到「静音 / 振动」这几项，认不出是点哪个入口进来的

### 降耦合收口（包级环 1 → 0）

- 包级环 **1 → 0**、包级边 **144 → 142**、`ui → host` **5 → 2**（判据与前后值记进 `docs/decoupling.md`）
- `AppPickerUiState`（连同 `SmallWindowBlock`）从 `ui/screen/apppicker` 进 `ui/state` —— 它与
  `ui → ui.screen.apppicker` 是同一个环的两条边；`rememberAppPickerUiState` 留在 `SettingsPage.kt` 末尾
  （它是 `SettingsPage` 扩展，跟进去会让 `ui.state → ui` 把环换个方向长回来）
- `appNameOf` / `appLabelOf` 从 `ui/screen/apppicker/AppNames.kt` 进 `ui/AppNaming.kt` —— 全项目共用的
  名字派生，挂在「选择应用」页的包里等于让 binding / command 两处 / 顶栏 / 页面分派反向依赖那一屏
- `AppCloneCatalog` / `AppEntry` / `MiniWindowSupport` 从 `host/action` 进 `bridge/` —— 列分身、包名→入口、
  支不支持小窗都是**查询**，两个进程都读；搁在执行层时页面层只能 `ui → host`
- `cloneUsersInDisplayOrder` 加进程内缓存（只记非空结果）：拼名字那条路是逐行调的，每次重列用户都要走
  `UserManager#getUsers` 的反射 + binder
- `TileMenuPopup` 的 `modes` / `parentTitle` 收成 `spec`（三者本来同源），参数个数也回到 detekt 阈值以内
