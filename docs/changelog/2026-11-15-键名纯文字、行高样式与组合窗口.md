# 键名纯文字、行高样式与组合窗口

今天这一批改了三件事：**界面里的名字不再是「标签」**、**垂直居中改由行高样式统一负责**、
**组合键的两个窗口各自独立**。第三件带两次结构抬版，前两件把二十多处 `offset` 补丁清成了零。

## 一、键名一律纯文字

### 名字标签整体删除

`NameChip` / `NameChipRow` / `ChipLook` / `chipLook` / `CHIP_RADIUS` **全部删除**：键名、应用名、
变量名不再有底色、圆角、描边、内边距，就是一行里的一段文字。

- 名字**没有任何专属样式**：用的就是旁边那句的 `TextStyle`（同字号、同字重、同颜色）。
  早先给名字叠 `FontWeight.Medium` 的写法已删 —— 同字号下 Medium 的行盒比常规体矮一截，
  而 `CenterVertically` / `Placeholder.Center` 按**各自的测量高度**居中，结果就是名字上浮
  （真机量到：正文墨迹 261–307，名字 259–305，高 1.5~2px）；
- `ChipFlow` 改名 `NameFlow`（去 `look` 参数，直接收 `style` / `color`，名字与分隔符同一个样式）；
  `ChipText` / `ChipLegend` / `ChipSentence` 同样去 `look` —— 这几处原本是公共的，于是
  **组合键名、场景条件的应用名、变量清单、顶栏副标题、确认窗**一起变；
- 顶栏键名从 `NameChipRow` 改为单个 `Text`（`maxLines = 1` + 省略号，与原 `clipToBounds` 同义）；
- 提示条仍按 `%s` 各归各位（`HintItem.chips` 一路带下去不变），只是不再画框；组合停用那两句
  回执不需要按颗排，直接 `joinToString` 成一整句；
- 连带删死代码：`comboTitleWidths` / `ComboTitleWidths` / `COMBO_CHIP_SLACK` /
  `namesToChipsTemplate` / `chipsOfNames` / `chipStyle` ——「量框宽」这条链只为框与框竖着对齐，
  没有框之后这件事不存在；
- 塞不下仍由 `NameFlow` / `ChipSentence` 换行兜。

### 分隔符两边统一带空格

顶栏副标题（`keyNames`）原来 `joinToString("×")` 拼出 `快捷键×音量加`，而列表行标题
（`comboTitleText`）、一句话叫法（`comboLabel`）一直是 `" × "` —— 同一页两种排法。
现在统一成后者：`keyNames` 用 `" $COMBO_PAIR_SEPARATOR "`，`NameFlow` 的分隔符文本改成
`" $separator "` 并删掉原来那档 `SEPARATOR_GAP = 6.dp`（两者叠加会太松）。

## 二、垂直居中交给行高样式

### 根因：库的行高样式把多余空间全放行下方、且不裁剪

COUI 的 `defaultTextStyles()` 每一格都带 `LineHeightStyle(Alignment.Top, Trim.None)`。
库那样选是为了模仿 Android 的 `lineSpacingMultiplier`（多余行距落在行下方、从不裁），
代价是：行盒 = `lineHeight`（1.158em 起），而**汉字墨迹只占行盒上半部**
（descent 那段留给拉丁降部 g / p / y）。

于是任何「把文字盒竖着居中」的布局 —— `Alignment.Center`、`CenterVertically`、
`Placeholder` 居中 —— 居中的都是**行盒**而不是墨迹，汉字一律看着偏上。项目原先为此养了
二十多处 `Modifier.opticalCenter` 一类的 `offset` 补丁，逐处把墨迹再挪回去。

### 改法：一档 `Center` + `Trim.Both`

`ui/style/AppTextStyles.kt` 是全项目唯一的文字样式入口（十四格都从那里过），换上一档：

```kotlin
internal val APP_LINE_HEIGHT_STYLE = LineHeightStyle(
    alignment = LineHeightStyle.Alignment.Center,
    trim = LineHeightStyle.Trim.Both,
)
```

- `Trim.Both` 裁掉**首行**上方与**末行**下方的空白 —— 单行文字两头都裁、行盒贴住墨迹；
  多行文字只动首末行，**行间行距仍由 `lineHeight` 管，一格没变**；
- `Alignment.Center` 把 `lineHeight` 与字体自身行盒的差值上下均分，而不是全塞到下面。

两件事合起来，行盒中心≈墨迹中心，所有 `Center` 类布局直接得到视觉居中。`withLineBreak()`
随之改名 `withAppTypography()`（它现在管折行与行高分配两件事）。

### 删掉的东西

- `ui/model/page/TextMetrics.kt` **整个文件**：`opticalCenter` / `opticalBlockCenter` /
  `opticalTightTop` / 三个 `dy` 缓存 / `BLOCK_CENTER_BIAS` / `inkRect` / `glyphBounds`；
- `PageMetrics.opticalBlockBias`（那个「上下内边距互相让」的折法）及其对 `blockDy` 的依赖；
- `SwitchRow.contentBias` 参数与 `contentMargin()`；
- `CardRow.ItemText` 里按单行 / 双行分流的 `blockModifier`，连带两个只为量它存在的
  `titleStyle` / `summaryStyle`；
- `SectionTitle` 的 `SECTION_TITLE_TEXT_OPTICAL_Y = 1.dp`（小标题文字下移那 1dp）与外面那层
  `Box(Modifier.offset(...))`；
- **23 处** `.opticalCenter(...)` / `.opticalBlockCenter(...)` / `.opticalTightTop(...)` 调用，
  分布在 `PageHeaderWidget` / `MenuPopup` / `PagePicker` / `AppTile` / `BindingTile` /
  `CommandDetailOverlay` / `CommandFormats` / `SavedCommands` / `DonateListScreen` /
  `HomeActivationCard` / `PageSnackbar` / `CardRow`。

### 不再往回加

新界面只要用 `Center` / `CenterVertically` 就是对的，不需要任何 `offset`。真要动，
改的是 `LineHeightStyle` 那一层，不是在调用点补偏移。

**代价**：单行文字的行盒从 `lineHeight` 收紧到字体实际高度（约矮 1~2dp），列表行、卡片、
胶囊的高度会跟着略降；多行正文不受影响。

## 三、组合键

### 等待组合支持「按顺序触发」

- `ComboKey` 新增 `ordered`（`false` = 只看集合，与之前一致）；同一批成员键因此可以建多档：
  2 键「不分顺序 / AB / BA」、3 键「不分顺序 / ABC / ACB / BAC / BCA / CAB / CBA」；
- 判定侧 `ComboDetector` 新增按下序号表 `pressSeq`（按事件到达先后单调递增），`orderMatch`
  把有序档按真实按下顺序逐位比对（`ComboKey.matchesOrdered`），三个取候选的地方
  （`pairFor` / `multiFor` / `absorb` 升级）都过它；
- 选择器：选完键再弹一窗（不分顺序 + 各排列），已加过的顺序置灰；「不分顺序」覆盖所有按法
  —— 它一存在，其它顺序（含它自己）全禁用，`addCombo` 里也拦；
- 落盘（`ComboDto`）与广播（`ComboWire`）都带 `ordered`；
- 有序档的显示名用「→」分隔（`[侧键]→[电量+]`），与「×」（一起按下）分开。

**按住组合同样支持**（成员键 ≥ 2 时）：选完首键再弹一窗「成员顺序」，同一首键 + 同成员集合
可建多档（`[首键,A,B]` 与 `[首键,B,A]` 是两档）；比的是 followers 之间的先后。
去重新增 `holdUnorderedMemberTaken` / `holdOrderedMemberTaken` / `usedHoldMemberOrders`，
`writeNewCombo` 按首键 + 成员顺序细分判重。

### 固定窗口起点

`ComboKey.fixedWindowStart`（`null` = 跟随公共）+ `GlobalConfig.comboFixedWindowStart`
（默认关），走广播（判定在注入侧）：

- 开 = 从首个成员按下起一个固定窗口，整串只等一个窗口（`comboSpanFor` 不再按成员数放大）；
- 关（默认）= 每个成员按下清掉计时重新等（原行为）；
- **判据不分档**：`Config.comboFixedWindowStartFor` 对等待档与按住档同一份，
  `ComboDetector.multiFor` 的成员接收窗口也接这一位。

### 固定窗口长度是**另一笔账**

「按键之间的等待」量的是**相邻两颗**，逐次重置时整串会被放大成它的 (n-1) 倍；开了固定窗口
起点之后整串只等**一个**窗口，那个窗口该多长是另一件事（三颗的组合往往要得比 80ms 长，
两颗的用不着）。混用一份的话，调宽三颗那一档会把两颗的手感一起拖钝。

- 配置两位：`GlobalConfig.comboFixedWindowMs`（公共）+ `ComboKey.fixedWindowMs`
  （这一档自己那份，`0` = 跟随公共，受「使用独立设置」管）；
- 公共那一位走广播（`combo_fixed_window_ms`），档内那一位随 `ComboWire` 一起带 ——
  判定在注入侧，`Config.comboSpanFor` 的第一支改读 `comboFixedWindowFor`；
- 出厂值 **80ms**，与「按键之间的等待」同一个数：这一位出现之前固定窗口起点借的就是它，
  升级前后行为不变；
- 扫描窗口取最大值时也带上这一位（不带的话扫窄了永远配不上）；
- **按住档成员接收窗口也接这一位**：开了固定窗口起点后，`ComboDetector` 用这一档的
  `comboFixedWindowFor`（经新增的 `fixedWindowFor` 回调，与 `fixedWindowStartFor` 对称）
  判成员窗口，不再写死 150ms；逐次重置那一支仍用 `HOLD_FOLLOWER_WINDOW_MS` 常量 ——
  那是「紧接着落下」的判据，与「从首成员起一个窗口」不是同一件事；
- 独立设置页打开时把它与 `windowMs` / `holdMinMs` 一起播种（`withSeededComboFields`）；
- 界面：两张卡各多一根滑杆，样式照抄单击设置那一根（`PageIcons.DelayTap`、20~1000 区间、
  10ms 一档、行尾写数、常显 —— 藏起来会让人以为这一项不存在，开关一拨还会让整张卡高度跳一下）。
  **按住组合那张卡摆在最后两行**（「首键松手后仍执行长按」下面）：它调的是判定时机，
  前面三条才是这一档的主参数。

### 等待中途触发另一档事件时补发

`HeldPresses` 压窗口期间排一支**长按检测枪**：被压的键按住超过它自己的长按阈值，就提前补进
单键判定器（判长按），并 `flushOthers` 把其它还压着的键也补发（补它们的单击）。

场景：A 按下松手进入等待，B 按下并按住到长按阈值 —— B 走长按、A 的单击跟着补发，而不是都拖到
窗口结束（那样 A 晚一个窗口、B 长按也判不出来）。

### 列表行与一句话场合的念法

- **有序档**：主标题里成员之间用 `→`（等待档 `NameFlow` 与按住档 `ChipSentence` 各加一个
  分隔符参数，默认仍是 `×`）—— 先后直接画在名字之间；
- **不分顺序**：副标题写「不分顺序」（`comboOrderSummary`）—— 标题上读不出「顺序不限」，
  单独标一句；按住档只看**成员键**，只有一个成员时不写副标题；
- 一句话场合（顶栏 / 删除确认 / 回执）仍由 `comboLabel` 用「→」区分；
- 顺序选择器里被禁用的行**按原因说话**：「不分顺序」那句灰了 = 这组已有一档；其它顺序灰了
  且已有不分顺序 = 「已有「不分顺序」的档，不能再加其它顺序」；否则才是「这种按法已经添加过了」
  （新增词条 `combo.order_any_taken`）。

## 四、外观

### 使用预测返回手势

- 外观卡多一行开关（第 7 行，紧接「界面振动反馈」，图标 `hand-finger-left`）：
  开 = 返回时整页跟着手指走，关 = 松手才一次性返回；
- 配置一位 `GlobalConfig.predictiveBack`（只落盘、不进广播，与 `uiVibrate` 同一档；`ofFields`
  里那行读它靠「缺项兜默认」，已补注释说明不随广播走）；
- 读它的是宿主进程里的返回拦截：`registerBackCallback` 在 API 34+ 且开关开着时才注册
  `PredictiveBackCallback`（逐帧进度），否则注册普通的 `OnBackInvokedCallback` ——
  与 API 33 那条退化路径同一份实现，**不新增第二条返回路径**；
- 拨完**立刻重挂**，不必退出重进。这一步走 `SettingsPage.onPredictiveBackChanged` 那条注入的
  通道（`ui` 不许反向依赖 `ui.hook`，由 `BackInterception` 进页时反向接上）；
- 关掉时**首页也自己接**（`needsBackCallback` 第一档就判这一位）：首页那一退平时留空给系统，
  是为了让它做「窗口跟手关页」那个动画 —— 那也是预测返回的一部分，关掉这一档之后同样不要。
  挂着回调即取消它，末尾那一档由 `handleDiscreteBack` 自己 `finish()`；
- API 34 以下没有逐帧进度，拨到哪一档都是「松手才弹」，副标题因此不承诺版本。

## 五、拦截窗与提示

### 正文点名「挡路的是谁」

删按键 / 停用键 / 开「只参与非首键的按住组合」这几张拦截窗，正文不再只报个数或说「某一档」：
到底哪几档组合挡着、连带哪几项会跟着停，一档一行列在句子里。

- 新增 `ComboNameLines` / `KeyNameLines`（弹窗正文里那一串点名项，居中、一档一行），
  删键拦截、只参与组合拦截、启停连带那一问三处共用；
- 「只参与非首键的按住组合」拦截窗带上挡路的那几档组合；词条
  `combo.combo_only_blocked_body` / `_wait_body` / `_tail` / `_wait_tail` 改成复数口径；
- 「关掉松手时触发」那一问的组合清单改用同一套写法（按住档读成「按住 A 后再按 B」）。

### 修：顺序选择器里排列选项的文字看不见

排列行的 `label` 是空串、只给了 `chips`，而 `ChipText` 靠 `label` 里的 `%s` 占位符把名字
填进去 —— 没有占位符，名字无处可塞，整行空掉。改成给排列行一条带占位符的模板
（`%s → %s → …`，`orderTemplate`），「不分顺序」那行改成纯文字（不传 `chips`）。
