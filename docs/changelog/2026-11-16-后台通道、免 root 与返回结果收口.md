# 后台通道、免 root 与返回结果收口

## 改

### 改：真 Shizuku 那一路改成「本应用自己常驻」，绑不上就换进程而不是叫醒服务

- 宿主 bind 一个没在跑的模块进程会被 ColorOS 的启动管理拦掉（`prevent start … Type bs`），
  而那道闸对**任何**「起服务」的调用方都拒（宿主、shell、连 system_server 自己都试过，见
  `docs/device/lsposed.md` 四十二），所以「广播代起 / 排闹钟 / 重试三秒」那一整套去掉：
  `ShizukuShellClient.bind` 绑不上就照实报，不再自己想办法把服务拉起来；
- 换成「先让自己活着」：`ShizukuShellService` 转型成常驻前台服务（`IMPORTANCE_MIN` 的一条通知），
  由 `EntryActivity`（打开模块那一下）与 `BootReceiver`（`BOOT_COMPLETED` / `MY_PACKAGE_REPLACED`）
  各起一次 —— 之后宿主 bind 只是建连接，随用随通；
- 清单补上 `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_SPECIAL_USE` / `RECEIVE_BOOT_COMPLETED`，
  服务声明 `foregroundServiceType="specialUse"`；开机 / 换包广播只做「把这条通道立起来」一件事；
- 失败提示拆成两档：连不上模块进程与「模块进程自己回没有可用 Shizuku」分开报
  （新增 `command_failure.shell_channel_off`）。

### 改：请求授权时把一个新进程换上来，不再让人去点模块图标

- binder 只推给**那之后新起**的进程，活着的老进程永远等不到（见 `docs/device/lsposed.md` 四十二）；
  所以「以 Shizuku 执行」点开那一刻，若通道连得上却问不到实时状态、或通道根本没在跑，
  都不再原地等：先请旧进程退场，再由宿主拉起模块跳板换一个新进程，随后重新问一次状态；
- 「退场」是后台通道的一条新消息（`ShizukuShellService` 收掉自己并退进程）；binder 断开时也走
  同一条 —— 留一个永远拿不到 binder 的僵尸进程只会把「没有可用 Shizuku」这个假答案一直说下去；
- 换 binder 时拉起的那一次跳板只起进程与通道（带 `EXTRA_WAKE_ONLY`），连「转设置页」那条广播
  都不发；正常入口的起页动作补上 `CLEAR_TOP | SINGLE_TOP` —— 用户正开着的那一页不会被重开，
  页里自己管的子页（命令详情、抽屉 …）也不会退回第一页；
- 换完仍然拿不到才报失败，文案改成「Shizuku 暂时连不上，再点一次试试」，
  不再指挥用户去 LSPosed 管理器点模块图标。

### 改：执行身份那两个开关改成「点开才申请」，勾不再跟着授权状态翻面

- 「以 root 执行」与「以 Shizuku 执行」都只在**打开那一刻**去拿授权：拿到才停在「开」上，
  拒绝 / 关掉框就退回「关」；两行仍互斥（开一个把另一个关掉）；
- 进命令页时 **root 探一次 `su`**（与真执行同一条判据）：机器上已经没了 root 的命令，勾不再亮着；
  Shizuku **不读**（授权按 uid 记，读一次要跨进程问模块进程；它回「没有」时把用户存着的「开」
  显示成「关」等于替用户改配置）—— 勾显示的就是存下来的值，真没授权时按侧键会得到同一句失败提示；
- 两行只留标题与开关，删掉那四条状态副标题（`command.root_desc_*` / `command.shizuku_desc_*`
  连同生成物里的常量一并删掉）；
- 申请途中不锁住这一行（框可能被直接关掉，锁着等一个不会来的结果是「一直挂起」的观感）。

## 修

### 修：自检没跑完时点灰控件，会出现两行同样的字（一行转圈、一行 info）

- 「正在检查模块…」既是进页那次提示，也是自检没跑完时点灰控件的答案；
- 后者原先落到「禁用原因」那一位、也没带 loading，于是同一句话在屏幕上是两行、图标还不一样；
- 这类原因改回落检查那一位并保留转圈：落位由 `hintReason` 一处决定，三个投递点共用。

### 修：多条命令的步骤不再一律按 root 跑

- 之前多条命令的每一步都写死 `su`：被引用的单条命令即使选了「以 Shizuku 执行」或关掉了 root，
  在多条命令里仍按 root 跑；
- 现在每一步按**被引用那条命令自己的开关**跑（root / Shizuku / 都不用）；身份相同的连续 shell
  步骤仍合并成一条 `&&`，身份不同的就地断开、等上一步结束再起，顺序不变；
- 手改 / 老配置里的裸 `shell:` 步骤没有自己的开关，按多条命令自己存的那两位（默认 root）。

### 修：测试命令漏带执行身份与返回结果

- 以前「测试命令」只把正文与 root 带上：勾了「以 Shizuku 执行」也照旧走 `su`，返回结果选哪一档
  都按「不显示」跑；
- 现在草稿里的 Shizuku / 返回结果 / 流体云图标一起带上，测试跑的就是眼前这份。
