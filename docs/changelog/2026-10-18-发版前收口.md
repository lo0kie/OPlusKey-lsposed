### 管理器那颗「打开模块」的 FAB 现在能用了

- 清单里加**唯一一个** Activity：`EntryActivity` —— 无界面的跳板（透明主题、`noHistory`、不渲染任何东西）
- 用户装完第一反应就是点 LSPosed 管理器右下角那颗 FAB；之前「一条入口都不声明、让 FAB 消失」等于让它
  没反应，真机反馈就是「找不到入口」
- 跳板自己起不来宿主那一页：它带 `android:permission="oplus.permission.OPLUS_COMPONENT_SAFE"`
  （privapp 级，`aapt2 dump xmltree` 核过），普通 app 直接 `startActivity` 必被 `SecurityException` 拦
- 改成绕宿主一趟：跳板发 `ModuleWire.ACTION_OPEN_SETTINGS`（有序广播），宿主主进程用**自己包**的身份
  起页面；那条接收器是 `RECEIVER_EXPORTED`（发送方是另一个 uid），只做「调到前台」，不读配置不改状态
- 整条链路不碰 root；宿主没接上（模块没注入 / 换包没重启）时弹一句
  「没打开侧键设置：可以直接去 系统设置 › 快捷键，或换包后重启一次」
- CI 第 (4) 项从「零入口」改成逐项对账：`MODULE_SETTINGS` / `activity` / `activity-alias` /
  `LAUNCHER·INFO` / 跳板类名 必须恰好 `1/1/0/0/1`
- `AGENTS.md` 一、6 与 `docs/device-findings.md` 六之二 同步改写

### 配置的三个静默改写

- **布尔字段缺项走字段表默认值**：`JSONObject.optBoolean(key)` 在键缺失时返回 `false`，而
  `instantSingle` / `colorOsApi` 登记的默认值是 `true` —— 以前「有 `global` 段、但没写这一格」的文件
  读出来就翻面，而且**读 → 渲染 → 写回**一次就固化。现在先判 `has(key)`，缺项才用默认值。
  影响面：这类老文件里那两档会从 `false` 变回 `true`（回到它们登记的默认值）。
- **落盘不再退回「复制 + 删」**：`rename` 失败时原来会 `copyTo(overwrite = true)` —— 那是先清空目标
  再写，半途失败会在目标上留一份坏 JSON，而读方把它记成 `Unreadable` 之后就**永不再写**。
  现在失败只删 tmp、返回 false，调用方按「这次没写进去」处理。
- **目标里的用户前缀只认 ASCII 数字**：`Char.isDigit()` 把全角 `０-９` 也算数字，而 `toIntOrNull()`
  不认 —— 「９９９@包名」以前会被判成 0、却仍被 `withoutUser` 剥掉前缀，坏前缀静默变成
  「主用户 + 合法目标」。两处判据收成文件级的 `isAsciiDigits`。

### 配置写入的三态、命令库缓存、步骤串联

- `SettingsPage.write` 从 Boolean 改成**三态**（`CommandsSave.Ok` / `BroadcastFailed` / `Failed`）：
  以前「落盘成功、广播失败」也返回 false，改名那条路据此把命令库回滚到旧名 —— 主配置写着
  `cmd:新名`、库里只有旧名，那只手从此 NOT_FOUND。现在只有 `Failed` 才回滚；同一套判据也用到
  「导入配置」与「清空配置」，广播失败不再触发回滚主配置。
- `CommandLibrary.loadCached` **只缓存 `Load.Ok`**：读不懂时塌成的空表一旦按指纹记下来，
  指纹不变就一直命中 —— 一次 IO 抖动被记成「命令库为空」，要等到下次写盘才恢复。
- 零间隔的 shell 步骤从 `;` 改成 `&&` 串联：`sh -c "a; b"` 的退出码只取最后一条，前一步失败
  既不报错也不拦后一步，用户看到的是「没跑成却当成功」。失败当场停下、退出码非 0。

### 分身目标的语义：解析、载荷、用户

三条同源 —— 「分身就是**另一个 Android 用户**下的同一个包」，以前有几处把它当主用户处理。

- **显式组件退路会丢载荷**：`action` 起法失败后改试显式组件时，新建的 `Intent` 只设了
  `component` + `action`，场景表里的 extras（`triggerType` / `longPressEventType` …）全没带 ——
  服务照样被起、但已经不是用户要的那一下，日志却写着「退路成功」。现在两条路共用同一份载荷
  （抽成顶层 `Intent.putExtrasOf`，顺带把那次函数的圈复杂度降下来）。
- **分身目标在主用户 PM 里查不到**：`AppEntry.resolve` 只走当前用户（宿主自己恒 0），
  分身里的包在主用户 `PackageManager` 上**根本不存在**，于是「列表点得动、按下报找不到应用」。
  新增 `AppEntry.resolveAsUser(pkg, userId)`，走 `IPackageManager` 的
  `queryLaunchablesAsUser`（与最后一层判据同一套）；`AppLauncher` 在 `userId != 0` 时先按用户解析，
  也就不会再把分身目标误报成「可能已卸载」。
- **小窗起在了宿主用户上**：`startZoomWindow` / `startZoomWindowCode` 取 `userId` 时用的是
  `MiniWindowSupport.currentUserId()` —— 那是**宿主自己的用户**（恒 0）。`window:999@包` 这条
  就起在主用户上（表现是「前台换成了主用户那份同名应用」）。现在按命令参数带：`window:999@包` 传
  `AppTarget.userId(target)`，只有「收起前台那份任务」才用 `currentUserId()`（那本来就是当前用户的任务）。
  同一条判据也补进 `MiniWindowSupport.isSupported` / `querySmallWindowSupport`。

### 分身槽号与选择页的三个「以为知道了」

- **槽号查不到不再塌成 0**：`slotOf` 原先是 `indexOf(userId) + 1`，查不到得 **0**，而 0 是**主用户**的编号
  ⇒ 一个刚删掉的分身（或那个 user 根本不是分身类型）在界面上被画成「微信」，与真主用户那一行同名。
  现在返回 `UNKNOWN_SLOT`（负数），显示成 `微信 · 998`（挂 user id，一眼对得上日志与 `am get-current-user`）。
  查不到时会**重列一次**用户表（新装的分身还没进进程缓存），重列仍没有才记进「查无此人」的备忘录，
  同一份缓存期间不再重复走 `getUsers` 的反射 + binder。
- **`applicationInfo` 为 null 被当成系统应用**：`info.applicationInfo?.flags?.and(FLAG_SYSTEM) != 0`
  在它为 null 时算出来是 `null != 0` ⇒ `true`。读不到就当不知道（不是系统应用），否则「只显示用户应用」
  这一类筛选会把那条漏掉。
- **幽灵槽**：`entries` 里某一槽的可启动列表拿不到时，作废那份用户表缓存 —— 那一槽多半是删掉的分身，
  留着它会每次刷新都白查一遍，槽号也还按它算。
- **「不支持小窗」那张脸写回了错的绑定**：确认键里交的是 `app.packageName`，把 `999@`（分身）与
  二级页刚挑好的 `/类名` 一起抹掉，写回去成了「主用户、自动入口」。现在交完整目标（优先 `pending`）。
- **搜索词会降级绑定**：`resolveSelection` / 默认选中项以前按**过滤后**的清单判「那一项还在不在」。
  用户随手打一个字把当前绑定的那一行筛掉 ⇒ 页面判成「已经不在清单里」⇒ 选中态退回「自动」⇒
  一按 FAB 就把 `包名/类名` 写成了 `包名`。现在判据一律用**完整清单**（过滤只决定显示什么），
  清单还没到手时也**不判**「不在」（那是「不知道」）。快捷方式默认选中时连它自己的名字一起带上
  （不点行直接按 FAB，名字不会退回应用名）。
- 判据抽到新文件 `ui/screen/apppicker/ActivityPickerRules.kt`（纯函数，与 Compose 那棵树分开）：
  `ActivityPickerList.kt` 的函数条数贴着 detekt `TooManyFunctions` 那一档。

### 小窗验收：读不到 ≠ 没成

- `isTaskInZoomWindow` 增加三态版 `zoomStateOf`（`true` / `false` / `null` = 读不到）。四处验收改用三态：
  `window:包名` 的原地收、收起档、动画档、`appshortcut:w:…`。以前「读不到窗口信息」被折成「没成小窗」，
  于是**已经开好的小窗会被退路顶掉**（`appshortcut:w:` 再起一次全屏、`window:` 回桌面重起），
  真机症状是「小窗闪一下变成全屏」。收起档那一处还会拿读不到的事实弹「此应用不支持小窗」。
- `switchState` 的前置三字段没写全时**不再调它**：它前置不成立时第一句就早退、**不抛异常**，
  照「已调用」记账就是拿「没抛」当成功。现在直接回滚假字段并报出缺了哪几个；调进去之后那句日志
  也改成「已调进去（真变小窗没有由宿主侧验收判，这里不判）」。
- `anyTaskForId` 的 matchMode 从 `0/1/2` 收到 `0/1`：`2` 是 `…AND_RESTORE`，任务只剩 recents 记录时
  会把它**真恢复出来**——生产路径以为只是「查一个任务」，实际会顺手复活一个已经关掉的应用再收成小窗。
  探针与生产同一份档位（否则探针报的就是与事实相反的结论），找不到时日志里明说「没试 mode=2」。
- 文档同步：`docs/zoom-window.md` §九.2 与 §十 的「找任务」那一行。

### 命令页与选择页的六处「判据/状态放错地方」

- **保存按钮会为一串裸前缀亮起来**：单条那一档原先只判 `isNotBlank()`，`cmd:` / `app:` / `shell:`
  这种只有前缀的写法照样能存，而它执行时必然落空（`cmd:` 永远 NOT_FOUND）。新增
  `Action.isBarePrefix`，工具条的「有没有载荷」判据统一到 `commandPayloadReady()` 一处
  （原来 `commandToolbarVisible()` 与 `CommandActions` 各算一遍）。
- **两张步骤选择器能同时开着**：「替换第 n 步」与「添加命令」原本是两个互不知情的状态
  （`stepPick: Int` + `picking: Boolean`），点开某一步的选择器再去点「添加命令」会叠出两张。
  合成一份 `stepPicker: Int?`（`-1` = 添加那一行），并且步骤列表一变就把替换型收掉 —— 行下标
  在插入 / 删除 / 上移下移之后不一定还指着原来那一行。
- **删除步骤会抛越界**：`steps.removeAt(stepsIndex)` 的下标来自**这一次组合**，连点两下时第二下
  用的是旧下标（数据已经短了一格）—— 抛在点击回调里就是宿主页面崩掉。越界当场忽略并记一行。
- **「重置」收尾等错了动画**：等的是 `TAB_PAGE_SWITCH_MS + 60`（320ms，那是换 tab 的时长），
  而它真正要等的是步骤行退场（220ms）—— 多等的 100ms 里步骤行早已收完、表单还杵着不动。
  退场时长收成 `STEP_ROW_EXIT_MS` 常量，收尾改成 `STEP_ROW_EXIT_MS + 40`。
- **已保存命令卡的高度按「正在编辑的草稿」算**：`minHeightRatio` 取的是
  `commandDraft.draft.kind`，于是翻到「单条」那栏时整片网格的多条命令卡都被压成半个正方形
  （反过来也一样）。改成按**这一行里那些命令自己的类型**算，一行里两种类型混着时取高的那一档。
- **多开拼音搜索会被系统语言带偏**：`filter.lowercase()` 用的是默认 locale，土耳其语环境下
  `I` 会变成 `ı`，而排序键是固定 ASCII 小写 —— 那台机器上按读音搜不到东西。钉 `Locale.ROOT`，
  与「选择界面」页那一处同一份口径。

### 按键绑定页的焦点与判据

- **方向键跨组会跳错格**：焦点挪动原来是扁平下标加减 `COLUMNS`，而格子是**按组分行**的
  （每组各自 `chunked(COLUMNS)`、末行不满补空位），跨过组边界时那个式子落到别的组里 ——
  真机表现是「按一次下，焦点跳两行 / 跳到左边去」。现在按界面上真实的分行表挪
  （`BindingGridState.rows`，与网格同一份 `groupsFor` + 同一个 `COLUMNS`）：上下换行保持列、
  左右行内移动、落点超出行宽时收到该行最后一格。
- **确认键与格子是两把尺子**：格子是 `enabled && linkReady`（链路没就绪就灰着、点了不动），
  而确认键这条自己派发的路径只判了 `enabled` —— 于是灰着的格子按确认键反而进了「选择应用」页 /
  弹出了入口菜单，进去之后每一步都被 `pick` 拦下。现在两条路共用 `bindingConfirm` 一处判据。
- **顶栏不跟本次草稿**：「选择应用」页那行小标题读的是**当前绑定**，而这一行说的是「这一趟将要绑成
  什么」—— 在二级页挑完某个具体界面 / 快捷方式退回来，页里已经亮了新的、顶栏还写着上一个应用名。
  现在先看 `picker.draft`，没有才退回当前绑定（草稿由 `beginVisit` 每次进页清掉，不会残留）。

### 前台转小窗的动画改用框架动画器

- 「前台转小窗时使用动画」不再是「回桌面再真启动一次」：改成**原地收成小窗、紧接着播框架自己的那一段缩小动画**。
  以前那条要先把界面挪出栈顶，而桌面是竖屏 ⇒ 横屏应用被拽成竖屏比例的落点，目标占着前台时还常常压根收不起来。
- 动画**只在竖屏**播：终点几何用的是竖屏标定的落点与缩放，横屏照旧只做原地收（要横屏也播得换终点来源，属注入侧）。
- 首页那行的副标题由「此功能可能存在问题」改成实际行为「全屏应用缩成小窗时播放动画（仅竖屏）」。
- 删掉「先动画后转换」那一档与它专用的等待余量：任务还不是柔性任务时框架每帧都把动画挡回去，那条路结构上不成立。
- 文档同步：`docs/zoom-window.md` §2.2 的展开档流程、§十 的收口状态、§十二 的现行落点说明、§13.1。

### 日志：该露的露、该藏起来的藏

- **三处 W 级日志把命令正文原样打了出去**：`inject/ConfigChannel`（配置广播落地）、
  `host/SideKeyGestureHooks`（宿主进程读到配置）、`ui/SettingsPageDebug`（调试状态那一整行，
  连草稿正文与步骤表一起打）。`shell:` / `intent:` 后面是整条命令 / action 串，可能内嵌 token 与密码，
  而 W 级既进 logcat 也进「导出日志」那份文件。现在统一过 `XLog.redactToken`（只留长度 + 指纹），
  调试行里的草稿正文走 `XLog.redactCommand`。判据不受影响：按下的是哪个键、开哪个 App、引哪条命令
  都是 `app:` / `cmd:` 这些前缀族，本来就不脱敏。
- **八行判据级日志从 `d` 提到 `w`**：注入侧 i/d 在 LSPosed 日志页整档看不到、release 里还被消除，
  而这几行正是「按下去为什么没反应」的答案 —— `GestureDetector` 里四处「这一下没判成单击 / 长按 /
  双击」的取舍（已直判过、长按枪作废、双击窗作废、跳过补判），`GestureReceiver` 里四处
  「宿主收到没收到 / 补发那条被去重 / 主开关关着所以忽略（手势与松手各一条）」。同一段代码里
  判与不判两条路现在级别一致，不会出现「一半有一半没有」的日志。

### 反射：重载命中多个时不再靠 JVM 顺序

- `Reflect.methodByNameAndArity` 与 `callStatic` 都是「名字 + 参数个数」匹配，命中多个重载时
  取 `firstOrNull` —— 而 `declaredMethods` 的顺序在 JVM / ART 上未定义，取到的那个还会进缓存活到
  进程结束：同一台机器稳定、换台机器可能换成另一个签名（表现成「同一个功能时好时坏」）。
  现在按参数类型名排序后取第一个（同一台机器上稳定、跨版本可比），并把全部候选打进 W 日志
  —— 真挑错时日志里有据可查。

### ROM 落点与「清单闸」的旧口径

- **宿主设置页的类名又写了一遍**：`host/GestureReceiver` 自己留了一份
  `SETTINGS_ACTIVITY = com.oplus.gesture.actionbuttonkey.ActionButtonSettingsActivity`，
  而 `bridge/Framework` 的候选表里已经有同一个值（`HOST_SETTINGS_ACTIVITY`）。两处各写一份，
  换 ROM 时漏改任何一处，表现是「管理器那颗按钮点了没反应」。现在只认候选表那一份。
- **四处注释把「适配清单闸」复活了**：`BindingSettings` / `InstantSingleCard` 写着「吃同一套适配清单闸
  （`enabled && linkReady && deviceSupported`）」、`HomeHeaderMenu` 把 `deviceSupported` 列成第三个条件、
  `Framework.describeTables` 把 `DeviceSupport.ADAPTED` 注成「能不能注入」、首页自检那段写「清单外的机器
  本来就该一直禁用」。代码里**早就没有**这道闸（清单只回答「这一组验过没有」，AGENTS 一、13），
  注释照着旧状态写，下一个人很容易把它加回来。四处都改成今天的口径，并写明「别加回来」。
- **主开关关着时提示「确认作用域含 system」**：长按那张卡的置灰理由是
  `Strings.STATUS_DISABLED`，而这一档的正文是「模块未生效：确认作用域含 system，换包后需重启」——
  用户只是把开关拨回去了，却被告知去 LSPosed 里翻作用域。改用 `STATUS_KEY_DISABLED`（「按键绑定已关闭」）。

### 三处「同一件事两把尺子」

- **KSU 别名认领用了 `contains`**：`ui/model/ActionIcons` 按 `token.contains(SCREENSHOT_CMD_PREFIX)` /
  `contains(SIDEBAR_SERVICE)` 挑图标，而 `KsuCompat` 里写着「认领时用 `startsWith`，**不要用
  `contains`**」，还提供了一对 `isScreenshotAlias` / `isSidebarAlias`（前缀 + 这一条里没串别的命令）。
  包含式匹配下，`shell:echo oplus.intent.action.DIRECT_SIDEBAR_SERVICE` 这种只是**提到**它的命令
  也会被画成「识屏」—— 而执行侧根本不认它。改用那对判据，图标与行为回到同一把尺子。
- **命令库落盘不查重名**：同名两条命令时 `cmd:<名字>` 只命中第一条（执行侧 `CustomCommandRunner`
  与图标表 `CommandText` 都是 `firstOrNull`），第二条**永远执行不到**却还列在界面上。界面自己不许
  建重名，但导入配置 / 手改文件都绕得过去。在 `saveCommands` 这个唯一出口上按名字去重
  （同名留**最后**一条，与「导入覆盖」「已覆盖」同一档语义），丢了哪些写进日志。
- **执行时提示与步骤标题两套口径**：`host/action/ActionNotice` 少了 `ActionCatalog.modeName` 那一档
  （入口格 `nav:` / `key:` / `panel:` / `zoom:` 的名字都在那儿），于是界面上写「主屏幕」、提示里蹦出
  `nav:home`；快捷方式那一路也少了老配置 token 里 `|名字` 那一档。两处都补上，与
  `ui/model/CommandText.stepTitle`、`ui/appNameOf` 的优先级逐档对齐。

### 工作流本身的两处静默失效

- **`.github/workflows/build.yml` 解析即失败**：`printf '%s\n'` 里的换行被写成了真实换行，那几行
  顶到第 0 列、YAML 的块标量当场断掉（`could not find expected ':'`）。这种状态下 GitHub 根本
  不会跑这个 workflow —— 推什么都不会有构建，而页面上只留一句「Invalid workflow file」。5 处全部
  折回单行。
- **注入侧「不许 import 界面层」那道闸长期空转**：正则少了收尾的 `\)`，grep 报 `Unmatched ( or \(`
  并以 2 退出，而那一行末尾挂着 `|| true`，于是「出错」被当成「0 命中」，照样打 `ok`。
  现在正则写进独立变量、括号配对，并且把 grep 的 0 / 1 / 2 分开判：2 直接红（这条闸不能空转）。
  反向验过：往临时目录塞 `import androidx.*` 与 `import com.lookie.opluskey.ui.*` 都能抓到。

### 工作流拆成两条：构建归 push，发布归 tag

- `build.yml` 拆成 `ci.yml`（推 master / PR：gate + 依赖锁定 + 耦合审计 + 编译 + 验收 + 上传产物）
  与 `release.yml`（打 tag：取产物 + 验收 + 发版）。原先 push 的 run 图里恒挂着一个 skipped 的
  release job，模块仓库那套步骤也混在同一个文件里。
- 同一份提交不构建两遍：tag 那条按提交 SHA 去 `ci.yml` 在 master 上那条 run 取产物
  （`gh run download`），只做「验 + 发」。
- 取不到就红，**不退回自己构建**：没推过 master、那条 run 失败、产物过保留期（release 包留 90 天）；
  那条 run 还在跑就先等，最多 10 分钟。查询带 `branch=master` —— 推 tag 本身也是 push 事件，
  不带它会捞到别的 ref 的 run。
- 那 240 行验收脚本从 YAML 搬进 `tools/verify-apk.sh`：两条 workflow 调同一份，本地也能
  `bash tools/verify-apk.sh dist` 直接跑 —— 判据只有一处实现。
- 版本号那五行 `sed` 也从两份 YAML 搬进 `tools/read-version.sh`（同样两边共用），它自己写
  `$GITHUB_OUTPUT`，抓不到就 fail。
- 发版前先判「必须有本版的 `*-release.apk`」：缺了直接报「多半是 `signed=false`（Secrets 缺
  `KEYSTORE_*`）」，不再等建 Release 时抛一句含糊的 `no files found`；顺带挡住「产物名里的
  版本号与本条 tag 对不上」。
- 发版的并发组用 `cancel-in-progress: false`：发布半路被掐会留下「tag 推了、Release 没建」。

### 验收脚本在 `bash -e` 下会自己退出，而且死得无声

- `校验验收底线` 那一步的 shell 是 `bash -e`（日志里 `shell: /usr/bin/bash -e {0}`）。注入侧扫描
  改成「分开判 grep 的 0 / 1 / 2」之后，`hits=$(grep …)` 在**无命中**时返回 1 ⇒ 整个脚本在那里
  直接退出，后面的字典、封存两段不跑，日志上只剩一句 `exit code 1`、连一条 `::error::` 都没有。
  改成 `hits=$(grep …) || scan_status=$?`：`||` 列表不受 `-e` 约束，赋值照常生效、状态留得下来。
- 字典那三条 `[ -n "$x" ] && printf …` 是同一个坑：条件不成立时整条 `&&` 列表返回 1，
  于是**该报的那一条反而看不到**。改成 `if [ -n "$x" ]; then printf …; fi`。
- 本地复核时补上 `bash -e` 这一档 —— 之前用不带 `-e` 的 `bash` 跑同一份脚本，全绿，于是漏了这个坑。
