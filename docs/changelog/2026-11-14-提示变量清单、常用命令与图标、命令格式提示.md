# 2026-11-14 · 提示变量清单、常用命令与图标、命令格式提示

### 改：执行时提示的模板从三个占位符扩到六个

- 新增 `$parent` 父动作（`系统开关`）、`$name` 子动作（`WIFI`）、`$state` 状态（`打开`）—— 后三个是 `$action`（整句 `系统开关: WIFI - 打开`）的**拆法**，不是另一套说法。
- 三段与整句由 `CommandTitle.reading` **一次**算出来（返回 `ActionReading`），所以「整句」与「拆开」永远自洽；分两处取的话，将来一边改了拼法就会出现「整句是 A、拆开是 B」。宿主侧那一条跟着改名：`actionNoticeText` → `actionNoticeReading`。
- 回落只在 `ToastNotice.valueOf` 一处：`$parent` 没有就是**空串**（那一格是前缀，拿名字去顶会念成 `截屏: 截屏`）；`$name` / `$state` 回落到**这一档自己的名字**（`媒体控制: 上一首` 写 `$state` 念出 `上一首`，不带父名）。`截屏` 这种单一功能动作，三个都能念。
- 默认模板一个字没动：没改过这一项的人，升级前后弹出的仍是 `侧键 - 单击 → 手电筒`。

### 改：提示文案弹窗里那行说明变成变量清单

- 输入框下面那行不再是「`$key` 键名 / `$gesture` 手势 / …」一句话，而是六个**变量名标签**（与组合键的键名同一份框样式，`ui/row/ChipLabel.ChipLegend`），每个框后面跟着它换成什么；装不下换行，框与它那句说明绑成一组、不拆开。
- 顺序由 `ToastNotice.PLACEHOLDERS` 定；模板里 `%s` 的个数对不上时整句退回纯文字（与 `ChipText` 同一条兜底）。
- 公共页与每颗键「独立设置」里那两支编辑窗是同一份清单（`NameDialog.hintChips`）。

### 改：点一下变量名，把它接进输入框

- 那排变量标签**可点**：点一枚就把这个占位符原样接到输入框末尾（不替用户补空格，也不抢回焦点 —— 想接着打字就点一下输入框）。
- 长度已经满了时整枚都不放进去 —— 截一半会留下 `$sta` 这种半截占位符。

### 改：「用流体云提示」那两行副标题改短

- 开着写「显示在状态栏的流体云里」，关着写「以 Toast 弹出」—— 与行标题「用流体云提示」分开，也不再比标题长。

### 改：常用命令的「固定」回到每条自己决定

- 撤掉首页那张卡上的总闸（`showCommonCommands` 那一行），改回**每条一个开关**：「常用命令」页的行菜单里那一项按当前状态写「显示在按键绑定页」，点一下就地切换（这个开关即时生效，不再套一层「确定」）。
- 没固定的那几条，清单里标题压一档色 —— 一眼能看出哪些不会出现在按键绑定页。
- 绑定页那一段重新按 `CommonCommand.showInBinding` 过滤；**一条都没勾时这一段仍在**，只剩一行「去添加」（整段不画的话，这一页上就看不出还有「常用命令」这回事）。
- 首页「管理常用命令」那一行的副标题跟着补齐到「添加、改名、换图标与固定」（这一页现在管这四件事）。

### 改：常用命令能换图标

- `CommonCommand` 多一位 `icon`（`FluidIcons` 的 id，空串 = 用它本来那颗）。
- 行菜单里「图标」那一项打开的是**命令页同一个网格选择器**（`FluidIconPicker`），只是写回去的落点不同 —— 那边改命令正文里的 `<id>|`，这边改清单里这一条。选中之后**照当前配置重算整张清单**再写：改名 / 移除可能刚在同一轮里落过盘，拿调用点那份旧列表拼会把别的改动覆盖回去。
- **只在界面里画 `ImageVector`，不渲染 png**：常用命令只出现在模块自己的界面里（绑定页那一段、这一页的清单），不像 `fluid:` 与「执行时提示」要被宿主进程画到胶囊上 —— 那两处没有 Compose 运行时，才必须先把字形落成文件。前面那版曾给它加过一族 `okey-common-*.png` 与预渲染，已经整批撤掉。
- 绑定页那一格与清单那一行都读 `commonCommandIcon(cmd)`（换过就用换的，认不出 id 也退回按动作取）—— 两处各判一次会漂。

### 改：移除常用命令不再清空源绑定

- 常用命令只是快捷方式，它不该替用户决定「这颗键以后什么都不做」。移除只把这一条从列表里摘掉，源命令的绑定保持原样（`Config.withoutAction` 这一步撤掉）。
- 反向那一半保留：删掉一条自定义命令时，同一笔写入里把 `commonCommands` 中指向它的条目一起摘掉（`CommandLibrary.clearCommandBindings` 的 `stale`），不留指向不存在命令的死条目。
- 确认窗的第二句「已经绑定的按键保持原样。」随之删掉 —— 那句话在描述行为，而行为本来就是这样。

### 改：命令页「图标」那一档滑入滑出

- 从硬切改成项目统一的 `AnimatedColumn`（淡入 + 从顶边缘展开），选择器留在动画外面不被裁。
- 入口那一行与选择器抽成 `FluidIconRow`，命令页与「常用命令」页共用一份形状 —— 两处各写一套的话，同一次点选会长出两种说法。

### 改：「命令详情」输入框底下加一句格式提示

- 正文以哪种前缀开头，就在输入框正下方摆出**那一种的骨架**，七种各一句：`shell:<命令>`、`keyevent:<keycode>（数字）`、`intent:<Action>（广播 action 名）`、`notify:<正文>`、`fluid:<正文>（带图标写 fluid:<图标 id>|正文）`、`toast:<正文>`、`shortcut:<ID>（快捷指令 id）`。
- 加括号的四条都是有隐含约定的：`keyevent` 在格式卡上只能写 `<按键>`，而这里填的其实是 keycode 数字（写「电源键」这种名字，`Action.parseKeyEvent` 认不出）；`fluid` 多了带图标那一段；`intent` / `shortcut` 的占位符不解释就不知道填什么。
- 数据不另起一份：`CommandFormatLine` 多一格 `tip`，与「支持的命令格式」卡同一张表 —— 前缀改了只改一处。行首图标与这句提示共用同一个匹配（`formatTipOf` / `formatIconOf` 都走 `formatLineOf`），不会出现「图标是模拟按键、底下却说 shell」。
- 认不出前缀时整句不画（空输入、老配置、以及 `app:` 那类内建动作的 token），也就不占位；与输入框下面那条「必须以支持的格式开头」的红字天然互斥。
- 画在 `SingleCommandField` **里面**而不是页面那一层：`raw` 本来就在那儿读着，页面那边再读一次会把整页拖进每一次击键的重组里（与 `CommandNameField` 同一条理由）。

### 改：那句提示跟着前缀滑出

- 走项目统一显隐（`AnimatedColumn` → 淡入 + 从顶边缘纵向展开，退场先快淡出再收缩），换前缀时下面的「可用变量」不会硬跳一格。
- 退场那两百毫秒里提示已经算作「没有」了，但那一块照**最后一句**画（`LastTip`，普通对象不是 state）—— 否则这一帧是一个空盒子在收缩：字先没了、底下的内容才慢慢合上。

### 改：注脚收成一份（`CommandFootnote`）

### 改：图标选择器铺满「模块用过的全部字形」

- 原先那份清单是从 `PageIcons` / `ActionIcons` 的引用里手抄的，漏掉了动作字形那半 —— 音量 / 亮度 / 媒体 / 录屏这些全在 `DrawnIcons`，只看页面那张表根本找不到。现在按全仓 `TablerIcons.*` 的引用逐个核过：207 颗一颗不落。
- 再加 `DrawnIcons` 那 21 支手绘（音量 ±、铃声音量 ±、亮度 ±、媒体播放暂停、录屏、小窗展开收起、电源菜单、手电筒、酷安、侧键那颗）。它们与 Tabler 同一支笔：24 视口、24dp 默认尺寸、描边色占位为黑，所以导出那条路（`exportPainter` 刷白）照样走得通。

### 改：五颗字形换掉、六个死别名清掉

- 「长按延迟」`hand-grab` → `clock-bolt`（钟 + 闪电：按到这一刻就是长按那一下）。
- 「命令间隔时长」`clock-hour-4` → `clock-play`（钟 + 播放：等这么久再走下一步）。
- 「按键之间的等待」新增 `clock-pause`（`ComboWait`）。
- 「系统场景在首键按下时固定」新增 `lock-cog`（`ScenePin`）：锁读作「定在这一刻」，与 `Scene`（调整滑杆，说的是「哪一块场景」）分开 —— 这一行问的是**什么时候取**。
- 「首键按住时长」新增 `clock-record`（`ComboHold`）：与「长按延迟」那颗闪电分开 —— 一颗管**持续**（按满这么久才开始算组合），一颗管**那一下**（到这一刻就算长按）。原先两行共用 `DelayHold`，同一颗字形说了两件事。

- 连着删掉五条失效 import，`MiniWindow` / `LongRelease` 的注释里指向这些名字的地方一并改掉。

### 改：触发方式选择窗三处

- **置灰那一行点了要有话说**：`PickerRow` 的可点性原来直接挂在 `clickable(enabled = …)` 上，置灰行收不到点击，那句「为什么点不动」没地方出。现在置灰行仍可点，转给新的 `onDisabledClick`，回执是「这种触发方式已经添加过了」（说清是**这一种**，而不是笼统的「整组都加过了」）。
- **出场动画**：这一窗原来写成 `if (order != null) { … }`，点选那一刻数据清空、整支当帧从组合里消失，库的退场根本没机会跑。改成让在场状态**比数据慢一格**（`modeShown` 等窗自己播完再落），内容照**最后画过的那一份**画（`LastHoldOrder`），否则退场那两百毫秒里行上的键名会先变空。
- **补齐三种时说清「齐了」**：同一组键补到第三种触发方式（等待 + 两种按住顺序）时，回执换成「3 种触发方式都已添加 …」—— 补到第三种的人要的是这个结论，再报一次「已添加」读起来像什么都没发生。

### 改：选择按键窗的禁用提示分两种情况

- 按住那两种顺序都加过 ⇒ 「所有触发方式都已添加」；等待那一种已存在时仍是「这组按键已经添加过了」（那种情况下另一类往往还能加，说「所有」不准确）。
- 判据收成 `comboRoomLeft` / `comboAllModesTaken` 一对，界面那一句与 `addCombo` 的去重共用同一份 —— 原来界面上数条数、判定里过滤，两处各算一遍。数条数还认不出「同一档重复两次」这种废配置，改成按 `usedComboModes` 判「哪几档已经有人」。

### 改：颗数上限那句话按类分两条

- 原先一条「一个组合最多 N 颗按键」管两类，而它对按住是**错的**：那一条报的是 `MAX_KEYS`（3），按住入口勾满两颗之后第三颗就勾不上了 —— 用户会去找一颗根本不存在的第三颗。
- 拆成「等待组合最多 3 颗按键」与「按住组合只能是 2 颗按键」，两处调用共用 `comboMaxKeysHint(hold)`（选键窗勾满上限、`writeNewCombo` 的越界兜底）—— 各写一遍迟早有一处报错类。
- 按住那条用「只能是」而不是「最多」：它必须正好两颗，不是「不超过」。

### 改：按住组合「先问、再写」

- 原来 `addCombo` 先落盘、再问「起点键不是松手时触发，要不要切」—— 那一问于是只是做样子：点取消时那一档已经在列表里了，而起点键没改，它是一条永远不成立的废档。
- 现在**确认之后才写**：`ComboModeAsk` 多记一份「待添加的成员」，确认时由 `writeNewCombo` 把「新增这一档 + 把起点键改成松手时触发」一笔落盘；取消就等于什么都没发生。
- `writeNewCombo` 把所有闸再过一遍（等确认这段时间里用户可能又加了一档），不拿提问那一刻的结论当数。

### 改：起点键「只参与组合」时拦一道

- 那一档位的意思是「这颗键不判单键手势」，它自己的「松手时触发」开关在按键设置页是灰的。放它继续走「切换为松手时触发」，用户点完不会有任何效果，只会落下一份 `combo_only=true` 又 `long_fire_on_release=true` 的自相矛盾配置。
- 所以直接说明、不添加：新的 `ComboStarterBlocked` + 说明窗，正文「[键名] 已设为只参与组合，无法用它作为按住手势的起点。」（键名仍是名字框），动作项「知道了」。

### 改：「只参与组合」反过来也要拦一道

- 上面那条只管「先开了只参与组合、再想拿它当起点」。反过来同样会撞：先拿一颗键当了某档按住组合的**起点**，再去按键设置页打开它的「只参与组合」—— 那一档要求起点键「按住到点」再松手，而只参与组合的键根本不判单键手势，落下去就是一份自相矛盾的配置。
- 现在打开这一项时先查 `Config.holdCombosStartedBy`（判据与 `ComboKey.starterKey` 同源，与上面那道问的是同一句话），命中就弹窗说明、**不写盘**：开关会自己回弹到原位，不会出现「看起来开了、实际没开」。
- 拦法用弹窗而不是悄悄拦住：正文两段，一段说「`[键名]` 是某一档按住组合的起点，不能设为只参与组合」（键名是名字框），一段给出路「先把那一档组合改成等待组合，或者删掉它」—— 上面那道是死路（起点键的「松手时触发」本来就是灰的），这一道能自己解开，只写「不行」会让人以为这一项坏了。
- 判据返回的是**整张表**不是「第一档」：同一颗键可以同时是两档的起点（`A+B` 先按 A、`A+C` 也先按 A），只报一档的话用户删掉那一档、回头再点还是一样被拦，而界面再也说不出「还剩哪一档挡着」。日志里把挡着的几档都列出来。
- 停用的那几档也算 —— 停用只是暂时不生效，重新启用时同一个矛盾还在。

### 改：按住组合的顶栏副标题写成一整句

- 组合编辑页的顶栏原本摆两枚框 `A × B`；按住那两档改成和列表一样的一句话「按住 A 后再按 B」（键名仍是框）—— 那两档的判据就是「谁先按住」，只摆两枚框读不出顺序。
- 第二颗先按住那一档，句子里两个名字对调。
- `ChipSentence` 从 `ComboListCard` 的私有实现提到 `ui/row/ChipLabel.kt`，列表与顶栏共用一份。

### 改：「关掉松手时触发」那一问

- **出场动画**：`if (target == null) return` 让整支从组合里消失、退场来不及播。改成照最后画过的那一份画（`LastFireOff`），壳自己按 `show` 播进出场。
- **正文键名用框**：正文原来是一整段带 `[侧键]` 的字符串 —— 那是这个界面里另一套记号（键名一直是圆角框）。为此 `ConfirmDialog` 多一格可组合正文槽 `body`（`DialogBody` 同时补了 composable 重载，`weight` + 滚动 + 左右内缩都一样），正文改成「一句引导 + 每档组合一行框 + 一句后果」。
- **动作项报个数**：`关闭并改回等窗口` → `禁用 N 个组合`。这一步真正发生的是那几档被退回等窗口，数目比动词更直接。
- 文案随之拆键：`binding.fire_off_body` → `fire_off_lead` + `fire_off_tail`；「按住手势需要松手时触发」那一问同样拆成 `combo.mode_ask_lead` + `_tail`，正文一样用框。

### 改：一句话夹名字框改成行内占位（`ChipSentence`）

- 原来是 `FlowRow` 把「模板里那一段文字」当**一个整体**：前半截一长就整段换行，第一行只剩一枚框（真机反馈「键名后面直接换行了，整行只剩键名」）。
- 改成 `AnnotatedString` 的 `appendInlineContent`：框是**字流里的一个词**，前面的字照常排、后面的字接着同一行排，到行尾才折行。占位尺寸要自己量（新版 `Placeholder` 收 `TextUnit`），宽度补上左右内边距与描边，否则行尾那枚容易被挤下去。
- 名字为空、或模板占位与名字数对不上时退回纯文字（把 `%s` 直接去掉）—— `appendInlineContent` 的 `alternateText` 不许为空串，塞进去会把整页崩掉（真机已复现）。

### 改：回执与「点不动」原因里的键名改成标签

- 组合的新增/删除/启停、添加自定义键、重命名、组合触发方式切换：键名不再拼进文案，改由提示条的 `chips` 逐颗画成标签（与列表行同一套长相）。
- 「点不动」的原因通道改成携带模板 + 名字的 `HintText`，菜单行同步多一格 `disabledChips`；按键与组合的「已停用」那两句也在其中。`LocalDisabledHint` / `LocalDisabledClick` 两个组合局部变量把这条通道接到页面上，各处不必各拼一遍。
- 文案里 `[%s]`、`｢%s｣` 那一对方括号/引号去掉（标签自己就是框），中英两份字典同步。

### 改：按住组合的松手额外动作真的会执行

- 症状是「松手后执行动作有效、松手后执行**额外**动作不生效」。长按那一档本身跑得动，说明判定链没问题 —— 卡在执行侧：`GestureExec.handleCombo` 的 `Release` 分支上有一道 `combo.isHold` 拦截，是早先「按住档抬手只收尾」那条口径留下的。
- 那道拦截去掉，三种触发方式在松手这一档上完全同一套（用户口径）。松手仍按**抬手那一刻**的条件重判，不沿用按下时命中的那一块。

### 改：移除「松手沿用按下时的场景」（`releasePin` 退场）

- 这一位原本让「松手执行额外动作」沿用长按那一档命中的场景块。松手改成一概重判之后它没有语义了 —— 留着只是一格能配却不生效的开关。
- 删掉的东西：`SceneRule.releasePin`、`SceneRuleDto` 那一格、`ConfigFields` 的字段、场景块编辑页那张卡（`SceneReleasePinCard.kt` 整个文件）、三条文案（`binding.release_pin_*`）、`GestureExec` 的 `pressPins` / `rememberPressPin` / `consumePressPin` / `PinnedRelease`。

### 改：按住组合的系统场景改由「首键按下」时固定

- 按住那两档从按下首键到真的派发要隔 `comboHoldMinMs` + 长按阈值，这段时间里换了应用的话，「按下时的场景」与「派发时的场景」不是一回事。
- 新配置 `GlobalConfig.comboSceneOnStarter`（默认开）+ 每档 `ComboKey.sceneOnStarter`（`null` = 跟随公共，受「使用独立设置」管，打开那一刻播成当时的公共值）。**开**：首键按下那一刻定下来；**关**：组合凑成那一刻再取。
- 注入侧只报**时刻**（`ComboDetector.onHoldStarter` / `onComboFormed` → `GestureForwarder.forwardComboScene` → `ModuleWire.EXTRA_SCENE_STAGE`），条件由宿主判（`GestureExec.handleComboScene` 存 `SceneSnapshot`），派发时按配置取用（`takeComboScene` / `sceneActionOf`）。判一次、整一按都用它 —— 连续触发的每一条派发都看同一份。
- **等窗口那一档不参与**：凑成即是派发，两种口径没有区别，维持派发时现判。**松手那一档也不参与**：按抬手那一刻重判。
- 两处界面：公共那张卡加一行（在「首键按住时长」下面），某一组的独立设置页加同一行（只在按住那两档出现，文案逐字相同）。

### 改：删掉「无操作时执行按键命令」

- 组合某一格是「无操作」时就是什么都不做，不再让两颗成员键各跑一遍自己的绑定：想「两颗键各干各的」就不要配这一档组合。
- 公共设置里那一行、组合独立设置里那一行、以及它们的三项配置（`combo_passthrough` 与每组的 `passthrough`）一并删除；配置版本 60 → 61，老文件里残留的两格按未知键丢掉。
- 注入侧判「吞不吞 ROM 的组合判定」时不再看这一档有没有绑动作：配了组合就吞 —— 顺带修掉「留空那一格时系统截图照旧触发」。

### 改：捐赠名单的格子能吃按压

- 名字 / 金额那两格加了涟漪（`clickable` 吃 `LocalIndication`，与库里可点组件同一份）。
- **不加任何缩放或下沉**：表格格子的行列线是连着的，缩一格就把线带歪了。
- 涟漪用 `clipToBounds` 裁进这一格，否则会漫过竖线糊到旁边那一格上；表头那一行不吃点击（列名不是可点的东西）。

### 改：「重启服务」确认窗去掉正文

- 只留标题与两颗按钮（用户口径）。那句「未保存的改动将丢失」读起来像个警告，而用户点的是「重启」—— 一个下一步马上就好、也没有可失去的东西的动作。
- `DIALOG_RESTART_MESSAGE` 与 `dialog.restart_message`（中英各一条）一并删掉，不留一条没人读的文案。

### 修：电源 + 音量都被接管后，两颗一起按仍触发系统截图

- `ChordGuard` 两道：一是「两颗键都归模块管就吞」，不再要求这两颗恰好配成了某一档组合（原先要求配组合，于是没配组合的用户按下电源 + 音量时，组合判定接住了、ROM 的截图判定也照样接住）；二是参数解析两种形态都认 —— 上游那个方法有的机型收 `int[] keycodes`，有的收事件对象，原先只认前者，后者走空表等于不拦。

### 修：老写法的手电筒 / 免打扰没有状态词，提示里只剩「手电筒」

- 三态改版之前落盘的 `flashlight` / `oplus:no_disturb` 只表达「切一下」，取名那一步拿不到状态段 —— 现在补上「切换」，读作 `系统开关: 手电筒 - 切换`（与新写法 `setting:flashlight` 一致）。
- 判据在 `ActionCatalog.switchStateLabel`：`SystemSwitches.idOfLegacy` 认得出的那两个 token 给「切换」。老配置不迁移，执行照旧，但念法不能比新写法少一段。

### 修：「使用原版动画」打开某些应用时动画完全没有

- 原因不在动画本身，在**我们交出去的那份启动**：原版自己的入口（`ActionRemoteStartContentProvider`）给 intent 补了 `FLAG_ACTIVITY_RESET_TASK_IF_NEEDED` 与 `android_action_key_launch_type=true`，并把整件事 post 到主线程才调 `d.m`；我们只带了 `NEW_TASK`、还在工作线程上直接调。
- 少了 `RESET_TASK_IF_NEEDED`，目标的任务已经在表里时这一下只是「把那个任务提到前面」，不是一次新的 OPEN 转场，远端动画没有转场可挂 —— 表现为**完全没有动画**（`com.coloros.ocrscanner` 的清单写着 `alwaysRetainTaskState`，任务一直留着，第二次起就再没有入场动画）。
- 两处对齐：`stockLaunchIntent` 补上那两个标记，`OriginalLaunch` 转到宿主主线程再调（拿不到类 / 方法时仍在本线程立刻回落）。
