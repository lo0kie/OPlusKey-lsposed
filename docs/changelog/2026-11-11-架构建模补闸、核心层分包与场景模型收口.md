### 行内文字统一最多 3 行

- 「标题最多几行」从调用点收回到**行**这一层（`ROW_TEXT_MAX_LINES = 3`）：标题与副标题同一个口径，超出省略号。`CardRow.Item` 不再有 `titleMaxLines` 这种参数，原先三处给它 `Int.MAX_VALUE` 的调用点一并回落。
- 不按内容无限撑高：一条命令 / 一串条件说明可以任意长，放开之后一整行会被几行字吃掉半屏，同一张卡里行高也不再是一个量级。
- 删掉副标题那一档从没用过的「左句 + 右块」参数（`summaryExtra`）：零调用点、也没被真机验证过，留着还会多一条与「一律 3 行」不一致的分支。它的渲染分支与配套的间距常量一并移除。
- 唯一真需要「不省略」的那一行（场景条件里的「前台应用」）不再靠这个参数：应用名改成标签框、装不下换行（见下面两节），于是「给一个大数放开行数」这条口径整个消失。

### 按键 / 组合键禁用时设置入口也禁用

- 「独立设置」的两个入口（按键菜单那一行、组合菜单那一行，以及两页顶栏那颗设置键）跟着这一档的启停走：停用的键 / 组合点不动，点一下给出与页面其它按不动的控件同一句提示。
- 「这一档停用了没有」与那句提示收在 `SettingsTarget`（`enabledIn` / `disabledReason`）一处，三个入口都问它，名字走 `keyName` / `comboLabel`。
- 「系统场景」那一行仍不跟启停：停用期间先把场景表配好、再回去启用，是常见顺序。

### 滑杆行的当前值挪到主标题行

- 滑杆行的当前值从行尾那一列挪到主标题右侧；行尾空出来之后，中间那格拿到整行宽度，摘要（副标题）跟着全宽折行。
- 值仍读拖动中的那个值，拖动时与滑块同步跳动；整行可点、点轨道跳值、灰着时的提示都不受影响。

### 系统场景整条路只看整页闸门

- 「按键绑定」页那条场景入口行、两页 ⋮ 菜单里的「系统场景」、场景表那几行、场景动作页，都不再叠加这一颗键 / 这一档组合 / 这一块自己的 `enabled`：停用的那一份照样能进去把场景配好、再回去启用，闸门只剩主开关 / 链路 / 只读。
- 「这一档停用了」那一类说法随之收掉：入口行的 `scenarioBlockedReason`、场景块的 `pageBlockedReason` 与 `binding.scene_off` 一句一并删除；`pageBlockedReason` 只剩组合键那一支在用，`LinkCheck` 里「这一页在编的那一份先说话」那一段也只剩组合键一支。

### 场景表不再拦「不会执行」

- 「死分支」那一整套判据删掉：行尾红字、点「确认」时的拦截（恒成立 / 被更宽的一条盖住两句）、以及只为它存在的 `BranchDeadCause` 扫描。
- 保存前只剩「条件没配完 / 时间区间重叠」两种拦截；表怎么排就怎么执行。
- 只服务这套扫描的 `ConditionKind.exhaustive` 与 `SceneRule.isEmpty` 一并移除，`command.branch_dead` / `_saturated` / `_subsumed` 三条文案随之下线。

### 条件去重只看本块

- 「这一档的取值在表里用过了」不再跨块算：一块里配过 `A开`，另一块照样能配 `A开 + B关` —— 判据收成 `blockKindsOf` 一处，只数**当前这一块**里已占掉的档。
- 二级取值弹窗不再置灰任何一档；一级「取值全用掉了」那一档连同 `usedConditionsOf` / `UsedCondition` / `exhausted` 一并删除。
- 挑应用那条走同一条规矩：同一个应用可以当不同块的条件（`[微信 + 充电]` 与 `[微信 + 耳机]`），跨块拦下与那句提示一并去掉，`command.branch_duplicate_value` / `_app` 两句下线。
- 时间区间本来就是只与同块其它区间比，这次三处口径一致。

### 重复场景改按整块判

- 跨块条件去重撤掉之后留下的洞补在**块**这一层：同一组条件在表里出现了两次 ⇒ 后一块算重复（判定侧「从上往下第一条成立的赢」，先出现的永远赢）。
- 判据收在 `BlockRules.duplicateBlockIndexes` 一处，两块场景表（按键 / 组合键）共用。它只在草稿上算：后那一块的小标题行尾标红字「与上面重复」，点「确认」时拦一句「有两块的场景完全一样，请并成一块」。
- **只比条件、不比手势**：一块本来就是「一组条件 + 三档手势」，同一组条件只该有一块；而要按手势分工，把三档配在同一块里就行。更关键的是这一页的顺序是「先配条件、动作进场景动作页慢慢挑」—— 拿「配了动作的那几档」当判据的话，用户在配条件这一步永远看不到重复，要等配完动作才冒出来。
- **不在点条件那一刻拦**：一块的重复要等条件配齐才成立，逐条拦会在「先挑微信、再挑充电」这种正常顺序上把人堵死。所以做成实时标记 + 保存前拦截。
- 停用的块不参与比较，也不会被标 —— 启用回来要能照常生效。
- 条件答案按**取值**比，不按种类比：屏幕状态 `on` / `off` / `locked` 是两块不同场景，`[熄屏]` 与 `[锁屏]` 不许被并成一块（同一块里怎么放由下面那一节管）。
- `Command.kt` 里「锁屏算熄屏的一种、三档不互斥」那段旧说法改掉：实际判据（`ConditionChecks.screenMatches`）是三档互斥，而互斥正是上面两条界面判据的前提。

### 同一种条件可以加好几条（块内「或」）

- 块内几条条件不再一律「且」：**同种类之间「或」，不同种类之间「且」**（`SceneRule.appliesTo` 按种类分组，组内 `any`、组间 `all`）。于是 `[亮屏, 熄屏]` = 没停在锁屏界面，`[亮屏, 熄屏] + [微信]` = 屏幕没锁 且 微信在前台。
- 上限是 `choices.size - 1`（`blockKindsOf` 改按条数封顶）：屏幕 / 响铃 / 方向那几档能加两条，两档的那几种（开关类）仍然只能加一条 —— 加满就是恒成立，等于没写。「前台应用」仍只一条（那一条自己就能多选 `包1||包2`），「时间区间」仍不限。
- 一级菜单那句置灰原因随之改成「这一类场景已经加满了」：`command.branch_duplicate` 下线，`command.branch_kind_full` 接上。
- 二级取值弹窗置灰**本块里这一档已经用过的取值**（`usedValuesOf`）：`[锁屏, 锁屏]` 与 `[锁屏]` 是一件事，重复那一档点不动；跨块仍不置灰 —— 同一个取值出现在别的块里是另一条场景。
- 条件行的行身份带上「同一取值的第几次出现」（`ConditionLine.rowKey`）：手改 / 导入来的配置里两行相同取值不再撞成同一行，进出场认不错。
- 顺带修掉一处老 bug：一块里两条**不相交**的时间区间本来是「且」，永远不成立（`branchTimeOverlaps` 恰恰允许它们并存）；改成「或」之后才是它们本来要说的意思。
- `SceneRule.isContradictory`（同档两个不同取值 ⇒ 永远不成立）删除：块内已经按「或」算，那条判据不再成立，也没有调用点了。

### 「场景动作」页只写自己那一块的三档手势

- 那一页那颗「确认」不再整表写回：整表写回会把「系统场景」页还没确认的条件改动一起落盘，等于替用户按了上一页那颗「确认」。现在它只替换配置里对应的那一块（`SceneBlockSave.saveSceneBlock`），别的块与别的键一个字节不动。
- **也只写三档手势，不整块写**：草稿里那一块是同一个 `SceneRule`，上一页改了还没确认的 `conditions` / `enabled` 就挂在它身上 —— 整块写下去等于把「这一块在什么时候生效」也一并确认了，连「条件还没选完」那种半成品都会进配置（上一页那颗「确认」本来会拦住它）。落盘的那一块是「配置里的条件 + 草稿里的三档手势」。
- 快照跟着按**落盘那一块**记（`BranchDraft.noteBlockSaved`）：条件改动没跟着走，这一块在草稿里就还是脏的，退回上一页那颗「确认」照常亮着。
- 凭什么能只写一块：草稿每一行记着自己在配置里的**槽位**（`BranchDraft.slots` —— 载入时按位置对齐，加块时为 `null`，删块 / 挪块都跟着行走）。两道闸过不去就**不写**（改动留在草稿里，上一页那颗「确认」照样能整表写下去）：这一块是新加的（还没有槽位）、槽位上那一块已经不是载入时那一块（配置在别处变过）。
- 退页改用 `popBackStack`：草稿里还留着上一页没确认的改动时，`goBack` 会弹「放弃未保存的场景」—— 用户刚确认的是这一档，不该被那张窗拦住。
- 回执跟着改：「已保存系统场景」→「已保存这一档动作」（`command.branch_action_saved`），且只有真写下去时才报。
- 落盘那一段收成 `writeScenes` 一处（整表 / 单块共用）；`BranchDraft.noteSaved` 与 `saveScenes` 里那两处「在场景动作页只挪快照」的分支一并删掉 —— 现在只有本页那颗「确认」整表写。

### 场景文案统一成「场景」，取值选择器去掉行首图标

- 术语统一为「场景」：`添加条件` → `添加场景`、`删除这条条件` → `删除这条场景`、`这一档已经加满了` → `这一类场景已经加满了`、`有两块场景的条件一样，请并成一块` → `有两块的场景完全一样，请并成一块`、变量页副标题 `命令与条件里可以引用` → `命令与场景里可以引用`；英文一侧的 `Condition %d` / `No conditions yet` / `Conditional actions` 等同批改成 scene。
- 「前台应用」多选在列表行里的分隔符由顿号改成 `×`（`微信 × QQ`）。
- 场景取值的二级选择器去掉行首图标：`PickerOption` / `PickerRowTraits` 不再带字形，取值那一层改用专门的 `ChoiceRow`（不再借菜单行）；列表行上的那颗状态字形不变。理由写进了 `PagePicker` 的注释：这一列本来就是「同一件事的不同取值」（亮屏 / 锁屏、开 / 关），每行再挂一颗图标会把「一列同族取值」读成「几种不同的东西」，而那颗字形在**列表那一行**上已经有了。
- 通用选择器的行间细线：两端内缩都改成行自己的左右内边距（等于标题左缘），线的左端起在字头、右端与左端同宽。不照抄 `CardList` 那条（卡片行首有图标列，它的左内缩是 56dp，套到这儿会让线从半个行宽处才开始）。

### 名字框装不下就换行（组合列表与场景条件同一份）

- 原先按可用宽把每枚框**等比压缩**：名字一多、或者三颗键那一档在窄屏上，每枚框被压到只剩一个圆角矩形的壳（真机口径「选多一点只剩框了」）。现在 `ChipFlow` 用 `FlowRow` 排，放不下的排到下一行，每枚框始终保有自己的字宽。
- `×` 是**前一枚框的尾巴**，不是独立一项：独立一项时换行会让某一行以 `×` 开头，读起来像漏了一个名字。
- 组合列表的框宽改成**全局量一次**（全部组合里最长的那个键名）：换行之后「一行里的第几枚」不再等于「第几颗键」，按列分宽度没有意义；取全局最长值，每枚框仍然一样宽、左边仍然竖着对齐。
- 长相（样式 / 字色 / 闸门）合成一个 `ChipLook` 传：`ChipFlow` 本来就要收名字、宽度、前缀位，再摊三个就过 detekt 的 `LongParameterList`。
- 组合列表那句判据行保留（`组合框宽：chip=… widest=… lang=…`）：真机口径「缩小界面 / 切英文后键名显示不全」时，这一行直接给出量到的宽度。

### 顶栏圆键补齐禁用样式（字形）

- 顶栏那颗圆键的禁用样式补成三件：圆底、描边、字形一起灰 —— 原先只灰前两件，字形照旧亮着，看着像「还能按」。
- 字形这一件做在按钮自己那一层：`HeaderIconButton` 按 `enabled` 把内容色（库的 `LocalContentColor`）在停用时换成 `disabledOnSecondaryVariant`（与行首图标禁用时同一档），调用点仍只写 `Icon(图标)`，不必逐处判状态、各挑一个灰。

### 转交手势：宿主进程被回收后把它叫醒（待真机验证）

- 转交侧的唤醒补一条**绑定**兜底（`BIND_AUTO_CREATE` 会创建进程，且不受「后台不许起服务」那条限制），绑上之后 5 秒自动解绑 —— 只叫醒、不长期保活。
- 补发由一条变两条：300ms（缓存进程被抬起）之外再加 1500ms（进程已被回收时的冷启动），三条带同一个 `sent_at`，宿主按它去重。
- 唤醒成败留判据行：`唤醒宿主：已绑上 …` / `唤醒宿主进程失败，手势可能被丢：…`，下次「按了没反应」能直接看出是没叫醒还是没送到。

### 屏幕翻译改成单动作多状态：屏幕翻译 - 打开 / 屏幕翻译 - 关闭

- 动作清单里那一格改成**一格两状态**：格子是「屏幕翻译」（`ActionCatalog.SCREEN_TRANSLATE_TILE`，标记 token、永不写进配置），点它**直接弹一行一档的单选弹窗**选「打开 / 关闭」，落成两条真取值 `oplus:screen_translate` / `oplus:screen_translate_stop`。
- 走的是 `STATE_ONLY_TILES` 那一档（与录屏 / 录音同一套）：文案念 `屏幕翻译 - 打开`（横杠），不是父子动作的冒号；格子行尾不挂选择器字形。
- 关闭那条走 `Context.stopService`（`RomProfile.BuiltIn.stop`），不是发广播、也不是 root：目标清单里那条 `GLOBAL_TRANSLATION_EXIT` 真机发出去 `result=0`、胶囊照旧；`stopService` 才真的收掉（`dumpsys activity services` 里那条记录消失，`ScreenTranslationToolCapsule` / `ScreenTranslationFullImageHolder` 两扇窗一起没）。
- 停用要 `com.oplus.permission.safe.AI_APP`，宿主持有；`shell`（uid 2000）去停会被直接拒（`Permission Denial`，真机日志）—— 所以这一档不需要 root。
- 字形：格子与「打开」用 `Language`、「关闭」用 `LanguageOff`；两行在弹窗里并排，一眼分得开。`ActionIcons` 补上不在清单里的 `NAME_SCREEN_TRANSLATE_STOP` 那一支。
- 执行侧拆出 `host/action/FeatureLaunch.kt`（`buildFeatureIntent` 与 `stopFeatureService`）：`AppLauncher` 的文件函数数已经贴着 detekt 的上限，`startOplusService` 也顶着 60 行那条线。
- 新标记登记进 `ActionTokenTest.menuOnly`：那份名单的用处就是「新加一个只作标记的 token 却没登记，测试当场失败」—— 这一档正好被它拦下来（`ai:screen_translate` 过不了 `hasSupportedFormat`，与 `ai:screen_record` 同类，永不写进配置）。

### 「默认界面」那条状态栏：颜色交回原版页，图标改成浅色

- 露出宿主原版页时**不再往状态栏那一条刷任何颜色**：那一条由原版页自己铺（截图实测 `y=0..140` 是 `(8,8,8)`→`(14,14,14)` 的渐变，而 `appbar` 的 `top=141` —— 条子在顶栏之上，不是顶栏画的）。
- 前两版都在猜颜色，两次都撞上「顶上多出一条白带」（真机反馈两次）：猜过纯黑、也猜过宿主主题的 `windowBackground`（浅色下是纯白）。
- 图标**恒刷成浅色**：这一页恒为深色（清单主题 parent 写死 `Theme.COUI.Main.Dark`），系统开着浅色时也一样 —— 早先按系统深浅判，浅色系统下给它配了深色图标，压在黑底上几乎看不见（真机反馈「状态栏没有反色」，截图里时钟与信号只剩 `(10,10,10)` 的灰影）。
- 连带删掉那条实心遮罩的整套机件（`statusFiller` / `coverStatusBar` / `removeStatusFiller` / `statusBarHeight` 与三处调用）：它只服务过这一档，留着就是死代码。露出的动作收成一句 `HostChrome.paintStockChrome`。
