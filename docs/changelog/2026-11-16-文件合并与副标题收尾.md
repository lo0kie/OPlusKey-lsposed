# 文件合并与副标题收尾

## 修

### 修：生成器会把混进生成物的代码整份抹掉

- `tools/gen-static-tables.py` 是整份重写 `Strings.kt` / `CommonCommandsTable.kt` 的：谁把代码并进
  这两个文件，下一次生成就连内容一起吃掉，而它自己照样打印「已重写」—— 2026-11-16 撞过一次，
  表现是 `Unresolved reference` 当场编译不过，事后才知道是生成器干的；
- 现在生成前先扫这两份的顶格声明，只认它自己那一份（`Strings` / `COMMON_COMMAND_ENTRIES`）；
  多出别的就**拒绝执行**、列出是哪几个名字、一个字节都不写，并说明「挪到别的文件」；
  `--check` 同样拒绝（CI 那一步先跑生成器再比 diff，于是会红在这一句上）。

### 修：补丁构建脚本的 `git reset --hard` 可能落到本仓库

- `patches/coui/build-patched.sh` 会先 `cd` 进 `.temp/coui-repo` 再 `reset --hard` + `clean`；
  可 `.temp/` 就在本仓库里面 —— 那个目录一旦不是独立仓库（`.git` 被删、克隆留下半棵树），
  git 会一路向上找到本仓库，把**未提交的改动整份抹掉**，而 `set -e` 挡不住（命令本身成功了）；
- 现在进目录先比 `rev-parse --show-toplevel` 与本仓库顶层，相等就拒绝执行并说明原因。

## 改

### 改：有效行数不到 100 的文件并进同目录的邻近文件

- `.kt` 从 415 个降到 223 个（删 193 份、新增 1 份 `core/wire/Wire.kt`）；
  「有效行」= 非空、非行注释、非块注释的代码行；
- 「就近」的判据：同目录内优先并进文件名共享词的那个，其次并进合并后仍最小的那个；
  合并后有效行超过 700 或函数数超过 detekt 那一档（60）就不合；
- **不参与合并的**：两份生成物、工具按路径读的权威落点（`KeyId` / `ConfigCodec` / `HintCenter` /
  `AppName` / `HostApp` / `ModuleInfo` / `KeyModule` 等，合并掉等于把闸读崩）、
  `BuildFlags.kt`（三个源集各一份）、`src/test`（一个文件一个被测对象）；
- `core/wire` 那一族并成一份之后按内容改名为 `Wire.kt`。

### 改：把「为过静态检查而拆」的那几份并回原处

- `ServiceCalls` → `SettingCalls`、`MiniWindowVerify` → `MiniWindowLauncher`、
  `ProbeCall` + `ProbeOps` → `ProbeChannel`、`ComboOnlyNative` → `SideKeyInterceptor`、
  `ShortcutStarter` → `AppLauncher`、`PageEntryWrite` → `PageEntry`；
- 判据是文件头自己写着「从 X 分出来 / 为了压函数数」—— 只并这些；语义本来就不同的
  （如 `SettingsPageDebug` 与页面骨架、跨包的那几份）不动；
- detekt 的 `TooManyFunctions` 从 40 抬到 60：合并后最大的那份正好停在 40 上，
  再加一个函数就会有人重新拆一次；
- 文件头里那几句过期的拆分说明一并改写（`ConfigChannel` / `KeyHooks` / `ProbeChannel` /
  `SettingCalls` / `MiniWindowLauncher` / `ConditionProbe`）。

### 改：「多击手势」与「使用独立设置」的副标题全部去掉

- 多击手势卡里那五行（只参与非首键的按住组合 / 启用双击 / 启用三击 / 启用四击 / 启用单击后长按）
  与「使用独立设置」那一行，都不再带第二行说明，只留标题；
- 随之没人用的 12 条字典键一并删掉（两份字典同步，`Strings` 由静态表重新生成）。

### 改：性能审计的豁免表补两条

- `SideKeyInterceptor` 里那次集合拷贝：只在配置变化 / 撤销待定手势时跑，且必须拷快照才敢
  边遍历边重排（与 `GestureDetector.reset` 同一情形）；
- `ComboDetector.describe` 的字符串拼接：自检 / 诊断通道把结论翻成人话用的，不在按键路径上
  （它只是和判定器同处一个文件）。
