### 适配清单：判定从「机型」扩成「机型 + 系统版本」

- `core/model/DeviceSupport` 的清单每行从「机型」变成「机型 + Android 版本 +
  ROM 版本」，判定结果从布尔变成三档：`ADAPTED`（清单命中）/ `PENDING`（机型在、系统版本不是那一档）/
  `UNSUPPORTED`（机型不在）
- 理由是同一台机器换一版 ROM 与换一个机型是同一类风险：接管点都是 ROM 私有的、可能整体换名换形，没验过就注入会变成「拦下来但什么都不做」（比直接不支持更难排查，见
  `docs/device-findings.md` 十九）
- 清单目前一行：`PLK110` + Android 17 + ColorOS 17.0.0（真机 `ro.build.version.oplusrom = V17.0.0`）
- ROM 版本从 `android.os.Build.DISPLAY`（`ro.build.display.id`，真机 `PLK110_17.0.0.105(CN01)`）里取 `17.0.0`：**不读
  `ro.build.version.oplusrom`** —— 那是 hidden 的
  `SystemProperties`，界面进程会被非 SDK 接口限制拦下，而两处判据（注入侧与界面层）都要读它。取法丢掉构建号（`105`
  随每次 OTA 变，算进判据里会让一次月度补丁把用户锁在门外），取不出来（段数不够 / 段里有非数字，如老 ROM 的
  `11.A.06`）返回空串
- **版本读不出来时不拦**：读不出来是「我们没读到」，不是「用户版本不对」，拿它去锁会把一台版本正常的机器整页禁用
- 判定仍是纯函数、仍不读 `android.os.Build`：机型 / Android / ROM 三个字符串由调用点自己传（`KeyModule` 与
  `ui/state/LinkCheck`）

### 修：模块页面不在前台时手势触发延迟偏长（2026-10-15）

- 根因：`system_server` 判好手势向宿主（`com.oplus.gesture`）转交广播时未挂
  `Intent.FLAG_RECEIVER_FOREGROUND`；当设置页不在前台时，宿主属于后台/被系统冻结进程，广播被排入 AMS 后台队列（`mBgBroadcastQueue`）并在系统批量解冻窗口滞留 200~500ms，导致宿主侧的触觉振动和动作执行感知变慢
- 广播提权：手势广播加上 `FLAG_RECEIVER_FOREGROUND` 与
  `FLAG_RECEIVER_REGISTERED_ONLY`，直走前台广播队列即时投递，强制唤醒并解冻宿主进程，送达延迟压到数毫秒级
- 首发零延迟：首发广播（`delayMs <= 0`）不再通过 `system_server`
  主线程 Looper 投递延时任务，直接就地发出，规避系统主线程消息队列排队耗时
- 跨进程广播协同：同步为配置广播（`ConfigBroadcast`）、状态栏与小窗控制广播（`StatusBarBridge` /
  `FlexibleWindowBridge`）补上 `FLAG_RECEIVER_FOREGROUND`，避免后台状态下跨进程通信受后台广播队列节流
