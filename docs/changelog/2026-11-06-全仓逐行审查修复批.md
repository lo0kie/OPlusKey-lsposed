# 全仓逐行审查出来的问题，修掉会吃用户操作的那一批

> 上一笔提交（`95b00dc`）之后这一轮的改动：`app` + `core` 的 372 个 Kotlin 文件逐行过了一遍，
> 本片段只记**动了代码**的那些。判为「不该改」或「要真机取证」的几条记在末节，免得下次再被当成漏项。

## 修复

### 修复：分叉页改一条条件，实际是往表尾追加一条

- 点种类那一档会先关掉一级菜单让位给取值弹窗，而关菜单把「改哪一块、第几条」一起清成哨兵值；
  取值回来再读就成了 `-2`，于是走「新加一行」那一支 —— 改完一看，原来那条没变、表尾多一条。
- 改成点种类那一刻把落点快照下来，随这次选择一路带到落盘（`ConditionPick` 多带 `at` / `slot`）。

### 修复：给「松手动作」挑应用，会一次退两层

- 那一趟的写盘自己已经退了一页，外面又补一次 `goBack()`，直接回到首页。
- 早退判据补上这一趟（原来只免了「多步命令」与「分叉」两条路）。

### 修复：收集过按键之后，下一次正常单击被吞

- 收集期记下的「这一下被吞了」只在抬手时摘，而下次正常按下的那一刻不会刷新它；
  隔着几秒再按，抬手把旧账摘走并判成「该吞」—— 判定器只收到按下、没有抬手，那一击不再派发。
- 改成不在收集期时按下即清该键的账：旧账只对**最近这一次按下**有意义。

### 修复：组合键挂住之后，整块键盘不再响应

- 成员键的抬手一丢（锁屏打断 / 事件被系统丢掉），组合就一直挂着，之后每颗键的按下都被当成
  「组合进行中」吞掉。原来只有「同一颗键再按」和配置广播能解开。
- 加了时长自愈：超过与重复链同档的上限就清空组合状态并打一行 `w`。挂在按键入口上，不另起定时器。

### 修复：改名 / 删掉一条命令之后，「松手动作」里留着指不存在的 `cmd:`

- 「这一格放过动作」的遍历点漏了「松手执行额外动作」那两格（单键与组合各一份），
  于是改名后那两格里的引用不跟着挪、删命令时也不清、删变量前的反查还数不到它。
- 两格补进同一份清单（`mapActions` / `actionTokens`）。

### 修复：两条命令重名时，命令列表直接崩

- 列表按命令名认身份，重名（手改 / 导入来的）就产生重复 key，Compose 当场抛异常把宿主带走。
- 改成按「位次 + 名字」认身份：既保住原来那份「不被邻居顶位」的意图，也不会重。

### 修复：删除按键 / 组合时写盘失败，界面却已经当成删掉了

- 三处（按键页批量删、组合编辑页删、组合删除本身）都是先收状态后退页，写盘被拒时配置里那几项
  还在，而界面已经退出编辑态、清了编辑目标 —— 回来是个「找不到」的空壳。
- 三处统一成「落盘成功才收场」，删除函数把结果带回给调用方。

### 修复：更新窗没有下载地址时，静默关闭

- 那个「去下载」会先把待更新状态清干净再取地址；地址为空（解析缺字段 / 手改）时窗口关了、
  浏览器没开、首页红点也一起灭了，用户什么都看不到。
- 改成先看地址，空的话给一句回执（新文案 `update.no_url`，三份字典已同步）。

### 修复：填名字的弹窗开着时，外面刷新一次就把输入抹了

- 输入框的初值连 `initial` 一起当成了重置键，滑杆回写 / 改名同步都会把它还原成初值、光标跳走。
- 改成只按开合重置。

### 修复：建页偶发读盘失败，整页永久停在启动底色

- 读配置那一步抛一次就再也没人重跑，用户看到的是「点进来一片空白」，只能杀进程重来。
- 改成失败重试一次（间隔 250ms，让正在写的那个进程先写完）；两次都不成才留错误日志。

### 修复：新建配置时附属写入失败仍报成功 / 导入覆盖时读不懂的原命令库被永久盖掉

- 新建：主配置写成了就返回槽名，命令库与变量表写没写成没人看 —— 失败时新配置会带着上一套的
  命令与计数上线。改成三段都成才算建好，否则撤掉这一槽。
- 导入覆盖：原来用「读不到就返回 null」的那支读旧命令库，于是「读不懂」与「没有」分不开，
  覆盖失败时还原不了，原内容被永久覆盖。改用三态读，「读不懂」直接拒绝覆盖。

### 修复：截图那条路会去读宿主的静态常量

- 诊断日志里为了打印 `SCREENSHOT_*` 的取值读了静态字段 —— 那会触发宿主类的 `<clinit>`，
  而 system_server 里宿主类初始化失败就被标 erroneous，之后任何访问都是 `NoClassDefFoundError`。
- 这段只做诊断，直接删掉。顺带把准备实例那一步也兜住 `Throwable`（`newInstance` 抛 `Error` 时
  原来会漏进 system_server）。

### 修复：菜单里的空组只剩一个标题，以及「行表空」之后这张菜单再也打不开

- 空组（这一档暂时没有可选项）原来照样画标题加一条通栏细线，读起来像渲染坏了 —— 整段不出。
- 有状态的那层菜单靠「行表空」判关闭，但开关位留在「开着」，再点一次写同值不触发重组，
  于是打不开。行表空时把开关一起复位。

### 修复：网格在组合期写共享表、同名开关共用位置、应用名缓存不是线程安全的

- 网格：每格的触点锚点改成进出各登记一次（`DisposableEffect`），不再在组合体里写普通 map。
- 开关：这一格的行位置按标题记一份，槽位被别的行复用时不会再沿用上一行的高亮。
- 应用名缓存：两个写入点分别在主线程与 IO 上，换成并发安全的那一档（普通 `HashMap` 并发扩容会丢条目）。

## 调整

### 调整：判据级日志统一升 `w`，正常路径的降回 `d`

- 升：KeyEvent 用哪个构造器（决定 `deviceId`，`isInjected` 靠它认自己的事件）、读配置读不出来、
  小窗支持性判不出来、文件选择走没走到平台 hook。`d` 在 release 里被编译期消除，这几档恰恰是
  「点了没反应」时要看的那几行。
- 降：提示条弹出（全页最高频，且它本身就是用户看得见的回执）、进编辑页时「载入 N 条规则」。

### 调整：一批底层加固（都不改界面行为）

- 绑定目标：用户前缀「看起来是数字但装不进 Int」时，取值与剥前缀两侧原来判得不一样 ——
  统一按「没有前缀」处理，坏前缀不会静默变成「主用户 + 合法目标」。
- 自定义键：新 id 的分配只扫了「有哪些键」，没扫绑定表里残留的条目，可能撞上还活着的那一条。
- KSU 别名：前缀之后必须是空格或结尾，`..._x` 那种只是长得像的命令不再被认成别名。
- 判定点击上限：本地算出来的那档按广播那一列的上限钳一次，两处不再各写一个数。
- 导出日志：缓冲为空也回一片空的，收方才能分出「进程在跑但没日志」与「进程没起来」。
- 更新解析：JSON `null` 不再变成字符串 `"null"`（版本号 / 更新说明都会中招）。
- 反射缓存：负命中按 `identityHashCode` 拼键，两个 loader 撞车会互相挡住 30 秒的重试。
- 日志缓冲：每条日志都按 `size()` 数一遍长度是 O(n)，满载时单条白跑两千次节点访问；
  换成带锁的队列，加与裁在同一个临界区里。
- 文件外皮：解封时逐字符线性反查替身字母表，改成下标表。
- 变量反查：展开时会把花括号里的名字 `trim`，反查是精确比 —— `${ 计数 }` 能展开却不算引用。

## 没改的（附理由）

- `AppLaunchAsUser` 的成功码区间 `0..3`：`3` 同时是「交给栈顶消化」与「退回调用方」的取值，
  收紧成 `0..2` 会把「目标本来就在前台」误报成启动失败。
- 语音助手起服务用的 Context 是否必须「非降级」那份：没有取证，凭猜测加闸可能砍掉本来能用的机器。
- 配置落盘仍在调用线程：改异步要动所有调用点对返回值的用法，属跨模块契约变更，另起一笔。
- 确认窗的预留高度算法、组合编辑页的分页菜单：要对着真机看才算数，改了只是换一种猜。
- 全仓的「编年体」注释（记的是当初试错过程而非判据）：纯文字工程，单独一轮做。
- **`isSynthetic` 的合成事件判据**（复审提的那条）：这张 ROM 的真按键也带 `deviceId = -1`，
  而音量±与电源是允许被收集的 —— 于是它们被当合成事件放行、永远绑不上。改法只有两种
  （注入侧换一个专属 `deviceId`，或按「刚注入过」的时标认），两种都要先在真机上量出
  实体音量键的 `deviceId` 才能定；猜错会让侧键注入整条失效，比现状更糟。
- **`audit-config-version.py` 的结构指纹不含字段类型**：补类型会让所有既有配置的指纹失配、
  要同时抬 `VERSION` 并写迁移，属配置格式变更，单独一笔。
- **`Framework.kt:119` 那条平台私有结论没进 `docs/device-findings.md`**：名与参数表都还没有
  真机取证，先补文档等于把没验过的东西写成结论。
- 复审里那批 P2 里**核过但不改**的（各有明确理由）：
  · 组合期写去重变量（`ComboListCard` 的 `logPairOnce`）：写的是一个「上次打到哪」的普通变量，
    幂等、不读状态；包一层 `SideEffect` 正好把 `ComboPairTitle` 顶破 detekt 的 60 行上限 ——
    收益不抵改动，保持原样。
  · `AboutMenus` 的 `ConfigProfiles.isFull()`（组合期多列一次目录）：它与 `createAs` 内部
    是**同一把尺子**（按槽位数，不是按读得出来的份数），改成从 `ui.profiles` 推算会在
    「有一份文件坏了」时给出不同答案 —— 那正是两处各数各的会踩的坑。
  · `CommandBranches.conditionAt` 的按需增长：锚点必须在**布局之前**就存在，挪出组合期就没有意义了。
  · `LinkCheck.localConfigTag`：它的缓存键已经带上「配置实例 + 命令库实例」，且
    `ConfigBroadcast.tag` 全程在内存里算（不读盘）—— 「主线程读盘」这一条不成立。
  · `PageControl.restartModule` 的进程查询、`GestureDetector` 持锁打日志：前者是一次用户主动
    点按、后者是整个文件几十处日志共用同一把锁，单改一处没意义。
- 复审 P2 里**下一轮要做的**（结构性的，已定好做法）：`ui/state` 反向 import `ui` 根
  （`UpdateState` 拿 `SettingsPage` 调 `moduleVersionName()` / `fetchText`）。做法是把这两样
  改成入参能力（`version: () -> String?` 与 `suspend (url) -> String?`），`UpdateState` 只认
  lambda，`ui` 侧留一层薄适配；调用点只有 `AboutScreen` 与 `UpdateDialog` 两处。
  同一规则两份实现那 5 对要在它之后再动（先定唯一口径，再删另一份）。
  **第一对的具体做法已经定好**（`ProfileCommands` 161 行 / `ProfileVars` 116 行，两份的
  `slotOf` / `swap` / `swapBoth` / `save` / `delete` / `writeRaw` 逐行同构，只差槽名前缀与
  「怎么编解码」）：抽一个 `ProfileSlotFile(prefix, encode, decode)`，两份实现退化成它的两个实例，
  各自只留自己的 DTO 转换；顺序是「先抽壳 → 两份都走壳 → 跑 gate + 耦合审计 → 再删旧函数」，
  中间任何一步编译过不去就停在「两份都走壳」那一档（那份态是绿的）。

## 复审追加（同一工作区第二批）

外部复审提了一批 P1 / P2，逐条核过之后**成立 9 条、判反 1 条**（见最后一节），这一批改的是成立的：

### 修复：组合键的「松手才触发 / 松手执行额外动作」只接了一半

- 组合键的广播里没带 `longFireOnRelease` / `longReleaseOn` / `longRelease` 三个字段，而注入侧
  的组合键只从这条广播来（它读不到盘）—— 于是那两个开关在判定侧永远是默认值：
  「松手才触发」退化成到点就触发、「松手执行额外动作」整条不派发。界面上是能配、能落盘的。
- 三个字段补进广播的编解码（都带默认值，老 JSON 照样读得回来）。

### 修复：从「松手执行额外动作」进「选择应用」，小窗开关与高亮全丢

- 那一趟会把 `gesture` / `comboId` / `forStep` 一起清掉（它写的不是手势槽），而
  「正在编辑哪个动作」只认这三处 —— 于是恒返回 `null`：小窗开关恒关、当前绑定不高亮，
  用户重挑一次就把 `window:` 静默降级成 `app:`。
- `editingAction()` 补一支：这一趟按「键上的 `longRelease`（组合那一趟读组合那张表）」取。

### 修复：文件选择那条 hook 在「每层都挂钩失败」时假装接上了

- 沿类链每一层都挂钩失败之后，仍然记下 `hookedClass` 并打「宿主没有覆盖」—— 下次 arm
  一进门就被早退挡回，整条路一次都没接上，日志还说自己接上了。
- 分成两种收尾：宿主**没声明**（记下、以后不再试）与**声明了但挂钩失败**（不记、下次重试，
  日志写明是哪一种）。

### 修复：删除按键 / 组合时把「已落盘但没通知到注入侧」当成失败

- 上一轮那两处改成看 `!= Ok`，于是 `BroadcastFailed`（盘上已经删了、只是广播没送到）被当成
  「什么都没变」：键删了、编辑态不退、`forget` 不执行，界面勾着一批不存在的 id。
- 按 `write` 的契约改成只把 `Failed` 当「没成」。

### 修复：只读态下切换配置 / 导入覆盖，盘已经变了、界面还说「未保存」

- 这两条都是**先动盘**再走通用写入：`switchTo` 一进去就把当前槽换人，`importInto` 一进去就把
  文件换成导入内容 —— 等 `write` 因为只读态拒掉，盘与界面/注入侧已经三方不一致（重进页面
  或重启后「当前配置」自己变）。
- 新增 `canWriteConfig()` 作为「动手改盘之前」的闸，两条入口先过它；`write()` 自己复用同一处，
  提示语不再各写一份。

### 修复：同一颗返回键，API 33 与 34+ 关的层数不同

- `onBackPressed` 那条路收「全部浮窗」，`OnBackInvoked` 那条只收最上面一层，而代码里写着
  「只收一层是用户口径」。两条统一成只收一层。

### 修复：清变量表失败仍报「已重置模块」

- 变量表清空的结果只进了日志，没进收尾判定 —— 主配置与命令库重置了、计数还在盘上，
  用户下一次 `+= 1` 接着旧值加。现在这一档单独报一句（新文案 `toast.config_clear_vars_failed`）。

### 修复：自动亮度那一档，亮度条刷新在写盘之前

- `ShellRunner` 是排队执行、立刻返回，而「刷新口令」写在下一行 —— SystemUI 读到的还是旧值。
- `ShellRunner.exec` 增加 `onDone`（包在池任务最外层，`execBlocking` 的所有出口都覆盖），
  自动档把口令挂在完成回调上；手动档是同步写，顺序不变。

### 修复：「立即触发单击」的中文说明与实现相反

- 英文写的是「two taps count as two singles」，与判定逻辑（双击无动作且开了这一档时，
  第一下就直判单击，两下各派发一次）一致；中文那句「按两下算单击」读起来像「两下合成一次」。
- 改中文（含代码里的兜底文案）：双击无动作时，两下各自立即算一次单击。

### 工具链：三处「0 命中 / 读失败」不再假装绿灯

- `check-i18n-fallbacks.py`：扫到 0 处调用时按失败退出（写法一变，这条闸就静默失效）。
- `audit-perf.py`：一个 `.kt` 都没扫到按失败退出；`--report` 模式命中硬判据时明确打「不是绿灯」。
- `verify-apk.sh`：字典校验从「只比键集合」补成「也比 `%s` / `%d` 的数量与顺序」——
  只差一个占位符时运行期 `String.format` 会直接抛。

## P2 批次（同一工作区第三批）

按主题清了一遍复审列的 P2，改的是「判据 / 回执 / 并发 / 工具链」这四类，结构性的留到下一笔。

### 日志档位：判据级要留得住，正常路径别刷屏

- **读配置读不出来**（`ModuleFiles` 的两个 catch 分支原来一处 `w` 一处 `d`）：同一件事统一到
  一个 `warnUnreadable()`；`ConfigStore` 那行同类提示改成「每进程第一条 `w`、之后 `d`」——
  宿主每条按键前都读一遍配置，文件坏一次就是每秒十几行，全降 `d` 又会在 release 里彻底消失。
- 滑动判定抛异常：`d` → `w`（判定器抛一次，这一档手势从此判不出来，而 `d` 在 release 被消除）。
- 系统开关指令拿不到目标值：原来裸 `return false`，四处补上 `w`（界面上那个开关照样播了动画）。
- 配置变化后「重问注入侧」那一广播没发出去：原来只在成功时打日志，失败一声不响 ——
  而失败的表现正是整页一直判「未同步」、控件全灰。

### 死回执 / 死分支

- 「导入配置 → 新增配置」到顶（已有三份）时，行置灰 + 点击回执「最多三份」——
  但 `PickerRow` 的可点性挂在 `enabled` 上，置灰行收不到点击，那句回执**永远不会执行**。
  改成：置灰行的字直接写「最多三份配置」（回执变成静态的），死分支删掉；
  `PagePicker` 的 KDoc 一并改正（原来写「置灰行点击仍会走到 onClick」，与实现相反）。

## 同一规则两份实现（同一工作区第五批）

复审列了 5 对，这一轮做了 3 对，另外 2 对**核过之后不做**（理由在下面，不是漏了）。

### 合并：命令库与变量表的「对调 / 删除 / 写原文」

- `ProfileCommands`（161 行）与 `ProfileVars`（116 行）的 `slotOf` / `swap` / `swapBoth` /
  `delete` / `writeRaw` 逐行同构，只差槽名前缀与「要不要让宿主主进程读得到」。

  三条踩过坑的规矩（**读不懂 ≠ 没有**、**第二步失败要还原目标槽**、**老配置只搬当前不动目标**）
  从此只有一份实现 —— 原来两处各写一遍时，漂出来的坏法只在「刚好有一份文件读不懂」时出现。
- `ProfileCommands.Load` 三态与 `save`/`load`（要过外皮与 `CommandLibrary`）留在原处：
  那是命令库独有的语义，不动。

### 合并：「已启用 / 已停用」两处措辞

- `KeysList.stateSummary` 与 `ComboListCard.comboStateSummary` 是同一个函数（同一对 i18n 键、

  组合那边改调它，删掉自己那份。

### 合并：「最近任务」那张表的反射链

- `ForegroundApp.infos()` 与 `MiniWindowLauncher.topAppInfos()` 各写了一遍
  「找 `OplusAppInfo` 管理器 → `getInstance` → `TOP_APP_INFOS_METHOD/0`」的反射链，
  连「哪一步断了」的话术都是两套。收进 `MiniWindowFacts.topAppInfos(loader, warn)`。

  所以这一层自己不打日志，只把「断在哪一步」交给 `warn`。

### 没做的两对

- `BranchPickers` ↔ `CommandBranchMenus.applyBranchCondition`：共用的只是「新增一行 / 换第 N 条 /
  追加一条」那六行机械动作，而**槽位策略完全不同**（前者要按「已有前台应用就换它」去猜，
  后者由菜单显式给出下标，还要照顾插入动画的 `freshCond`）。合并会把 UI 概念塞进挑应用那条路。
- `ComboSequence` ↔ `ComboDetector`：前者是纯函数式的「这一串按下凑成哪一档」，后者是运行时
  状态机（含长按枪、连发、消费集合）。两边共享的是判定**口径**而非实现，真要合一得先有一份
  判定用例表做对照，否则改完只能靠真机手感验 —— 单独一笔。
