- 「控制中心磁贴」那一页整个撤掉，改成网格里**一格入口 + 一层浮动菜单**：点「系统开关」那一格弹菜单，
  里面十行全是开关 —— 蓝牙 / WLAN / 移动数据 / 自动旋转 / NFC / 飞行模式 / 免打扰 / 手电筒 /
  暗色模式 / 省电模式，每行一个自己的字形；选中即写配置，与别的入口格（系统导航 / 媒体控制）同一套

- 为什么撤那一页：控制中心里点得动的第三方磁贴必须**先在控制中心里加过**，而用户真正常绑的那几个是
  SystemUI 内置的简写 token（没有组件名），永远进不了那张列表 —— 那一页最终是「一列大多数点不动的磁贴」
  加「几颗查不到的系统开关」；而十个开关摊成十格又太长，所以走「一格 + 菜单」

  反射、状态栏 `click_tile` 广播、临时加挂 addTile/removeTile 全部删除
- **执行不再用 `su`**：宿主（`platform_app`）读当前状态 → 广播把「切成什么」交给 system_server（uid 1000），
  那边按名字 + 参数个数试签名调服务：`wifi.setWifiEnabled`、`bluetooth_manager.enable/disable`、

  `power.setPowerMode`、`window.freezeDisplayRotation` / `thawDisplayRotation`（自动旋转的锁没锁只有
  `isRotationFrozen` 说得清，所以状态也在那边读）
- 读状态在宿主侧做：`settings` 里那几个键（`wifi_on` / `bluetooth_on` / `mobile_data` /
  `airplane_mode_on` / `zen_mode` / `low_power` / `ui_night_mode`）都公开可读，而 system_server 里
  借来的 Context 用 ContentResolver 必 NPE；读不到就**不切**（盲调会把开着的关掉）
- 热点没放进来：`cmd wifi start-softap` 必须现给 SSID 与密码（照它开等于把用户配好的热点名改掉），

### 收口：菜单与卡片的几处微调

- **浮层菜单超过一屏就滚动**：入口格菜单（十个开关）与「按键绑定」页 ⋮ 都传 `maxHeight = STEP_PICKER_MAX_HEIGHT`（320dp），与「添加命令」浮层同一档。不传时面板按内容长，会顶到屏幕外且滚不动（真机反馈）
- **菜单标题的裁切从 6 个汉字收到 5 个**（`MENU_TITLE_MAX_WIDTH` 由 12 格改 10 格）；英文仍按格数算，`English` 这类 7 字符不会被误截
  —— 这一条后来**又放回 6 个汉字**，见「浮层菜单的选中态改到行首」
- **按键菜单的分隔**：侧键与自定义按键之间是加深带（两组），清单与「添加 / 重命名 / 重置 / 删除」之间也是加深带；四行动作彼此用细线。中间那版「自定义按键」小标题已按用户口径撤掉
- **整页禁用时右下那颗 FAB 不再变透明**：它进的是「自定义命令」页（命令库不挂在某颗键上），灰着又拦点击比直接放着更难解释 —— 顺带删掉只服务它的 `disabledAlpha` 与那层透明吃事件层
- **单条命令的卡片封顶在正方形**：`CommandTileRow` 新增 `maxHeightRatio`（单条 `1f`，多条 / 混排不封顶），摘要在卡内三行封顶 + 省略号。先前一条长命令能把卡片撑到两三个正方形高，一列里只剩它一张

### 系统开关的执行分工（对上面第一节的更正）

- 第一节写的「`phone.setDataEnabled` / `power.setPowerMode`」那一版已经换掉，实际分工改成：
  · **移动数据 / 省电模式**：宿主有 `WRITE_SECURE_SETTINGS`，直接写 `Settings.Global.mobile_data` / `low_power` —— Phone 的 `DataEnabledSettings` 与 `PowerManagerService` 各有一个 ContentObserver 盯着，写键就等于替系统按了开关
  · **免打扰 / 手电筒**：不另写一套，复用已有的 `Action.Oplus`（宿主侧）与 `Action.Flashlight`（`FlashlightController`）
  · 其余（WLAN / 蓝牙 / 飞行模式 / NFC / 自动旋转 / 暗色）在 system_server 里按**dump 出来的签名**调服务：蓝牙 `disable(AttributionSource, boolean persist)` 的 `persist` 必须传 **true**（false 只是临时关，`bluetooth_on` 不变）；这块 ROM 的 `INfcAdapter` **没有 `isEnabled()`**，开关状态一律走 `getState()`（3 与 4 都算「开着」）；自动旋转没有可读的开关，只有 `isRotationFrozen()`
- 读写分工的实测依据见 `docs/device-findings.md` 第二十四节

### 命令失败原因多一档 `SHELL_NO_ROOT`，说清 root 该授给谁

- 新增失败原因 `SHELL_NO_ROOT`：「权限不够：root 要授给宿主 %1$s，不是本模块」—— 跑命令的是**宿主进程**（`com.oplus.gesture` / `:ui`），授权给模块自己的包名没有用；只说「这条命令要 root」对「我已经授权了」的人等于没说
- 为此 `CommandFailure` 的 `hint` 变成 `open val`，这一档覆写成带包名的 `I18n.format`

### 修「只有抬手、没有按下」：合成事件判据收窄

- 用户反馈「单独按侧键不触发，电源键 + 侧键才有时触发」。PLQ110 的日志给了答案：策略回调里一次按压的
  DOWN / UP **两条都带 `deviceId = -1`**，被 `isSynthetic` 当成我们自己注入的合成事件整条放行，
  只剩偶尔从另一条路径漏进来的 `UP 780`，走「孤立抬手补判单击」才偶尔触发一次
- 判据改成「`deviceId < 0` **且** keyCode 不在认领白名单里」——`KeyInjector` 只下发动作里的那几颗码，
  735 / 780 / 781 / 782 从不由我们自己注入，即便 -1 也是真按键（反过来的自持循环仍然挡着）
- 同时把「合成事件」那行从 `d` 提到 `w`：本次故障的唯一证据就是它，正式包里 `d` 会被编译期消灭
- 真机结论记进 `docs/device-findings.md` 第二十五节

### 导出日志改成三个进程合并

- 以前「导出日志」只导**本进程**（`:ui`）的缓冲：判据行散在 `system`（接管点、按键认领）与 `host`（收到手势、执行动作）里，用户交回来的日志常常一条按键行都没有 —— 上次排查「只有抬手」就是卡在这儿
- 新增一问多答：设置页发 `ACTION_LOG_PULL`，另外两个进程各自把 `XLog` 缓冲切片回 `ACTION_LOG_CHUNK`；设置页等 700ms，收齐后**按时间戳合并**成一节，每行前缀 `[system]` / `[host]` / `[ui]`
- 分片是必需的：一次广播塞几百 KB 会撞 binder 事务上限且静默失败。`LogWire` 按**行**切（单行超长才硬切），带序号与总数
- 三个落点：`inject/KeyHooks`（system_server 侧，post 到主线程再回包）与 `host/GestureReceiver`（宿主主进程）；收侧是新文件 `ui/hook/LogPull.kt`，导出本身挪到 IO 作用域，拼好再回主线程弹 SAF
- 合并成一节而不是按进程分节：排查看的是**时序**（按下 → 判定 → 转交 → 执行），分节之后最容易漏的正是「另一头压根没动」

### 分段控件的滑块改成跟手

- 横向滑动内容时，滑块不再「停稳后再弹过去」，而是按浮点页码**实时插值**，与页面同进同出；
  「按键绑定」的三手势页与「自定义命令」的单条 / 多条页同一套
- 位置取 `pagerState.currentPage + pagerState.currentPageOffsetFraction`。这是个连续量：
  拖过一半时前者已翻到下一页、后者恰好变成负数补回来，两段接得上，所以不会跳。
  符号由 Compose 自己那支 `offsetDistanceInPages` 定死 ——
  `(page - currentPage) - currentPageOffsetFraction`，正值表示「已朝下一页走了这么多」，
  即浮点位置对首页是**加**、不是减（反了滑块会倒着走）
- 滑块**不能**只喂整数 `selectedTabIndex` 让库自己弹过去：库内是阻尼比 1、`stiffness = 438.65`
  的临界阻尼弹簧（COUI `SpringForce(response = 0.3, bounce = 0)`），起步慢、落点还带余量 ——
  手指已滑过一格，滑块才走到一半。早先那版「跟手」就是因此撤掉的，读起来是
  「跟页面对不上拍」，不是位置算错
- 补丁 `patches/coui/0007-fractional-tab-position.patch` 给 `TabRow` / `TabRowWithContour` 加可选入参
  `selectedTabPosition: Float?`：非空时跳过位置与宽度两条弹簧，中心与宽度都按相邻两格插值，
  越界值夹到首尾（横向回弹到两端时滑块贴边，不跟着冲出控件）
- 标签的粗细与颜色仍按 `currentPage` 整页切（跨过中点才换），只有滑块是连续的
- 补丁库版本 `1.1.0-subtitle6` → `1.1.0-subtitle7`（`build-patched.sh`、`app/build.gradle.kts`、
  `app/gradle.lockfile` 同步）
- `patches/repo` 里只留 `subtitle7`：`subtitle4` / `subtitle5` / `subtitle6` 三份旧产物一并删掉
  （每份 2.4MB，合计 7.4MB）。`subtitle4` 唯一还能对上的是 lockfile 里那行
