# 手势判定层去业务化与外观菜单收口

## 改

### 改：`inject/input` 变成业务无关的判定层

- 判定状态机只吃自己定义的五个值对象：`Gesture`（替 `GestureTrigger`）、`KeyRef`（替 `KeyId`，身份用 `Any` 原样带、另给 `name` 供日志）、`ChainSpec`（替 `ClickChainParams`，15 位毫秒 / 布尔 / 次数，不含任何 `Action`）、`ComboBinding`（替 `ComboKey`，16 位：身份 / 名字 / 成员表 + 判据字段，另给 `starter` / `followers` / `matchesOrdered()`）、`DetectorWindows`（替 `ComboWindows`）—— 业务字段一改，判定层不再跟着编译不过；
- 动作「是什么」不进判定层、只进「有没有」：`clickThenLongRelease` / `longRelease` 两个 `Action` 换成两个存在位，「场景块松手」那一支折进存在位，判定层从此看不见 `sceneChainRelease`；
- 业务翻译收在 `inject/key/GestureBridge` 一处（`chainSpecOf` / `comboBindingOf` / `detectorWindowsOf` 往里翻，`keyIdOf` / `comboKeyOf` / `gestureOf` 往外翻），装配点 `SideKeyInterceptor` 在每个回调边界各翻一次；
- `MULTI_MIN_KEYS` / `HOLD_FOLLOWER_WINDOW_MS` / `MIN_REPEAT_INTERVAL_MS` 提成判定层自己的常量，不再向配置要兜底值；
- 探针用的 `ComboPlan` 也换成判定层自己的一份（`keys: Set<KeyRef>`，探针拿字符串 id 直接当身份，不绕 `KeyId`）；
- `ComboDetector` 压住 detekt 的 `LargeClass`（740 行有效代码 / 阈值 600）：那六七个数是**同一份**判定状态的几个视角，拆开就要把「谁在什么时候改它」一起搬，接口比实现还长 —— 理由写在类 KDoc，等真长出一块自洽子状态机再动手。

### 改：`core/judge` 的纯判据泛型化

- `poolWithinWindow` / `pressOrder` / `orderMatch` / `pickPairHit` 四处签名改成泛型 + 谓词，不再认识业务类型；两个测试跟着补谓词参数与显式类型实参；
- 「按顺序触发」的比对本体新收成 `matchesOrderedTail`，判定侧与业务侧都调它（见「修」里那条）。

### 改：`GestureForwarder` 从 `inject/input` 移到 `inject/wire`

- 它是跨进程广播派发器（发送线程、`bindService` 唤醒宿主、`ModuleWire` 载荷），不是判定逻辑 —— 新判据一立起来就抓到它引 `core.model`，移包后清零；各处注释与文档的路径指针（`Framework`、`GestureExec`、`SideKeyGestureHooks`、`docs/device/side-key.md`、`docs/architecture/structure.md`、`tools/audit-perf.py`）同步改指。

### 改：新增 `ui/kit` —— 业务无关的界面通用件

- 七件搬进去（3383 行、零 `core.model` 引用）：`ConfirmDialog` / `MenuPopup` / `PageMenuPopup` / `PageConfirmDialog` / `PageNameDialog` / `SectionTitle` / `ChipLabel`，弹窗外壳与按钮行等帮手随文件同迁；
- 边界按「它依赖谁」定：`PageSlider` / `CardRow` / `PageSheet` / `IconInput` / `EmphasisText` / `Dividers` 要业务行的参数类型，留在原地；
- `ui/row` 里「通用件认识某一行界面」的注释举例去掉（改说「一张行数会变少的卡」）。

### 改：`tools/audit-coupling.py` 新增两条架构判据

- `inject.input` 与 `ui.kit` 两个档位各禁引 `core.model`（翻译与业务行各有各的落点）；`bucket_of` 同步加档；实测 249 个 Kotlin 文件、41 条包级边、0 环、0 越界。

### 改：组合判定视图按配置快照缓存

- `bindingOf` 不再每次现造 `ComboBinding`：一次按压里 `pairFor` / `multiFor` / `absorb` 会问好几遍，每次都是 N 个字段对象 + 成员引用列表 + 每个成员一次线性查名；
- 缓存以 `ConfigChannel.config` 的**身份**为界：一次广播才换一份快照，换了就整表作废；
- 成员显示名的那次回查也跟着省掉（缓存里已经带上了）；
- 线程归属写进注释：问它的只有 `bindingsFor` / `widerFor` 两个回调（都在输入线程），主 looper 那几枪不碰；容器仍取 `ConcurrentHashMap`、快照引用带 `@Volatile` —— 将来哪条延时枪顺手问一次，最坏是多造一份（幂等），不会把表写坏。

### 改：`HeldPresses.hold` 改为返回「这一下压住了没有」

- 配了多击的键不压窗（见「修」里那条口径），这时返回 `false`，调用方**落到单键判定**而不是把 DOWN 吞掉 —— 吞掉就是「按下没反应」；
- 其余情况仍压窗、到点补发，返回 `true`；`SideKeyInterceptor` 那一支据此二选一。

### 改：「Monet 配色」挪进主题菜单底部

- 「外观」卡不再单摆这一行；主题菜单最底一行是它（文案去掉「使用」两字），用加深带与上面三档深浅隔开；
- 它在那层里是开关：点一下就地翻、菜单不关、打勾跟着当前状态；
- 主题行的行尾在开着时拼成「浅色 - Monet」，不点开也看得出两件事。

### 改：外观卡的四行收进手风琴「更多外观设置」

- 「随机图标配色」「减少界面图标」「界面振动反馈」「使用预测性返回手势」移到外观卡最底部，收在可展开表头下面（表头用齿轮加号字形，新键 `more.appearance_more`）；
- 「界面缩放」上移一位紧跟「强调色」—— 外观卡上面只剩「这一页长什么样、多大」。

### 改：「强调色」里那一档从「默认」改叫「系统默认」

- 文案只改一处：`more.palette_default` 中「默认」→「系统默认」、英「Default」→「System default」。行尾摘要、配色菜单那一行读的都是这一份（`PageCopy.paletteLabel`），所以两处一起变；
- 改名的理由：那一档的语义是**跟随系统取色**（换壁纸 / 换系统配色它跟着变，见 `PagePalette.DEFAULT` 与 `colorsOf`），叫「默认」容易被读成「模块自带的那个蓝」—— 而那个蓝是另一档「蓝色」（`blue`）。`id` 不动（仍是 `default`），配置文件、旧存档与 `PagePalette.ofId` 的兜底全都照旧。

### 改：「系统默认」与五套预设色之间加一条加深带

- `PaletteMenu` 里那一行置 `dividerBefore = true` → 渲染层出 `MenuPart.HeavyLine`（`AppHeavyDivider`，组与组之间那一档），不再与下面五套走同一条细线；

- 分组的理由：头一档说的是「跟系统走」（换壁纸 / 换系统配色它跟着变），后面五套是「自己挑一个色」—— 换的是类别不是行。

## 修

### 修：「单击后长按」松手那一档的两半判据在去业务化时丢了

- `ChainSpec.clickThenLongReleaseActionExists` 被翻成「松手开关开着 + 挑过动作」，把原先 `ownRelease || sceneChainRelease` 的两半都丢了：① 只在场景块里配了松手的配置，抬手那一档整条不派发；② 「主档设为无操作时不被松手动作顶替」那条主语守卫没了（`clickThenLongReleaseOn` 是存位，值关掉仍留着）；
- 现在与业务侧 `KeyConfig.clickThenLongReleaseAction` 同一套四位判据（含场景那一半与主语守卫）；`ChainSpec` 里没人读的 `clickThenLongActionExists` / `longReleaseOn` 两个字段一并删掉。

### 修：成员连击让位组合长按时看错了格子

- 判据从结构位 `hasLong`（= 非顺序档就有这一格）改回「这一档的长按真有事可做」：`ComboBinding` 新增 `longActionExists`（装配方取 `ComboKey.longActionExists`），让位与 `scheduleLong` 里的收手都看它；
- 不改的后果：只配了成员单击 / 双击、没给组合长按配动作时，成员连击照样被让掉、组合长按派发出去又没人执行 —— 按住到阈值后什么都不发生。

### 修：判定日志里的成员键退化成 id 字面量

- `bindingOf` 补上 `nameOf`（按 id 查显示名）：`ComboBinding` 的成员日志回到「电源键 / 自己起的名字」，不再是 `plus` / `ck1`。查不到（那颗键刚删、组合没跟着更新）仍退回字面量。

### 修：一条有序判据两份实现，单测喂的是没人用的那份

- 「按顺序触发比结尾」原先在 `ComboKey.matchesOrdered` 与 `ComboBinding.matchesOrdered` 各写一遍，线上跑的是后者、`JudgeMathTest` 测的是前者；判据本体收进 `core/judge` 的 `matchesOrderedTail`，两边都调它。

### 修：判定层与配置层的连发间隔下限各写一个数

- 判定层那份取 30、配置层 `KeyConfig.MIN_REPEAT_INTERVAL_MS` 取 50：`GestureDetector.scheduleRepeat` 与 `ComboDetector.scheduleRepeat` 两个读者拿到的值都被配置层先钳到 50 以上，那一道夹制**永远夹不到东西**；而注释还写着「不指望配置那层夹过」，把分层说反了；
- 判定层改取 50，注释按真实分层重写（配置层是权威、盘与广播两条通道都在那儿收口，判定层这一份是**自保**：那一层不吃 `core.model`，引不到那个常量）；`KeyConfig` 那边补一句「另有一份同值副本，改这个数要两处一起改」，免得单边改动后静默顶掉用户配到下限以下的值。

### 修：回调抛异常时清一次判定状态机

- `KeyHooks.onIntercept` 的 catch 里补 `resetJudgement()`（只清判定侧：`detector` / 压窗账 / 组合状态机）；`keyIdOf` 抛错时 `onDown` 可能只写了一半，不清掉下一次按压会带着旧状态判、而且一声不响；
- 注释写明**影响面是所有键**：`reset(null)` / `drop(null)` 会把别的键正在等的连击窗口一起摘掉 —— 异常之后那一瞬可能少判一次（退回系统原生行为），但不会错判成别的动作。

### 修：多击与组合抢同一段时间的口径写进文档

- `HeldPresses` 不压窗那一条写明代价：连击窗口 < 组合窗口时「单击 + 组合」两个动作都执行，且这组合用户配得出来（两处上限都能到 800ms）；`docs/runtime/key-to-gesture.md` 新增同名小节（含对照表与「为什么不用 `min` 去压」）；
- `README.md` 的「已知限制」跟一句用户口径的说法（原来只有「自动亮度」那一条）。

### 修：`decoupling.md` 多一个代码围栏，把「一、判据」整节吞进代码块

- 删掉那一行误开围栏的三反引号（紧跟 `ui/kit` 边界那一段之后）；同时把基线表里的边数 42 改回实测 41，并补上 `31 → 41` 这一跳的来历（`inject.input` / `inject.wire` / `ui.kit` 拆档后的记账，不是新增耦合）。

### 修：两处过时的注释说「默认档是 COUI 那套蓝」

- `GlobalConfig.DEFAULT_PALETTE` 的 KDoc 还写着「COUI 自己那套蓝」——那是 2026-11-02 拆档之前的事，现在那一档跟着系统走、蓝另立一档 `blue`；`PagePalette.PALETTE_DEFAULT_SEED` 的注释同理（它现在是 `BLUE` 的种子兼「系统取色三级都取不到」的兜底，不是「默认档的种子」）；
- 只有注释在动，没有行为变化。

### 修：公共页那颗「成员连击共用窗口」的判据算了没人看

- 公共页把「这一档开没开成员连击」平移成 `cfg.combos.any { it.memberGestures?.isOn == true }`，而唯一读者带着「标签不是 `INTERVAL_MULTI` 才显示」那道闸 —— 公共页的标签偏偏就是 `INTERVAL_MULTI`，那行副标题永远不显示，算出来的布尔是死输入；
- 那句话本身也不成立：`memberGestures` 只在两键按住档上非空，而那一档这一格**只**服务成员连击（「成员之间接收」要三颗起），开关已经叫「多击固定窗口起点」——「成员连击的单击窗口也用它」是同义反复；三颗以上那一档读的是成员间隔，与连击无关；
- 于是整套删掉：`ComboParamSource.memberWindowShare`、两处构造点的赋值、读者那一支、字典里 `combo.member_window_share` 与它生成的常量；「这一档用不用得到那两行」的置灰判据（`holdWindowLive`）照旧。

### 修：公共「按住组合」那两行不再按现有档位置灰

- 公共页的「固定窗口起点」与「等待窗口」恒可拨：`ComboParamSource.holdWindowLive` 默认 `true`，这条判据只留给独立设置那一份（那一档自己用不到时才灰）；
- 原来公共那份按「配置里存不存在用得到这两格的按住档」推空转，两处都推不住：公共值是「没单独设过的组」与还没建出来的那一档的默认值，要先把档建出来才让调默认值是倒过来；而独立设置开着时那两格回落走的是出厂默认、不是公共，公共压根不在读；
- 禁用时那句「未开启多击手势」说的是别的档的开关，摆在公共页也当不了理由。
