### 「自定义命令」页首次进入弹风险提示

- 首次进「自定义命令」页弹一份**独立**的风险提示（正文按 markdown 渲染、关键句加粗）：
  「自定义命令是**高度危险**的功能。本模块**不会对你输入的命令做任何检验或保护**，
  请自行确认命令安全并承担相应后果。」—— **不复用**首页那份免责声明的文字
- **不接受就退出这一页**（`goBack()`）；接受则记下这一笔
- 与首页那份免责声明**分开记**（新增 `Config.commandDisclaimerAccepted`，编解码键同名）：
  两者说的不是一件事（那一份讲「注入系统进程」，这一份讲「不做任何检验或保护」），
  在首页确认过不等于知道后者
- 导出／导入一律把这一位归零（与 `disclaimerAccepted` 同一口径）⇒ 清空配置后要重新确认
- 新增字典键 `dialog.command_disclaimer_title` / `dialog.command_disclaimer_content`（中英各一份）
- 新增 `acceptCommandDisclaimer()`（只记这一笔，不碰主开关）
- 配置只读时不弹：那时写盘会被拒，弹了也记不下

### 数据一致性（命令库 / 配置）

- `ActionCatalog.Spec.label`：**自定义命令的名字不再拿去查内置字典** —— 用户把命令叫「截图」「录音」
  时，网格与菜单里会显示成内置动作的译文（切英文更明显）。判据是 `commandKind`：非空即用户那条
- `saveCommands` 的返回值从 `Boolean` 换成三态 `CommandsSave`（`Ok` / `BroadcastFailed` / `Failed`）：
  原来 `publishConfig` 的结果被丢掉 —— 命令库改完没广播出去时界面一声不响，而注入侧还是旧指纹
  （页面随后判「未同步」整页变灰，用户看不出原因）
- `saveCommands`：落盘抛异常也走同一条回滚（原来状态已改成新表、文件没写，界面显示改了、文件没改）
- `saveCommands`：命令库只读态拒写，并明说「未保存」（新增 `toast.commands_read_failed`）
- 改名保存：绑定没挪成时把**命令库回滚**成改名前的样子。原来库里是新名、手势上还绑着 `cmd:旧名`
  —— 那只手按下去就是「这条命令已经不在了」，而用户看到的是「已修改」
- 删除命令：按三态分别处置（`BroadcastFailed` 时不再叠一句「已删除」，`Failed` 时才回滚绑定）
- `CommandLibrary.loadState()`：命令库补上**「读不懂」这一态**（外皮解不开 / 被截断 / 正文不是 JSON），
  页面新增 `commandsReadOnly`。原来一律退化成空表，之后任何一次保存都把它写回盘 —— 用户的命令静默丢失
- `resetAll`：写盘失败时**还原**只读位。原来先清掉就不管了，之后任何一次普通写入都会以那份默认值落盘
- `ConfigCodec`：`language` 改走 `textOf`（手写 `"language": null` 不再得到字符串 `"null"` 被当成有效值）
- `CommandScreen.testCommand`：补异常兜底（页面动作绝不外抛）

### 修：几个会真出错的地方

- `AppEntry`：`app:pkg/.Activity` 不再被拼成 `pkg..Activity`（点开头的类名要直接接在包名后面）
- `RingerController`：内部通道写完**用内部通道回读**。免打扰开启时公共 `am.ringerMode` 恒读静音，
  拿它回读会把 `rememberedMode` 记错 —— 免打扰期间循环从错档起步（真机反馈过「切不动」）
- `GestureDetector`：双击窗口那一枪也**存进 `Pending`** 并带上 `pressAt` 身份判据（与长按枪同一条），
  `reset()` 能摘掉它。迟到的旧窗口原来会读到后来那次按压的标志、抢先补一次单击并清标志 ⇒ 后一次单击丢了
- `ShellRunner`：读输出的流 `use` 关闭；`waitFor` 抛异常那条出口补 `onFailure`（原来进程杀了、用户毫无反馈）
- `AppLauncher`：界面与广播两条路都失败时报一句「没执行成功」；小布快捷指令查不到接收者时留一条判据日志
  （`sendBroadcast` 不抛异常，原来那条 `sent == 0` 永远走不到）
- `ProbeChannel` / `FlexibleWindowBridge`：自己建的 `SurfaceControl.Transaction` 在提前 return 的出口上关掉
  （交给框架那一份不关 —— 所有权已经转移）
- `BackInterception`：不再需要自己接返回时**无条件注销**。原来静态引用指着旧 Activity 实例时两个分支
  都不成立，旧实例上的回调与那份引用就永远留着（钉住已销毁的 Activity）
- `Reflect`：负命中带 30 秒重试窗口。原来「查不到」永久缓存 —— 挂点太早 / loader 还没就绪时，
  那个注入点会一直失效到重启
- `I18n`：读失败的字典**不记账**。原来失败也把文件名记下，同语言下再 reload 会被短路 ⇒
  坏一次就一直空白，只有换语言才重试（本会话新写的代码）
- `ConfigTransfer`：导出日志不再弹「已导出配置」—— 新增 `ExportKind` 分开请求码 / 日志前缀 / 成功与失败文案
  （补 `toast.log_export_failed`，`toast.log_exported` 原来定义了没人用）
- `MenuPopup`：标题截断按**码点**前进（标题里有 emoji 且正好截在它中间时，原来会切出半个代理字符）
- `PageHeader`：顶栏底色改成**按比例缩 alpha**，与 `PageConst.FROSTED_SURFACE_ALPHA` 那条纪律对齐
  （原来 `copy(alpha = …)` 整个换，深色板里半透明的同名色会被顶成亮色）
- `IconInput`：组合期不再写状态（挪到副作用）
- `AppPicker`：搜索空态里的过滤词走 `escapeMarkdown`（与同页另一条空态同一纪律）；图标位图的 key 带上
  密度算出的大小（原来密度一变还是老尺寸的位图，发虚）
- `FileObfuscation`：打包时遇到 Base64 字母表外的字符不再静默丢（记一条 `w` 并原样保留 ——
  丢了会让解包那边只能看到「解不开」）
- `ActionCatalog.groupTitleLabel`：分组标题的译文收成一处（网格与「添加命令」浮层共用）——
  两处各写一遍时，新增分组只会漏一边，而 `else` 分支静默显示中文
- `ConfigCodec` 的 `md5` 说明改对：**键序会进 md5**（原来写着「键序弄乱也认」，与实现相反）

### 界面与导入导出：三处收尾

- `BindingScreen`：自定义命令那组格子改成按 `key(spec.token)` 认身份（与内置那组同一写法）
  —— 那一段是按**位次**排出来的，删一条 / 改名重排之后，格子里的状态（焦点圈、进出场）会跟着
  位次挪到下一条命令身上
- `AppPicker`：图标缓存不再用全局版本号通知「某一行取到了图」—— 一屏十来行依次到位就是十来次
  全表重组，而别的行除了重跑一遍查表什么也没得到。取回来的图改存**这一行自己的状态**，版本号只留
  「清缓存」那一档。顺带：视口里的行不再因为别的行补图 / 缓存淘汰而退回通用字形
- `ConfigTransfer`：导入的整份读 + 解析、导出的整份写都挪到 IO 上 —— 这一族从宿主的
  `onActivityResult` 回调里发起（宿主主线程），而 SAF 的 uri 可能落在云盘 provider 上，读写没有上界；
  结果回主线程再报。**落盘那两步仍在主线程**：它们写的是自己的小文件，与别处每一次写盘同一条路

### P1 核实后的注入侧修复

- `Framework`：同一个类上同时命中 `PM_EXT_ENTRIES` 那两个名字时做**同层互斥**（只留靠前的那个，
  被丢弃的打 W）—— 两个都装会把一次按压喂判定器两遍（双击被吃成两次单击、长按枪反复作废）。
  `AMS_BROADCAST_ENTRIES` 的多重载照旧**个个都装**（漏一个就等于收不到配置广播）；去重口径的注释
  改成实情（按 owner + Method 对象 + kind）
- `SideKeyInterceptor` / `ConfigChannel` / `KeyHooks`：主开关**翻到「不接管」那一刻**撤销已排下的
  长按枪 / 双击窗 / 连发任务。原来只在拦截点那条 early return 里判开关，而按住不放时没有新按键
  事件走进来 ⇒ 连发任务会一路派发到 30s 上限
- `KeyHooks`：状态栏 / 小窗 / 探针三条指令的执行挪到主线程（原来在 AMS 广播入口那条 binder 线程上
  同步跑反射与 binder 往返）；来源校验与 `chain.proceed()` 留在原线程
- `ProbeChannel`：`call` 加准入闸 —— 要显式 opt-in（extra `unsafe=true`）**且** `cls` 命中前缀白名单
  才执行，其余打 W 判据行拒绝（`invoke` 会触发宿主类 `<clinit>`，正是开机循环那条红线）
- `FlexibleWindowBridge`：两处「已预置 / 已喂」改成成功才打（原来不判 `invoke` 的结果，失败也照打）；
  两处早退补日志（写清缺的是哪一项）；`switchState` 失败时把写进去的假字段写回原值
- `SystemContext`：「缓存那份 Context 真正可用」的注释改成分层口径（`ContentResolver` 在
  system_server 里必 NPE，与拿的是哪一份无关）

### P2 剩下的那批：安全、缓存、死代码

- **日志脱敏**：命令正文不再整条进日志 —— `shell:` / `intent:` 两族的正文换成「长度 + 指纹」，其余判据
  token（`keyevent:` / `app:` / `cmd:` …）照旧可见。带 token 的命令从此不进 logcat，也不进「导出日志」
  那份文件。`ShellRunner` 的子进程输出**仍原样打**：那是排查「命令为什么失败」的唯一凭据
- **导入配置**：加了 1 MiB 体积上限（读之前先按 provider 报的字节数挡，拿不到大小就照读，不为判上限先
  全量读一遍），并把来源文件名 / 字节数打进判据行；`Activity#onActivityResult` 那个 hook 补上按实例过滤
  —— 同进程里别的 Activity 撞上我们的请求码时，它那一次回调原样放行（原来会被静默吞掉）
- **`ShellRunner` 收尾**：杀进程改成杀**整棵进程树**（`ProcessHandle.descendants()`）。`sh -c "…&"` 留下的
  孙进程会一直握着管道，读线程拿不到 EOF ⇒ 每次超时/异常都泄一个读线程 + 一对 fd，且无上限累积
- **命令库的缓存改成文件指纹**（原按「距上次读没满 1 秒」），与主配置同口径 ⇒ 改完命令库立刻按键不再
  执行上一版
- **`ConfigStore`**：宿主目录按**当前用户**拼（原来写死 `/data/user_de/0`，副用户 / 工作资料读不到自己的
  配置）；临时名带 pid + 时间戳；缓存指纹并进 **inode**（写盘走 tmp + rename，inode 必变，堵住「同长度
    - 同一个 mtime 粒度」的漏命中）
- **注入侧四处（待真机验证）**：`Reflect` 三处 `isAccessible = true` 收进 `runCatching`（原来会从 hooker
  体外抛）；`SystemContext` 降级品那条 W 改成每进程一条（原来按手势次数刷屏）；`GestureForwarder` 唤醒
  失败首次打 W（原来只有 `d`，release 里整档消失 ⇒ 手势静默丢失无痕）；`ConfigChannel` 只在广播**带**
  `enabled` 时才改主开关（缺项的畸形广播原来会把它静默关掉，还会误触发撤销回调）
- **界面**：动作网格的可用性与 `pick` 同一判据（原来「亮着、点了被拦」；按键设置那张卡**故意**少判一道
  —— 它写的是参数，不需要注入侧回话）、滚动即收入口浮层、主开关关掉时 pager 不再能横滑；「添加命令」
  补步数上限兜底；步骤行的 `exiting` 改成 state（原来靠「同帧写过 targetState」顺带重组，是巧合）；
  「已保存的命令」格子按 `key(cmd.name)` 认身份；图标表 `getValue` 改 `getOrElse`（漏项不再在宿主组合期
  崩）；`hazeStatesByPage` 挪进 `DisposableEffect` 并在 `onDispose` 摘除
- **`AppLauncher`（待真机验证）**：action 起法失败后按「`service` 像不像类名」退一次显式组件；
  `intent:` 的广播回落把这个事实写进日志（没带包名，只可能命中动态注册者）
- **死代码**：`Strings.kt` 里 64 个无人引用的常量与两份字典里各 63 行死文案一并删掉（键集合仍逐条对齐，
  236 / 236）；`AppLanguage.label`、`SideKeyGestureHooks.hookCount`、`tools/dexdump.py` 里 `fail()` 之后
  那句 `return` 一并删掉；`HostChrome` 那处裸 `findViewById(ID_APPBAR)` 收口到 `findAppbar`
- **注释与事实对齐**：`MarkdownBody` 的转义集补上 `<`（原来有 `>` 没有 `<`，`a<b` / `<b>` 这种名字会
  被 markdown 当成标签吞掉）、`Haptics` 的 `LocalView` 读者清单、`TextMetrics` 区间注释整体错位一格、
  `IconInput` 冗余的 `maxLines`

  `init { reload() }` 之后**，而 Kotlin 按声明顺序跑属性初始化与 `init` 块 ⇒ `<clinit>` 里
  `reload()` 执行时该字段还是 `null`，`loadJson` 解析成功后 `loadAttempts.set(0)` 抛 NPE，
  被自己的 `catch` 当成「解析失败」
- 后果：**每个进程的第一次取文案都白跑一趟**（结果不错，靠 `dict()` 的重试兜回来）——
  所以界面层一直没暴露，宿主侧也只是首次提示晚一拍。与「去掉中文兜底才看得见」同一类隐藏缺陷
- 修：把 `loadAttempts` / `MAX_LOAD_ATTEMPTS` 移到 `init` **之前**，并在 KDoc 里写明这条约束
- 顺带自查：全仓只有两处 `init {}`，另一处（`ui/state/FallbackOwners`）两个字段都声明在前面，顺序是对的

### 适配清单没有加 OnePlus 12（拿它验的是版本锁）

- 实测一台 ColorOS 16 机器（2026-10-16，`getprop` 原样）：`ro.product.model=PJD110`、
  `ro.vendor.oplus.market.enname=OnePlus 12`、`ro.build.version.release=16`、
  `ro.build.display.id=PJD110_16.0.10.501(CN01)`、`ro.build.version.oplusrom=V16.1.0`
  ⇒ 按 [romSeriesOf] 取出来的系列串是 `16.0.10`（构建号 `501` 按设计丢掉）
- **它不进清单**：这台是**三段式按键、没有侧键**，而模块的核心就是接管那条侧键 ——
  清单里放的是「这台机器上模块能用、接管点验过」，不是「装得上」。拿它验的是**版本锁那三档**
  与下面这条口径，与「能不能用」是两件事（这条理由写进了 `ADAPTED` 的注释，免得以后又被加回去）
- 顺带修一处**会让人永远命不中**的口径：`Adapted.rom` 原来的注释说它等于
  `ro.build.version.oplusrom` 去掉 `V`，而两者只在 PLK110 上碰巧一致（`V17.0.0` ↔ `17.0.0`）；
  PJD110 上是 `V16.1.0` ↔ `16.0.10`，并不等价。注释改成按 [romSeriesOf] 那一串写
  （[check] 收到的就是它），并写明「别照抄 `oplusrom`」
- `Adapted` 的 `android` + `rom` 改成**数组**（新 `SystemVersion`）：一台机器一行，
  多验一版 ROM 就在那一行的 `systems` 里加一项 —— 原来一台机器两版系统要写两行，
  机型名与那一段注释都得抄一遍
- 判定口径不变：本机那一组与 `systems` 里**任意一项**相同即 ADAPTED，一项都不中才是 PENDING，
  机型不在表里仍是 UNSUPPORTED
- 「一加 15 / Android 16」那一项仍是**猜的**（`16.0.0`，注释里写明了）：这次在另一台 ColorOS 16 上
  量到的是 `16.0.10`，说明那个猜法至少已经错过一次；要支持就量一次那台机器的 display 串
- 取证：两个变体编译绿；镜子按真机原样串再跑一遍 —— PJD110 在 release 下判 UNSUPPORTED
  （debug 侧因为不做那道闸仍是 ADAPTED，这也正好是「拿它验功能」的前提），见上一节那张表

### 「锁住的命令」在网格与「添加命令」里置灰

- 新增一条判据 `ui/model/ActionCatalog.isLocked`：**本机 ROM 没有这条命令的落点**时按下去什么
  都不会发生（执行侧记一行 `w` 后跳过）⇒ 网格格子与「添加命令」的选择行都**置灰、不吃点击**
- 判据与执行侧**同一个**（`RomProfile.hasLanding` = 原来的 `builtIn()` 非空）：那一族的落点表按
  ROM 系列分档，本机那一档没有、而本包又不猜时才锁 —— 「灰着的正是不会发生的事」
- 落在这一档的是四条：「一键闪记 / 免打扰 / 录音」（`oplus:` 族）与「小布识屏」（清单里写作
  KSU 那条 shell 别名，执行侧实际走 `AppLauncher.startSidebar` → 同一个落点表）
- 网格里的格子与「添加命令」的行用同一个判据；**确认键**那条路也拦（它由页面自己派发、
  不吃格子的 `Card` 回调，不拦就会绕过置灰写进配置）

- 小窗 / 电源菜单 / 通知与控制中心那几族走的是猜的反射面（`RomProfile.effective`），
