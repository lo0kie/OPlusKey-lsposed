# 配置与按键停用

> 本批合并了两个片段（原 `2026-10-26-配置行编号与重命名.md` 与 `2026-10-27-按键与场景停用.md`）——
> 它们同属一次提交。

### 改：「重命名配置」缩成「重命名」

- 菜单那一行与命名窗的标题都只写「重命名」：它和「新建配置」「删除配置」挤在同一层菜单底部，
  上半截就是配置列表，「重命名的是配置」不言自明；「重命名配置」还跟「新建配置」只差一个字，
  一眼扫过去像同一件事的两半；
- 文案键 `profile.rename` 跟着改（zh-CN「重命名」/ en「Rename」），兜底串两处一起改 ——
  菜单行与窗标题读的是同一个键，不会再出现一处长一处短。

### 新：配置行首的数字牌面

- 「切换配置」与「导出配置」两处菜单共用的行表（`profileRows`）按**第几份**取图标：
  `number-1` / `number-2` / `number-3`，与首页「按键」卡里那几颗自定义键、组合键列表里的「第几组」
  同一支笔（`PageIcons.menuKeyNumber`）；
- 编号只数**自定义**的那几份，「默认」不参与 —— 它仍用「一叠纸」（`PageIcons.Profiles`）：
  它是升级时落在原位置上的退路，不是用户建的第 N 份配置，给它编个号反而像「第 0 份」；
- 数字跟着**列表位置**走（与列表同一份 `ConfigProfiles.list()`，排序不变），删掉中间一条之后
  后面的各自前移一位，与屏幕上看到的顺序一致；
- 上限三份（`MAX_PROFILES`），`menuKeyNumber` 认到 5，越界不可能发生。
- **「导出配置」那层不打勾**（用户口径：单纯列出来就行）：打勾的语义是「现在生效的是这一份」，
  而导出与「当前」无关 —— 点哪份导哪份。行表加一位 `markCurrent`：切换那层给 `true`
  （顺带把当前那行滚进视窗），导出那层给 `false`，一行勾都不画。

### 改：新建配置的默认名字从「配置 1」起

- 命名窗的起点原来数的是「现在一共有几份」—— 而列表里永远有一行「默认」，于是第一份新建出来
  预填的是「配置 2」，看着像丢了一份；
- 改成只数**自定义**份数（`ConfigProfiles.list().count { !it.isDefault }`）：第一份新建出来
  就是「配置 1」，之后依次 2、3；
- 补正上一份片段（`2026-10-25-截图改由注入侧代注入.md`）里「把当前配置复制成新的一份」一句：
  现在建的是**空白配置** —— 绑定全回默认、命令库空，但属于本机的那几项跟着带过来
  （总闸 / 语言 / 配色 / 振动 / 判定参数 /「已确认免责协议」）。新建是「另起一套要配的东西」，
  不是「拿现在这套改改」。

### 新：组合按键可以停用（停用前要确认）

- 「组合键编辑」页 ⋮ 多一行「停用组合按键 / 启用组合按键」（锁 / 开锁两颗图标，随状态换），
  写的是这一档自己的 `ComboKey.enabled` —— 与模块总闸是两层，与「按键绑定」页那三行
  （停用启用 / 重命名 / 删除）同一套顺序与口径：停用在前、删除压最下面；
- 点「停用」先弹确认（「X 将不再触发。」），确认才写；**启用不弹**（那是把它开回来，
  没有可失去的东西）；
- 判定侧本来就认这一位（`ComboKey.isUsable`）：停用之后 `Config.comboFor` 不认这一档，
  两颗键各按自己的绑定照常执行；「参与组合的键要先等一个窗口」也随之消失（`joinsCombo` 同一条判据）；
- **列表里的说法与按键列表一致**：副标题两档都写一句「已启用」/「已停用」（共用
  `binding.key_*_state` 那一对文案），行首的数字牌面在停用时换成禁用图标（与按键列表同一颗）。
  成员被删掉的那一档（本来就废了）同样是禁用图标；
- 停用那一档的编辑页跟着收：顶栏那行小标题旁边挂一枚禁用标记并压暗（与「按键绑定」页同一枚、
  同一档压暗），短按 / 长按那条分段控件灰掉、网格与设置卡都改不动 —— 要改先在 ⋮ 里启用；
  ⋮ 里「条件执行」也灰掉，点一下说「%s 已停用，可在菜单里启用它」（组合名自带括号，
  所以另起一句，不套两层引号）；
- 已经停用的那一档，回执是「已停用 %s」（`%s` 是带括号的成员名）；值没变就不落盘、也不报。

### 改：停用按键要先问一句

- 「按键绑定」页 ⋮ 菜单里的「停用按键」不再一点就生效：先弹一句确认
  「「X」上的绑定将不再生效。」，确认才写盘；
- 为什么非要拦一下：这一行和下面那行「删除按键」**只差一个字**，后果却是两种 ——
  一个是「暂时不接管、东西都还在」，一个是「从清单里没了」。不确认就很容易点错；
- **启用不弹**：那是把它开回来，没有可失去的东西，弹一句只会多一次点击。

### 新：系统场景也能停用

- 入口在每条场景**右上角那颗「更多」菜单**里，紧跟在「添加场景」下面（用户口径：
  它也是「这一行现在怎么样」，与「再加一条」同类）；下面一条加深带之后才是「上移 / 下移」，
  再一条之后是「删除」。文案与图标随状态换（锁 / 开锁）；
- 点「停用场景」先弹确认（「这条场景将不再生效。」）；「启用场景」不弹，点一下直接改；
- 写的是这条自己的 `StateRule.enabled` —— **条件与动作都留着**，只让它这一趟不生效。
  判定侧只在 `StateRule.appliesTo` 一处读这一位，所以按键与组合键两条路同时生效，
  别处不需要再判一次；
- 停用的那条在**条件行行尾**标一句「已停用」（弱色）。它与「不会执行」占同一个位置：
  两条同时成立时说「已停用」—— 那是用户刚做过的动作，也是更直接的原因；
- 「死分支」那套扫描**跳过停用的行**：它既不替任何一档取值凑数（否则后面的行会被误判成死的），
  也不会被谁「盖住」（它的不生效是自己关着，与顺序无关）；
- 改的是**草稿**：这一页所有改动都等右下角那颗「确认」才落盘，停用也一样 —— 与页内
  其它操作（换条件 / 换动作 / 上移下移）同一个规矩，不单独走一条立即写入的路；
- 配置版本 **17 → 18**（`StateRuleDto` 多了 `enabled`）。老文件没有这一格 ⇒ 读回来是
  「启用」，行为与升级前完全一致，**不需要迁移**；老版本的读方遇到 `enabled: false` 会按
  启用处理（那条照旧生效），这一档只在「读方已经换成本版、写方还是旧版」时出现，不值得为它加版本闸。

### 新：小标题自己包一层（`ui/SectionTitle.kt`）

- 库那个 `SmallTitle` 只能给一串字：要它**可点**、要在行尾挂一颗按钮，每个调用点都得自己套
  `Row` / `Box`（全项目三十来处直接 import 库组件，形状迟早走形）。现在有了一份自己的
  `SectionTitle`：文字与内边距仍是库那一份（不重画样式），补的只有三件事 ——
  **可点**（`menu`）、**文字末尾那颗会转的箭头**、**行尾那一格**（`trailing`）；
- 两样都不给时它就是把库组件原样透传（纯标题的调用点换过去是零行为变化）；
- **全项目 29 处小标题已全部换过去**（11 个文件：首页 / 更多选项 / 按键绑定 / 组合键两页 /
  命令页 / 命令菜单 / 条件执行 / 选择应用 / 通用设置），代码里不再有直接调库 `SmallTitle` 的地方；
- 用上这几样能力的只有两处：**组合按键列表**（`menu` 打开筛选菜单）与**系统场景块**
  （`trailing` 挂行尾那颗「更多」，不再是调用点自己套的 `Row` + `weight`）；
- 带菜单那一档的点击区收过两轮，最后落在：**文字 + 箭头 + 左右 12dp / 上下 2dp**，
  页面缩进（16 / 32dp）与行高余量都留在点击区**外面**。踩过的两个坑记在这里：
  · 缩进和行高余量包进可点区 ⇒ 「点标题左边一大片空白、点上下一整行也弹菜单」；
  · `padding` 写在 `clickable` **外面** ⇒ padding 只留白、不参与命中，怎么调点击区都不变
    （链式顺序必须是 `clip` → `clickable` → `padding`）。
- 箭头紧贴文字（文字右侧那层内边距去掉再画箭头），`chevron-down` 16dp，菜单开合转 180°；
  文字整体下移 1dp 作光学修正 —— 汉字在行盒里重心偏上，几何居中时看着「浮起来一档」。

### 新：组合按键列表可以按按键筛选

- 「组合按键列表」那条小标题**可点**：点它弹一层菜单，第一行是「全部」，往下是**出现在组合里**
  的每一颗键（侧键 + 自定义键，行首图标与首页「按键列表」同一套）。**单选**，打勾的是当前那一档；
- **顺序也按首页那一套**（侧键在前、自定义键按收集顺序）—— 直接取 `combos.flatMap { it.keys }
  .distinct()` 是「组合表里第一次出现的次序」，真机上就是「侧键 / 1 / 3 / 2」这种看不懂的序；
- 选一颗键 ⇒ 这张表只剩含这颗键的组合（两颗键里只要有一颗是它就算）。行首的「第几组」仍按
  **全部组合里的位置**算，不会因为筛过就重编号；
- 筛着的时候标题后面接着写「- 键名」（`组合按键列表 - 侧键`）—— 不写的话，从别处回到这一页
  只会看到一张短了的表，第一反应是「组合丢了」；
- 只列**被某组用到**的键：一颗谁都还没用上的键，选了只会得到一张空表；
- 那个键后来不再出现在任何组合里（组合被删 / 键被删）⇒ 自动退回「全部」，不会留一张空表；
- 筛选**不落盘**：它是「这一趟想找哪一组」，不是配置的一部分（`ComboEditState.filterKey`）。

### 改：各页底部留白统一成首页那一档（32dp），不再为 FAB 抬高

- 条件执行页（那颗「确认」）与自定义命令页（那颗「排序」）原来在有 FAB 时多让一档
  （`FAB_BOTTOM_CLEARANCE` = 128dp），于是翻页时底部那段空白忽高忽低；现在一律
  `PAGE_BOTTOM_PADDING`（32dp），常量 `FAB_BOTTOM_CLEARANCE` 一并删掉；
- 组合按键列表原先**没有**底部留白（最后一张卡贴着屏幕下沿），补上同一档；
- 空态居中那一档跟着改（条件执行页用 32dp 算可见高度，不再是 128dp）。

### 改：组合键列表与通用设置的 header 允许折叠

- 这两页原先在 `pageScrollBehavior` 的「钉住标题」名单里（理由：短内容页，折起来会显得空）。
  两页的 `nestedScroll` 其实早就接好了，只是被名单钉住；现在移除，跟其它页一样随滚动折叠；
- 名单里只剩「首页 / 关于模块 / 捐赠列表」三页真正短的内容页。

### 修：交错按三颗键时，该出的组合不再落空

- 配对原来只拿「窗口内**任意一颗**」配一次（`recent.entries.firstOrNull`，而 `ConcurrentHashMap`
  的迭代序是散列序、不确定）：A → C → B 交错按、只有 A+B 配了组合时，B 有可能先配到 C，
  一配不上就整个落回单击 —— **A+B 这一档直接落空**，三颗各判各的；
- 改成把窗口内的候选全过一遍，**配不上的候选不占位**；都配得上时按**按下时刻由近到远**取
  （最近按下的那颗与当前这一下最像同一次组合），日志里的「间隔」跟着取这一颗的按下时刻；
- 三颗键同时按着仍然只出**先凑成的那一组**（组合进行中再来的按键整条吞掉，这是原设计）。

### 修：先后按两颗组合键，只该出组合，不再两颗键各来一次

- 组合的配对判据只是「两颗键的 DOWN 相差不超过窗口」，**不要求两颗同时按着**；而单键那一侧
  早先一抬手就把压着的那一按补进判定器 —— 于是「按 A、松手、紧接着按 B」这条路上，
  A 的单击先跑掉（还要再等一个双击窗口才派发），B 到时组合又成立，一次按键冒出三下动作；
- 现在抬手只记一笔「松了」，**等满窗口**再连着 DOWN+UP 一起补给单键判定器；这期间组合要是
  成立，压着的那一枪直接被摘掉 —— **组合的等待压过单键的单击**；
- 配对那张表与「还按着」那张表分开（`ComboDetector.recent` / `down`）：松过手的键仍参与配对
  （顺序按下也算这一档组合），而「一起按住才算长按」仍只认还按着的那几颗；
- 顺手结掉两笔旧账：组合进行中按下第三颗键，它那条抬手会被当成「孤立抬手」补判一次单击
  （现在整按吞掉）；早松开的那颗不再记进「待吞抬手」的名单里 —— 留着的话，下一次正常按它时
  那条 UP 会被吞掉，表现是「这颗键偶尔按了没反应」；
- 同一颗键快速连按两下不会丢第一下：新的 DOWN 到来时，压着的那一按先补发再换新的
  （否则第二下会把还在窗口里的第一下顶掉）；
- 代价：参与组合的键，一次快速单击最多晚一个窗口（出厂 80ms）才有结果 —— 这个窗口就是
  「组合按键设置」里那一行，它的子标题早就写着「会导致额外的等待」。

### 修：菜单装得下时「按住滑到禁用行再松手」会弹提示

- 菜单内容**没超过最大高度**时列表滚不动，库会切到「跟着手指换行、抬手选中手指下那一行」
  那一档（`isDynamicSelection`）：按住往下滑、滑到一行禁用项上松手，那一下就被当成「点了禁用行」，
  弹出「为什么不能点」的提示；
- 启用行早有一道闸（`onSelectedIndexChange` 里按**这一段手势的位移**判「滑动还是点一下」），
  但禁用行走的是另一条路 —— 库里 `PopupListGestureHost.onUp` 直接派发 `handle.onClick`
  （`enabled || disabledClickable`），**绕过**了那道闸。现在补上同一道：
  位移动过触摸阈值就吞掉这次点选，只在日志里留一行「这一段是滑动 ⇒ 已吞掉这次点选」；
- 顺带把「浮层正在淡出」也纳进来（原来那个闭包是 `remember` 出来的，`interactive` 被钉在创建
  那一刻的值上）：淡出期间的禁用行不再说「为什么不能点」；
- 列表**滚得动**时本来就没事：拖拽是在滚动，库走 `cancel` 不选行 —— 这条只影响装得下的短菜单。

### 改：禁用态的提示收进一个组件

- 「这块点不动，点一下就说哪句」原先每个调用点自己拼（投递口、语义位、lambda 的 `remember`
  三样各写一遍），现在收进 `ui/DisabledHint.kt`：调用点只给一句话，`null` 表示用整页那条原因；
- 卡片行的行级说法、步骤行尾的上移 / 下移、底部工具条的「保存」都改走它，并且**共用「禁用原因」
  那一个语义位** —— 连点几处只会改同一条提示里的字，不再一条条往上叠；
- 两处只为一件事存在的私有包装（步骤行那颗按钮、工具条那颗「保存」）随之删掉；
- 「保存」灰着被点时那句话现在也落到「禁用原因」位（原先落在命令页那一位）。

### 改：长按那组设置单键页与组合键页共用一张卡

- 「长按连续触发 / 连续触发时振动 / 触发间隔 / 长按延迟」四行原先在「按键绑定」与「组合键」两页
  各写一遍，现在卡片本体只有一份（`ui/LongPressSettingsCard.kt`）；

- 行序、文案、显隐判据与「什么时候整卡置灰」不再有两处，改一次两边一起走。

### 改：顶栏那条分页带子收成一份

- 「自定义命令」页单条 / 多条那条带子原先照抄了「按键绑定」那条（约 55 行，含禁用时的压暗与
  透明吃事件层），现在两者共用 `ui/PageTabBand.kt`；命令页那一支只留「哪几档、可不可点、
  高度报给谁」；
- 带子本体从「按键绑定」那个包里挪到共用层 —— 它本来就服务三个页面。

### 改：步骤卡「添加命令」行首那颗 `+` 的配色走全项目那一对

- 原先自己拼 `animateColorAsState`，改用 `rememberRowIconColor`（与开关行、滑杆行、输入框行首
  同一对色），两档色只在一处定义。

### 改：静态检查那 5 条收口

- 删掉「条件执行」页三个已经没人用的私有常量（小标题行那颗「更多」的宽高、两列格子的圆角）——
  它们跟着那组格子搬走之后留在原地；

- 结果：`detekt` 零问题，`gate`（格式 / detekt / Lint）两道模块一起绿。

### 改：已保存命令卡片右上角换成「更多」菜单

- 原来那颗「测试」换成**横向三个点**（与小标题行尾那颗同一个组件 `MoreButton`），点开是一层菜单：
  **测试 / 编辑 / 删除**；卡片长按开的是同一层菜单，于是长按菜单里也有了「测试」；
- 菜单弹在**按下的那一点**：从三个点打开就弹在那颗字上，长按打开就弹在手指处；
- 「编辑」多一条口径：**正在编这一条、草稿又没动过**时，再点「编辑」就是「重置」——
  与底部工具条那颗「重置 / 取消」走同一份实现（多条命令带步骤时步骤行照常走退场动画）；
  草稿有改动时不重置，先弹「放弃未保存的命令」那一句（复用原有确认窗），确认后回到已保存的内容；
- 卡片右上角那颗在排序态下跟着整片一起置灰、不吃点击。

### 改：默认那份配置叫「默认配置」

- 配置列表、切换 / 导出菜单、重命名与删除的确认句里，原先那个「默认」一律改称「默认配置」——
  与「配置 1 / 配置 2」摆在一起时才读得出它也是其中一份；英文档跟着改成「Default config」；
- 它仍是**不许改名、不许删除**的那一份（两句提示原本就写着「默认配置」）。

### 改：条件执行页场景块那颗「更多」的右缩进（改过又改回）

- 中间试过把它的 20dp 右边距归零，指望两颗「更多」的右边线都落在 `PAGE_MARGIN` 上；
- 实机看着不行：这一页的正文（那些卡片）自己有内边距、字头离屏幕边缘本来就远一截，
  归零之后这颗反倒比左邻的内容更贴边。**现在回到 20dp** —— 右缩进多一点就多一点。

### 改：添加命令抽屉里的小标题回到默认内边距

- 抽屉里那几组小标题（系统 / 媒体…、「已保存的命令」）原先被压到左右 16dp，
  比其它页浅一档；改回 `SectionTitle` 的默认值（库的 32dp）。

### 改：自定义命令的「重置」挪到顶栏右侧

- 底部那条浮动工具条只剩「保存 / 修改」一颗，「重置 / 取消」挪到顶栏右侧（与「条件执行」页
  那颗「添加」同一个位置、同一档尺寸）；
- 它只在**表单里有东西可清**时出现（判据与底栏那条「该不该在」同一处），空表单上不留一颗灰按钮；
- 文案跟着编辑态走：编一条已有命令时是「取消」，新建时是「重置」—— 与它原先在底栏时一致。

### 修：点「重置」表单没被清空

- 根因是一套**悬空的收尾机制**：多条命令带步骤时，「重置」只置了一个挂起标记、等页面级协程在
  步骤行退场之后真正清空 —— 而那个协程早就不在了（标记置上、行也退了、`reset()` 没人调）。
  于是表单原样留在那儿，`reset()` 永远不会来；
- 现在「重置」就是一次 `draft.reset()`：步骤行照样播退场 —— 数据一变，
  展示层的差分自己把对不上的行标成退场、播完 shrink 摘除；
- 顺手清掉那套挂起机制（挂起 / 放弃 / 指纹对账三个字段、两条 `LaunchedEffect`、
  `StepRowDisplay` 里的 `exitAll` / `restoreAll`、`contentFingerprint()`）—— 已经没有调用者了。

### 改：表单与步骤都空着时「重置」置灰

- 顶栏那颗「重置 / 取消」不再时有时无：空表单上也留着，只是**置灰**；
- 灰着被点一下说「表单是空的，没有可重置的内容」（新字典键 `command.reset_empty`，中英各一条）。

### 改：命令卡右上角那颗「更多」贴住右边线

- 那张卡的内容有 16dp 内边距，颗字形原先在 40dp 点击区里居中 ⇒ 比左边那颗类型图标多缩进 10dp；
- 现在字形贴住点击区右端，右边线与左侧图标对称（点击区宽度不变，只是多出来的那半格向左伸）。

### 改：单条 / 多条两页的表单完全独立

- 两页各有一份 `CommandForm`：名称、正文、步骤列表、步骤间隔、**编辑态（正在改哪一条）**与载入快照
  都归各自那一份；`CommandDraft` 上那些字段变成「当前这一页」的快捷方式，调用点一行没改；
- 于是切 tab 什么都不清（只摘排序态）：名称不会丢、**来回切一下不再从「修改」变回「新增」**，
  名称格的重名 / 成环红字也各算各的；
- 判据跟着收窄：`hasContent` 与 `dirty` 只看当前这一页的字段（单条比名称 + 正文，多条比名称 +
  间隔 + 步骤），退出时的「放弃未保存的命令」只在**当前 tab 的表单有改动**时才弹 ——
  另一页写了一半不再牵连这一页（那部分内容随之丢掉，不再提示）。

### 改：多条命令卡片里「间隔」前面加了那颗图标

- 行首补一枚小图标，与下面的摘要行同一支笔、同一档尺寸（14dp + 4dp 间距）；
- 图标就是「命令间隔时长」那一行用的那枚（`PageIcons.DelayStep`）—— 同一个参数，同一颗图标。

### 改：版本 1.2.0 → 1.3.0（versionCode 8）

- `versionName` 与 `versionCode` 一起抬（管理器判新版本是严格大于，只增不减）；
- debug 档的 `versionNameSuffix` 仍挂着 `-debug`，应用信息里的版本行随之变成 `1.3.0-debug`。

### 改：命令卡里的步骤行与间隔行补光学修正

- 卡里那几行「小图标 + 一行小字」原先只做几何居中（`Alignment.CenterVertically`）——
  行盒居中不等于墨迹居中，汉字在行盒里重心偏上，整行字看着浮一档；
- 现在一律走 `Modifier.opticalCenter(footnote1)`，与卡片标题、单条摘要、卡片行同一支笔：
  多条命令的「间隔」那一行、摘要里逐条列出的步骤行都补上了。

### 修：命令卡右上角那颗菜单按下去「波纹歪」

- 根因在上一版那次「字形贴住右端」：挪的是**格子里的字形**（`contentAlignment = CenterEnd`），
  而 COUI 的按压反馈不是圆形涟漪 —— 是盖满整个可点节点的**矩形状态层**（`COUIIndication`）。
  字被推到格子右端之后，那 40×20 的底色仍以格子为中心 ⇒ 按下去一整块偏在字左边十格、
  右边一点没有，看着就是歪的；
- 现在改挪**整个点击区**（右移半个余量 = `(40 - 20) / 2 = 10dp`）：字形恒居中、右边线仍落在
  原来的位置（内容右边线），底色与字形同心；
- 代价：那颗的点击区与底色各有 10dp 伸进卡片的内边距里（离卡片右边缘 6dp），仍在卡片内。
