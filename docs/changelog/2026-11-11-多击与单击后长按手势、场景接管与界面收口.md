# 2026-11-11 · 多击与单击后长按手势、场景接管与界面收口

### 三击 / 四击：从「一直在」改成「自己要才有」

- 「按键绑定」页默认仍是三页（单击 / 双击 / 长按）；**三击、四击要在「独立设置」页顶部各自打开**才出现。关着的档：界面不排那一页、场景块不列它、判定不数到那儿（`clicksForJudge` 只算开着的）、执行恒「无操作」—— 单击也就不必为它多等窗口。
- **逐档一个开关**，不是一位统领：开三击让单击多等一个窗，开四击还要让三击也等；只要三击的人不该被迫接受四击那份延迟。两档互不依赖，只开四击是合法配置。
- 这两个开关**不跟随「使用独立设置」那颗总闸**：那一族是「公共设置这一项可以另设一份」，而公共设置里根本没有「多击」这一项。
- 关掉再打开，`extraClicks` 那张表原样回来（关的时候不清表）。老配置按「表里有没有东西」倒推，手改过 `extra_clicks` 的人升级后三击照旧能用。
- 字形按档位分开：三击 `hand-three-fingers`，四击 `hand-ring-finger`。

### 单击后长按（新档位）

- 第 1 击抬手之后，**第 2 击在连击窗口内按下并按住**超过长按阈值 ⇒ 触发 `click_then_long`。它与双击互斥：同一颗键的第 2 击，快速抬起是双击、按住不放是这一档。
- **它不延长连击链**：判定仍只数到第 2 击，单击的等待窗口与这一档出现之前一样。它只是在第 2 击按下时顺手排一枪长按。
- 自己一套参数（与长按那族**同名不同槽**，调这一档不动普通长按）：长按延迟 / 连续触发 / 触发间隔 / 每次都振动 / 松手执行额外动作。界面在「单击后长按」那一页，与长按那张卡同源、同文案。
- 「松手才触发」那一行不摆：这一档本来就是按住之后松手才结束。
- 与三击共存：第 2 击按住时若链上继续数到第 3 击，那一枪自己作废，三击链照常。
- 字形 `hand-move`。

### 场景块现在能接管这两档

- 「系统场景」的动作行按**同一份档位清单**排（`slotsOn`）：这块能接管哪几档由它自己的表说，所以三击 / 四击 / 单击后长按都能进场景。
- 场景块多了**「单击后长按」的松手**（`chain_release_on` / `chain_release`）：与长按的松手同一对，挂在另一档上；那一页用小标题「单击后长按」摆一族，写回走草稿。块里配了它时注入侧靠广播位 `scene_chain_release` 决定抬手发不发。
- 只在场景里配了长按的键不会被当成「长按无操作」：宿主现算 `scene_long` 带过去（注入侧看不到场景表）。

### 判定侧的几处收口

- **松手那一刀要看主档有没有动作**：长按（或「单击后长按」）本身是「无操作」时，松手额外动作不执行 —— 那一格是「这一档执行完之后」的收尾，主语没有就不该有谓语。界面整族压灰，判定侧与执行侧各拦一道（执行侧那道是为「改了判定、没重启」的情况留的）。
- **「忽视无操作」把长按也一起忽视**：长按没人要时，按住不放不再白等一个阈值，抬手直接走单击。
- **连发闸门**：多条命令与灵感语音不重复（与长按那一档同一套判据），「单击后长按」那张卡也跟着压灰。
- `clicksForJudge` 在开了「单击后长按」时下限是 2 —— 不加的话，「忽视无操作」那条「抬手即判单击」的快捷路会把第二击抢掉，这一档永远命中不了。

### 配置格式 38 → 43

- **39**：`extra_clicks_on`（多击档位启用没有）—— 多击从此是「自己要才有」的。
- **40**：同一格从布尔收成**击数数组**（`[3]` / `[3,4]`）：两档代价不同，不能再用一位统领。读侧同时认 39 的布尔与「缺格」，所以 39 的文件读进来行为逐字不变。
- **41**：`click_then_long_on` / `click_then_long`（单击后长按），默认关 + `none`。

- **43**：`SceneRuleDto` 多了 `chain_release_on` / `chain_release`（场景块里「单击后长按」的松手）。

### 场景条件字形按状态取

- 电源菜单换成 `menu-2` + `power` 拼接：三条横线（原坐标）加右下角电源符号，右端在缺口圆上收笔；原来那颗「滑杆 + 齿轮」不再用。
- 屏幕状态：亮屏 = `brightness`，熄屏 = 同一颗带斜杠（`brightness-off`），锁屏仍是带锁的方块；类别那颗从 `brightness` 退回「一台手机」。
- 充电状态：「没在充电」从一颗**空电池**换成同一颗电池带斜杠（`battery-off`）。
- 两族因此与 WiFi / 蓝牙 / 移动数据 / 飞行模式 / 台灯那几对同一套语法：先认出底图说的是哪件事，再看有没有那道斜杠。
- 为什么这么改：原先亮屏是一台手机、熄屏是同一台带斜杠 —— 一列条件扫下来两颗都像「一台手机被禁用」，「亮着」这件事根本没画出来；空电池则读成「电量低」，而这一档说的是「没插着电」。

### 提示条：正圆弧胶囊，滚动期间不到点收

- 形状换成正圆弧的胶囊（半径 = 高度一半），不再是超椭圆：超椭圆的半径顶到 `min(宽, 高) / 2` 之后没法再大，同样半径下两端也比圆弧「方」一档 —— 想再圆只能换圆弧。高度不变。
- 文字改成垂直居中（原先按行盒算，读起来偏上）。
- 文字比胶囊宽时要滚：滚动那几秒里**不能到点收**，所以每条提示多记一个「到期时刻」（`HintQueue.deadlines`），滚动开始时把到期往后推 —— 只拿计时器推不出来，协程里 `delay` 的剩余量读不到。

### 开关行按住时的波纹不再与上一行让出缝

- 根因是「双行光学居中」把**整行**挪了 1~2dp（`Modifier.offset`）：可点区域与波纹跟着挪，波纹上沿就空出一道缝。不是行高不够。
- 开关行改成**上下内边距互相让**：上边 +这个位移、下边 −这个位移，标题与副标题照样下移同样多，行高与可点区域一动不动。

### 输入弹窗的行首图标取触发它的那一行

- 「重命名按键」「添加按键」「新建 / 重命名配置」三个输入弹窗原先写死一颗「名字」的标签图；现在都取**触发它的那一行**的图标（按键改名取那颗键在列表里的图标，添加按键取「添加按键」那一行，配置改名取配置那一块）。
- 与滑杆、提示文案、变量值那三支同一个口径 —— 同一个弹窗不再因来处不同而换脸。
