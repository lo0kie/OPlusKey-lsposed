# 顺序组合自带一组窗口、独立设置去掉播种与装机包缺工程 dex

## 改

### 改：组合窗口的出厂值与上限按「固定等 / 逐次等」分成两档

- 出厂值：**固定等 350ms / 逐次等 250ms**（原先是四格统一 150ms）。固定等 = 固定窗口起点开着、
  整串一个窗口（`wait` / `hold` 与顺序组合同名两格）；逐次等 = 关着、相邻两颗各一个
  （`waitPair` / `holdFollower` 与顺序组合同名两格）；
- 上限也分开：**固定等 1000ms / 逐次等 500ms**（原先统一 1000）。逐次等那一档会被 `(n-1)` 放大成
  整串跨度，参与组合的键按下后就要等这么久 —— 五颗组合配 1000ms 就是四秒的单击延迟；
- 单击那三档同步：`doubleClickMs`（固定窗口起点开）出厂 350 / 上限 1000，`multiWaitMs`
  （每次松手重新起算）出厂 250 / 上限 500；`multiWaitMs` 的 `0` 仍是「跟随单击延迟」，只留给老配置；
- 某一档自己存的那四格原先没有任何钳制（`ComboKey` 上那几位随 `ComboWire` 落地），补上读口的
  `Config.windowClamped`；公共那八格仍由 `GlobalConfig.ofFields` 按格钳；
- 代价明说：老配置里超过新上限的值会被**静默钳回**（800 → 500）。

### 改：长按延迟与连续触发的出厂值、连发上限

- 「长按延迟」出厂 500 → **350ms**（逐键、组合、成员「单击后长按」三处同一个常量）；
- 「连续触发」间隔出厂 300 → **200ms**，上限 1000 → **500ms**（一秒两下是「看得出在连发」的极限）；
- 长按阈值上限仍是 1000ms。

### 改：按住组合那两行窗口兼管成员连击

- `Config.comboMemberChain` 改读**按住卡那两格**：窗口取 `comboWindowsFor` 的按住半边
  （固定窗口起点开 = `hold`、关 = `holdFollower`），判定时机取那颗开关本身（`waitMultiWindow` 是它的反面，
  所以传 `!fixedStart`），不再读单击那三项（`doubleClickMs` / `multiWaitMs` / `waitMultiWindow`）；
- 于是按住卡上拨一次窗口，成员双击 / 三击 / 单击后长按与「成员之间接收」一起变 —— 用户口径：
  这个设置就是给多击手势用的；
- 按住卡那两行（含顺序组合那一对）的置灰判据是 `holdWindowLive`，两件事任一成立就算活：
  **成员之间的接收**（`followers.size > 1`）与**成员连击**（`MemberGestures.isOn`）；
  一档多击都没开、又只有一颗成员时置灰并说明（`combo.hold_window_idle`），不摆空转的旋钮。

### 改：独立设置页只摆一对窗口行

- 顺序组合的那一对**不再在这一页重复出现**：这一页只有一对，顺序档让那一对直接读 `ordered*` 那一组
  （`comboStoredOrderedWindowsFor` + `comboOrdered*FixedWindowStartFor`、写回 `setComboOwnOrdered*`），
  标签仍是「固定窗口起点 / 等待窗口」—— 数已经在里面了，再标一句「顺序组合」等于同一件事说两遍；
- 公共设置页照旧两对都摆：公共值是所有档的默认值，两套数得分开调。

### 改：顺序组合自己有了一组窗口

- 「等待组合」与「按住组合」两张卡在原来那两行之后各多一对：**顺序组合固定窗口**（开关）与
  **顺序组合等待窗口**（滑杆），只对「按顺序触发」的那几档生效；
- 正反值分开存，滑杆按上面那颗开关换格：开着写「整串」那一格、关着写「相邻两颗」那一格；
- 出厂值与不分顺序那四格同一套（固定 350 / 逐次 250、两颗开关关），不配这两项时行为一个字都不变。

### 改：判定侧按「这一档有序吗」挑组窗口

- `Config.comboWindowsFor` 按 `ComboKey.ordered` 挑一组：有序档读顺序组合那四格，
  不分顺序那一档读原来那四格；
- `comboSpanFor` 的开关取值走合并后的 `comboWindowStartFor` / `comboHoldWindowStartFor`；
- 注入侧两处装配点跟着换（`ConfigChannel.windowsFor` 仍是 `comboWindowsFor`，
  `SideKeyInterceptor` 的 `holdFixedWindowStartFor` 换成合并后的那一支），`ComboDetector` 本身没动；
- `Config.comboScanWindowMs` 把顺序组合那四格也算进「最宽的那一档」—— 它比不分顺序那四格宽时，
  扫候选仍按旧那四格取会「扫得到、等不到」。

### 改：独立设置不再「抄一份公共值」，没写过就是出厂默认

- 打开某一档的「使用独立设置」时不再按公共值播种：`KeySettingsScreen.withSeededComboFields`
  整个函数、`commitOwnField` 里「先播种、再把本次改动叠回去」那一段一起删掉；
- 取值改成：总开关关着看公共；开着且那一格**没写过**取出厂默认（`GlobalConfig.DEFAULT_*` /
  新增的 `ComboWindows.DEFAULT`）；开着且写过就用这一档自己的值；
- `OwnSettings.ownSettingsSeeded` 这一位整条删掉（接口声明、`KeyConfig` / `ComboKey` 两个实现、
  `ConfigFields` 的 `OWN_SETTINGS_SEEDED_EXTRA` 与 `F_OWN_SETTINGS_SEEDED`、`ConfigDto` 两个字段
  及其映射、`OwnSettingsValues` 与两份 `withOwn` 里那一行）；
- 组合那几格的兜底从「公共现值」改成出厂默认（`comboStoredWindowsFor` /
  `comboStoredOrderedWindowsFor` / `comboStoredHoldMinFor`），`comboField` 因此多一个 `default` 参数；
- 独立设置页那几根滑杆的「双击回落」也改成出厂默认（原先回落的是当前公共值，
  而这一页在总开关关着时显示的本来就是「打开之后会用的数」）；
- 存量已播过种的档位不会自己回默认：那些值当初被写进盘里了，分不出「播出来的」与「用户自己拨的」，
  要清就按顶栏「重置」。

### 改：顶栏副标题在「整页禁用」时不再压暗

- 原先这一页在编的那颗键 / 那一组停用时，标题下面那行小标题会把 alpha 再乘一半
  （`SUBTITLE_DIM_FACTOR`，判据是 `bindingTargetOff` / 那一档的 `enabled`）；
- 现在恒定用库那档次要色（`onSurfaceVariantSummary`）—— 那行装的是「这一页在编哪一颗键 / 哪一组」，
  名字本来就该看得清，停用与否由页内那句原因与内容区整片变灰表达；
- `PageHeader` 的 `subtitleColor` 参数与 `PageMotion.SUBTITLE_DIM_FACTOR` 一并删掉（它们只为这一处存在），
  所有页都走同一个默认色。

### 改：判定时机的反位收进一处访问器

- 存储位 `waitMultiWindow`（`false` = 固定窗口起点）与界面上那颗「固定窗口起点」是反的：
  原先界面两个入口、判定侧两处各自写 `!waitMultiWindow`，三处注释都在提醒「别照抄」；
- 新增 `ClickChainParams.fixedWindowStart` 与 `GlobalConfig.fixedWindowStart`（同一条翻法、
  都在 `core` 里），界面两侧与 `GestureDetector` 的判据一律改读它；**存储位与落盘键不动**
  （`wait_multi_window` 已经落在用户机器上）。三处提醒改成指向这个访问器。

### 改：按住卡那根窗口滑杆说明「成员连击也用它」

- 那两格同时是「成员之间接收的窗口」（按下 vs 按下）与「成员连击的单击窗口」（抬手 vs 按下），
  起点不同、数只有一份 —— 调连击手感会连带拖动成员接收窗口。这层耦合是按用户口径有意保留的
  （不另开一套窗口字段），所以不拆，但要在会受影响的那一档上说清；
- 这一档开着成员连击时，滑杆下面挂一句「成员连击的单击窗口也用它」（新键
  `combo.member_window_share`）；没开成员连击的档位不挂，免得变成噪声。

### 改：提示文案统一措辞（同一行为同一句式）

- 停用那一族统一成「%s 已停用，可在菜单中启用」（原先单键写「菜单里」、组合写「菜单中」）；
- 依赖上一级开关统一成「需先开启 X」/「需先关闭 X」：使用独立设置、使用 ColorOS 接口、
  振动反馈、以及互斥的「松手执行额外动作」（原先先打开 / 需要开启 / 需先开启 / 先关掉 四种动词混用）；
- 上限那一批统一成「<范围>最多 N <单位>」：自定义按键、组合、系统场景、变量、选应用、配置份数
  （原先「最多只能添加」「最多 %d 组」「最多选」几种句式混用）；
- 能力限制一律用「不可」：不可改名 / 不可删除 / 不可添加（原先「不能」「无法」混用）；
- 「读不出来」那几句去掉口语并统一标点：配置读取失败、命令库改为只读、单份配置损坏，
  以及状态卡那句「未生效：请在 LSPosed 中勾选 系统框架 与 手势体感，然后重启手机」；
- **按场景保留差别**：`这一块最多 %d 条场景`（按块计数）、`顺序排列已满，无法再添加不分顺序`
  （与「已有按顺序的组合…」是两种不同条件）、`编辑中，请先点右下角的完成`（说了在哪儿点）、
  `按住 / 等待组合最多 %d 颗按键`（哪一档组合）。

### 改：「独立设置」页不再跟着总开关换一份值

- 那张卡原先显示**生效值**：总开关关着看公共设置，一打开整片就换成这一档自己的值
  （这一档没写过时就是出厂默认）—— 于是拨一下开关，「接口」与「按键行为」里的数字全变，
  读起来像刚配好的东西被重置了；
- 现在整页始终显示**这一档自己那份**，总开关只决定这几行能不能点（以及哪几行出现：
  振动关着就没有强度那一行、提示关着就没有文案那一行），**拨开关时一个数都不动**（用户口径
  「切换开关时只该禁用 / 启用」）；
- 总开关关着的档位仍整片灰着并挂一句「先打开 使用独立设置」，灰着的数字不会被当成此刻的行为；
- 组合那两张参数卡里的六颗开关（场景时机 / 首键松手仍触发长按 / 四颗固定窗口起点）同样改成
  「这一档自己那份（没写过 = 出厂默认）」—— 它们原先读的是 `...For`（生效值），一拨总开关整片换成
  公共那份；**执行侧不变**，仍由 `comboWindowsFor` / `combo*For` 按总开关取值；
- 同一页下半的「单击」卡与组合参数卡本来就是这条口径，现在三张卡一致。

### 改：「独立设置」页的「重置」= 关主开关 + 整页写回默认

- 原先只关总开关、把播种标记清掉，值原样留在盘上 —— 再打开看到的还是上次那一套；
- 现在关掉主开关，并把这一页所有项写回默认：七项公共项回 `DEFAULT_*`；**单键那张「单击」卡的三位**
  （判定时机 `waitMultiWindow` / 等待窗口 `multiWaitMs` / 单击延迟 `doubleClickMs`）也回出厂值
  （250 / 350，原先写的是「跟随单击延迟」与 150）；组合那几格写成「没写过」的形态
  （八格窗口 `0`、`holdMinMs` `0`、四颗起点开关与 `sceneOnStarter` / `starterKeepLong` 写 `null`）；
- 写 `0` / `null` 而不是写死具体数字：那正是「刚建出来这一档」的样子，取值侧遇到就取出厂默认，
  口径只有一处；
- **动作绑定一律不动**（短按 / 长按 / 场景表 / 多击）—— 那些是这一颗键 / 这一组键「是什么」，
  不在「独立设置」这一页上；
- 确认窗正文改成「关闭独立设置，并将本页各项恢复为默认值；按键绑定不受影响。」——
  与另外两页（`reset.about_message` / `reset.general_message`）同一句式，不再罗列具体项。

### 改：「提示执行结果 → 流体云」随 ColorOS 接口置灰

- 自定义命令的「提示类型」菜单里，**流体云**那一档在公共设置「使用 ColorOS 接口」关着时置灰，
  点一下说的是与首页那颗「用流体云提示」同一句原因；
- 命令本身没有独立的接口开关，读的是公共那一份；其余三档（不显示 / 提示 / 通知）不受影响。

### 改：「提示执行结果」这一行的标题

- 从「显示执行返回结果」改成「提示执行结果」（键名与四档取值都没动）。

### 改：按住组合启用被拦时的回执点名起点键

- `keys.combo_needs_fire` 从「起点键没开 松手时触发，这组也停用」改成
  「%s 的长按没有启用松手时触发」，`%s` 是那颗起点键的名字 —— 同一组里「谁没开」只有它说得清。

### 改：配置版本 81 / 82

- 81：`GlobalDto` 多了 `combo_ordered_wait_window_ms` / `combo_ordered_wait_pair_ms` /
  `combo_ordered_hold_window_ms` / `combo_ordered_hold_follower_ms` /
  `combo_ordered_fixed_window_start` / `combo_ordered_hold_fixed_window_start`，`ComboDto` 多同名六位；

## 修

### 修：debug 包只并进依赖 dex —— 模块页一点就崩、快捷键回落系统默认页

- 现象：装机后点模块入口直接闪退，崩溃日志是
  `ClassNotFoundException: Didn't find class "com.lookie.opluskey.EntryActivity"`；
  点快捷键出来的是系统默认界面（注入侧也一起没了 —— `KeyModule` 同样不在包里）。
- 原因：**并发构建**把 `app/build/intermediates/built_in_kotlinc/debug`（debug 的
  Kotlin 类产物）与 dex 中间目录清掉，而 `compileDebugKotlin` 仍被判 UP-TO-DATE ——
  同一个构建里先报过 `Could not delete …\kotlin\compileDebugKotlin\cacheable\caches-jvm`
  与「Detected multiple Kotlin daemon sessions」。于是 dexBuilder 拿到的是空的工程类目录，
  打包只并进依赖那几份 dex：包照样出、照样装得上，但 26 份 dex 变成 12 份，
  其中一份 36MB 全是依赖。
- 修法：删掉 `app/build/intermediates/dex/debug`、`app/build/intermediates/built_in_kotlinc/debug`、
  `app/build/tmp/kotlin-classes`、`app/build/intermediates/javac/debug`，再
  `./gradlew :app:assembleDebug --no-build-cache`（不走构建缓存，那条坏产物就在缓存里）。
  dex 回到 26 份、`EntryActivity` 与 `KeyModule` 都在。
- 附带口径：**同一份源码不要同时跑两处构建**（两个 Gradle / Kotlin daemon 抢同一个
  `app/build` 就是这个结果）；装机前先验包，验的是**要装的那一个文件**。

### 修：`tools/verify-apk.py` 补一条「跳板类在 dex 里」

- 原来的 (4) 只读二进制清单、(6) 只核 `java_init` 那一个类 —— 两个都在时，
  工程 dex 整份没打进去照样全绿（这次就是被它放过去的）。
- 新增 (6b)：`Lcom/lookie/opluskey/EntryActivity;` 必须在 dex 字节里找得到，
  否则置红并说明处置办法（清 dex / kotlin 产物 + `--no-build-cache` 重编）。
  包名取的是**代码里的包**，不是 `applicationId`。
- 反向验过：把含该类的那两份 dex 从包里删掉后，这条与 (6) 一起报红。
- 装机后还能拿设备上的包复核：
  `adb exec-out cat $(adb shell pm path io.github.lo0kie.opluskey | sed 's/package://') > /tmp/device.apk`，
  再 `python tools/verify-apk.py <那个目录>`。

### 修：单击等待窗口的两档默认值装反（重置后停在 350）

- 判据在 `KeyConfig.clickWindowMs`：`waitMultiWindow` 为真（每次松手重新起算）读 `multiWaitMs`，
  为假（固定窗口起点开）读 `doubleClickMs`；上一版把两档的默认值接反了，
  于是出厂那一档（逐次）显示的是固定等那个数，顶栏重置后也一样；
- 现在 `doubleClickMs` 350（固定等）/ `multiWaitMs` 250（逐次等），上限随之为 1000 / 500；
- 单击那根滑杆的 `max` 与「双击回落值」都按当前那一格取（`collect` 开 = `doubleClickMs` 那一对）。

### 修：「独立设置」页的重置漏了单键那张「单击」卡

- 单键那一页吃总开关的不止七项公共项：下面还有「判定时机（固定窗口起点）+ 等待窗口」那张卡，
  上一版重置只清了七项，于是按了重置、固定窗口仍停在原来那档；
- 补上三位：`waitMultiWindow` / `multiWaitMs` / `doubleClickMs`（后两者写出厂值 250 / 350）。

### 修：「按键设置」页的重置把「固定窗口起点」改成了开着

- 那一档原先写 `waitMultiWindow = false`（= 界面那颗「固定窗口起点」**开**），而模型出厂值是
  `true`（每次松手重新起算）—— 重置出来的状态与全新装的那一份相反，也与「独立设置」页那颗重置对不上；
- 改成 `true`，三处（模型默认 / 公共页重置 / 独立设置页重置）对齐。

### 修：按住卡那颗「固定窗口起点」的副标题说的是等待档的口径

- 两张按住卡原先与等待卡共用同一对副标题（`combo.fixed_window_start_desc_on/off`，写着
  「第一颗按下就开始计时」），而按住档的窗口是从**第一个成员**按下起算的
  （`ComboDetector.multiFor` 的 `followers.firstOrNull()`），首键按住多久都不计时 ——
  同一句话在等待卡上准、在按住卡上错；
- 新增 `combo.hold_fixed_window_desc_on/off` 与 `combo.ordered_hold_fixed_window_desc_on/off`
  四句，两张按住卡各用自己那两句；等待卡不动。
