# 2026-11-11 · 输入框收口、挑应用页报个数与文案收口

### 单行输入框收成一个入口（`AppInputField`）

- 全项目包住库 `InputField` 的只剩这一处：换行怎么折、长度怎么截、展开态怎么定，都收在这一层，重命名 / 命令名 / 变量值 / 两页搜索框不再各记一遍。
- 粘进带换行的字不再出现「框里空的、值却还在」：默认把连续换行折成一个空格，没有换行时一个字符都不动。
- 长度上限按**码点**切，不再从代理对中间断（emoji / 扩展区汉字不会留下半个字）。
- 命令正文那一栏例外：换行折成 `; `（多行脚本粘进来是依次执行），折成空格会得到一条语法错误的命令。
- 「选择应用」「选择界面」两条搜索带共用 100 字上限，两页同一副长相也同一条账。

### 「选择应用」页：多选那趟的顶栏、确认键与返回拦截

- 给条件挑「前台应用」是多选，顶栏只报个数（`已选择 3 个应用`），与一级菜单那行子标题同一句；一个都没勾时写「没有选择应用」。
- 那一趟的确认键常驻：把勾全点掉之后不再消失；按下时若一条都没勾，提示「至少选择一个应用」，不写任何东西。
- 返回拦截补上「勾选改过」这一条：勾完 / 勾掉再按返回会问「放弃本次选择」，不再静悄悄丢掉整趟。
- 其余几趟（按键绑定 / 组合键 / 结束应用 / 命令某一步）不变：单选，顶栏仍写应用名。

### 搜不到时不再复述搜索词

- 「选择应用」「选择界面」两处空态只写「没有匹配的应用 / 没有匹配的 Activity」——那串字就写在上面搜索框里，空态不再念第二遍（长词在窄屏上还会折成两行）。
- 空态判据随之不再收搜索词，也不再往文案里嵌用户输入。

### 确认窗：删掉只是复述标题的正文

- 「删除这条场景」「停用场景」「删除按键」「停用组合按键」四处只留标题与动作项。
- 「停用按键」那一问本来就没有调用点，常量与字典条目一起清掉。
- 其余确认窗的正文都留着：写的是名字、条数、连带影响、不可逆或原因（「动作一起删」「绑定会改成无操作」「未保存的改动将丢失」「这一份无法读取」）。

### 文案去口语：「丢 / 删掉 / 就 / 还没 / 试试」一律换书面说法

- 弹窗：「返回就丢掉这次选择」→「返回将放弃本次选择」；「未保存的内容会丢」→「未保存的改动将丢失」；「会一起删掉」→「将一并删除」；「继续会换成」→「继续将替换为」。
- 长按那一族：「按到长按时长就立刻执行」→「达到长按时长即立刻执行」；「松手才触发」→「松手时触发」。
- 状态与空态：「页面还没就绪，重进本页试试」→「页面尚未就绪，请重新进入本页」；「还没添加步骤 / 还没有添加场景 / 有场景还没选」→「尚未……」；「还没有变量 / 捐赠记录」→「暂无……」。
- 提示类：「仍见本行就去 LSPosed 确认」→「仍见本行请前往……」；「再按一次试试」→「请再按一次」；「上一条命令还没跑完，稍后再试」→「上一条命令尚未执行完毕，请稍后再试」。
- 设置页说明：「调大会让参与组合的按键多等这么久」→「调大后，参与组合的按键等待更久」（两处调用点）。
- 「页面尚未就绪」「模块未就绪」里的「就绪」是 ready 的书面说法，不动。

### 引号统一成半角方括号

- 两份字典里 44 处「」全换成 `[]`，代码里的兜底串同步 —— 中英混排时不再一半全角引号、一半方括号。
- 新增一句 `app_picker.branch_at_least_one`（多选那趟一条都没勾时的提示）。

### 过闸时收的几处（参数与判据归位）

- `AppInputField` 的九个参数挤成五个：禁用、行首图标、怎么折换行、长度上限收进 `AppInputOptions`（detekt 的 `LongParameterList` 上限是 6，逐个数着摆顶破了）。
- 配色不再逐个调用点传：两处调用都是 `couiInputColors()`，收进组件里取一次。
- 「这一趟挑过还没落盘」的判据收进 `AppPickerState.unconfirmedChanges`（草稿 / 两个窗口开关 / 多选集合三样合一），`SettingsPage.hasUnconfirmedPick` 只再叠一次「是不是这一页」—— 下次再加一样时不会又漏一处。
- `tools/ratchet.txt` 的 `count.settings_page_ext` 516 → 517：上一笔的 `ruleActionLines` 是为让 `RuleBlock` 留在 detekt 长度线内抽出来的，它读两个页面成员、只能是页面扩展。放宽是例外，不是维护动作。
