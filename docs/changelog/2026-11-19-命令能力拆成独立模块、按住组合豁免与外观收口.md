# 2026-11-19 · 命令能力拆成独立模块、按住组合豁免与外观收口


## 修

### 修：架构判据的扫描范围漏了 `:command`

- `tools/audit-arch.py` 补 `COMMAND` 根；`entryFailure` 的两条判据改在 `app` + `command` 上数（拆分后 helper 与三个调用点都在 `:command`，只看 `app/` 会读成「0 / ≥3」）；
- 「失败分类就地手写」改成按文件排除实现，不再用「总数减一」—— 零命中时那会算成 -1，读起来像「有负一处手写」；
- 其余「唯一实现」判据（格式键 / `ActionCatalog.label` / `KeyId.builtins` 遍历 / `Action.None` 取反 / `AppTarget.label` / 开关 id 裸比较）同样并入 `:command`，实测数值不变。

### 修：`inject/input` 引了 `core.model.ThenLongParams`

- 那个值对象搬进 `core/judge/ThenLongParams.kt`（全是毫秒 / 布尔 / 次数，正是判定层要的那几样）；判定层改从 `core.judge` 取，业务侧 `ClickChainParams.thenLongAt` 照旧产出它；
- `core.model` 引 `core.judge` 不构成回环（`core/judge` 现在没有任何跨包 import）；耦合审计恢复「禁止边零越界、包级依赖无环」。

### 修：CI 的依赖锁定只看 `:app` 与 `:core`

- `ci.yml` 那一步加上 `:command:dependencies --write-locks`，锁文件 diff 与报错文案一起扩到三份。

### 修：两页的「重置」各自漏掉后长按那根按住时长

- 「按键设置」页顶栏那颗（公共那一份）补上 `clickThenLongPressMs` 与 `comboMemberClickThenLongPressMs`，按 `KeyConfig.DEFAULT_LONG_PRESS_MS` 写回；
- 「独立设置」页那颗补上这一档自己的两格：单键 `clickThenLongPressMs` 写回默认值、组合 `memberClickThenLongPressMs` 写回「跟随公共」那个 0 哨兵；
- 漏了的表现是「按了重置，按住时长还是原来那个数」—— 那两根滑杆就在这两页上，重置却一项都没带走。

### 修：首键的长按那一档没有动作时，按住组合不再被它的阈值截断

- 按住组合的上界改成「首键那一档长按真有动作」才成立：`SideKeyInterceptor` 的 `longPressPassed` 增加 `KeyConfig.longActionExists`（直接绑了动作，或某块场景里给长按配了动作）；
- 长按配成「无操作」、或配成「松手才触发」（动作押在抬手）的首键不再有这条上界 —— 那两种到点什么都没执行过，谈不上「一次按压两个动作」；
- 连带：`ComboDetector.longPressPassed` 的接口注释与 `docs/runtime/key-to-gesture.md` 的按住档小节写明这条豁免。

## 加

### 加：命令能力独立成 `:command` 模块，第二个模块可以直接接

- `host/action/` 那一整套（动作派发、各执行器、命令文本解析、shell 与 Shizuku 两条执行通道）搬进新模块 `:command`，包名 `com.lookie.opluskey.command`；
- 只为执行服务的平台封装一起搬走：`AppEntry` / `AppCloneCatalog` / `MiniWindowSupport` / `RingerController` / `FlashlightController` / `BuiltInMessenger` / `RecorderStateBridge` / `SeedlingClient` / `SystemActionButtonConfig` / `shizuku/`（含 `ShizukuShellService`，清单里的服务名跟着改成新全名）；
- 搬不走的那几样改成端口 `CommandPlatform`：状态栏指令、倒计时、背光、系统开关、按键注入、小窗收起 / 缩小动画、结束应用；本模块的实现是 `bridge/host/CommandPlatformImpl`，设置页那个「试一下」也走同一份；
- 跨模块用到的声明从 `internal` 放开成 `public`（`ActionRunner`、`CommandFailure`、`FailureNotice`、`ConditionProbe`、`FluidAction` / `NotifyAction`、`AppEntry` 等）；
- `TimedCache` 从 `bridge/SettingCalls.kt` 提到 `:core`（两个模块都要用）；`bridge/AppEntry.kt` 拆开：入口解析进 `:command`，注入侧那两个 helper（`asSystem` / `hookGuarded`）留在 `bridge/HookSupport.kt`；
- 工具链：`gate` 加 `:command` 三项；`tools/relock.py` 的模块清单加 `:command`；`tools/audit-coupling.py` 扫这一层并新增禁止边（不许引 `inject/` `bridge/` `host/` `ui/` 与界面库）；
- Lint 关掉 `NotificationPermission`：通知挂在宿主名下、模块从不用自己的身份发通知，清单里本就不该声明它；
- `AGENTS.md` 与 `docs/architecture/structure.md` 同步成三个模块。

## 改

### 改：顶栏圆键的描边换成一层淡阴影，首页大卡片共用同一档

- 那一圈描边压在磨砂顶栏上仍像一枚端着的按钮（用户口径「边框换成淡阴影，再淡一点」）：`HeaderIconButton` 去掉 `border`，改挂 `Modifier.dropShadow` + `SOFT_SHADOW`；
- 新增 `ui/style/SoftShadow.kt` 收这一档 —— 顶栏圆键与首页「模块状态」卡共用一份，各写一套迟早深浅不一；
- 首页那张卡的投影按卡片轮廓画，用 `RoundedCornerShape(CARD_CORNER)` 近似 —— 这一版库没公开 squircle 形状，4dp 模糊下四角那点曲率差看不出来；
- `HEADER_BORDER_ALPHA` 改名 `PANEL_BORDER_ALPHA` 并挪进 `style/Dividers.kt`：现在只剩「细线分隔」与浮层菜单面板那一圈读它；
- 阴影不跟 `enabled` 走 —— 它是「这一块浮在栏上」的几何，不是这一颗此刻能不能按。

### 改：非 Monet 配色下首页大卡片底色收淡一档

- `MIX_PLAIN_LIGHT` 0.26 → 0.20、`MIX_PLAIN_DARK` 0.34 → 0.28：底色仍认得出是强调色的卡，但不再整块压成色斑；
- Monet 那两档不动（它掺的是自带壁纸色相的 `surfaceContainer`，8% 已够）。

### 改：捐赠名单页的表格换成与卡片同款的圆角

- 表格的圆角与底色由 `RoundedCornerShape` + `CardDefaults.CornerRadius` 改成库的 `squircleSurface` / `squircleBorder`，半径取 `CARD_CORNER`：这一页上下都是卡片，夹在中间的板子要跟它们同一份形状；
- 描边排在 `squircleSurface` 之后，框线不会被裁掉半条。

### 改：常用命令那一行的行尾由箭头换成选择器，行首图标不再跟着「减少界面图标」收

- 点开的是浮层菜单而不是换页，行尾按「还有一层菜单」那颗画（`RowEndIcon(PageIcons.Selector)`）；
- 这一页整排行首图标保留（`keepIcon = true`）：那一颗是「这一条是什么动作」的唯一线索，收掉之后只剩一串名字；
- 编辑态里选择器换成勾选框，固定标签的读法不变。

### 改：「支持的命令格式」卡与闸共用一份名单

- 新增 `Action.HANDWRITTEN`（`HandwrittenFormat`：前缀 + 两列文案的字典键），`hasSupportedFormat` / `prefixOf` 直接读它；
- 界面那张「支持的命令格式」卡改成从它生成（`COMMAND_FORMAT_LINES` 不再逐行写前缀，只留「前缀 → 行首图标」这一层），认不认不再由界面决定；
- 新增一种格式只改 core 那一处：闸与卡同时变，不会再出现「能写但没列」或「列了但存不进」。

### 改：`timer:` 移出名单，有图形入口的一律不收手写

- 判据收紧成一条：**只有「支持的命令格式」卡上列出来的写法才算手写命令**；
- `timer:` 原先为了让「快捷功能 → 计时」挑出来的动作能存成单条命令的正文，在闸里多留了一格 —— 现在按同一条判据移出，从格子绑到按键 / 场景照旧可用，只是存不成自定义命令；
- 删掉「无参数前缀」那张小表（只有 `timer:` 用过它），`hasBody` 回到一条判据：前缀认得之后后面还有没有东西；
- 文档：`ui-decisions.md` 7.2 的收录表按新名单重排，`timer:` 与 `cmd:` 都归到「无」那一档，并写明这张清单就是闸本身。

### 改：场景空态的回落说明改成一句书面话

- `command.branch_empty` 中英文都去掉悬空的 `%s`：中文「将沿用按键绑定中的动作」，英文「Falls back to the actions bound in Key bindings」；
- `branchEmptyText()` 直接取文案；原来「删 `%s` 再压连续空格」那段与它用的正则一起删掉。

### 改：提示条不再按颗排名字

- 名字（键名 / 应用名）在进队列之前就填进句子（`HintText.plain`），提示条只收一整句、走单行跑马灯；
- `HintQueue` / `HintCenter` / `hint()` / `hintReason()` 的 `chips` 参数与 `HintItem.chips` 删掉，`HintCapsule` 只剩整句那一档；
- `ChipText` 只剩选择器那一列在用，注释同步。

### 改：弹窗头区多一行副标题，字数 / 条数 / 范围 / 说明都挪过去

- `FrostedDialog` 新增 `subTitle` 槽（主标题下面一行，与标题同属头区、随头区一起量，正文再长也不滚走），字号 `footnote1`、次要色；`titleTrailing` 保留给「必须与标题同行」的东西；
- `NameDialog` 也接 `subTitle`：给了它就顶掉填名字时那格字数统计（同一格只放一句）；
- 调用点：重命名 / 起名（`n/24`）、命令全屏编辑（`n/1024`）、流体图标选择（`(48)`）、多选选择器、「按下想添加的按键」、滑杆输入窗的「范围 / 步进 / 默认」、捐赠窗那句「您的慷慨…」；
- 计数格式收成一支 `counterText`（标题行尾那格与副标题共用），两行之间那一档收成 `DIALOG_SUBTITLE_GAP`（4dp）；
- 收集窗正文只剩「正在等待 / 还有几秒」，捐赠窗正文只剩收款码与「备注昵称…」那一行。

### 改：「选择按键」弹窗在标题下面写明这一类最多选几颗

- 等待组合与按住组合两处各写一句（`comboMaxKeysHint`），措辞与勾满上限时那条消息同一句，不再用「选 N 颗」这种口语说法；
- 上限在勾选之前就看得见，不必等勾满再被消息条告知。

### 改：「该按键仍被组合使用」这句不再数条数

- 正文改为「该按键仍被组合使用，请先删除相关组合。」，去掉「N 档」这种界面词与重复的计数；
- 挡路的那几档组合本来就由正文下面逐行列着，条数由那几行说，正文只说删不掉的理由。

### 改：常用命令改名的「留空则使用动作名称」挪进占位文案

- 输入框下面那行小字去掉，提示改由占位文案承担（与「提示文案」那一窗同一个写法）；
- 文案键由 `rename_label` / `rename_hint` 两支并成 `rename_placeholder` 一支，`hint` 不再传。

### 改：删除组合的确认窗不再抄一遍组合名

- 标题由「删除 <组合名>？」改成「删除组合按键？」，英文同步为 “Delete this combo?”；
- `ComboDeleteDialog` 与它的宿主不再接 `label`，`comboLabel` 那条链一并去掉；改名的回执等别处仍照旧带名字。

### 改：提示文案的变量清单按「名字 + 说明」一组一项排开

- 输入框下面那六个变量改成一组一项地排（`ChipLegend`）：组内 4dp、组间 8dp、换行后行间 6dp ——
  两档间隙分开之后，这一行读得出「六件事」而不是一句均匀的字流；
- 字典那一条去掉 `/` 分隔符（`%s 键名 %s 手势 …`）：斜杠是字流的一部分，换行时挂在行尾，
  六个变量原本因此排成「三项 + 两项 + 一项」，最后一行只剩一个变量；
- 点「名字 + 它那句说明」的任意一处都算点这个变量，不再只有名字那几个字能点。

### 改：提示文案弹窗去掉「重置」那颗按钮

- 按钮区回到「取消 / 确定」两颗；清空输入框再按「确定」= 回到默认提示，落盘时**把默认模板直接写进配置**
  （判据收进 `ToastNotice.templateOrDefault` 一处，与执行侧读的时候同一个判据）；
- `DialogButtonRow` / `NameDialog` 的 `onReset`、`ResetButton` 一并删掉（只有这一档在用），
  字典键 `dialog.reset` 删除，`Strings` 重新生成（846 条）。

### 改：页面左右留白跟弹窗面板那一档（16dp）

- `PAGE_MARGIN` 由 12dp 改成弹窗**面板离屏幕边**那一档（`DialogDefaults.outsideMargin`）：卡片行、顶栏、
  固定带、抽屉、空态说明、捐赠列表一起落在这一条线上，弹窗压上来时面板边缘与卡片边缘同一条竖线
  （不取正文那 24dp：卡片没有「面板」这一层，照它对齐会比弹窗还宽）；
- 网格页（「按键设置」那些格子）跟着一起宽：网格的左右 padding 与列距都取 `PAGE_MARGIN`，
  363dp 机身仍是两列（每格约 158dp），列数照旧按可用宽度算，不写死；
- 「条件 N」那一行的小标题横向内缩从 20dp 收到 16dp（外层已经让过一档更宽的页面留白），
  与页内其它小标题仍在同一条字头上。

### 改：按键绑定网格里没画行尾字形的格子不再预留那一格

- 取值格未选中时行尾本来就没有字形，却仍占着 20dp + 4dp：标题因此提前被省略号截掉
  （用户口径「没有行尾图标的格子不用手动设文字上限，让它自动裁」）；
- 现在按这一帧**到底画不画**决定要不要占位：入口格的箭头 / 选择器恒占，勾与圆点只在选中时占，
  空着的格子把那一格还给标题，文字长度由它自己在格边裁；
- 代价：同一格切换选中态时，长标题会左右动一点点（圆点 / 勾的淡入仍然在，`Box` 没被拆掉，
  只是尺寸收到 0）。
