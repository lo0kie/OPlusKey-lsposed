# 2026-11-12 · 链路断点修复、条件扩容与图标收口

这一批 66 个文件，三件事混在一起：**判定链路上的断点**（配了却不执行、执行了却判错）、**两处新能力**（松手沿用按下时的场景、条件多一档「前台应用以外」），以及**图标与文案的收口**（条件那一族不再按取值换图标、系统按键的音量两颗分开画、配置菜单同一族）。

涉及的两个模型位都抬了版本：`ConfigCodec.VERSION` 43 → 44（`release_pin`），封存容器格式 1 → 2（条目名进 AAD）。

### 「单击后长按」的绑定终于走得到注入侧

- 新增广播字段 `click_then_long`（`ConfigFields.F_CTL`），登记进 `KEY_FIELDS` 并接进 `fieldValues()` / `ofFields()`。
- 修的是「卡片里配了动作，松手却不执行」：注入侧拿到这一档恒为「无操作」⇒ `clickThenLongActionExists` 恒假，卡片自己那一格整条死掉 —— 只有场景块里的松手能走通，且不报错。落盘那一侧本来是对的（DTO 有这一格），断的只是广播这一条。
- 同一处补了 `scene_chain`（`F_SCENE_CHAIN`）：场景块里给这一档配了动作时，注入侧也要认为「这一档有人要」，否则判定侧不会为它排那一枪。

### 改名 / 删命令要覆盖全部动作位

- `ConfigActions.mapActions` 与 `actionTokens` 补上 `clickThenLong`、`clickThenLongRelease`，以及场景块里的 `chainRelease`。
- 修「改名后那两档里的 `cmd:` 仍指向旧名（按下必然找不到）」与「删命令时反查说没引用，库删了引用还留着」。

### 侧键认领窗口不再大于扣留时长

- 认领窗口 300ms → 150ms（= 扣留时长 `HOLD_MS`）：原先依赖「派发晚于扣留」这个隐含假设，启动时那条「窗口越界」的 W 一直为真。
- 表现是偶发的「按了没反应」：150~300ms 之间到达的认领会把紧接着的下一条派发判成模块自己的而吞掉。

### 执行成败收成「本次执行」的局部量

- `ActionRunner` 的失败标记从实例级一格改成每趟一个作用域（`RunScope` + `openScope`），派发返回即摘掉。
- 修「上一条的异步失败污染下一次执行（下一次明明成功却返回失败）」。异步失败（shell / su / 亮度 root 档）仍不进本趟结论 —— 它本来也无法与某一趟配对。

### 无操作的那几档不再拦单击收线

- 「忽视无操作多击手势」这一位原先只看双击：三击 / 四击开着时它其实管不到，标题也只写「双击」。现在判据收成 `KeyConfig.clickThenLongCounts`（开着**且**真有动作），判定侧三处（`GestureDetector` 的第 2 击分支、长按枪、松手补发）统一问它。
- 「单击后长按」那一档配成**无操作**时，等于这一档不存在：第 2 击照常走双击那条路，双击也没有时由 `instantSingleNow` 收成两下单击（用户口径：视为两次单击）。
- 标题与说明跟着改口径：`setting.ignore_double` → 「忽视无操作多击手势」，开了「单击后长按」时换成「忽视无操作多击与单击后长按手势」（`instantSingleTitle` 一份，行与写回回执共用，不再两处各拼一次）。
- 说明文案不再写死「两下」：`每一下各算一次单击` / `后续连击不生效`。

### 松手可以沿用「按下时命中的那一块」

按下与松手本来就是两个时刻：长按动作把前台应用换掉、或 WiFi 断了 / 屏幕转了，松手时重挑场景挑到的可能是**另一块**，甚至一块都挑不到 —— 「按下做 A、松手做 B」于是变成「按下做 A、松手什么都不做」。

- `SceneRule` 多了 `releasePin: Boolean = true`（默认开）：松手不再重挑，直接用**按下瞬间命中的那一块**的松手格；那一块没配松手就**真的什么都不做**，不再退回去补这颗键自己的松手格（退回去等于把另一档的动作混进来）。
- 界面是**一张表一格开关**，摆在「系统场景」列表**最上面**（表非空时才有），拨一次写整张表：它说的是「按下与松手怎么接」，不是某一块的动作，所以不进「场景动作」页那两档松手（原先摆在那里，两处各拨一次还容易只拨一处）。关掉即回到「松手时按当时状态重判」。
- 与顶栏的间距取 `SECTION_TITLE_PAD_TOP`（16dp），和「按键绑定」页那张「系统场景」条同一个数 —— 这张卡上面没有小标题，不让位就贴着顶栏。
- 模型上仍是**每块一份**（判定侧按块读），界面按「有任一块开着就算开」念；「添加场景」新加的那块继承整表的取值，不会插进一块与表不一致的。
- 记忆按「键 / 组合键 + 一次按压」记账（`pressPins` + `rememberPressPin` / `consumePressPin`，与 `pickAction` 共用同一套判据 `sceneIndexOf`）：按下时命中且开了这一档就记一行，只在两个松手相位取用一次即删；没开这一档的按下会顺手清掉上一次的残账。
- 落盘为 `release_pin`（版本 44）。注入侧不看这一位：判定与执行都在宿主的 `GestureExec`，它读的是配置里那张表。
- 顺带修掉一个断点：场景块「确认」落盘时只写了 `releaseOn` / `release`，`chainRelease*`（单击后长按那一族）被悄悄丢掉 —— 现在三个字段一起写。

### 条件多了「前台应用以外」那一档

与「前台应用」是同一族的两面（`ConditionKind.isAppFamily`）：取值写法（`包1||包2`）、多选、挑应用页、行内文案全部共用一份，只有判定那一步相反。

- 判定：`ConditionProbe` 里两档共用 `appMatches`，差别只在 `anyInForeground`。**读不到前台应用时两档都判不成立** —— 判不出不能当成「不是」，否则探针失败时这一条会在所有界面上凭空成立。
- 挑应用页**完全复用**「前台应用」那一趟：同一个列表、同一套多选、同一份预填。为此 `AppPickerState` 多了 `branchKind` 记账（与 `branchTarget` / `branchConditionIndex` 同生共死）—— 少了它，从这一行进去挑完会照 `APP` 写回，用户点的负面条件被悄悄改成正面那一档，而页面上一个字都不变。
- 写回的槽位也**按档**找（`SceneRule.appConditionIndex(kind)`）：一块里 `前台是微信` 与 `前台不是钉钉` 可以同时存在，按「第一条应用条件」换会把另一档覆盖掉。写失败留在原地重挑时，档位与槽位一起放回。
- 界面上凡是要问「这一档要不要挑应用」的地方一律问 `isAppFamily`：菜单行的二级箭头与点击分派、命令编辑页那一行的应用名框、条件行标题前的种类名（原先写死 `APP`，会把「前台应用以外」念成「前台应用」）。
- 文案：`command.cond_app_not`（前台应用以外 / Any app but），另加一句结论相反的多选提示 `app_picker.branch_multi_hint_not`。
- 判重与上限：`BlockRules.answerOf` 按族归一包名（`包1||包2` = `包2||包1`），`blockConditionCap` 对两档各限一条 —— 两档可以并存，同一档不会写成两行。

### 条件行的图标只留「种类」这一层

- 命令编辑页每一行条件原先**跟着取值**换图标（亮屏 / 熄屏、WiFi 开 / 关各一颗），一列扫下来全是只差一道斜杠的图，比文字还费劲。现在一律用**父图标**（`conditionIcon`：插头 / 路由器 / 耳机 / 一台手机…），具体哪个取值由文字说。
- 取值那一层的字形表（`conditionChoiceIcon` 与两档 / 三档那几张表）随之删除，「一级菜单与两态撞形」这件事也就没有第二个参与者了。
- 种类图标顺带换成更直白的一批：WiFi → `wifi`、耳机 → `device-airpods`、媒体 → `music-cog`、方向 → `rotate-rectangle`、时间 → `clock-24`；响铃仍是 `bell`，与「命令」那一侧的响铃状态同一颗。

### 系统按键的音量两颗改成喇叭 + 三角角标

- 「音量加 / 音量减」这两条是**模拟按一下音量键**，原先与「增加 / 减少音量」共用加减号角标，在网格里分不出。现在换成喇叭 + 右下角正 / 倒三角（`VolumeKeyUp` / `VolumeKeyDown`），加减号留给真正调数值的那两行。
- 三角角标按图标库 `triangle` 的比例画（`TRI_HALF` / `TRI_HEIGHT`），底图缺口先按放大前的墨迹半径（`TRI_INK`）让位 —— 先把形状定下来、再回头对齐缺口的两步走，代码里写明了后续怎么收尾。

### 配置菜单三项图标改成同一族

- 重命名 / 重置 / 删除配置改用 `file-pencil` / `file-minus` / `file-x`，与「新建配置」（`file-plus`）同属「一张纸 + 中间一笔」的形状族，四行并列时可辨认为同一组。
- 浮层菜单里的「重命名」（`edit`）与「重置」（`eraser`）不变：那两颗服务的是按键改名与命令 / 首页重置，对象不是一份配置。

### 导出配置那层补行尾箭头

- 那一层每行点下去是进系统的「保存到」，按「还会再开一层」的样式补右箭头；切换配置那层仍是选中打勾（`profileRows` 多了 `enter` 一位，判据是「点完去了哪」）。

### 「检查更新」图标改为 `cloud-search`

- 与首页顶栏的「重启模块」（`reload`）分开，两颗同形会被读成同一个动作；查到新版时仍是 `download`。

### 选「跟随默认」的回执不再写成 `follow`

- 「跟随默认」只在场景那份清单（`BRANCH_GROUPS`）里，而「一个动作怎么念」走扁平表（`ALL`）—— 它查不到名字就退回原始 token，回执成了「已绑定「follow」」。
- 现在那一格收成一份常量，`specOf` 一并查它：回执、网格小字、任何按名字念动作的地方都是「跟随默认」/「Follow default」。
- 加了一条单测（`ActionTokenTest.followIsNamedInsteadOfItsRawToken`）：判「查到了哪条字典键」，不判中文那四个字。

### 场景动作页不再出现两行一样的「松手执行额外动作」

- 「单击后长按」的松手卡原先按「只要是场景块就摆」写，于是单击 / 双击 / 三击 / 长按每一页底下都跟着一对逐字相同的行 —— 在长按那页上就是两行一样的东西。
- 现在它只摆在这一档自己的页面上（`target is Scene && g == ClickThenLong`），小标题也换成「按键设置」，与长按那一族并排时读得出是哪一档。

### 反射缓存不再把「这一趟没解析成」当成「没有」

- `Reflect` 的 `method` / `field` / `methodByNameAndArity` / `callStatic` 区分三态：命中 / 真没有（`NOT_FOUND`，写缓存）/ 这一趟解析不了（`ABORT`，不写缓存、下次重试）。
- 修「早期一次瞬态类解析失败会让那一处反射与 Hook 到进程结束都不再重试」，与文件里那句「不缓存，下次重试」对齐。

### 签名闸判不出来也算不放行

- 宿主接收器那道闸从「只拦签名不符」改成「只有判成官方包才装」：读不到签名先重试 3 次（间隔 1 秒），用完仍判不出来按「不是本包」处理。
- 修一个被改过、又把签名读崩的包仍能照常执行动作（fail-open）。

### 封存容器：IV 先判等再分配、条目名进 AAD

- 格式版本 1 → 2（读侧 `Seal` 与构建脚本 `SealReleaseAssets` 同名常量一起改）：条目名进 GCM 的 AAD，同一份容器里两条密文不能再互换位置（换位会让 tag 校验不过）。
- IV 长度改成「必须等于 12」之后再分配，不再先按 8MB 上限开一块。

### 「重启服务」收到宿主回执才杀自己

- 新增 `ModuleWire.ACTION_PAGE_RELAUNCH_ACK`：宿主主进程接下请求先回一条，设置页收到才杀自己；1 秒内没回执就提示失败、页面留着（原先没有人接收广播时照样杀 `:ui`）。
- 「本包进程」那条日志不再只列主进程（子进程 `:ui` 也要列），判据收成 `processName == PACKAGE || startsWith("$PACKAGE:")`。

### 录音状态查询：一次调用一份预算、一条常驻线程

- 等连接与等事务共用 2 秒总预算（原先是各 1.5 秒，一次判定最坏 3 秒、判定 + 停录最坏 6 秒，界面像卡住）。
- 发事务改在一条常驻的后台线程上等结果（`Future.get` 带超时）：对端卡住时只挂这一条，不再每失败一次就泄一条线程与两个 `Parcel`。

### 配置导出不再静默丢掉命令库

- 命令库读不懂（只读态）时直接报失败，不导出一份「命令全没了」的备份。
- 「保存到」没回结果时挂 120 秒兜底，解除导出占用 —— 原先一次结果不来，之后每次导出都被挡在门外。

### 多选应用分清主用户与分身

- 多选集合与行选中改用带用户维度的键（`appKeyOf`：`包名` / `999@包名`），条件里存下来的也是这个写法。
- 修「主用户与分身共用一格、选一个亮两个」与「分身那一条条件永远不命中」—— 判定侧只比包名（本机没有可靠的「前台属于哪个用户」判据），所以存的时候就要分得开。

### 快捷方式两处收口

- 注入侧那趟没回包（没 root / 超时）算「这一节没查全」（`LoadNotes.shortcutsFailed`），已绑的 `appshortcut:` 不再被静默降级成 `app:`。
- 快捷方式 id 里的 `%` / `/` / `|` 在目标写法里转义（`%25` / `%2F` / `%7C`），含分隔符的 id 也能读回来；不含这几个字符的老绑定一个字节都不用改。

### SystemContext 少扫一遍、少一行假告警

- 验缓存那份 Context 还在不在，区分「真的不在了」与「容器形状不认识」：后者按「还在」处理，不再每次取 Context 都全量重扫一遍并报一句假的「进程已经不在了」。
- 借 Context 时优先主用户的进程（分身 / 次要用户的进程活得更短）。

### 状态栏那条失败不再被吞掉，高频日志降到 `d`

- `StatusBarBridge.toggleRecentsLocal` 改走 `asSystem { ... }`：反射调用失败会真的报出来，而不是被 `call` 那层吞成「返回 null 也算成功」。
- 注入侧三条高频日志（「参数里没有 KeyEvent」「这颗键没开接管」「丢弃来源不明的广播」）与滑杆提交、浮层收起一起从 `w` 降到 `d`；判据级那几行（装没装上、这次按键是不是侧键、判成什么手势、配置到没到）仍是 `w`。

### 两处注释与实现对齐

- `KeyConfig.fieldValues` 的 KDoc 不再声称「落盘与广播都按它取值」：落盘的取值在 DTO 上另写一份，加字段必须两边一起改。
- `Config.comboFor` 的 KDoc 说清它与 `comboOff` / `liveCombos` 的差别（成员键是否接管由调用方补判）。
