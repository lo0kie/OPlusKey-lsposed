# 2026-11-11 · 快捷方式读系统活数据、组合键不再抢跑、命令正文折成一行

### 发版：1.4.1

- 版本号 1.4.0 → 1.4.1，`versionCode` 14 → 15。
- `ModuleInfo.BUILD_ID` 同步升到 `2026-11-11-0001`：这一版注入侧动了三处（快捷方式读取、撤 `HostWarmup`、组合键等宽），不换这把尺子的话，换了包、`system_server` 里还是旧的，界面照样判「同一次构建」。
- 用户可感知的那一版写在 `docs/release-notes/1.4.1.md`。

### 快捷方式：桌面上钉住的那几条改由注入侧读

- 「选择界面」的快捷方式一节新增「钉住」这一档：宿主读不到（它不是桌面宿主），改由注入侧按系统身份读快捷方式服务的活数据，与本进程读到的那批按 id 去重、本进程那份优先。
- 新增一问一答通道：宿主发查询、注入侧回结果，按编号配对，宿主最多等 300ms；等不到就只列本进程读到的那些，不清空清单。
- 桌面库（`launcher.db`）那条路试过并撤掉：库属桌面、宿主没有 root、uid 1000 直读被拒，只留服务活数据一条。
- 新增探针 `probe/shortcuts`（`pkg` / `user` 两个参数）：不动界面就能验「注入侧读不读得到」，与正式通道共用同一份读法。
- 已知限制补进 `docs/runtime/known-limits.md`：「起」这一条仍走既有 `ShortcutStarter`，能不能起还没有真机结论。

### 组合键：小的那一档不再抢在大的那一档前面派发

- `{A,B}` 凑成之后，若还有一档成员更多的组合（`{A,B,C}` 及更长）整串跨度还没用完，就先压住派发、到点再发 `{A,B}`。
- 等的期间来了大的那一档缺的那颗 ⇒ 换过去，派发的是大的那一档；成员已经松过手、又按下了别的键 ⇒ 小的那一档当场收尾派发，新按下的那颗走正常判定。
- 长按照旧按这一档自己的阈值派发，派发过之后不再升级。
- 判据按**真子集**算、跨度按成员颗数放大，四颗以上的链（`{A,B}` ⊂ `{A,B,C}` ⊂ `{A,B,C,D}`）走同一条路。
- 整串跨度的放大倍数封顶改用判定侧认的成员上限（`ComboKey.MAX_JUDGE_KEYS`）：原先按界面那三颗封，四颗以上的组合会被压成两个窗口、永远凑不齐。
- 新增两行判据级日志：「先不派发（还差几颗、窗口还剩多少）」与「等到点也没凑成」。

### 命令正文：换行在写进草稿那一刻折成一行

- 粘贴一段多行脚本、或打开一条带换行的老配置，正文折成一行（换行接 `; `，行尾 `\` 按连行处理，整行注释丢掉），单行输入框里不再出现「框是空的、值却还在」。
- 折在写入口一处：粘贴、全屏编辑写回、载入老配置三条路都过同一个 setter，调用点不必各折一次。
- 全屏编辑仍能显示多行（长命令在那里左右蹭着看），落盘的值是单行。
- 没有换行的输入一个字符都不动：逐行 trim 会吃掉正在敲的尾空格。

### 自定义命令：单条 / 多步两页表单各自独立

- 两页是两个独立编辑会话：存完一条、清空一栏、从菜单新开一条，动的都只是它自己那一页；另一页正编着的内容不再被无提示清掉。
- 「要不要放弃未保存的改动」改判**这条命令所属那一页**，不按当前停着的那一页判 —— 原先会问错人：问了却没丢东西，或者真编着的内容被静默覆盖。
- 保存时读值、判「在编哪条」、存完清空都落在同一个表单引用上，不再每次按当前页重新解析（两页各解析一次会拼出「单条正文 + 多条步骤」那种命令）。
- 整页归零只在页面出栈时发生（两页一起清）。

### 选择应用 / 选择界面：拿全才显示，默认档先上屏

- 两级页面进页先转圈、清单一次性铺出来，不再先铺缓存再换新的（会闪一下上一次的内容）；缓存只当「这一趟查失败」的兜底。
- 「选择应用」分两档交回：有启动图标的 + Xposed 模块 + 分身算好先上屏，剩下几百个没有图标的应用在后台接着算完再合并。
- 「选择界面」那一趟含一次跨进程往返（等注入侧回快捷方式），整趟跑完之前不铺列表 —— 先铺出去只会先列一半、再自己多几行。
- 两级共用同一套加载 / 空态组件，只有文案各说各的（新增 `app_picker.loading_activities`）。
- 判据行：`可启动应用：默认档 N 个先上屏，耗时 Xms（其余在后台接着算）`。

### 撤掉「开机预热宿主」

- 删除 `HostWarmup`：它在注入侧开机就拉起宿主那颗键服务，代价是每次开机自己弹一次模块页。
- 回到「开机后约 15 秒内侧键动作不执行」，已写进 `docs/runtime/known-limits.md`。

### 静态检查清零

- `ShortcutRead` 的 detekt 六条（`serviceInstance` 复杂度与 return 数、两处循环多跳转、`pinned` 的 return 数）已按函数拆分清掉，不再留「已知未过」。
- 同一轮清掉的还有：`ShortcutPull` 反向依赖 `ui.hook`（挪进 `apppicker`）、主线程 `Thread.sleep`（改挂起等待）、注入侧每次按压新建集合（判据改成直接收键）、`BlockedPrivateApi` 两处反射（注明只在 `system_server` 执行）。
