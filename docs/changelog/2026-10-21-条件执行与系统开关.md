### 上架流程：tag 留空就取最新那条存档

- 「上架到模块仓库」的 tag 输入改成可选：留空时取本仓库最新那条存档 Release 的 tag，点开 Run workflow 就能直接跑（原先必填，每次都要手抄一遍版本 tag）；
- 解析结果供后续每一步复用：checkout 的 ref、tag 与版本号一致性校验、取资产、清旧资产、组装 Release 正文；
- `concurrency` 改成全局串行（原先把 tag 拼进 group，而 group 在 job 之前就要定，留空时会变成空 group）。

### 条件执行：挂在按键上的一张顺序表

它以前是命令库里的一档命令，要从「按键绑定」页挑出来绑到某一档上；现在它只是**叠在按键绑定之上的一张顺序表**：

- 名字从「条件分叉」改成「条件执行」：顶栏标题、页内小标题、按键绑定页那颗菜单项、说明文字一起改；英文用 `Conditional actions`；剩下带「分支」的说法也都改成「条件」；
- 顺序就是判定顺序：按下的那一刻从上往下找，**第一条成立的就执行它的动作**；
- 一条都不中就走**按键绑定里这一档绑的命令** —— 分叉不占用绑定，表尾一句注脚标着这个去处（`快捷键 - 单击`，键名 - 点击类型，侧键那一组仍叫「快捷键」）；
- 每条 = 一个条件 + 一个动作（内置动作，或者「已保存的命令」里的一条），一行**左右两个格子**：左边条件、右边动作，中间一枚竖排三点；
- 两列**各点各的**：点左列换条件、点右列换动作，菜单各自弹在被点的那一格旁边；两列行首各带自己的图标；
- 中间那枚竖排三点**自己也是一个触点**：点开是「上移 / 下移 / 删除」；删除只在这里，条件菜单里不重复放一份；
- 中点「删除」**先弹确认窗**（「删除条件」/「这条条件和它的动作会一起删掉，下面的条件会往上顶一条。」）：上移下移都能挪回来，只有删除不可逆，而那颗三点离右列只隔几个 dp；
- 两列的壳与「按键绑定」网格的格子**同一套**（`Card` + `surfaceContainer`，按下 `surfaceContainerHigh`，按压只要涟漪），高度也取同一档（`TILE_HEIGHT`），字号比整行标题小一档（`body2`）；
- 格子里的文字走全项目那一处**光学竖居中**（`Modifier.opticalCenter`）：行盒居中于字、却不居中于墨迹（汉字不占 descent 那一段），偏移按字体实测，见下面「文字的光学居中」；
- 行距与网格同一档（`GRID_ROW_GAP`）；
- 一条都没有时给一块**空态**（字形 + 一行字，与「自定义命令」页那块同一个样子，字形也是同一档 22dp），说的是此刻的行为：「执行按键绑定里的 快捷键 - 单击」；表尾那句注脚讲的是同一件事，所以**表空时它不出现**（同一句话不在一个屏幕上说两遍）；
- 「添加条件」**直接加一条**，不弹条件菜单；新加的那一行**条件空着**（界面上写「未选择」），不替用户先填一个默认条件 —— 先填「亮屏中」看着像用户自己选的，一旦成立就悄悄接管这一档。空条件的行执行时永不成立、保存时也会被拦（「还有条件没选完」）；
- 列表有**增删动画**：加一条从 0 高度展开（淡入 + 纵向展开，只有刚加的那一行播，进页不整片展开），删一条先收缩再动数据（规格与「多条命令」的步骤行同一套）；行距挂在行自己身上，退场时那档空档跟着一起收，下面的按钮是一次平滑上移；
- 行身份（`BranchDraft.ids`）与规则一一对应：`AnimatedVisibility` 默认按**组合位置**记状态，删中间一行会让后面的行继承「已退场」的状态（当场再播一遍入场、下方还跳一下）——有了 id，删谁都只动那一行；
- 条件菜单顶部有一行小标题，写的是**这一格现在**的文字（与格子里那半行同一份文案，如「微信 在前台」/「未选择」）—— 打开菜单第一眼看到的是「我现在是什么」，不是十种可选；
- 中间那颗「更多」**纵向填满行高**（按图标那 24dp 算的话上下各有一截点不到）、左右各 2dp（图标自身留白之外只补一点，再多就把两格推远）；行高按格子那一档定死，`fillMaxHeight` 才有意义；
- 动作菜单里每个**小标题**（系统导航 / 媒体控制 … / 已保存的命令）与它下面那一列之间统一加一条细线；「添加命令」浮层与条件菜单顶部那行小标题也一样 —— 这条线现在由菜单按结构自己生成，调用方一项分隔都不写（见「菜单收拢」）；
- 条件菜单里**已经用掉的那几档置灰**（空着的那一行不算用掉），点一下只说「这个条件已经加过了」；
- **「前台应用」可以加多条**（微信一条、相机一条），只有**同一个应用**不能出现两次 —— 顺序表里两条相同条件时后一条永远轮不到。所以那一档不参与「置灰」，重复在挑完应用时拦（「这个应用已经加过了」，留在选择应用页不落盘）；其余九档仍是一档一条；
- 从这一页进「选择应用」时**不挑界面、也不挑小窗**：那一趟点一行就是**选中**（行尾画勾、其余行不画「点进去」那枚箭头），顶栏菜单里「以小窗口打开」不出现，写回去的一律是 `app:包名` —— 条件记的本来就是包名，而 `window:` / `包名/类名` 在这里没人读；进页还会把这一支**当前那个应用**点亮（条件取包名、动作取 token 里的目标）；
- 「（未选择命令）」这类占位改成「未选择」，不带括号；
- 表按「键 × 手势」各一份：在哪个手势页签进分叉页，编的就是哪一档，顶栏小标题也写这一档；
- 页内只有草稿：加一条 / 换条件 / 换动作 / 上移下移删除全都不碰配置，右下角那颗**「确定」是唯一的落盘点**（样式与「按键绑定」页那颗 FAB 同一份，往下滚就藏、往上滚就露）。半成品（空条件 / 空动作）按下去就地给一句原因，不灰着拦点击；
- 那一条底部的浮动工具条**撤掉了**（分叉页不再有重置 / 保存两颗圆按钮），草稿的作废交给返回时那道确认窗；
- 「添加条件」那颗按钮换成 COUI 的 **`Button` 本体**（默认次要配色，最小高度 / 圆角 / 内边距 / 按压反馈全走 `ButtonDefaults`），撑满整行所以关掉按压缩放；左右边距收进组件自己（`PAGE_MARGIN`，与列表同一档）—— 原来表里那份靠外层 `Column` 的 `padding`、空态那份直接铺满整宽 ⇒ 表一空按钮就贴到屏幕两边；
- 「其他情况」那一档去掉了 —— 它不再是列表里的一行，而是表尾那句注脚，写的是「以上都不成立时执行 快捷键 - 单击」；
- **修掉「退不出这一页」**：改了还没保存就按返回时，`goBack` 会拦住并置「放弃未保存」那一位，而分叉页没挂那个确认窗 ⇒ 返回被吞掉、界面上什么都不发生。现在那一页把它挂上了（放弃时两份草稿一起清）；
- 命令库里不再有分叉这一档：老文件里 `kind: "branch"` 的条目读的时候按认不出的类型跳过（那批数据不再执行）。

### 可分叉的条件

「添加条件」先挑条件种类，这一版支持九种（**菜单与格子共用同一份短词**，一条一行只占半行）：

- **前台应用**（取值：包名，从「选择应用」页挑；格子里写「微信 在前台」）；
- **屏幕状态**（取值：亮屏 / 锁屏 —— 原来是「亮屏」「锁屏」两档，合并成一档：两档其实是一个维度的两端，分开摆要选两次才知道在问什么；亮屏那颗字形用一块屏 `device-mobile`，锁屏那一档的取值行用锁头）；
- **充电**（含充满，字形 `battery-charging`）；
- **耳机**（取值：已连接 / 未连接 —— 有线 / USB / 蓝牙 A2DP 都算「接着」；两档是真正的正反两面，所以「未连接」直接取反）；
- **媒体播放**（取值：播放中 / 暂停中 —— 「暂停中」的判据是「眼下没有音频在放」，`isMusicActive` 取反；要区分「真有会话但暂停」得读 `MediaSessionManager`，那需要通知读取权限）；
- **WIFI**（取值：开 / 关）；
- **小窗**；
- **响铃档位**（响铃 / 振动 / 静音；格子里直接写「振动」）；
- **屏幕方向**（竖屏 / 横屏；格子里直接写「竖屏」）。

判据都只用宿主 uid 本来就拿得到的系统接口（项目里权限按 uid 判，清单里声明什么对宿主没用）；**判不出时按「不成立」处理** —— 直接落兜底，不猜一个值。

**老配置的兼容**：`screen_on` / `locked` 这两个类型名在 `BranchCondition.parse` 里翻译成 `screen:on` / `screen:locked`（读的时候归一，不往用户文件里偷写）；`wifi` / `media` 以前没有取值，现在靠 `ConditionKind.defaultChoice` 按 `on` / `playing` 解释。

### 系统开关：一个动作变三档

- 「系统开关」那一格从**快捷工具**移到**系统操作**分类（它动的是系统状态，不是某一颗按键）；
- 点开之后仍然是那十条开关，但**点某个开关不再是立刻落一个「切换」动作**：再弹一层「切换 / 打开 / 关闭」，三行各有自己的字形（切换用开关自己的图标，打开 `toggle-right`、关闭 `toggle-left`）；
- 落盘写法：切换仍是老样子 `setting:wifi`，明确开 / 关是 `setting:wifi:on` / `setting:wifi:off`（`Action.Setting` 多一位 `on: Boolean?`，`parse` 认最后一段后缀，认不出就当 id）；
- 执行侧：**切换**才读当前状态（读不到就不动，避免把开着的关掉）；**开 / 关**直接把目标值交给 system_server，不读状态；
- 自动旋转 / NFC 这两条的状态只有服务自己知道，注入侧改成「`on` 有值就用它，没有才读一次再取反」；
- **免打扰与手电筒也收进 `setting:` 那一族**（`setting:dnd` / `setting:flashlight`），于是它们同样有三档：明确的开 / 关要能把目标状态写进 token，而老的 `oplus:no_disturb` / `flashlight` 只能表达「切一下」。老写法仍按原路执行，只是不再写新的；
- 这两条的执行各走各的通道：手电筒由宿主的 `FlashlightController` 调 `CameraManager.setTorchMode`（明确档传目标值，「切换」仍走 ColorOS 侧键服务，失败退 CameraManager）；免打扰由注入侧调 `notification.setZenMode`（`ZEN_MODE_OFF` 之外都算开着）；
- **修掉「NFC 切换无效」**：注入侧那一支把「当前开着」当成了「目标开着」，切换永远变成「设置成它现在的样子」。真机日志是 `getState=3` 紧跟着 `目标=开`；取反补上之后才对。自动旋转那条的写法看着像同一个坑，其实两个否定叠起来正好是取反，加了注释免得被「顺手修正」。

「选择应用」页里当前选中的那个应用**只在菜单里上主题色**（行首换对勾、文字走 `primary`）—— 列表行本身保持原样；条件菜单里**这一条现在那一档**同样画成选中，改条件时不必从十行里自己找。中间那颗「更多」不再左右留白（缝由两列之间的间距给）。

### 按键绑定页与首页分工调整

- **按键清单搬到首页**：首页新加一节「按键」，一颗键一行（侧键在最上面，收集来的键按清单顺序往下排），点哪颗就进哪颗的绑定页；
- **「添加按键」也搬到首页**：那一节的最后一行，流程与原先一致（按下要收的键 → 起名字 → 确认才落盘）；到数量上限时那一行灰着，副标题写清原因；
- 停用的键在清单里照样能点进去，副标题写一句「已停用」（那一页顶栏另有一枚同样的标记）；
- **「按键绑定」页顶栏那份 ⋮ 菜单只剩对当前这一颗键动手的三行**：重命名 / 停用（启用）/ 删除 —— 顺序按破坏性从小到大；
- **「重置绑定」整条路去掉**（菜单项、确认窗、对应文案与那段写配置的代码一并删）——它旁边就是这三档绑定本身，删掉之后少一条「按下去什么都没了、还不知道从哪改回来」的路；
- 「按键绑定」卡片因此变成两行：主开关 + 通用设置。

### 「条件分叉」从页签变成独立页

- 「自定义命令」页的页签回到**两个**（单条命令 / 多条命令）；
- 「条件分叉」改从「按键绑定」页 ⋮ 菜单进，**单独一页**（标题与菜单项同名）。页面本体仍是那一套表单（名称、分支表、已保存的命令、底部保存 / 重置），只是不再有类型选择器带子；
- 两页共用同一份草稿：进分叉页先把草稿清空、类型拨到分叉（这是「新建」的入口，与命令页那颗 FAB 同一条规矩）；
- 退出时的「放弃未保存的命令」、未保存就没收的草稿、底部工具栏在分叉页同样生效；
- 挑条件的应用 → 「选择应用」页 → 选完**退回分叉页**：不再往「自定义命令」页跑（那会让调用方多退一层、还会弹出那个放弃草稿的确认窗）。

### 卡片列表改成项目自己的一份实现（`ui/CardRow.kt`）

- 新增 `CardList` + `CardRow`（`Item` / `Switch` / `Custom` 三种行）：**行数、行在卡里的位置（首行 / 中间 / 末行）、行间那条细线**全部由列表自己算，调用点只写「这张卡有哪几行」；
- 条件行不再靠 `rows = BASE + if (…), cardListPositionOf(i, rows)` 那种手算 —— 用 `buildList { if (…) add(…) }` 组出来，行数自然是真相（少一行、多一行都不会再让卡片首尾圆角错位）；
- 会时有时无的行（振动强度、连续触发时振动 / 触发间隔）用 `visible = …`：**连分隔线一起**做进出场，不再需要各处手写 `AnimatedColumn { HorizontalDivider(); Row() }`；
- 已在用它的页：首页三张卡、通用设置两张卡、更多选项的四张卡（运行状态 / 配置 / 外观 / 关于）、按键设置三张卡、分叉卡、命令间隔卡、捐赠空态卡、「自定义命令」入口卡；
- `PageMetrics` 里那批「这张卡有几行」的常量（`HOME_BINDING_ROWS` / `ABOUT_ROWS` / `MORE_CONFIG_ROWS` …）随之删掉，整类账消失。

例外两处**保持原样**（都不是普通列表，行级动画是它们的功能）：`CommandSteps` 的步骤行（增删 / 上移下移时行要单独收缩退场）、`LinkStatusCard` 的机型 + 链路明细已经改用 `CardList`，其行增删的交叉过渡一并去掉。

### 首页按键行

- **停用的键换行首图标**（`pointer-cancel`）：一眼扫过去先看见「这颗不接管」，不再只靠整页变灰反推；
- 副标题**两档都给**：「已启用」/「已停用」—— 行高一致，且「停用」不只靠颜色区分。

### 首页「其他」卡

- 「通用设置」下面加一行「自定义命令」（与那一页顶栏同名，副标题「一条命令或多个动作」）：
  点了进命令库那一页，先把草稿清干净（与「按键绑定」页那颗 FAB 同一条规矩）；
- 这一行与「通用设置」同一档：吃整页总闸（它会写配置）。

### 删除按键

- 删除成功后**直接回首页**：删掉的正是这一页正在编辑的那颗键，留在这里已经没有对象（选中态落回侧键、页面内容换成侧键的绑定，看着像删错了）。写盘失败不退走 —— 那颗键其实还在配置里。

### 分叉那几张菜单

- **锚点改成「每行一份」**：原先好几个分支行共用一份 `PreciseClickState`，而库记的是「这一行被按在哪」—— 共用时只有最后布局的那一行说了算，菜单于是总弹在同一处、不跟手指。现在每一行（含末尾两行「添加」）各持一份，点哪行就把那份递给菜单；
- 第二层（选动作里的入口格 / 条件里的响铃档位与屏幕方向）**由各自那张一级菜单持一份锚点**，二级挂在它上面 —— 触发点在菜单里，没有卡片触点可用；
- **条件种类菜单与「选择命令」菜单限高**（与「添加命令」那层同一档 320dp），十种条件放不下时滚动，不再顶出屏幕。

### 图标

- 「自定义命令」那两处入口（首页「其他」卡、按键绑定页那张入口卡）行首换成 `code-plus`：
  入口行的图标表示**去处**，纯加号留给「加一条」这类**动作**（FAB / 加一步 / 添加分支）。

### 分支菜单每一项各给一颗自己的字形

- 「选择条件」那张菜单十种条件各有一颗（前台应用 / 亮屏 / 锁屏 / 充电 / 耳机 / 媒体 / Wi-Fi / 小窗 / 响铃 / 方向），不再共用同一颗 `arrows-split`；
- 「响铃档位 / 屏幕方向」那层按取值分字形：响铃 / 振动 / 静音各一颗，竖屏 / 横屏也各一颗；
- 第一层「选择命令」那一行显示这一支**现在真正执行的动作**的图标（引用命令库时是那枚引用字形，存的是内置动作时是那个动作自己的图标），未选时才是空命令那颗。

### 响铃档位 / 屏幕方向改成真二级

以前点这两档是「收起条件菜单，再弹一张取值菜单」—— 两次开合在手上就是菜单闪一下又换了一张。

- 现在一级**留着**，取值挂成二级（与「选择命令」里入口格那一层同一条路），一次点开就到位；
- 条件那十行只在**要取值的两档**与**前台应用**上画行尾指示：前两档是选择器字形，后者是右箭头（那档要跳「选择应用」页挑应用）；
- 二级选中后两级一起收，落条件仍是原来那一步（取值没填的条件照旧不许存）。

### 菜单收拢：调用方只给「行」和「锚点」

- `MenuEntry` 只剩两种：`Row`（一行内容，`dividerBefore` 标它前面该用加深带）与 `Section`（小标题 + 一组行）。**行间细线、小标题下那条线、组与组之间的加深带全部由菜单按结构生成** —— 原先八个调用点各写一遍 `RowLine` / `GroupLine`，漏一处就少一条线；
- 单层菜单统一走 `PageMenu(entries, 锚点, onDismiss)`：`show` 由「行表空不空」表达（`takeIf { 开着 }.orEmpty()`），最大高度、压暗、锚点转发、页面离开登记全在组件里。业务层不再出现 `MenuPopup(...)`；
- 「点一行还要再叠一层」的那类（入口格的档位、系统开关的切换 / 打开 / 关闭）统一走 `ModeMenuPopups(tile, current, onPick, onDismiss)`：两层、以及两层之间的守卫（第二层开着时第一层不接关闭请求）只有这一份实现。**网格那条路原先漏了守卫**，真机表现是「点一个开关，两层一起消失、什么都没选中」；
- 「这一行点了还有没有下一层」由模型回答（`ActionCatalog.stateMenu`），界面不认 token —— 手电筒这类只有一种写法的开关自然只给一行；
- 入口格菜单里**有下一层的那几行**才画行尾选择器；叠层的位置改用**上一层里手指按下的那一点**，不再钉在格子上；
- `modeEntries` 搬进组件层：它服务网格 / 添加命令 / 条件执行三处，原先住在「只服务命令那一屏」的文件里，等于让通用组件反过来认识具体屏（`docs/decoupling.md` 的判据）。包级依赖边 31 → 30 条。

### 文字的光学居中

- 早先按字重写死两个比例（Regular 0.035em / Medium 0.1em），那是从两个**特定字体文件**的 `hhea` 度量里量出来的 —— 中文字体刚好、英文字体偏下；
- 只关 `includeFontPadding` 不管用：它去的是行盒外层留白，不动 `ascent : descent` 的比例，真机实测零变化；
- 现在 `Modifier.opticalCenter(style)` 的偏移**全是量出来的**：行盒高与基线位置来自 `TextMeasurer`（按当前 `TextStyle`），墨迹上下边界来自 `Paint.fontMetrics.top/bottom`（字形极值，比 `ascent/descent` 贴近真实墨迹）。换字体、换字号、换字重都自动跟着变，没有常数；
- 用在十处竖居中的单行文字：网格格子标题与小字、应用种类胶囊、选择应用行标题、条件执行的格子、命令参数行、已保存命令的标题与摘要、提示胶囊、捐赠表格单元格；
- 多行文字不加：眼睛看的是基线，整体挪一下反而让行距看着不匀。
