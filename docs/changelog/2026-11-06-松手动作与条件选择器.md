# 松手动作接应用控制、条件改用选择器弹窗

> 上一笔（`a8fcfb7`）之后这一轮的改动。那一笔的片段已冻结，不再改。

## 修改与修复

### 修改：松手动作抽屉补上「应用控制」、行首不再换成对勾

- 「松手后再执行」那个抽屉里现在有「应用控制」：点它选打开 / 结束，再进「选择应用」挑应用 / 组件 / 快捷方式，写进这颗键的松手动作。变量那一格仍不列（这一趟没有那条去路）。
- 抽屉里「当前那一档」不再把行首字形换成对勾：换成对勾之后，「当前是哪个」与「这一行是什么」只剩颜色能分，扫一列下来全是对勾。选中仍由整行主题色说。

### 修改：键名的引用统一用半角方框

- 「已停用 / 已启用 / 已删除 / 会从按键清单里删掉」这几句里的键名，从 `「侧键」` 换成 `[侧键]`（与组合键列表、确认窗那一套同一个长相）。

### 修改：录屏那三档带后缀

- 选择器里三行写成「开始录屏 / 结束录屏 / 切换录屏」，不再是光秃秃的「开始 / 结束 / 切换」——那一层是从「小布 AI」菜单点开的，小标题只写「录屏」，短到只剩动词时一眼分不出说的是哪件事。

### 修改：场景命中时，松手那一档让位

- 长按那一档配了系统场景、并且命中了规则时，「松手执行额外动作」不再执行 —— 一次按压只有一个结果；场景一条都不中时松手照常执行（它只做补充）。

### 新增：组合按键也有「松手才触发 / 松手执行额外动作」

- 组合键的长按卡补齐这两行（与单键同一张卡、同一套判据）：判定侧在抬手时补发一条松手事件，执行侧按这一档组合的 `longRelease` 取动作。
- 「松手才触发」时不连发（与单键那三条时序的互斥同一条口径）。
- 松手动作可以挑应用 / 组件 / 快捷方式，写回落在这一档组合上。

### 修改：场景的取值改用选择器弹窗

- 点场景里的一行条件，一级仍是浮层菜单；选完种类后取值的**第二层菜单换成选择器弹窗**（标题写这一档的名字，用过的取值置灰，当前那一档行尾打勾）。
- 条件菜单里那几行的**行尾选择器撤掉**：点下去弹的是弹窗、不是另一层菜单，那枚「还有一层」的字形会读错。「前台应用」仍进另一页挑应用，那一枚右箭头留着。

### 修复：「选择应用」页挑完没提交就返回，草稿无声丢掉

- 二级页点过确认、还没按右下角那颗提交就按返回时，先问一句「放弃这次选择」，说的是将要丢掉的那一条。
- 选「放弃」才退页；取消就留在这一页，草稿与那颗提交键都还在。
- 只在**挑中过一条**时问：进页看一眼就退的那一趟没有可丢的，不会被这一问拦住。

### 修改：非 Monet 配色下首页状态卡的底色加深

- 非 Monet 那套的字色不再掺强调色，色相全压在底色上，原来那两档（浅色 16% / 深色 24%）在真机上仍是一张浅灰卡 —— 提到 26% / 34%。
- Monet 两档不动。

### 修复：多条命令列表的编辑态里，行尾三颗按钮叠在一起

- 库把行尾槽限在行宽的六成，三颗 32dp 的按钮加两档间距超过那条上限后被压成同一处，图标互相压住、只有最上面那颗点得到。
- 三颗改成并排、按行尾槽的实际可用宽度一起收紧（下限 28dp），图标跟着缩，不再叠。

### 修改：「已绑定 …」那条回执改用格式化后的动作文案

- 内置动作、入口格档位与自定义命令那一档不再取裸名，改走与步骤行、命令卡摘要、执行提示同一支实现 —— 绑定自定义命令现在报「已绑定「自定义命令: 录音」」，与步骤行里那一行逐字一致。
- 打开 / 结束应用那一族仍是「父格 + 动词 + 目标」，不变。

### 修改：「松手后再执行」改称「松手执行额外动作」

- 长按设置卡上的那一行开关与它下面那一行，文案统一改成「松手执行额外动作」/「额外动作」。
- 挑动作那一层抽屉的标题同步改名。

### 修改：「松手执行额外动作」与「长按连续触发」不再互斥

- 两者可以同时打开：按住期间照常连续触发，松手那一刻再执行额外动作。
- 连续触发那一族不再因为配了额外动作而置灰。
- 「松手才触发」仍与这两项互斥：开着它时，连续触发与额外动作都置灰但不隐藏，点一下会说明原因。

### 修改：系统场景的一条规则改成两张卡片

- 「场景」与「动作」各占一张卡，中间留一档间距；动作卡不再靠一条加深带与场景行分隔。

### 修改：主题「跟随系统」换图标

- 由自动亮度那颗「A」换成半黑半白的对比圆，与浅色太阳 / 深色月亮、系统配色色板摆在一起时同一族。

### 修改：抽屉里「录屏」那一行去掉行尾图标

- 抽屉里录屏那一行不再挂选择器字形（它点开是弹窗，不是下一层清单）；网格那一格与其它入口格不变。

### 修改：滑杆手动输入窗的范围提示

- 输入框占位从「手动输入（200–2000）」收成「手动输入」。
- 值域与步进只在输入框下面说一次：「范围 200–2000，步进 50」，填着字时也看得见；标题行尾那格不再重复画区间。

### 修改：录屏三态选择器把「切换」移到最上面

- 弹窗行序改为「切换 / 开始 / 结束」，最常用的切换留在第一行。

### 修复：多条命令切进编辑态（排序态）必崩

- 现象：命令页「多条命令」那条，点右下角进排序态，行尾长出上移 / 下移 / 删除三颗时宿主直接闪退，`IllegalStateException: Asking for intrinsic measurements of SubcomposeLayout layouts is not supported`。
- 成因：上一轮为收窄这三颗按钮加的 `BoxWithConstraints` 建在 `SubcomposeLayout` 上；而 COUI 的 `BasicComponent` 在量行尾槽之前会先问一次它的**最大固有宽度**（`Component.kt` 里算 `endHardCap` 那行），问到 `SubcomposeLayout` 就抛。
- 改法：宽度改由 `Modifier.onSizeChanged` 拿 —— 回调里就是库按 `endHardCap` 定下来的实际槽宽，与原先的 `maxWidth` 同一个数，但不参与固有尺寸计算。首帧还没回调时按「放不下」算（28dp 下限），量到之后再放开到 32dp。

### 修改：放弃草稿那一问改念格式化后的目标

- 正文里那个名字原先是 `draft.label` 裸名（应用名 / 界面名 / 快捷方式名），退出时看不出丢的是「微信」还是「微信(扫一扫)」。
- 改走 `appTargetLabelOf`：应用名 [+ 小窗] [+ 组件名 / 快捷方式名]，与顶栏「已选择」那行、网格小字、命令卡摘要同一套拼法；`shortcutId` 与「小窗口打开」那一档一起带过去。

### 修复：配置结构变了但 VERSION 没抬

- `ComboDto` 多了 `long_fire_on_release` / `long_release_on` / `long_release` 三个字段，`ConfigCodec.VERSION` 仍是 26 —— 已有配置会被 md5 校验判成「读不懂」，表现是页面只读、注入侧不接管。
- 抬到 27，并刷新 `tools/config-shape.txt`。

### 修改：绑定回执不再自己拼动作名

- `ActionCatalog.label` 的全项目直接调用从 2 处收到 1 处（只剩 `actionTitle` 一族）；`tools/audit-arch.py` 的上限跟着收紧。
- 两处 i18n 兜底跟上字典：`toast.key_deleted` 改用 `[%s]`，`binding.long_press_release_title` 用「松手执行额外动作」。

### 修改：「松手才触发」不再连坐连续触发

- `KeyConfig.longRepeats` 的排除项从「松手那一下的两种时序」收到只剩「松手才触发」：额外动作管的是抬手那一刻，与按住期间重复几次互不干扰。
- 「松手才触发」开着时，连续触发与额外动作都仍置灰（它们都要用「松手那一下」，同时开就是同一刻执行两个动作）。
- `KeyConfig.longOnReleaseTiming` 这一位随之撤掉；`GestureDetector` 那处 KDoc 跟着改。

### 修复：三条时序的互斥口径写在数据层注释里是错的

- `KeyConfig.longFireOnRelease` / `ConfigFields.LONG_FIRE_ON_RELEASE_EXTRA` 里写着「三者互斥」，实际生效的只有两条（见上），注释与判据一起对齐。

### 修改：抽屉里「应用控制」保留，只剔变量那一格

- 长按卡那个抽屉（`StepSheetFilter.excludeTiles`）原先连「应用控制」一起剔 —— 那一项现在确实能写进 `longRelease`（打开 / 结束应用走「选择应用」页，落点 `PickTarget.Release`）。
- 变量那一格仍不列：这一趟没有那条去路，点了只会关抽屉。

### 修改：录屏三档的键名从「开始」改成「开始录屏」

- 新增 `catalog.screen_record_start` / `screen_record_stop` / `screen_record_toggle` 三条文案，不再借 `common.start` / `common.stop` —— 那一层是从「小布 AI」菜单点开的，短到只剩动词时看不出说的是哪件事。

### 修改：主题「跟随系统」那颗图标

- 由 `brightness-auto`（一个「A」）换成 `contrast`（半黑半白）：与浅色太阳 / 深色月亮、系统配色色板摆在一起时同一族。

### 修改：条件一级菜单的二级收口

- 二级取值改成选择器弹窗后，一级菜单在弹出弹窗那一刻收起（`menus.closeConditionMenu()`），不再两层浮层叠着。
- 弹窗的收起动画要播完：`subKind` 变 `null` 时记一档 `lastKind`，`show` 单独给，不做「一变就摘」。

### 修改：`PickerRow` 支持行首图标与置灰

- `PickerOption(label, icon, enabled)` 替代原先的裸 `String` 列表：取值那一列（亮屏 / 锁屏）靠字形分档，纯文字那几列不给。
- 壳仍只有 `SinglePickerDialog` 一份，`labels` 那两个重载原样留着（内部转成 `PickerOption`）。

### 修改：`PageNameDialog` 的值域只在一处说

- 填数值时不画标题行尾那格小字（原先是取值区间），区间与步进改由 `hint` 常驻在输入框下面（`slider.input_range`）。
- 填名字时行尾仍是字数统计。

### 过闸

- 抽了三处顶破 detekt 的函数：`StepButton` 收成 `StepButtonTone` 枚举（参数 6 → 5）、`goBack` 的两张确认窗各抽一支再并进 `when`（ReturnCount 5 → 3）、`writeToken` 的落点判断抽成 `writeLongReleaseTo`（圈复杂度 15 → 阈值内）。
- `GestureExec.handleCombo` 的 ReturnCount 从 6 降到 4：两道前置守卫合并、松手那一档抽成 `runComboRelease`。
- `config/detekt/baseline.xml` 新增 5 条 —— 全是本轮新写的代码带来的，不属于「存量容忍」：
  · `LongMethod:PagePicker.kt$PickerRow` —— 加了行首图标以后那一支超 60 行，拆开会把「一行怎么画」拆到两个函数；
  · `MatchingDeclarationName:PagePicker.kt$PickerOption` —— 与 `PickerRows` 同处一文件（三件一体，拆文件反而难找）；
  · `LongMethod:CommandConditionMenus.kt$BranchConditionMenu` —— 一级菜单 + 二级弹窗同一处的状态又多了一位 `lastKind`；
  · `TooManyFunctions:AppPickerState.kt$AppPickerState` —— 多了 `openForRelease` 一族；
  · `LongParameterList:SinglePickerDialog(options=…)` 那条是误加（函数上已有 `@Suppress`，detekt 把 `@Suppress` 也当签名的一部分记下来了），随后撤掉。
- `PagePicker.kt` / `AppPickerState.kt` 两处 KDoc 叠在别的声明上，已各归各位。
- 未使用的 `Gesture` import 从 `ComboDetector.kt` / `GestureForwarder.kt` 删掉。
