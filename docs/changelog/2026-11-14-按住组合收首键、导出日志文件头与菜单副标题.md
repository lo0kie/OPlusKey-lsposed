# 2026-11-14 · 按住组合收首键、导出日志文件头与菜单副标题

### 改：按住组合改成「首键一颗 + 后续成员任意多颗」

- 原先「先按住第一颗」与「先按住第二颗」是两个模式位，而且只对两颗成立（三颗读回来被夹回等待档）。现在合成一档：`keys` 有序，第一位就是首键，其余成员在窗口内陆续按下即可，**颗数不限**。
- 于是「按住 A 再按 B、C」与「按住 B 再按 A、C」是两档不同的组合（首键不同）；后续成员之间**没有顺序要求** —— 三根手指排好队落下这件事人手做不到。
- 新增组合那一窗按成员数列行：三颗就列三行，每行把其中一颗排到最前；已经当过首键的那一行置灰（同一种按法只能有一档）。`comboModeTotal` 从常量 3 改成 `1 + 成员数`。
- 判定侧：后续成员的接收窗口写死 150ms（与 `windowMs` 分开 —— 那个数还管着单击手感，不该被这一档借走）；`ConfigChannel.inAnyCombo` 与 `joinsCombo` 分开，前者只答「归不归组合管」—— 拿后者挡的话，三颗的按住组合永远凑不齐。
- 配置 62：`ComboDto.mode` 的 1 / 2 归一成 1，读到 2 时把第二颗提到首位。老文件就地迁移，写回不再出现 2。

### 改：导出的日志带文件头

- 正文全是时序行，答不了「这是谁的机器」「三个进程都活没活」「界面自己说哪里断了」。导出时先拼一段文件头：设备与系统、三个进程各报的 `BUILD_ID` 与缓冲行数、界面侧状态、配置摘要。
- 三个进程的版本可以不一致（换包没重启时 `system_server` 里还是上一版），而「没回包」与「在跑但没日志」是两回事 —— 构建号与行数每片都带，收方直接写进头里。
- 缓冲的**溢出计数**与**最近一次异常的完整栈**也进去：前者让「日志缺了开头」能看出是被裁还是本来没有，后者是因为栈太长、进环形缓冲会把判据行挤掉，另存一格附在文件末尾。

### 改：首页菜单两行加副标题

- 「重启服务」下面写宿主进程已经跑了多久（`已运行 2 小时 13 分`）：时长取宿主报活时带过来的进程启动时刻，不另问一次。
- 「导出日志」下面写这次会导出去多少（`缓冲区 1234 行`）：跨进程把几份缓冲收上来再数。
- 两样都在**打开菜单那一刻异步取**（日志那条要等几百毫秒的跨进程回包），不进组合期。

### 改：删自定义键之前先反查组合

- 还在组合里的键不让删：点「删除」先看有哪几档组合用它，有就弹「无法删除」说明窗，正文点名那几档（键名仍是名字框），动作项只有「知道了」。
- 不拦的话删完那几档组合会指向一颗不存在的键，执行侧认不出、静默失效。
- 那一窗里按住组合那一句补了居中：`ChipSentence` 自己撑满整行，光靠外层 `Arrangement.Center` 只摆得动盒子、摆不动盒子里的字。

### 改：「重置模块」确认窗的「不可恢复」单独居中

- 正文拆成两条：第一句说明重置了什么（左对齐、长了会折行），「不可恢复」那一句短、单独居中。原来是一整段 `summary`，整段按长正文左对齐。

### 修：菜单行禁用时副标题不压暗

- 库那一套里只有 `disabledContentColor`（管标题与行首），摘要那两格没有对应的禁用档 —— 禁用行的副标题比它自己的标题还亮，读起来像「这一行还能点」。现在按行把 `summaryColor` / `selectedSummaryColor` 换成 `disabledContentColor`（面板那层仍是透明的，磨砂照旧）。

### 改：默认配置那一行补一句小字

- 升级时落下的那一份是退路（改不了名、删不掉），光看名字读不出这回事 —— 副标题写「无法改名或删除」。其余几份是用户自己起的名字，没有要解释的。

### 改：几处文案

- 按住组合的颗数上限：「只能是 %d 颗」改成「最多 %d 颗」—— 现在是「首键 + 任意多颗」。
- 新增 `menu.restart_uptime` / `menu.log_buffer` / `dialog.reset_module_irreversible` / `profile.default_summary` / `binding.delete_key_blocked_*` / `common.got_it`。
