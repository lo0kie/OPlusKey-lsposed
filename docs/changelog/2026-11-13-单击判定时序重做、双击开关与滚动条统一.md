# 2026-11-13 · 单击判定时序重做、双击开关与滚动条统一

### 改：单击判定时序重做，「忽视无操作双击手势」退场

- 删掉 `instantSingle`（界面上的「忽视无操作双击手势」）：它管的是「双击没绑动作时不等窗口」，而这件事现在由**动作表**直接决定 —— `judgeCap` 按绑了哪几档算，最高只数到一击时抬手即判，不为没有的第二击压一个窗口（用户报的症状：单击延迟设成 1000，按一下真等了一秒）。
- 两种判定时机各自说清，界面上那颗开关改名「固定窗口起点」（存的是 `waitMultiWindow` 的**反面**）：关着 = 窗口从**首击抬手**起算、后续按压不延长，一个窗口内收集到几击算几击；开着 = 每次松手重新起算，按压越久等待越长。
- 两者**数到最高档都当场判**，不再等窗口 —— 已经收够了，窗口里只可能是超出档位的第 N+1 下。
- 新增 `multiWaitMs`（「等待窗口」一根滑杆，只在「每次松手重新起算」时出现）：原来它和「单击延迟」共用一个值，于是压短单击就得同时压短连击窗口。默认 0 = 跟随单击延迟，升级前后手感一字不差。
- 配置 48 / 49 / 50：`multi_wait_ms`、`double_click_on` 各一格；`instant_single` 从 `KeyDto` 与 `GlobalDto` 一起删掉（老文件里那一格按未知键丢掉）。

### 新增：双击这一档也有开关了

- `KeyConfig.doubleClickOn`，默认**开**（与三击 / 四击默认关相反：双击是基础档，不会让单击白等窗口）。位置在独立设置那张手势卡里，「只参与组合按键」下面、三击上面。
- 关掉之后与「关三击」同一条口径：绑定页不排双击那一页、场景块的动作行不列它、执行侧对双击恒回「无操作」、`boundClicks` / `sceneClicks` 都不算它。表里配过的动作留着，再打开原样回来。
- `GestureTrigger.slotsOn` 多一个 `doubleClick` 参数，五个读者（分页器、绑定页、场景块、`BindingTarget`、调试页）一起按它过滤。

### 改：「单击」那三行从按键绑定页挪进独立设置页

- 判定时机 / 等待窗口 / 单击延迟整张卡搬到 `Screen.KEY_SETTINGS`，与上面「有几档」是同一片页面的事。原先同一个参数在绑定页和独立设置页各有一个入口，进哪页看到什么取决于刚才怎么点进来的。
- 改哪一颗键由调用方给（`toggleKeyParam(keyId, …)`）：原先它现取 `KeyWatchState.editing`，那是「按键绑定页当前选中的那颗」，挪页之后这份状态不再代表这一页在改谁。
- 窗口滑杆按 `judgeCap > 1` 判「有没有多击手势」，没有就灰着并给一句「没有启用任何多击手势」—— 与判定侧同一个判据，不在这里另写一遍 `doubleClickOn || extraClicksOn…`。
- 连带删掉 `InstantSingleCard` 与 `KeySwitchTexts`（后者只为那一行的标题与回执共用一份文案而存在）。

### 改：只参与组合的键改成「先吞后判」

- 那颗键按下时**先压一个窗口**再问组合：凑成了永久吞，没凑成由注入侧把系统本来该收到的那一次短按补发回去（`injectNativeShortPress`，异步投递）。
- 之前是「先放行、成了组合再补一次」，那颗键的原生动作（音量 ± / 电源）已经跑过一遍、撤不回来。代价是单按会晚一个窗口才出效果。
- 补发的事件会重新走一遍输入分发、再进一次拦截链 —— 认不出来就是死循环（吞掉 → 补发 → 又被吞）。所以带一本「回声账」（`nativeEcho`，keyCode → 条数 + 过期时刻，TTL 2 秒）：见到就放行一次、销一次账。
- `ComboDetector.comboCovers` 给收尾那一步一个判据：这颗键此刻是不是某一组组合的成员，只回答「归不归组合」，不回答「这一下成没成」。

### 改：多击档没动作时逐级回退

- 判定侧只报「数到了第几击」，报上来的那一档未必配了动作（只开四击、按了两下 ⇒ 报 `Click(2)`，而双击那格空着）。现在退到最近一个有动作的档，退到单击也算 —— 原先的表现是「按了没反应」。
- 注入侧看不到动作表（它只认 `judge_clicks`），所以这一步只能在执行侧做。

### 改：滚动条收成一份，抽屉与图标网格都接上

- 新增 `ui/row/AppScrollBar`：常亮、按住滑块走通用振动通道（`Modifier.scrollBarTick`，判据是「DOWN 已被库里 consume」）、轨道两端留白。三个重载分别吃 `ScrollState` / `LazyListState` / `LazyGridState`。
- 浮层菜单、选择应用列表、图标选择器、更新弹窗、抽屉五处全部改用它。原先各写一份，振动那段还有一处是内联复制的 —— 表现就是「这条滚起来有振动、那条没有」。
- 抽屉原先没有滚动条，这次补上；它的位置委托给调用点（`scrollBarModifier`）：滚动条自己的盒子只有 12dp 宽，只 `offset` 不加宽会把拇指移出盒子裁掉（真机踩过「滚动条看不见了」）。
- 菜单那条轨道留白取小标题上那一档再减 2dp，与同屏小标题对齐。

### 改：图标选择器补齐到项目用到的全部字形

- 差 5 颗：`ArrowsDoubleNeSw`（只参与组合）、`ListDetails`、`Photo`（图标入口）、`Pin`、`Window` —— 都是最近新加的行首图标，没同步进选择器。现在项目用到 203 颗、选择器 203 颗。
- 网格高度改成自己按行数算（不再交给 `matchParentSize` 跟网格量）：滚动条取的是约束里的 `maxHeight`，在 `Column` 里那个数是「剩下的空间」，摆出来会比网格长一截、thumb 落在窗中间。

### 改：三处「重命名」统一用同一颗图标

- 按键改名、常用命令改名、配置改名原先三种长相（`edit` / 铅笔 / `file-pencil`）。全项目所有改名共用一个记号，`ProfileRename` 那颗删掉。

### 改：系统状态变量插进命令时不再补空格

- 原先「正文不以空白结尾就补一个空格」，于是 `fluid:bluetooth|` 点一下变成 `fluid:bluetooth| ${sys.wifi}` —— 那个空格不是用户打的。现在原样拼接，一个字符都不动（空白该不该有由用户自己写）。

### 改：键盘收起时输入框自动失焦

- 新增 `ui/input/ImeFocusRelease`：键盘从**露过**变成**没了**的那一刻清焦点。只看「当前不可见」不够 —— 聚焦那一刻键盘还没弹起来，会一聚焦就当场失焦。
- 判据取两条（Compose 的 `WindowInsets.ime` + `LocalView.rootWindowInsets`）：弹窗那棵子树不一定收到 IME 的 inset，只用前者的话永远读成「没露过」。因为其中一半不是快照状态，`snapshotFlow` 收不到它的变化，改成每 6 帧看一眼。
- 弹窗里那 800ms 守卫窗口（`ImeGuard` 补键盘那一段）先让位，否则一清一补，表现成「键盘关了又自己弹起来」。

### 改：常用命令在绑定页恒显示

- `showInBinding` 这一位退场（「固定显示在按键绑定页」由开关改成结论）：这一段不再按它过滤，老配置里被关过的条目也一并显示。行菜单里那一项 `enabled = false` + 一句「常用命令始终显示」，把结论摆出来而不是让人二选一。
- 绑定页那一段的格子复用网格同一份实现（`ActionTile` 允许 `spec = null` + `title` + `trailingDot`）：模块自带清单的条目不在 `ActionCatalog.ALL` 里，查不出 `clickKind`，但外形与行尾那一枚选中圆点仍由同一处排。
- 那一枚圆点只在这一格是当前绑定的那条时淡入，位置、尺寸与间距沿用格子原来那套；点中一格补一次振动与「已绑定」回执，与网格里其它格子同一判据。

### 改：几处文案与判据

- 首页那一行「按键功能」改成「按键列表」，图标换成 `MenuKeyList`。
- 只写了前缀的命令（`shell:` 后面空着或只有空格）不再派发：它过了格式闸，派下去却是一条空命令 —— 与「点了测试、什么都没发生」同一个症状。新增 `Action.hasBody` 做这个判据。
