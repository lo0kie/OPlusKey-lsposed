# 2026-11-11 · 计数补三处、场景上限与系统开关三条

### 命令菜单的小标题右侧加档位计数

- 网格里点「有子动作」的那一格（响铃状态 / 媒体控制 / 系统导航…）弹出的档位菜单，顶部小标题多一格计数，写的是这一格底下有几档。
- 计数**紧随标题**、用半角括号包起来（`响铃状态 (4)`），与标题之间留一个半角空格，不推到行尾。
- 括号那一截降一档（常规体 + 压一档透明度），读作标题的附注，不比标题显眼；字号不缩，主次靠字重与颜色分。
- 标题长到要省略时括号跟着一起省略 —— 位置永远在字后面。
- 别的菜单不受影响（顶栏 ⋮、长按命令、条件取值那几张）：计数是逐张菜单给的，默认不画。

### 系统开关补三条：个人热点 / 护眼模式 / 旁路充电

- 「系统开关」那一格新增三项：个人热点（排在 WIFI 之后）、护眼模式（排在暗色模式之后）、旁路充电（排在省电模式之后）。
- 个人热点：读 `getWifiApEnabledState`、开 `startTetheredHotspot`（配置取 `getSoftApConfiguration` 现存那一份，不改用户的热点名 / 密码）、关 `stopSoftAp`，整条在注入侧执行（宿主没有 `NETWORK_SETTINGS` / `TETHER_PRIVILEGED`）。
- 护眼模式：写 `Settings.System.oplus_customize_eye_protect_enable`，写完颜色显示服务的 `eyeProtectEnabled` 当场翻。
- 旁路充电：写 `Settings.System.bypass_charge_state`，写完电池应用的 `BypassChargeController` 立刻把目标下发到充电 IC。
- 推翻 `docs/device/actions/toggles.md` 二十四之 4 那条「热点没有可用的开关入口、界面因此不列热点」，新入口写在同文档四十五。
- 待真机验证：热点这一条的端到端（按下之后热点真的起来）还没验过，其余两条按设置键验过往返。

### 一块场景最多九条

- 新增 `SceneRule.MAX_CONDITIONS = 9`：一块场景里最多九条条件。比原来那层「同一种类最多几条」（按各档取值数封顶）高一层 —— 那一条管「同一类别写重了」，这一条管**一块整体**的规模。
- 到顶之后三处一起收口，说的是同一句话（`command.branch_condition_limit`，「这一块最多 9 条场景」）：
  - 场景卡末尾那行「添加场景」置灰；
  - 一级条件菜单里每一档都点不动（原先只有「这一种类已经加满」的档才灰，理由换成整块那一句）；
  - `appendCondition` 早退 —— 手改配置 / 别的入口也越不过去。
- 改现有的一条不受影响：不涨条数，到顶了照样能改。所以菜单里那道判断只在「再加一条」那一趟算（`condIndex < 0`）。
- 原来那个 `MAX_SCENES = 20` 是整份表的上限，与这一条不是一回事，没动。

### 三处小标题加计数（都在行尾，**菜单在前、计数在最后**）

- **场景块**：「场景 N」这一行、三点菜单右边一格，写这一块配了几条 / 最多几条（`3/9`）。
  - 数字取 `rule.conditions.size`，不取条件行的条数 —— 一条都没配时卡里也有一行「未选择条件」占位，按行数会读成「已经配了一条」。
- **命令步骤**：`n/9`（`Command.MAX_STEPS`）。
- **命令详情**：正文写了几个字 / 最多几个字（`n/1024`，`MAX_SINGLE_LENGTH`），与全屏编辑那条标题同一个 `TitleCounter`。
- 三处都走既有的 `TitleCounter`（12sp、常规体、`onSurfaceContainerHigh`），不新造样式。
- 行尾几何：计数右边缘落在**页边 − 22dp**（与「命令名称」那格计数同一条线），菜单字形到计数 **20dp**（菜单点击格自带 10dp + `SECTION_TITLE_COUNTER_GAP` 10dp）。
- 菜单那颗**不再用 `flushEnd`**：它右边现在还有一格文字，整格右移会把那 10dp 挤掉（字形贴到数字上）。三处都没了调用者，`flushEnd` 这一位暂时空着，留着给「菜单是行尾最后一格」的行。

### 动作网格 / 抽屉的分组标题带条数（系统操作、快捷功能、自定义命令）

- **拼进标题那一段字**里，不在行尾另起一格：`系统操作 (12)`、`快捷功能 (6)`、`自定义命令 (3)` —— 与浮层菜单的小标题同一条口径（`响铃状态 (4)`：半角括号、括号前一个半角空格、与标题同一份样式，不降字重也不压透明度）。新增 `titleWithCount(title, count)` 一处成形。
- 覆盖五处：动作网格那几组（`BindingGrids`）、网格里的「自定义命令」那一段（`SavedCommandsTitle`）、抽屉里的内置几组与「自定义命令」组（`StepSheetGroups` / `SavedCommandsGroup`）、「命令列表」页那两段（`单条命令 (3)` / `多条命令 (2)`）。
  - 「命令列表」那两段原先写的是「网格自己就把有几条摆出来了，标题不重复报」—— 按用户口径改成也写；那一段空着时整段不画，所以写出来的都是真数。
- 条数**从这一趟真正拿到的那张表里数**（`group.size` / `specs.size` / `commands.size`），不写死：同一个组名在三张表里条数不一样 ——
  - 场景动作那张（`BRANCH_GROUPS`）第一组最前面多一个「跟随默认」；
  - 命令步骤那张（`STEP_GROUPS`）少一个「无操作」；
  - 抽屉里 `excludeTiles` 会再剔掉「选择应用 / 自定义变量」两格。
  写死一个数，换个页面 / 换个来处进来就会少一个、多一个。
- 「自定义命令」0 条时也写 `(0)`：那一格里摆的是「去创建自定义命令」，标题上写 0 正好对得上。
- 「跟随默认」本来就在场景动作那张表里（`BRANCH_GROUPS` 第一组最前面），这里只是让它被数进去。
