# 2026-11-09 · 系统场景翻成「一块 = 三档手势」

### 系统场景：一块 = 完整的三档手势（架构翻转）

- 数据模型 `StateRule`（一条规则一个手势）换成 `SceneRule`：一块 = 一组条件 + 单击 / 双击 / 长按三档动作，挂在 `KeyConfig.scenes` / `ComboKey.scenes` 上。组合键只看其中两档。
- 判定 `pickAction` 跟着翻：从上往下找**条件成立、且这一档不是「跟随默认」**的第一块，用它那一档；一块都不中就回落到按键绑定里那一档。
- 新增动作 `Action.Follow`（`follow`）＝**跟随默认**：只给场景块的三档用，也是三档的默认值。它与「无操作」是两件事 —— 前者不接管这一档（继续往下找），后者是命中后吞掉。`isBound` 把它排除在外，执行侧见到它什么都不做。
- 配置升到 v36：`KeyDto` / `ComboDto` 多 `scenes`，老的 `rules` 降级为**只读迁移列**。读到老文件时「条件完全相同的那几条」并成一块、各填自己那一档（同一档取最靠前的那条，停用的老规则整条跳过），升级前后行为逐字不变。
- 判定要多等一次抬手的判据（`sceneClicks`）改成只算**真的绑了动作**的档：某一块写着「双击 = 无操作」时不需要为它多等一次抬手。
- 新增 `Config.sceneTakes`：这一档有没有被某块场景接管 —— 「松手执行额外动作」靠它让位，判据与 `actionFor` 同一条（条件成立 + 这一档有值），只是不要动作、只要一个是非。
- 「换动作」与「列出动作」两条路都走 `ConfigActions` 里那一支 `mapActions`：一块的三档一起换，不会出现「一处改了三档、另一处只改一档」。

### 场景动作页：三页合一

- 点场景块里某一行动作**不再弹动作抽屉**，改成进一页**只编这一块这一档**的绑定页（`Screen.SCENE_BINDING`）—— 与「按键绑定」同一张网格、同一条手势带，进来时按点的那一行落页。
- **三页合成一份实现**：`BindingPagerScreen` 就是「一档手势一屏动作」那一页，「按键绑定」「组合键」「场景动作」三个 `Screen` 值都调它 —— 原来 `BindingScreen` / `ComboEditScreen` / 新写的 `SceneBindingScreen` 三份骨架逐行重复。差别收成三支纯函数：`bindingTargetsOf`（在编哪几档）、`bindingTargetEnabled` / `bindingTargetOff`（开不开）、`BindingTarget` 自己（写到哪儿）。顶栏那条手势带同样合成一条 `bindingTabBand`。
- **`Screen` 值没有合并**：栈里这三个位置可能同时存在（按键绑定 → 系统场景 → 场景动作），而取样源（`hazeStatesByPage`）、顶栏高度（`headerHeights`）、分页器都是**按 Screen 索引**的，同一个值出现两次会互相覆盖。分页器也各持一份（`PagePagers.gesturesOf`），三页各记自己停在哪一档。
- `BindingTarget` 多一支 `Scene(draft, at, gesture)`：前两支落盘，这一支**只改草稿**（`commitBinding` 一处分派）—— 场景表本来就要点右下角那颗确认才写回去。
- 这一页**不摆「系统场景」入口行**：它本身就是从「系统场景」里一行进来的，再摆一个入口成了自己指向自己。
- 「按键设置」那几张卡**这一页也摆**（单击延迟 / 忽视双击 / 长按那几项）：参数是这颗键自己的，换一个条件进去编，手感不该跟着变。组合键的场景块不摆（那张表背后没有某一颗键）。
- 网格的分组表改成**由目标决定**（`BindingGridState.groups`）：场景那一页用 `BRANCH_GROUPS`（多一行「跟随默认」，也是三档的默认值），其余三处仍用 `GROUPS`。切点 `builtInCount` 跟着改成 `groups.sumOf { it.second.size }`，`ActionCatalog.builtInCount` / `forGesture` 随之删掉。
- 挑应用 / 挑变量那两趟把「第几块」记进 `AppPickerState.sceneAt`；`editingAction` / `appPickerSelectedTarget` / `writeToken` 三处按它读草稿、写草稿，否则挑了应用到长按会改到这颗键上。
- 动作抽屉那一整套随之删掉：`CommandBranchMenus` 的「选命令」那张、`applyBranchAction`、`writeBranchCommand`、`PickTarget.BranchCommand`、`AppPickerState.branchCommandTarget` / `branchCommandGesture`、`openVarOpsForBranch`。条件那一侧不变（仍走 `openAppPickerForBranch`，只挑包名）。
- 文案补一条 `command.branch_binding_title`（「场景动作」/ `Scene actions`）：与「系统场景」**不同名**，两页同名时分不清退一层回到哪。

### 场景动作页：FAB 改成「确认」，返回时拦一下

- 右下角那颗从「进自定义命令」换成「确认」（`BoundConfirmFab`）：只在**这一块改过**时出现，点下去才写配置，**写成之后退回「系统场景」页**。另两页仍是原来的「新增命令」那颗。这一颗只管写这一块的动作，不查条件配完没、也不查死分支 —— 条件那一侧归「系统场景」页那颗「确认」。写盘失败时不退出。
- 「按键设置」那几张卡在**这一档选了「跟随默认」时一起压灰**（`binding.follow_no_settings`）：没有可设的项。灰着点一下提示**先换成一个动作**，而不是解释判定流程。
- 组合键的场景表也有长按那张卡：`BindingTarget.Scene` 多带一个 `comboId`，长按参数按它落到**那一组组合**（单键场景仍落到那颗键）。单击延迟 / 忽视双击两张卡不摆 —— 组合没有这两位，那一档的参数在一组的独立设置里。
- 落盘**只写这一块**：`saveScenes` 按栈顶页（`screen == SCENE_BINDING`）逐块写回，配置里别人那几块照原样带过去 —— 整表覆盖等于替上一页按了「确认」，它上面没确认的改动会跟着落盘。
- 检查挪到点击那一刻：`sceneRuleBlockedReason`（这一块条件没配完）+ `branchDeadReason`。时间区间重叠不在这里判（那是两块之间的关系，「系统场景」页才拦）。

### 场景的返回拦截与「放弃」语义

- 「系统场景」页的返回拦截改判**改过没**（`dirty`），不再判「表里有没有块」—— 存好之后按返回照样弹「放弃未保存的场景」，那张窗在说什么都没丢。
- 「场景动作」页新记一份**进来时那一块**（`sceneBindingBaseline`）：返回拦截与那颗「确认」的显隐都按它判（整份草稿的 `dirty` 会把上一页的改动算到这一页头上），写完 / 放弃之后一起挪。
- 「放弃」现在**真的回滚**：`LeaveDiscardDialog` 多一个 `onDiscard`，场景动作页在那一下把这一块还原成进来时那份。原先只弹栈，改动留在共享草稿里，退回上一页后那颗「确认」照样能把它写下去。

### 组合键：界面上限两颗 → 三颗

- `ComboKey.MAX_KEYS` 由 2 改成 **3**。收集入口（`ComboKeysDialog` 勾选、`addCombo` 兜底）与「最多 %d 颗」那条提示都读这个常量，一处改完三处跟着变。
- 判定侧原来那条「多成员凑齐」的路（`ComboDetector.multiFor`）**不能直接用在三颗上**：它按「整串只隔一个窗口」判，三根手指根本按不出来 —— 真机表现是「两颗的组合照常、三颗怎么按都没反应」，日志里一行都没有。判据连同它的镜像一起按成员数放大（见下一节）。
- 上限仍是两套：界面 3 颗 / 判定与落盘 9 颗（`MAX_JUDGE_KEYS`，宽松挡垃圾用，手改文件写四颗以上照常生效）。两者分开的理由没变，只是数字变了。

### 三颗的判定：整串跨度 = 相邻两颗的窗口 × (成员数-1)

- 新增 `Config.comboSpanFor`：「按键之间的等待」量的本来就是**相邻两颗**，n 颗整串就该允许 (n-1) 个窗口（倍数封顶在界面能造的最大颗数）。
- 判定（`ComboDetector.multiFor`）、它的镜像（`ComboSequence`）、注入侧的 `ConfigChannel.spanFor`、「按下之后先等多久才回落单键」（`holdWindows`）几处统一读它 —— 少改一处就是「扫得到、等不到」或反过来，结果同样是按了没反应。
- 两颗那一档的数值与行为都不变（(2-1) 个窗口就是原来那一个）。
- 诊断自检 `combo` 补一条「三颗 / 每颗之间正好隔一个窗口 ⇒ 仍凑齐」，这一条此前是按旧口径写的、看不出来。

### 三颗不被两颗的子集组合抢走

- 判定侧新增「升级」一档（`ComboDetector.upgradeTo`）：组合进行中又按下的那颗键，若把**更大的一档**凑齐了、且仍在那一档的整串跨度内，就把当前这一档换成更大的，抬手时派发的是它。
- 修掉「同时配了 `{A,B}` 与 `{A,B,C}` 时三颗永远输给两颗」：子集那一档在第二颗按下那一刻就成立，第三颗被「组合进行中」整条吞掉 —— 三颗那一档一次都不会响。
- 仍然只出一组：升级只是把当前这一档换掉，子集那一档一次都不会先响。

### 组合键列表：每颗键一枚框

- 标题从「两列写死」改成**按颗数摊开**：三颗那一档也排圆角框（`ComboTitle`），不再退回一整串文字 —— 同一列里「有的行是框、有的行是一行字」读起来像两种条目。
- 列宽改成**按位置取整列最大值**（`ComboTitleWidths` 取代 `ComboPairWidths`，第 3 列只在三颗的行上出现），前两列仍与两列的行竖着对齐。
- 装不下时按各列需要的**同一比例**缩（原来是「第一列保底 45%、其余给第二列」，那套在 N 列上没有对应物），每枚只差一点，不会某一枚截掉两个字、其余整整齐齐。
- 分隔符按**画它的字号**量宽（原来用框里那档小字号量）：三颗有两个分隔符，差出来的那点会一起挤到最后一枚框上。

### 独立设置：滑杆不跟总开关跳

- 上一版把独立设置页的显示统一改成「生效值」，开关对了、滑杆错了：拨一下「使用独立设置」，振动强度那根就从公共值跳到这一档自己的值，读起来像刚调好的值被改了。
- 滑杆改回读**这一档自己的值**：单键取 `owner.vibrateStrength`，组合取新加的 `Config.comboStoredWindowFor`（只做「这一组自己存着多少，没写过就退回公共」，不看总开关；`comboWindowFor` 改成复用它，判据只留一份）。
- 滑杆在总开关关着时本来就是灰的、拖不动，显示生效值没有行动价值；它的写入落点也是这一档，**显示与落点同源**才不跳。
- 行的可见性仍按生效值判（`visible = show.vibrate`）：按自己的值判会让「公共开着振动、这一档没设过」时那一行凭空消失。开关那几行也仍走生效值 —— 「显示关、实际会振」是骗人。

### 顶栏副标题：去掉格数天花板

- 原来有一道 `minOf(measured, 32)` 的封顶（32 格 = 16 个汉字），在 1272px / 560dpi 上只用到可用宽度的七成（46 格可用、画 32 格），长包名 / 长命令名右边明明还有空却被截了。
- 改成**能放多少画多少**：上限就是那一档实测出来的可用宽度，两端留白本来就由 `PAGE_MARGIN` 给。库给副标题的测量约束与我们算的 `栏宽 − 2 × PAGE_MARGIN` 完全一致，用满也不会溢出。
- `32` 降级成兜底值（`FALLBACK_SUBTITLE_COLUMNS`），只在主题字号为 0 / 栏宽为 0 那种病态情形才用。

### 亮度与音量的百分比弹窗：步进 5% → 1%

- `PERCENT_STEP` 由 5 改成 **1**：滑杆吸附、点轨道跳值、「增加 / 减少」的最小值三处一起跟着变。
- 连带的注释同步：弹窗不再画刻度点的理由从「5% 一格是二十个点」改成「1% 一格是一百个点」。
