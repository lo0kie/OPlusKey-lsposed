# 2026-11-14 · 计时器内置、流体云默认、单击参数分两处与一批链路修复

### 新增：计时器做成内置快捷功能

- 「快捷功能」多一格计时器：点格子直接挑时长（滑杆 + 一行 `5 分钟`，30 秒一格，最短 30 秒、最长 2 小时，默认 5 分钟），落成带秒数的写法。没有父子动作、没有下一层菜单、没有副标题之外的第二层入口。
- 执行落在时钟应用里，靠 `AlarmClock.EXTRA_SKIP_UI = true` 让状态栏直接开始倒数、不弹拨盘页；不带它时时钟只是把界面摆出来，秒数不走。
- 带秒数那条由 system_server 代起（`StatusBarBridge.sendTimer`）：宿主是普通应用 uid、按键那刻不在前台，自己 `startActivity` 会被后台起活动那道闸静默丢掉。起不来退回时钟主界面，连主界面都起不来才报失败。
- **秒表不做**：ColorOS 没给秒表任何外部入口（`stopwatch.ACTION_START3` 全包没有代码读，`StopWatchService` 是 `exported=false`），所以那条从动作表、执行器、文案里一并删掉。
- 这一族单独一份 `ClockCatalog`，不并进 `ActionCatalog`（那份已贴着 `LargeClass` 阈值）；`timer:` 仍在 `PREFIXES` 里能当命令正文，但不列在「支持的命令格式」卡上 —— 那张卡只收没有图形入口的写法。
- 格子的小字只写时长（`5 分钟`），点格子弹的是自己的滑杆弹窗（`TimerPopup`），抽屉里那一格同样走这一支：直接落 `onPick` 会把标记 `clock:` 当成动作写进命令。

### 改：用 ColorOS 接口时，提示默认弹流体云

- 「提示走流体云」改成 ColorOS 接口模式下的默认落点：判据是「提示挂着 且 这一档选了流体云 且 使用 ColorOS 接口开着」。关掉那一档的语义是「这套动作走 AOSP 通道」，回执跟着回落 Toast。
- 设置里那一行跟着置灰，副标题写「需要开启「使用 ColorOS 接口」」。
- 配置抬到 v63 并把 v62 及以前存下的 `toast_fluid: false` 折成开（判据用单独的 `VERSION_FLUID_DEFAULT`，不能写 `< VERSION` —— 那样下一次抬版本会把这一版用户自己关掉的又翻回来）。

### 改：单击那几项拆成「全局默认」与「逐键」

- 「判定时机 + 单击延迟」从「按键绑定」页挪走：**公共设置**里一份（`ClickDelayCard`，没开「使用独立设置」的键都按它判）、**按键设置**页一份（开了多击手势才可调）。单键也要有个地方改「按下之后等多久」，所以公共那份不吃「有没有多击」那道闸。
- 两根滑杆的关系不变：判定时机决定下面那根写哪一位（`waitMultiWindow` 关着写 `doubleClickMs`，开着写 `multiWaitMs`），两个值分开存。

### 改：「只参与组合」两头都拦

- 这颗键是某档**按住组合的起点**、或已经是某档**等待组合的成员**时，开「只参与组合」都要先问一句 —— 前者与「按住到点再松手」互斥，后者是「按下要吞一个窗口」叠「单键归系统」，两头不讨好。弹窗按原因分两套文案（`HoldGestureAsk.Reason`）。

### 改：通用 FAB 的图标加大

- 各页右下角那颗 FAB 上的图标从库默认 24dp 抬到 28dp；按钮本体仍是 56dp，右下角定位与两颗一摞的间距不动。
- 尺寸与字形色收到一处（`PageFabIcon`），各页不再各写一遍 `onPrimary`。

### 修：注入侧把「这一下归模块」认得太晚

- 「只参与组合」的键在判定窗口内快按一下，原生动作与模块都不发生：抬手不再把「还压着」那笔账提前摘掉，改成单独记一笔「已松手」，窗口到点按它补一对原生按下 + 抬起；三个出口统一结清，不留「按下放行、抬手被吞」的残留。
- 上一条动作慢时下一次按压会同时触发两套动作：认领改在**广播到达宿主**那一刻记，不再排在串行执行队列后面。补发的几条广播复用同一个 `sent_at`，按它去重。
- 接管点全落空时补 `installed = true` 与安装判据日志：重复进入安装不会再挂第二份广播入口与组合键 Hook。
- 按键观察者的候选类名回到 `Framework` 的候选表（`observerCandidates` / `observerEntries`），换 ROM 只改那张表。
- 宿主换 uid 之后功能广播不再被丢到整机重启：uid 缓存加 30 秒保质期，变了留一行 W。
- 注入按键拿不到返回值时不再当成功；方法表没读出来时也不再写成「ROM 没有这个方法」（`Reflect.methodsOfOrNull`）。
- ROM 中间态码那条 W 只在第一次按下记（长按 repeat 同样是 `ACTION_DOWN`）；合成事件不认领那一步补一行 `d`，自持循环不再无痕。

### 修：宿主执行那一侧

- 录音状态那条事务线程被对端挂死后，录音那一族动作整进程失效：超时后换一条事务线程（最多三条），预算改成先判再投。
- 流体云：绑定失败 / 抛异常时不再清空待发队列；超时任务按绑定轮次配对，上一轮的超时不会掐掉新一轮的连接。
- 快捷方式：整理解不出时只算「这一趟读不到」，不回包 —— 回空表会让宿主把一条 `appshortcut:` 当成「快捷方式不在了」降级成整个应用。
- `appshortcut:` 不再把「取不到 `LauncherApps`」报成「这个应用没有可启动的 Activity」：返回值分三档（已发出 / 没有服务 / 被拒）。
- 起服务不看返回值会记反「现在是开」：返回 `null` 时按没起来处理，继续试下一条起法。
- 结束应用的收尾核实也按进程名核（与强杀那一步同一句 `ps`），pid 被回收再分配时不再把成功报成失败。
- 音量写入抛异常会跳过后面几条降级通道：改成逐条兜住。响铃模式已经在目标档时也放那一下触觉。
- 用户删掉通知渠道之后提示再也不显示：渠道被删时重建。
- 设置页「模块在不在」与「导出日志」两条广播在主线程读盘：挪到 IO。
- 网络代取：状态码读不出来时就地断开再抛；正文恰好等于上限时多读一个字符，才分得清「读完了」与「还有」。
- 导出日志报实际发出去几片，缺片时说「N 片只发出去 M 片」，不再宣称整份已回。
- `window:` 对已经在小窗的目标不再重复收（与 `appshortcut:w:` 同一口径）；`appshortcut:` 失败日志不再打整个 Intent。

### 修：配置与模型

- 非当前那份配置坏一次就只能删：`readOf` 主文件读不懂时也试 `.prev`，`ConfigStore.load` 在「主文件与 `.bak` 都不在」时先看 `.prev`；`importInto` 补上「槽名是不是配置槽」那道闸。
- 两份「名字空 + 位次 0」的配置既改不了名也删不掉：「是不是默认配置」统一按列表里的 id 判，不再按名字形态。
- 导入一份超限的命令库之后任何保存都失败：条数上限的判据收进 `Command.overLimit`，导入时超限整份拒绝并提示。
- 停用的场景块不再让「松手额外动作」成立：「这一档有没有动作」只认启用中的块（`SceneRule.longBound` / `chainBound`），单键、组合键、广播给注入侧那两位同一条口径。
- 手改出来的多击窗口能是十分钟：`multiWaitMs` 落盘读入按字段表那对上下限钳一次。
- 老变量表里「同一次开机」判错、计数器多重置一次：没有 `boot_id` 时按开机时刻比，给 60 秒容差。
- 配置广播的指纹把复合 extra 的内容摘要也算进去，同长度换内容不再被当成「没变」。
- `mapActions` / `actionTokens` 覆盖 `global.commonCommands`：改名之后常用命令那一条跟着换名，删变量前的反查也看得见它。
- 删掉 10 个零引用的文案常量与两本字典里对应的 10 条（三份列表仍一一对应）。

### 修：界面

- 「选择应用」页首次进入停在第一行：目标不在当前清单里（清单没到 / 被「显示系统应用」滤掉）时下标是 -1，不再拿它去把一次性闸 `located` 置真。
- 常用命令能加到 21/20：抽屉那条入口改用与「挑应用」同一条 `addCommonCommand`（去重 / 上限 / 落盘都在那里）。
- 240ms 内连删两条常用命令第一条删不掉：退场状态从「一个 token」改成集合，每一笔删除各自一条协程。
- 重启服务在「广播没发出去」那一支漏摘 ACK 接收器 —— 残留回调日后会把**当前**页面进程杀掉。
- 「开关行」在 200ms 内连翻两次时，`LaunchedEffect` 被取消会留下脏 `positions`，下次重建首帧画成旧值。
- 抽屉定位只有第一轮记 W、之后降到 `d`（内容整段放得下时原来会打满 8 条）；快捷方式回包一到就醒，不再固定睡满 300ms。
- `snapToStep` 在上下限反了时不再让 `coerceIn` 抛异常；两圆求交的 `sqrt` 开方前夹到 0（太阳内圈只差 0.0005 就翻负，NaN 会让整颗字形空白）。
- 一句话夹名字框切模板用 `CHIP_SLOT`，不再写字面量 `"%s"`；成员键认不出的按住组合用键 id 占位，标题不再渲染成「按住 后再按 」。
- 配置满额改用菜单打开时那份清单现算，不再在组合期扫目录；导入覆盖的回执用选择器带过来的显示名，不再自己判「空名 = 默认配置」。
- 建页读盘失败时不再把「注入侧活过没有」抹成 false —— 那会让首页指引用户去勾一个本来就勾着的授权。
- 「重置模块」不吃只读闸：只读态正是它的用场，跟着闸走就成了「提示让你重置、而那一行是灰的」。
- 步骤图标认内置那几条常用命令（`cmd:common.*`），root 角标不再丢。
- 提示条的状态栏偏移改用页面密度换算（它是在 `LocalDensity provides pageDensity` 那一层里被消费的）；「系统是不是深色」收成一处判据，页面与 hook 侧各给各的兜底。

### 改：文案与判据对齐

- 删除命令的文案改成「连同绑定一起删除；别的命令里引用它的步骤会失效」—— 实现只摘绑定与常用命令那一条。
- 「设置生效」不再把「用户没关、执行侧读到关」说成「主开关已关闭」，改说「未同步」。
- 适配结论不再把「读不出版本号」说成「已适配」，改给「此版本未实测」。
- 传状态 token 进「系统开关」菜单不再造出 `setting:wifi:on:on`：开关 id 统一由 `SystemSwitches.kindOf` 定。
- 提示模板那条 KDoc 的承诺与实现对齐：「认不出的占位符原样留着」。
- 时长弹窗不再把没动过的值改写掉：手写的 `timer:86400` 打开弹窗再点确定会原样回传；弹窗那个同名常量改名成 `TIMER_SLIDER_MAX_SECONDS`，写明它是量程、不是上限。

### 改：日志、脱敏与死代码

- 动作解析失败的日志脱敏：认不出的写法走 `redactCommand`、带正文的走 `redactToken`，`setvar:` 只打名字与符号；「测试命令」那两条也改用 `redactCommand`（原来截正文前 32 字符）。
- `Reflect.call` 的失败 W 按「类#方法」去重：ROM 改了签名之后是「每次都抛」，不去重就是一条 W 占满缓冲。
- 删 `Action.Fluid.withIcon`（零调用，注释还声称它是界面唯一写入路径）、`LocalHint`（提供了但没人读）、`ConfigChannel.windowOnFor`、与 `MEDIA_TILE` 同 token 的死分支。
- `StepRowDisplay` 里那句 `!row.exiting` 恒真，去掉；`ConfigState` 里按日期记账的注释改写成「现象 + 为什么」。

### 改：工具与流水线

- `ci.yml` 的 build job 加 `timeout-minutes: 30`；发布流水线把「取本版更新公告」提到「清掉这一版旧资产」之前。
- `audit-perf.py --report` 在硬判据失败时也返回 1：退出码是这条闸对流水线说的唯一一句话。
- `verify-apk.py`：占位符比对认位置写法（`%1$s` / `%2$d`）；`module.prop` 从「键在不在」改成「值对不对」（两条 API 档位必须是整数、`targetApiVersion ≥ minApiVersion`）。
- `check-i18n-cache.py` 的「`remember { }`（无键）」分支原先永远进不去，正则改成同时匹配两种形态，并自测确认能命中。
- `audit-config-version.py` 的结构指纹加上**声明类型**（原来把 `Int` 改成 `String` 指纹不变），顺带补回两条旧正则漏掉的字段（123 → 125），基线已刷新。

### 复核后不改（记下理由，免得下次又被当成问题）

- **「批量删除按命令名做身份」**：`cmd:<名字>` 本来就是命令在全项目的唯一身份，勾选集合在确认那一刻按当前列表过滤，改名 / 重名都不会误删。要按实例认，得先给命令加一个稳定 id —— 那是契约变更。
- **`CommandSteps` 与 `StepActions` 两套写入口径**：`draft.steps` 与 `serialForm.steps` 是同一份列表的两个名字，增删移落在同一处；后者多出来的只有上限闸与导航。
