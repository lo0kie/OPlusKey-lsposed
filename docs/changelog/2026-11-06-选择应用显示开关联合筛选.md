# 选择应用：两个显示开关联合筛选

### 修复：「显示失效应用」会顺带放出没有启动图标的系统应用

- 两个显示开关现在**各管一维**：「显示系统应用」管有没有启动图标，「显示失效应用」管点不点得开；一行要同时过这两关才留下。
- 以前「显示失效应用」开着时，没有启动图标的系统应用会一并涌出来 —— 用户只想看打不开的那些，不该被另一个开关连坐。
- 空态那句跟着拆开：被哪一维挡着就说哪一维；两维都放行了才不再提「去开哪个开关」。
- 这两条判据原先在列表过滤、空态文案、选中项清空三处各写了一遍（还是「失效开着就算无图标的也放行」那种写法），现在收在 `AppPickerState` 上的一处 —— 以后调这条关系不会再漏掉某一条路。

### 修复：结束应用那一趟的「显示系统应用」拨了没反应

- 结束应用那一趟**一律全列**（停掉一个没有启动图标的应用正是它的用处），两个显示开关在那边都拨不出变化；可菜单里只撤了「显示失效应用」，「显示系统应用」还留着 —— 按下去什么都不发生，读起来像开关坏了。
- 现在那一趟这两项都不出现。菜单里一行都不剩时，顶栏那颗菜单按钮也一起摘掉：点开一个空面板，比没有这颗按钮更让人以为界面坏了。

### 修改：非 Monet 配色下，首页状态卡的字与提示图标不再跟着强调色

- Monet 下「已激活 / 未激活」两档的标题与说明是从强调色往正文色拉出来的（带一点状态色相）；非 Monet 那套是「固定中性底 + 一支预设强调色」，同样的掺法就成了浅灰卡上写一行蓝字。
- 非 Monet 下标题改用主题正文色，说明与提示段行首那颗图标用正文色压到七成半（**不是**那档 40% 的次要色 —— 浅色下它比原来浅一大截，整行读起来发飘）。色相只留在底色与水印上，Monet 下不变。
- 状态仍然一眼分得出来：底色掺色与右上角那颗水印还在，只是字不再跟着染色，主次也还在（说明比标题浅一档）。

### 修复：组合键拦截的返回值与吞键判据

- 吞掉 ROM 的组合键判定时，按原方法的**声明返回类型**回填（`void` 给 `null`、`boolean` 给 `true`、其余原始类型给零值），不再一律 `null`。
- 只有「这一对键都归模块管、并且确实绑了某一档可用组合」才吞；把电源与音量都收成单键但没配这一组时，系统的组合键判定照旧交给 ROM。
- 输入层组合键的候选类命中、但方法名对不上时，继续试下一个候选，不再当场放弃。

### 修复：注入侧代取网络请求的读取上限与重定向

- 正文改成读到上限就停，不再先整份读入再截断。
- 重定向手动跟随：每一跳都重新校验 https、限制跳数，并加一条总时长上限。

### 修复：被取消的按键不再判成一次动作

- 抬手上带取消标记（窗口失焦、来电打断）时，先结掉组合与「等窗口」那两笔账，再撤掉判定，不派发任何动作。
- 组合判定里已消费的键集合改为并发安全的集合；组合侧的时间基准与单键判定统一。

### 修复：组合键拦截不再被侧键接管点落空连带跳过

- 侧键接管点一个都没找到时，组合键那条链路照样安装，日志分别说明两条各自的结果。

### 修复：`keyevent:` 注入模块自己认领的键码

- 执行侧在注入前对照当前配置（内置键的码、自定义键收集来的码、ROM 族码），命中即拒绝并给一句回执。
- 注入被系统拒绝时也会给回执，不再只有一行日志。

### 修复：只给双击配了场景时双击永远不执行

- 「这颗键最高认到第几击」把条件分支里可执行的单击 / 双击场景也算进去，判定侧不会再在第一次抬手就直判单击。

### 修复：改名、删命令、删变量漏掉的引用位置

- 配置里的动作位置改为**一处清单**收口：补上每颗键的第 3 击起连击、以及组合键的条件分支。
- 删变量前的反查复用同一份清单，不再与「删命令」各维护一套。

### 修复：结束应用的进程复核与结论

- 强杀前逐个复核 pid 现在是否仍属于目标包，不再直接对开工时那张清单下手。
- 目标本来就没有进程时按「已结束」给出结论；本模块自身与 system_server 一律拒绝执行。

### 修改：shell 的排队上限与失败收尾

- 执行队列改为有界（超出直接按「上一条还没跑完」拒绝），不再无限排队到几十秒后才执行。
- 两条「等不到结果」的路径统一先 `destroy` 再宽限期强杀，避免留下不理会 SIGTERM 的子进程。

### 修复：小窗与语音助手的成功判据

- 小窗「从最近任务收」只把 0 / 2 当成功，1 与负数走兜底路径。
- 唤醒小布时校验 `startForegroundService` 的返回值，组件没被接受不再记成「已下发」。

### 修复：配置导入覆盖失败时主配置没有还原

- 导入覆盖失败时，命令库与主配置一起还原；此前只还原命令库，用户看到「导入失败」而旧内容已经被换掉。
- 「还能不能再建一份」按槽位数计算，当前槽缺失时不再少算一格；删除接口只接受配置槽。

### 修复：模块文件扫描把锁文件当成一个槽

- 槽扫描只收 `.conf` / `.conf.bak` / `.conf.new` 三种形态，重置模块的结论与实际残留一致。

### 修改：配置摘要按规范化形态计算

- 摘要改在 map 段落按键名排序后的正文上计算，手改调换行序不再整份判成「读不懂」；此前写出的文件按原顺序继续校验，升级不会失效。

### 修改：按键执行移出宿主主线程

- 一条手势进来之后的读配置、读变量表、条件探测与动作派发改在单独一条执行线程上串行跑，广播回调只做取参投递。

### 修复：挑一步变量之后多退一层

- 「挑一步」写入前先记下这一趟的去向，不再在写完之后才判断，避免多退一层把刚挑进去的步骤连同草稿一起丢掉。
- 删除变量在落盘前再核一次引用，仍被引用的直接拒绝。

### 修复：网格方向键与真实列数不一致

- 焦点分行表改用界面实际列数，横屏、平板、分屏与超大字号下方向键不再跳错行。

### 修复：条件执行页的草稿判定与删条件

- 退出时三档手势的草稿一起判脏，不再只看当前那一档。
- 删一条条件在动画结束后按**那一条本身**重新定位，期间改过就不删。

### 修复：选择界面列表的去重与行身份

- 快捷方式与应用界面两节各自去重，同一个目标出现在两节时都保留（绑定的 `appshortcut:` 不再从列表里消失）。
- 两节的行身份各带节前缀、按目标取键，不再按下标复用。

### 修复：收集自定义按键的兜底与写盘复核

- 「等按键」弹窗的收场兜底改看「还没收场」，收场回调正常到达时不再提前打开命名窗。
- 落盘前用当前配置再核一次保留码、数量上限与重名，并在判定为不可收时给出理由。

### 修复：返回拦截的回调残留与清理顺序

- 注册返回回调前先摘掉旧的那一份，避免两个实例上各留一个回调。
- 「交还宿主」那条路先关页面再清引用，退场动画期间不再拿到被清空的运行期状态。
- 宿主自己覆盖的结果回调挂钩失败时不再记账，下次进页会重试。

### 修改：设置页覆盖层、组合期读取与取服务实现

- 同一个容器里已经有模块页时先摘掉旧的再铺，不再叠第二份。
- 「关于」页的配置列表、按键绑定页的应用名、捐赠名单的资产读取都移出组合期。
- 注入侧取服务的三份实现收口到 `ServiceCalls.service` 一处。

### 修改：注释里的图形符号

- 注释与工作流脚本里的双向箭头、警示符号、对勾改为词，判据级日志的字面量与 `→` / `⇒` 不动。

### 修复：从组合键进来挑应用，重进这一页选中的那一行不亮

- 进页时读「这一趟在编辑哪个动作」漏了组合键那一支：读到的永远是**当前那颗键**绑的动作，于是组合键上明明绑着某个应用，重进「选择应用」页一行都不亮、右下角确认键也不出现，往下点还会把绑定写回那颗键。
- 现在按进页时记下的组合键 id 读组合那张表，与写回侧同一个判据；那一档组合已经被删掉时按「没有绑定」处理，不退回键上的动作。
- 「以小窗口打开」那项与「选择界面」页该点亮哪一行同源，一起跟着修正。

### 新增：长按之后「松手后再执行」一个动作

- 长按那一档多一组「松手后再执行」：**开关** + 开关为真时滑入的「松手动作」一行。按住到长按时长先执行长按动作，**松手再执行这一个** —— 两个事件分开、各配各的。
- 开关与动作是两位：开着但还没挑动作是合法状态（松手什么都不做），不会因为拨一下开关就执行一个没挑过的动作。
- 这一组真的有事可做时（开关开 + 已挑动作），「长按连续触发」置灰但不隐藏，值原样留着；「连续触发时振动」与「触发间隔」跟着置灰。灰着被点一下会说出原因（开关行原来没有这条通道，点上去一声不响）。
- 没配就是原来的行为：判定侧不发那条松手广播。
- 组合键那一档暂时没有这一项（松手没有广播通道），那张卡上不画这一组。
- 配置版本 21 → 25（`long_release` 存动作 token，`long_release_on` 是那个开关，`long_fire_on_release` 见下一条），老配置读回来是「未设置」。
- 上一版把它写成**布尔开关**、已经落进配置的那几份：现在那一格兼容布尔，读到就按「未设置」处理，下次写盘自动换成动作 token（在此之前整份配置会被判「读不懂」，页面顶成只读）。

### 新增：长按「松手才触发」（到点即触发 / 等抬手才触发）

- 长按那一档最上面多一行「松手才触发」：关着是原来的「按到长按时长就立刻执行」；开着则**按到长按时长先不执行**，抬手那一刻执行**一次**。
- 三条时序只能占一条：到点即触发（默认）/ 松手才触发 / 松手再执行一个动作。开着「松手才触发」时，「松手后再执行」与「长按连续触发」都**置灰但不隐藏**，灰着点一下会说出原因（`DisabledHint`）。
- 判定侧只置状态位、不派发：计时器到点仍然把这一按标成长按（否则抬手会把它当短按再补一次单击，一次按压执行两个动作），动作统一在抬手那一刻走 `GestureDetector.finishLong` 的三条分支之一。
- 互斥收在数据层：`longOnReleaseTiming`（= 松手才触发 || 松手那档真的有事可做）挡住连发，`releaseBound` 被「松手才触发」排掉。判定侧与界面都只读这两位。
- 拨这一位**不清**松手动作：让位但值留着，关掉之后原样回来。
- 组合键那一档同样没有这一项，那张卡上整行不画。
- 配置版本 24 → 25（`long_fire_on_release`），老配置读回来是 `false` = 原来的行为。

### 修复：「松手才触发」在抬手事件丢掉时整次长按零响应

- 这一档把唯一一次执行押在抬手事件上。UP 被锁屏打断 / 被 ROM 吞掉时它什么都不做，表现和「这颗键坏了」完全一样 —— 默认时序没有这个问题（到点已经执行过）。
- 现在到点之后再排一枪兜底（15s）：还按着就按「UP 已丢」处理，就地执行一次，并把这一次按压封掉（`Pending.closedWithoutUp`）；那个迟到的 UP 只清状态，不会执行第二次。谁先到谁负责，两侧都在同一把状态锁里判。
- 兜底那行日志写清是兜底（`长按（松手才触发，但 15000ms 未见抬手 ⇒ 兜底执行一次）`），与正常的「长按（松手才触发）」分开。

### 修复：松手那条广播被 2s 过期闸丢掉

- 旧代码把「松手」放在过期 / 去重两道闸之前，改成通用触发条件之后它走到了闸后面：抬手那条广播若晚于 2s 到达，这一下被判过期丢弃 —— 对「松手才触发」就是整次按压零响应。
- 现在 `release` **免检过期、只走去重**（`GestureExec.handle` 传 `keepLate`）：积压的按下可以丢（丢的是「再来一下」），丢一条松手却是「这一按什么都没发生」；转发侧的补发（`sent_at` 相同）仍会被去重挡掉。
- 顺带把「认哪一档」挪到闸之前 —— 过不过期这条判据现在要看是哪一档。

### 修复：打开设置页当场崩溃（`isBound` 自递归）

- 「媒体控制」那一格与它的菜单首行共用同一串 token，逐行判「这一行绑没绑」时会把取值表展开成它自己 —— 无限递归，打开设置页就 `StackOverflowError`。
- 展开时排除与自身同 token 的那一项；一条都不剩时走常规判据。

### 变更：灵感语音拆成「开始 / 结束」两个平级动作

- 「小布 AI」那一格里的「灵感语音」改成「开始灵感语音」，并新增「结束灵感语音」—— 两行都是独立取值，绑哪一档就执行哪一档。
- 两行不再只出现在长按那一页：单击 / 双击 / 长按三档网格、多条命令的步骤、条件执行的候选表里都能选。
- **松手不再替你收尾**：以前长按绑灵感语音是「按下开始、松手结束」，现在开始之后一直录，要停就按绑了「结束灵感语音」的那一档。
- 两档都不支持「长按连续触发」，界面照旧置灰并写明原因。
- 升级提示：原先绑在长按上的「灵感语音」现在等于「开始」，松手不会再停；要停下来就按绑了「结束灵感语音」的那一档。不做自动迁移 —— 迁移也猜不出用户原本想要的是「按住说话」还是「按一下开录」。
