### 退出拦截：**有编辑就拦**，不看「在哪一页」也不看「改没改」

- 判据从 `draft.dirty`（与载入时的快照比）改成「表单里还有东西」：
  - `COMMANDS`：**两页表单都看**（`singleForm` / `serialForm` 任一 `hasContent`）。`form` 只是「pager 停在哪一页」
    的快捷方式，停在「命令列表」不代表另一页里没在编。
  - `BRANCHES`：三档任一「有条目 或 dirty」（条件页没有编辑态，进来就是编这张表）。
- 效果：点开一条命令看一眼、原样返回也问一句 —— 原先那种「没改动就直接退」会让人分不清「我改的没生效」
  还是「我根本没改」。
- `wouldConsumeBack` 读同一个函数，预测返回与真退两条路不会再分叉。

### 「编辑命令」先确认、再切页

- 点「命令列表」里的一条（或菜单里的「编辑」）：草稿脏时 `loadDraft` 只挂起「放弃未保存的命令」那张窗，
  可调用点紧接着就切了页 —— 窗还摆在屏幕上，背后已经换成表单页、表单里还是旧内容。
- `loadDraft` 改为返回「有没有真的灌进去」；切页只在它为真时发生，脏着的那一路由确认窗在用户点「放弃」之后
  自己发起（`draft.load` + 同一个切页回调 `openSaved`）。取消则窗关掉、页面留在原地。

### 挑完应用点确认不再弹「放弃这次选择」

- 「选择应用」页那两个开关（以小窗口打开 / 使用原版动画）是**跟着这一条一起写下去的**，但进页那一刻的基线
  没跟着挪。草稿刚被 `clearTarget` 清掉之后，`hasUnconfirmedPick` 只剩这一条还能为真 —— 用户拨过开关、再点确认，
  写盘成功了却当场弹一张「放弃这次选择」。
- 确认之后把基线挪到当下（`markWindowTogglesBaseline`），退页就不再把这趟算成「挑过但没提交」。

### 卡片行的上下留白统一

- 行的上下内边距一直是对称的（库给 12dp / 12dp，真机像素量 42 / 42），但**末行是副标题**时它行盒底留着
  `descent` 那截汉字不占的空白：肉眼看到的下留白比上留白多 9~10px。而「只有标题」的行原先做过单行光学修正、
  看着居中 —— 同一张卡里两种形态并排就是「上下不一致」。
- 新增 `Modifier.opticalBlockCenter(first, last)`（`ui/model/TextMetrics.kt`）：量整块首行的「行盒顶→墨迹顶」
  与末行的「墨迹底→行盒底」，取差的一半往下挪。**单行仍走 `opticalCenter`**（那一档的行内容被库垂直居中，
  不吃这条公式）。
- 开关行走同一条尺子：`SwitchRow` 加 `modifier` 参数，由 `CardRow.RowContent` 传入 —— `SwitchPreference` 的标题
  是库画的、插不进修饰符，只能整行挪。
- 补了一档 **0.6dp 实测偏差**：公式按 `TextMeasurer` 的行盒算，比实际渲染矮一档，不补只到 48 / 52。
  真机（PLK110 / 560dpi）改前 45 / 55 → 改后 **50 / 50**；单行 65 / 64 不变。
- `CardRow.Custom`（滑杆 / 输入框）不动：那不是文字行，上下留白是控件自己的 padding。

### 选择器列封一档高

- 只靠「行数少时维持原高、超出才滚」那两条，弹窗的高度上限是**整块可视区**：选项一多（组合键「由哪几颗键组成」
  能列到几十颗）就长成一整屏，读起来不像弹窗、底下那页也被糊得只剩一条边。
- 给那一列自己封一档高（`PICKER_ROWS_MAX_HEIGHT` = 320dp，与「添加命令」浮层同一档）：到顶之后由这一列自己滚，
  面板高度只随「标题 + 这一列 + 按钮栏」走。

- 「灵感语音」那一行点开的选择器原先只有「开始」「结束」两行，光看行认不出开的是什么。改成
