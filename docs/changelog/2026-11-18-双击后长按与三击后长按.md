# 双击后长按与三击后长按

## 改

### 改：「后长按」按击数索引，新增双击后长按 / 三击后长按

- `GestureTrigger.ClickThenLong` / `ClickThenLongRelease` 从单档改成带击数的档位：`count` 1 / 2 / 3 分别是单击后长按（第 2 击按住）、双击后长按（第 3 击）、三击后长按（第 4 击）；
- 落盘与广播的档位 id：第一档沿用 `click_then_long` / `click_then_long_release`，另两档是 `click2_then_long` / `click3_then_long` 与各自的 `_release`，老的 id 与已落盘的场景配置照旧认得；
- 判定侧不再写死「第 2 击」：`chainStep` / `longShotStillWaiting` / `longShotIsChained` 改读「哪几击按住会变长按」的集合（`ClickChainParams.thenLongClicks`），长按枪带上排枪那一刻的击数（`Pending.longShotClicks`），到点按它作废；
- 判定上限跟着最高那一档走：`judgeCap` / `clicksForJudge` / `boundClicks` 三处读同一个下限，只绑了「双击后长按」的键不会在第 1 击就把单击派发掉；
- 松手那一档同样带击数：三档各读自己那一格松手动作，不再一律落到第 1 击那一格；
- 界面：「按键设置」页那一族开关从一颗变三颗（`thenLongRow` 一个函数按击数取文案与字段），绑定页 / 场景动作行 / 手势带按开着的档排页。

### 改：三档「后长按」各有一整套时序与收尾，按住时长三档共用一个

- 双击后长按 / 三击后长按各有自己的连发、间隔、每次触发都振动、松手开关与动作、松手时触发、是否多条命令（与「单击后长按」那套同名不同槽）—— 调一档不动另外两档；
- 判定侧取参收成一处：`ClickChainParams.thenLongAt(clicks)` 回答「按多久算数、排不排连发、松手还有没有事」，装配成 `ChainSpec.thenLong` 按击数索引；
- 按住时长仍只有一格（`click_then_long_press_ms`）：三档只差前面点了几下，手按下去的节奏不该跟着变；
- 长按阈值上限 1000 → **800ms**（长按那一档与三档「后长按」共用这一个上限，滑杆与钳制同源）。

### 改：三档「后长按」的按住时长在公共设置里也有一份

- 公共设置新增 `global_click_then_long_press_ms`，没开「使用独立设置」的键改读它 —— 此前它只有每颗键那一层，公共设置里没有地方能改；
- 广播前按「这颗键开没开独立设置」解析成生效值再发（注入侧读不到公共那一份）；
- 「单键」那张卡从两行变三行：判定时机 / 连击等待窗口之后多一根「连击后长按延迟」，标题就写在这根滑杆上，不另起小标题、也不另开卡片；
- 第三行单独一道闸：三档一个都没开时压灰并提示「未开启连击后长按手势」，没开「使用独立设置」时跟随公共那一份；公共设置那一页这一行**始终可调**；
- 卡片只有一份（`ClickDelayCard` + `ClickParamSource.delay`），两侧只换状态源。

### 改：两页的小标题改叫「单键」，两行标题加「连击」限定

- 「按键设置」与「独立设置」两页的 `key_settings.click` 从「单击」改叫「单键」，覆盖下面那一族单键定时参数；
- 「等待窗口」改叫**连击等待窗口**、「X 击后长按延迟」改叫**连击后长按延迟**，禁用提示改成「未开启连击后长按手势」；
- 英文两份跟着走 `Single key` / `Multi-click wait window` / `Multi-click then hold delay` / `Multi-click then hold gesture is not enabled`；
- 「独立设置」页原来挂在「多击手势」卡尾的那一行撤掉（并入上面那张卡）；组合页的「等待窗口」不在这笔里。

### 改：按住组合的成员连击也有这两档

- 「按住首键 + 唯一成员键连击」那一档同步支持双击后长按（成员第 3 击按住）与三击后长按（成员第 4 击），`MemberGestures` 带上「哪几击按住会变长按」；
- 判定走同一套集合（`MemberChainView` 把三档开关翻成击数），`judgeCap` 跟着算到第 3 / 4 击；
- 两档各有自己的一整套参数（连发 / 间隔 / 每次触发都振动 / 松手开关与动作 / 松手时触发 / 是否多条命令），与成员「单击后长按」那套同名不同槽 —— 不再借用；
- 组合页的「成员连击」卡那一行开关按击数拆成三行（`memberThenLongRow`），绑定页那一档只摆自己的那几族。

### 改：成员「连击后长按延迟」挪进「按住组合」卡，公共设置也有一份

- 那一行从「成员连击」那张卡挪进**按住组合**那张卡的末行 —— 组织与单键那张卡的第三行一致：窗口 / 门槛定完，再定按住多久；
- 公共设置页同一张卡也摆这一根：没开「使用独立设置」的组合读公共这一份（`global_combo_member_then_long_press_ms`），两页共用一个入口；
- 独立设置那一份跟着总开关压灰，三档成员连击一个都没开时同样压灰；多成员 / 等待组合没有成员连击，这一行不摆；
- `member_click_then_long_press_ms` 改以 `0` 表示跟随公共，生效值只在 `Config.comboMemberThenLongPressFor` 一处解析，广播前盖成生效值再发。

### 改：三颗手势图标自绘，单击后长按那颗也换族

- 四击换成自绘的**四根手指**（`hand-stop`）：图标库那份 Kotlin 常量里还没收录这颗，形状按上游那条 d 字符串原样落进 `DrawnIcons`；

- 单击后长按那颗从「移动的手」换成同一族的第一颗（图标库 `hand-click`），三档按手指根数分开；
- 三颗都并进图标选择器清单（`handstop` / `handclicktwo` / `handclickthree`）；
- 独立设置页那两行文案改叫「启用双击后长按」「启用三击后长按」，与「启用双击 / 启用三击」同一族。

## 修

### 修：熄屏下「打开应用」起界面时屏幕不亮

- `app:` 起界面之前补一次点屏：原先只有登记了 `wakeScreen` 的内置两档（相机 / 计算器快捷）会点，从应用面板挑的那一批照样起在幕后 —— 用户按完看到的仍是黑屏；
- 「该不该点」收成一处（`AppLauncher.wakeBeforeLaunch`），`app:` 与内置特性两路共用，`requestWake` 那支 `@hide` 签名仍只有一份；
- `window:` 小窗那一趟仍未接这一处（熄屏起小窗还是不点屏）。

### 修：装回旧包之后配置被整批判成「读不懂」

- 配置读取：文件的 `version` 比本版大（装回旧包）时不再按 md5 判读不懂，按本版认得的字段读入，只保留「能解析 + 键段完整」这道闸；
- 页面因此不再进只读态：切换配置、新建配置恢复可用，配置列表里也不再把这几种文件列成「（读不出来）」并允许当成坏文件删掉（那一删会把「默认配置」这份退路一起带走）；
- 装回旧包时补一条 W 级日志说明「新版本那几格为什么不见了」，按版本号去重（解析会被反复跑到）；
- 代价与判据写进 `ConfigCodec` 与 `docs/runtime/config-channel.md`：本版下一次写盘按本版格式重写，更新的版本里那些字段不在本版认识范围内（原文留在 `.prev` 快照）。

### 修：组合成员连击的「连续触发」只来一次、抬手后多补一下单击

- 组合在成员连击第一发派出去之后就把自己收掉了，而连发那几发随后到达时 `memberChainCombo` 已经是空 —— 判定层直接丢掉，用户看到的就是「按住不放只响一下」；
- 现在「这一轮成员连击出过动作」单独记一笔：到点派发后**不收尾**，组合与连击链一起留到成员抬手，抬手喂完链才按原路子收（首键长按补派 + 组合收尾）；
- 抬手那一下才出动作的档位（松手时触发 / 松手额外动作）也走同一条收尾：不收的话组合会挂到首键抬手，在那里被当成「两颗一起短按」再派一次单击；
- 顺带堵住同一按的第二个动作：首键先于成员抬手时（连发演到一半）不再补「两颗一起短按」，那一按的结果已经在连发那几发里。

### 修：连发的「每次触发都振动」在「后长按」那几档上读错了格

- 宿主 `executeCombo` 的两处重复判据都读组合长按那一格（`ComboKey.longRepeatVibrate`），成员连击三档各自的 `memberClickThenLongRepeatVibrate` / `memberDoubleThenLong…` / `memberTripleThenLong…` 一次都没被读过 —— 用户在这三档打开「每次触发都振动」后，按住不放一次都不振；
- 单键侧同一个缺口：`repeatVibrate` 只认 `count == 1`（单击后长按），双击 / 三击后长按的连发落到长按那一格；
- 两处都改成按 `GestureTrigger.ClickThenLong.count` 取对应档（1 / 2 / 3）；组合侧新增 `comboRepeatVibrate`，与单键那份 `repeatVibrate` 并列在对象外（同一类纯函数，理由与 `colorOsRinger` 相同）。
