# 性能收口（指纹 / 日志 / 正则）

## 修

### 修：用原版动画打开应用时没有动画、随后整个宿主失效

- 原版启动控制器原先「静态字段里没有就自己 new 一个」—— 而转场开播时读的是宿主自己的懒单例，
  于是 COE 状态写在了没人看的那一份上，回调取 `mCoeAnimName` 当场抛异常；
- 那一枪跑在宿主主线程，宿主进程直接崩，表现先是「没有动画」，接着「所有按键都没反应」；
- 现在控制器一律按宿主自己的取法拿（静态字段 → 伴生对象的懒入口 → 自建并写回）；
- 顺带：原版链路认不出启动类型时会连界面都不起，这种情况改由模块自己起（原来会被当成「已交出」）；
- 交给原版链路的那份 intent 只补过「组件 + 没有 action」，补不到「有 `MAIN`、缺 `LAUNCHER`」
  那一档；防分身选择器那个标记也改成挂在真正交出去的那个 intent 上。

### 修：「首键松手后仍执行长按」从来没生效过

那个开关从出现起就是死的，链路上有三层断点，逐层修掉：

- **判定分支进不去**：补派那一支挂在「这一组已经判出长按」这个条件上，而按住组合的常规按法是
  「首键一直按着、成员点一下就松」—— 成员一松这一组当场收尾，长按那一枪被撤掉，
  那个条件**永远不成立**（真机反馈「拨了没效果」，日志里连一行都没有）。现在补派与
  「有没有判过长按」无关：组合收尾那一刻一律结算（取消的那一下仍不算数），首键先松就当场补、
  首键还按着就记下欠账等它抬手时补；两条路各自留一行判据日志。
- **这一位没进配置广播**：`ConfigFields.F_COMBO_STARTER_KEEP_LONG` 原先写成 `Field(null, …)`，
  理由记的是「抬手已经在注入侧判完了」—— 那句把因果说反了：**正因为判据在注入侧，才非走广播不可**。
  于是设置页写得进、界面显示已开启，注入侧拿到的却永远是默认 `false`；**连配置指纹都不变**
  （`ConfigBroadcast.tag` 按 extras 算，这一位不在其中 —— 「改了却没变指纹」本身就是这条 bug 的凭据）。
  现在给了 extra 名 `combo_starter_keep_long`，编码 / 解码 / 指纹三处一起打通。
- **每档自己那份没带过去**：`ComboWire` 不传 `starterKeepLong`，于是即使某一档开了独立设置、
  单独拨过这一行，判定侧读到的仍是 `null`（只跟公共值）。现在按三态原样带过去。

### 修：独立设置里的「无操作时振动」拨不开

- `KeyConfig.withOwn` / `ComboKey.withOwn` 把独立设置那份值写回配置时**漏了 `vibrateOnNone`**
  这一位 —— 它比另外几位晚加，两个 `copy` 都没跟上，注释里还写着「六个字段同名同义」；
- 表现正是「拨了打不开」：开关算出的新值是对的、也交回了页面，写盘时被丢掉，重组后又读回旧值；
- 两处补上，并把那条注释改成「必须把 `OwnSettings` 的每一位都抄到」，写清漏一位的症状；
- 落盘与广播两路本来就是表驱动的（`KeyDto.toValues` / `KeyConfig.ofFields`），只漏在这一处手工 `copy`。

### 修：双击关着时两下轻点什么都不做（只剩一次无操作振动）

- 现象：只开「单击」与「单击后长按」、双击关着，快速点两下 → 没有任何动作，只有「无操作时振动」
  那一下回执；
- 根因：双击关着时 `KeyConfig.actionOf(Click(2))` 恒回 `Action.None`，而「单击后长按」把
  `judgeCap` 抬到 2、连击链必须数到第 2 击才收线 ⇒ 那两下必然被判成 `Click(2)` ⇒ 无操作；
- `1c4f833` 删掉 `doubleFallsBackToSingles` 时给的替代说法「想两下各算一次单击就关掉启用双击」，
  只在双击是链尾时成立 —— 链被「单击后长按」（以后还有三击 / 四击）拉长后就落空了；
- 现在收尾处看到 `clicks == 2 && !doubleClickOn` 就**连发两条 `Click(1)`**
  （`GestureDetector.fireClicks`，抬手 / 窗口到点 / 窗口已过期当场补三处共用）；
- 判据只看双击开关，与链有多长无关；3 击 / 4 击关着时 `judgeCap` 数不到那一档，走不到这里。

## 改

### 改：文件读缓存指纹收成一处实现，一次 stat 取齐

- 主配置 / 命令库 / 变量表三份读缓存原先各自算一遍「修改时间 + 长度 + inode」，每算一次是三次
  系统调用；现在统一走同一处，一次取齐；
- 宿主按键路径上每次按键要问好几次配置，这条固定开销随之降到三分之一；
- 「什么算命中」从此只有一条判据（`inode != 0` 且三项相同），不再有三份各自演进的空间。

### 改：注入侧与按键热路径的详细日志改成惰性求值

- 那批 `XLog.d("…$…")` 在 release 包里函数体被折掉、实参照样求值 —— 每条事件都白拼一串字符串
  （有的还顺带调一次对象的 `toString`）；现在整段跟着编译期常量一起消失；
- 覆盖按键认领、手势转发、触摸与滑动判定、组合判定计划的每一处 per-event 日志；
- log 包里看到的每一行字面量与级别都没变。

### 改：三处正则改成只编译一次

- 输入框折换行、场景页空态文案那一句、更新检查里版本号前缀，三处原先都在表达式里现编 `Regex`；
  输入框那一处每贴一次东西就重编一遍，空态那一句每次重组都重编；
- 现在都是文件级常量。

### 改：性能审计新增三条硬判据

- 指纹只许在唯一那处出现（别处再写 `lastModified` / `Os.stat` 即红）；
- 注入侧不许有急求值的详细日志（必须是 lambda 版）；
- 正则只许在顶层 `val` 里编译（写在表达式里即红）。

### 改：单击 / 等待组合 / 按住组合三张卡各收成一份，公共页与独立设置页共用

- 三张卡原先在公共设置页与「独立设置」页各写一遍（单击那两块还是两个不同名的组件），
  文案、图标、区间逐字重复，改一处要动两处；
- 现在各是**一份组件 + 一份状态源**：`ClickDelayCard` / `WaitComboCard` / `HoldComboCard`
  （各自一个 `*ParamSource`），公共页给全局那份、独立设置页给这一档自己的那份；
- 组合那两张卡按**触发方式**分：一档组合只认一种按法，「按键之间的等待」归「等待组合」，
  「首键按住时长」「系统场景在首键按下时固定」「首键松手后仍执行长按」归「按住组合」——
  原先并在一张卡里，四行读起来像同一套设置的四个旋钮；
- 独立设置页按手势只摆自己那张：单键只摆单击，组合只摆它自己那一种触发方式；公共页三块都摆；
- 小标题沿用组合列表页那两个（「等待组合」/「按住组合」），没有新增词条。

### 改：几颗页面图标换字形，删掉没人用的别名

- 「系统场景在首键按下时固定」换成 `lock-cog`，与「场景」那颗滑杆字形分开：这一行说的是**什么时候取**；
- 「按键之间的等待」换成 `clock-pause`、「首键按住时长」换成 `clock-stop`，与「命令间隔时长」的
  `clock-play`、「长按延迟」的 `clock-bolt` 一并读作同一族的几颗钟，各自一个动作；
- 「首键松手后仍执行长按」原先借「松手执行额外动作」那颗抬手字形，两件事语义不同却长着同一张脸；
  换成「光标 + 一支分出去的箭头」，读作这一次按压被组合动作与首键自己的长按共享；
- 那一行的标题去掉「按住组合：」前缀 —— 小节标题已经写着同一句，读起来是重复的；
  中英两处字典与四处调用点兜底一并改；
- 删掉 6 个 0 引用的别名（随「松手沿用按下时的场景」「触发方式」「显示常用命令」退场留下的）。
