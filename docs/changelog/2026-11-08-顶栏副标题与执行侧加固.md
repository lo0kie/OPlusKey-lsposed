# 2026-11-08 · 顶栏副标题与执行侧加固

### 顶栏副标题挪到大标题下面

- 所有页面的副标题都改走库的 `subtitle` 槽位：排在标题下面、自己占一行，不再贴在大标题右边把标题压成省略号；宽度上限从 24 格放到 32 格。
- 宽度**不是一个常数**：展开态左右各让一个 `PAGE_MARGIN`；折叠态再扣掉「返回」那一格、右侧动作组与库的两个 Gap —— **多一颗按钮就少一格字**（`HeaderSubtitleBar`，三个宽度由 `PageHeader` 在布局里量到后写进账本）。
- 两档之间不逐帧算：`derivedStateOf` 把 `collapsedFraction` 折成一个布尔，只在落定那一刻换一次文案，中间过程不换（否则滑入时会闪）。
- 同一行那一档（`trailingSubtitle`）不再使用，`PageHeader` 的 `subtitleBelow` / `trailingSubtitleIcon` 两个参数随之删掉。
- 「按键绑定」「组合键编辑」页停用时的行尾禁用记号一并撤掉：标题下面只剩一行文字，库那个槽位不收图标；停用状态仍由整页控件变灰、副标题压暗与 ⋮ 菜单里「启用这颗键」那行动词表达。

### 顶栏副标题的光学修正

- 副标题原先直接坐在库的行盒里，**没有做光学修正**：汉字不占行盒下半那截 descent 留白，14sp 的副标题排在 32sp 的主标题下面，设计间隙 3.5dp 看着像 **11.7dp**（真机像素量：主标题墨迹底到副标题墨迹顶 41px @560dpi）。
- 加了一支 `Modifier.opticalTightTop(style)`（`ui/model/TextMetrics.kt`）：量「行盒顶 → 墨迹顶」那一档，把副标题上提这么多，让墨迹从设计位置开始。偏移量是**量出来**的（`TextMeasurer` + `getTextBounds("国")`），不写比例常数。
- **必须用 `getTextBounds`，不能用 `Paint.fontMetrics.top`**：后者是**字体**极值（含拉丁字母的重音空间，约 -1.15em），比汉字自己的墨迹顶（约 -0.88em）还高，减完基线会得到 0 或负数 —— 上提量直接失效。
- 量出来 **5px（1.4dp）就是正好的量**。试过往上再补 3dp（把主标题那一侧约 6.9dp 的降部留白也吃掉），真机上贴得太紧，已撤回。
- 库的 `subtitle` 槽位只有 `String`、插不进修饰符 ⇒ 补丁 `0014-subtitle-optical-modifier.patch` 给 `TopAppBar` / `TopAppBarLayout` 加 `subtitleModifier: Modifier = Modifier`（挂在副标题那个 Box 上），库版本升到 `1.1.0-title2r2` —— `build-patched.sh` 的 `VER_TO`、`build.gradle.kts` 两处 `strictly`、`gradle.lockfile`、`gradle/verification-metadata.xml` 的 sha256 四处一起改（漏最后一处会报 `Dependency verification failed`）。
- `offset {}` 只改绘制、不改测量：顶栏高度、折叠几何、副标题那本「能放几格」的宽度账本都不受影响。

### ⋮ 菜单与抽屉

- 「按键绑定」与「组合键编辑」两页的 ⋮ 菜单顺序对调：**系统场景在前、独立设置在后**，两页一致，KDoc 序号一并改。
- 「按键绑定」页的抽屉打开后滚到当前选中那一行（原先多数情况下停在顶部）。实现是有界重试（8 次 × 40ms ≈ 320ms，覆盖面板滑入与内容高度过渡那一整段），判据是「视口 > 0 且请求成功且位移没变」—— `bringIntoView()` 在视口还没量到时既不抛异常也不滚动，漏了这一条第一次就提前收工。
- 滚动状态从 `rememberScrollState()` 提成 `remember { ScrollState(0) }`，**不按 `show` 重建**（按它重建会让关闭时退场动画播到一半列表跳回顶部），归零改成打开时 `scrollTo(0)`。

### 组合键：每组一份「按键之间的等待」

- 「按键之间的等待」原先只有公共一档、所有组合共用。这一个数同时管两件事：**算不算同时按下**，以及**第一颗键要等多久才回落单击** —— 三颗的组合要宽一点，而两颗的调宽了会让那颗键整套单击都变钝。现在每组可以单独设一份，没设过的跟随公共。
- 判定拆成两步：扫描按**最宽**的那一档扫（按下当前这颗键时还不知道会凑成哪一组，扫窄了会漏掉宽窗口那一档），命中之后再拿**那一组自己**的窗口复核间隔；压键等待按「这颗键参与的几组里最长的那一档」算（等短了宽窗口那组永远凑不齐）。
- 组合的「独立设置」页多一档滑杆（与公共页那一行同一个参数、两个落点）；文案两处逐字相同，不再有「只影响这一组 / 默认值」这种特判。
- 上限从 300ms 放到 **1000ms**（`GlobalConfig.COMBO_WINDOW_MAX_MS`），下限仍是 20ms、步进 10ms（20~1000 共 98 档）。
- 「组合判定计划」那行日志现在是每组各打自己的窗口，按法对不上时能直接看出是哪一组配错了。

### 独立设置收口

- **「独立设置」页显示的是生效值了**。原先那张卡直接读这一档自己存的那五位，而总开关关着时它们**不参与取值** —— 于是「公共开了振动、这颗键没单独设过」时，页面上写着「振动反馈：关（灰）」，按下去却会振。现在显示统一走 `Config.effectiveFor`（关着 = 公共那份），写入仍落到这一档。
- **「振动反馈」对「切响铃」那一下的触觉生效了**。那一下由执行侧在切完档之后放（`RingerHaptics`），判据原先直接读 `global.vibrate`：公共关、这颗键开 → 切响铃不响；公共开、这颗键关 → 反而响。现在与「使用 ColorOS 接口」同一条路（`ActionRunner` 每次执行前写一格，执行器读那一格）。
- **播种不再把刚刚拨动的那一项盖掉**：老配置里没有 `ownSettingsSeeded` 这一位，升级上来的用户第一次拨任何一项都会被「用公共值播种」覆盖回去。顺序反过来：先播种，再把这次改的那一格叠回去。
- **组合的「使用独立设置」现在是七项一起生效**（原先只播那五项，`passthrough` / `windowMs` 还各自停在「没设过 ⇒ 跟公共」）。打开总开关那一刻把公共的透传与窗口也一并播进这一组；要回公共就关掉总开关（唯一入口，关掉不丢值）。
- 组合那一页「无操作时执行按键命令」的写入改为**现读配置**（`updateCombo`）：一行快照一行现读时，先拨开关再拖滑杆会把刚写进去的开关顶回旧值。
- 独立设置页的开关也有回执了（接口 / 振动 / 提示 / 总开关 / 组合那一项），滑杆与文案窗不给（松手就会 commit 一次，弹了只会刷屏）。
- 那一档已不存在时退回上一页，不再留一个只剩顶栏的空壳页。
- 「使用独立设置」的副标题补一个「等」字：组合在这一档上还多两项。

### 选择应用页

- ⋮ 里补上「以小窗口打开」—— 与顶栏那颗开关**共用同一处** `setSmallWindow`（互斥地关掉「原版动画」、不落盘、带一行判据日志），不是两份实现。
- 菜单分两组：「列表怎么显示」（系统应用 / 失效应用）与「写成哪个动作」（小窗口 / 原版动画），中间一条加深带断开；后两行只在会写 `app:` 的那几趟出现。

### 命令与步骤

- 「命令列表」里每一步的标题不再限一行（`titleMaxLines = Int.MAX_VALUE`），长句整段折行 —— 那一行写的是「打开应用: 微信 - LauncherUI」这种整句，单行会把「做什么」裁掉一半。
- 「添加命令」从清单卡里拆出来、单起一张单行卡（隔 `CARD_GAP`）；「添加按键」「添加组合按键」留在各自清单里当最后一行。清单本身一行都没有时不摆空卡（`CardList` 收到空表仍会画一条带内边距的窄条）。
- 多条命令卡的步骤间隔时长从名字下面挪到顶行、跟在类型图标右边，窄卡上可被省略号截断而不顶掉右边那两颗动作键。
- 命令列表的编辑态**离页时整份归位**（`resetForLeave`：编辑态、勾选、两个确认窗的开关一起收）。留着它们的后果是跨次误删 —— 上次勾着三条退出，下次进来点「删除」会把那三条一起删掉，而用户早忘了。

### 执行侧：线程、回执与竞态

- **小窗一族有了自己的执行线程**（`opluskey-mini`）。这一族每一步都是跨进程（`getAllTopAppInfos` / `startZoomWindow` / `startActivityFromRecents-ForFlexible`）再加一层反射；侧键那条路本来就在后台，但设置页「测试命令」是从主线程调进来的 —— 那一下就是把一串 binder 压在宿主 UI 线程上。主线程进来的整段挪过去，后台进来的就地跑。
- **小窗验收带「按键令牌」**：连按 `window:A`、`window:B` 时，A 那次排下的回调还在路上，它读到 A 没成小窗就去**回桌面重起 A** —— 屏幕上用户刚打开的 B 被顶掉。现在每次按下换一个编号，过期的回调直接作废。
- **多条命令整条链跑在自己的线程上**（`opluskey-cmd`），续步不再借调用方那个主线程 Handler；**有步骤间隔的 shell 步骤等它真的结束再排下一步**（`execShell` 是「起进程就返回」，原先两条其实并发跑，「先建目录再往里写文件」把间隔设多大都可能抢在前面）。
- 命令链的**每一条出口都要回执**：漏一个，那条链就停在半路、`runningSerial` 的占位不还，之后所有多条命令都被「已有命令链在跑」挡掉。续步本身也套了异常壳 —— 抛出去就是那条线程死掉，之后所有自定义命令都不再执行。
- **注入侧自己的单线程**（`opluskey-inject`）跑「替宿主干活」那一类动作（状态栏 / 小窗 / 按键注入 / 导出日志 / 弹提示），全是 binder 往返，对端卡住会挂住 `system_server` 主线程（watchdog 直接杀进程）。判定定时器仍留在主 looper —— 那是按毫秒卡时间的东西。
- 拉起应用：内置能力（手电筒 / 勿扰）走 Messenger 绑定失败时原先**什么都不报**，现在报一次「这次没执行成功」。`app:` 那条路上 `ActivityNotFoundException` 分支是**不可达**的（`AppLaunchAsUser.start` 全程 `runCatching`，ANFE 在里面就被吞成 `false`），于是「包还在、组件被停用」那档提示从来没出现过 —— 改到失败分支里按「显式点名组件 + 包还在」分档。
- 亮度：写盘被拒时不再发 `screen_brightness_duration` 口令（那等于告诉 SystemUI「亮度变了」，控制中心那根条会跳到一个根本没生效的值上）。
- 应用名：步骤标题、绑定回执、长按「松手」那几行拿到的是**目标写法**（`999@包名/类名`），原先走只认包名的取名字函数，查不到就把整串原样吐回来。改走认目标写法的那一支（分身、具体界面、快捷方式都认）。
- 流体云连接超时时解掉那条死绑定（原先只复位标志，下一条消息复用死连接，从此一条都收不到）。
- 手电筒：先取服务、摘成功了再清引用（原先先清字段后取 `CameraManager`，取不到就 return —— 回调既摘不掉也没人再持有，下次 toggle 会再注册一个）。
- 场景派发的「补投回放」按 `Message` 实例认（原先用全局计数，别的派发会把计数吃掉、本该吞的原生动作跟着弹出来）。
- 侧键接管点**按层安装、整层 0 个才降级**（原先只按查找结果选一档，第一档全军覆没就无处可退）；安装日志补上目标方法的**声明返回类型**（接管分支返回 `null`，降级分支按声明类型回填零值，两条口径不同）。

### 判定侧

- 注入侧收到配置时，内容 / 指纹 / 组合成员表 / 每颗键的等待时长收成一个**不可分快照**（`ConfigChannel.Arrived`）：分成几个字段逐个赋值时，中间那几个纳秒里读者会看到「新配置 + 旧指纹」（链路自检据此回「已生效」）或「新配置 + 旧成员表」（组合那一颗键这一下不等窗口）。
- `ComboWire` 补上 `useOwnSettings` 与 `passthrough`：原先广播那条通道少带这两位，注入侧解出来的每一组都是「没开独立设置」⇒ 判定（`ComboDetector` 的扫描 / 复核、`ChordGuard` 吞不吞 ROM 判定）一直用公共值 —— 表现就是「独立等待怎么调都没作用」。
- `ChordGuard`：配了组合**不等于该吞**。这一档一个动作都没绑、而「无操作时执行按键命令」开着时，吞下去的结果是「系统那一下没了、模块也什么都不做」（电源 + 音量 = 系统截图，表现是「截图键突然不灵了」）。这种情形放行，让 ROM 自己那一下照常发生。
- 参与组合的键「按下先等窗口」与补发那一枪抢同一把锁 —— 原先松手落在「已摘出表、还没读松手标记」中间时，抬手被吞、补发又不补，一次单击被判成长按。取消（窗口失焦 / 来电）不再派发长按那一档的收尾动作。
- 组合的「松手」档不再被当成过期丢掉（`keepLate` 按触发档给）；成员键被删掉与「被停用」同一档判废（原先只查 `enabled`，这种组合会被界面显示成「还在用」，判定侧再也不会有它）。
- 配置到达时那三行判据级日志（自定义键码与阈值 / 组合清单与判定计划 / 每颗键的判定投影）从 `ConfigChannel` 分到 `ConfigArrivalLog`，通道本身贴着 detekt 的函数数上限。

### 配置与落盘

- 配置格式 **v35**：`ComboDto` 多了 `window_ms`。校验口径是「拿当前 DTO 重新编码再算 md5」，加字段不抬号会让每一份已有配置的正文校验失败、被判读不懂（页面顶着「配置读取失败」、整页只读）—— 这个坑第四次，版本史里补了第四例。
- `windowMs <= 0` 原样保留：`clamp` 会把它抬到下限 20，那就成了「这一组显式设了 20ms」，界面上再也回不到跟随。
- 切换配置时「当前那份读不懂」改用**三态读判**（`ConfigStore.load()`）：原先用文件层判据，外皮坏了 / 正文 md5 对不上时它照样给「读到了」，于是直接拿目标内容盖掉那份还能救的坏文件。
- `.prev` 快照改成**临时文件 + `fsync` + rename**（原先原地覆盖，复制到一半掉电连退路一起毁）；主文件读不懂时**不复制**快照 —— 那时的 `.prev` 往往正是唯一还能救的副本。
- `commands` 槽的跨 uid 可读口径收成一个常量（`OPEN_READABLE_COMMANDS`）：命令库与配置档写的是同一份文件，两处各写一个字面量时，debug 包里谁最后写就决定它可不可读。
- 结构基线（`tools/config-shape.txt`）随之刷新：这道闸只比「相对上一次抬版本有没有变」。

### 跨进程与渲染加固

- 两条跨进程广播（执行提示、请注入侧代注入按键）定向到本包：正文里有应用名与命令名，裸着发等于谁都能注册接收。
- 更新说明的 Markdown 按 AST **递归**渲染，深度由正文自己决定（一段 `**`×5000 就是两千多层）—— 加了深度上限，超限那一层改为直接画原文：样式没了但字还在，弹窗也不崩。
- 弹窗正文里**落单的 `**`** 现在按字面显示（`EmphasisText.pairedMarks`：先扫出所有未被转义的记号、两两配对，末尾落单的不入表）。原先无条件翻转，一个落单的星号会让后半句整段变粗、星号还消失 —— 而注释里写的就是「只认成对的」，只有文字没有实现。
- 磨砂取样源按**实例**判摘除：退场动画期间同一个页面可能已经被新实例重新登记（「返回上一页 → 立刻再点进同一页」必现），按页名 `remove` 抹掉的是新那一份。
- 三处主线程读盘挪到后台：「重启服务」要先扫宿主主进程（一次 binder + 逐个读 `/proc/<pid>/cmdline`）、「切换配置 / 导出配置」点开时要扫一遍盘、捐赠收款码窗口在 `LaunchedEffect` 里同步读 assets 并解一张 900×900 的 WebP。
- 系统侧键配置的列名日志改成 W：这一行是「列名随 ROM 版本变」的唯一凭据，而 `d` 在 release 里被编译期消除。
- 用户表缓存加 30 秒 TTL：装 / 删分身都会让这张表变，缓存永不过期时删掉的分身会一直占着槽号。
- 检查更新的两条协程都加了异常兜底：`CancellationException` 原样抛（吞掉会让调用方的 `join` 永远等不到），其余 `Throwable` 记一行并返回失败 —— 它们跑在页面级 `LaunchedEffect` 里，异常漏出去会穿进 Recomposer，把整个 `:ui` 进程的界面拖垮。
- 字典加载里「取资源流」那一步包进 `runCatching`：它在调用方的 `try` **之外**（先取流、再进 try 读内容），loader 是自定义实现、`getResourceAsStream` 抛了就会一路穿出 `fromClassLoader`，于是「从 APK 里读」那条兜底根本不会执行。

### 文案、图标与配色

- 界面文案精简：去掉重复的后果说明与括号里的机制解释，两句并列的合成一句；「交还系统」改成「按系统原生行为」（那一档动作整条早已删除）。免责声明、需要精确菜单路径的权限提示、占位符说明与「不可恢复」警告保持原样。
- 动作目录的命名口径收成三档：**格子即动作**（录屏 / 录音，只写状态 `切换`）、**格子是父**（系统开关 / 系统导航 / 前台转小窗，写 `父: 子 - 状态`）、其余照常。名字那一段在字典里只是**动词**（`切换` / `开始`），整句「切换录屏」只由选择器那一层拼 —— 同一个动作两处各写一份，改字典时必然只改到一处。
- 「前台转小窗」改成**父子动作**（点它弹菜单、一格两行带选择器），不再走那个两行单选弹窗。
- 亮度 / 音量在句子末尾带当前值（`音量: 增加 - (10%)`）：那个数带半角括号，横杠后面直接跟数字会被读成负号。

### 构建与工程

- CI：PR 里**绝不落签名文件**（`pull_request` 跑的是别人提交的代码，工作区放着明文 keystore + 口令时，改一行 `build.gradle.kts` 就能读走）；PR 只构建 debug。收尾用 `always()` 清理签名材料 —— 失败时工作区还留在 runner 上，那正是最需要清掉的时候。
