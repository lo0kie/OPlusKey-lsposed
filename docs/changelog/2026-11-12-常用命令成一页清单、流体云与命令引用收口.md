# 2026-11-12 · 常用命令成一页清单、流体云与命令引用收口

这一批把几摊活并在一起：**新增「弹一条流体云」**、**「常用命令」从四条静态条目长成一页能打理的清单**（钉一条 / 改名 / 逐条决定显不显示，选中态与品牌图标一并补齐）、**命令引用收窄成「单条不引用、多条的步骤只引用单条」**、**「命令详情」的格式闸收到卡片上那六种前缀**、**发布流水线的前置条件不再静默跳过 + tag 不补前导零**，以及 `adb-find.sh` 与「捐赠列表」两处收口。

### 新增动作：弹一条流体云（`fluid:正文`）

- 新增 `fluid:` 动作：借宿主自己那只 Pantanal Seedling SDK 弹一颗文字胶囊（状态栏 / AOD 上那一条，通知中心里不留记录）。文字能换、模板换不了（业务 action 固定 `pantanal.intent.business.app.system.ACTION_KEY`）。
- SystemUI 那条 `SEEDLING_SERVICE` 通道验过**发不了自定义文字**：只认四类内置胶囊，`RingModeTip` 会用 SystemUI 自己的字符串覆盖调用方塞的文案。
- 落点：`Action.Fluid`（取值 / 解析 / `isBarePrefix`）+ `host/action/FluidAction`（反射 `i9.e0.k(ctx).q(logo, text, showA)`，候选表 + 落空记 W）+ `ActionRunner` 的一支；「支持的命令格式」卡里加一行说明，命令标题按「自带正文」那一族念（`commandTitleOf`）。「why」与两条通道的结论写进 `docs/device/actions/feedback.md` §42。

### 常用命令扩到四条

- 表里从一条扩到四条：微信扫一扫 / 微信收付款 / 支付宝扫一扫 / 支付宝收付款，四条都经 root 的 `am start`。

- 支付宝两条走 `alipays://platformapi/startapp?appId=`（`10000007` 扫码 / `20000056` 收付款），组件名带版本味，`appId` 更稳 —— 四条都按「跑完看前台是哪个界面」真机核过。
- 入口已放出（`CommonCommands.SHOW` = true）：绑定页那一段与「按键设置」那颗开关都显示。要收起来只改这一位 —— 表、执行侧的兜底与配置位一律不动，已经绑上去的 `cmd:` 照常执行。

### 常用命令那四行按各自的品牌画图标

- 每一条都带上了自己的品牌（`CommonCommands.Brand`，`:core` 只给标识、不给图），界面那一侧翻译成行首字形：微信两条是微信的字形，支付宝两条换成支付宝的字形。原先四行全画微信那颗。
- 转译层单独一个文件（`ui/model/CommonCommandIcons`）：那一段在 `screen/binding`、「常用命令」页在 `screen/common`，各写一份 `when` 就会漂（加一个品牌时只改一处、另一处继续画错）；而 `PageIcons` 是「字形本身」的表，不该认识 `CommonCommands` 这个业务类型。

### 选中内边框抽成卡片行的一等属性

- `CardRow.Item` 新增 `selected` 一位：选中就地画一圈内边框（`selectedRowRing`），调用点不再各自拼 `Modifier`。改过来的四处是「选择应用」「选择界面」「命令抽屉」和「常用命令」。
- 画法与尺寸只有一份 —— 就是命令抽屉里原来那一份（超椭圆描边、向内让 2dp、四个角一律全弧）；挂载点从调用点挪进 `CardRow`，调用点碰不到笔宽与颜色。
- 常用命令那一段选中的那一条现在有内边框与主题色标题（原先只有行尾那颗勾）；三种读法一起留着 —— 圈说「这一行就是当前这一档」，标题说「念的是哪一条」，勾说「选中是这一条」。

### 绑的是清单外写法时，焦点圈不再套在「无操作」上

- 焦点格的初值与重定位改成**原样接受 −1**（`BindingGridState.focusedIndex`）：绑的是「常用命令」的 `cmd:common.*`、命令库里删掉的 `cmd:`、或手改配置写进来的任意串时，网格里没有一格代表它，因此一格都不亮。原先 `coerceAtLeast(0)` 把圈压到第 0 格 —— 那就是「选中常用命令，高亮边框却在『无操作』处」。
- 圈不在任何一格上时按一下方向键，落点仍是第一格（`moveFocus` 的入口判断），键盘操作不会因此失灵；确认键在没有圈时不做任何事。

### 命令引用：单条不引用、多条的步骤只引用单条

- 口径：**单条命令的正文不引用任何命令；多条命令的每一步只能引用单条命令**。于是引用图只有「多条 → 单条」一个方向、单条没有出边 —— **不可能成环**，所以整套环检测都不需要。
- 历史：更早这一批先把引用整个删过一次（`CustomCommandRunner` 的 `depth` 参数、`MAX_COMMAND_DEPTH`、单条与多条两条展开分支、`dispatch` 的第二参，以及库侧的 `cyclePath` / `renamedReference` / `dropReference` / `referencedNames`）；随后按上面那条口径把「多条的步骤引用单条」这一半放回来，**库侧那几样不恢复** —— 没有环可检。
- 执行：`CustomCommandRunner.expandStepRefs` 把每一步换掉 —— 引用单条时它的正文就是这一步，一层替换完就结束，不递归。两种情况跳过该步并报错：目标不存在（`NOT_FOUND`）、目标是一条多条命令（`REF_ONLY_SINGLE`，只有手改文件才会出现）。`REF_NOT_ALLOWED` 只由单条那一支报（正文写 `cmd:` 时）。
- 步骤间隔只认外层那条命令自己设的：换过来的一步就是一步，被引用命令自己的间隔不参与，否则相邻两步之间等多久会变得没法解释。
- 界面：`StepSheetFilter` 去掉 `allowCommandRefs`，换成 `singleCommandsOnly`；多条命令的步骤那一趟只列 `kind == SINGLE` 的命令，条件执行那几档仍列全部（它们绑的是绑定位，单条多条都合法）。
- 删掉或**改名**一条被引用的命令时**都不去改别的命令**：那一步会在展开时找不到目标、跳过并报 `NOT_FOUND`（改名同理 —— 库侧的 `renamedReference` 没有恢复）。清它要再扫一遍命令库并整份重写，而结果只是把「跳过 + 一句提示」换成「这一步凭空少掉」—— 后者更难看出发生过什么。
- `CommandScreen` 里那条 `cmd:` 成环提示（`commandReferenceCycle` + `COMMAND_CYCLE_ERROR` 键）一并删掉：没有环可判，那个输入框只剩「重名」一条判据。
- detekt 基线里 `ActionRunner#dispatch` 的签名跟着同步（少了一个参数），否则那条 `CyclomaticComplexMethod` 会因为签名对不上重新报出来。

### `adb-find.sh` 进脚本先摘掉 offline 死传输

- 第 3 路扫描会对 /24 上每个开了 5555 的地址 `adb connect`，失败的那些在传输表里留下一条 `offline`；攒多了之后任何 `adb` 命令都变成 `more than one device/emulator`。
- 进脚本先 `drop_offline`：只按 `host:port` 逐条 `adb disconnect`，**绝不碰 `state=device`**（`adb kill-server` 会把正在用的无线调试一起断掉）。

### 常用命令有了自己的页面

- 清单从「模块自带的静态表」变成**配置里那张自己的清单**（`GlobalConfig.commonCommands`）。模块**不再预置任何条目**：默认空表，原先那四条（微信 / 支付宝的扫一扫与收付款）从界面上撤掉 —— `CommonCommands` 那张表留着只为老配置里已绑过的 `cmd:common.*` 兜底（执行与显示名照旧）。
- 新增「常用命令」页（`Screen.COMMON_COMMANDS`）：右下角那颗按开抽屉**添加命令**（复用命令页那一层，与「松手额外动作」那几处**同一套过滤** —— 命令库那一组照列，只剔掉两个「换一页挑」的格子，「无操作」那一格不列）、点一行可**重命名**（留空 = 用动作名称）/**逐条决定是否出现在按键绑定页**/**移除**（移除前弹确认窗，正文说清「绑定它的按键会恢复为无操作」）。
- 绑定页那一段改读配置：只画勾了「显示」的那些，顺序即清单顺序；点一条照旧落它的 token，执行侧不需要认识这张表。那一段的小标题点一下进「常用命令」页（与「自定义命令」那一段同一个读法）。
- 入口在「按键设置」页那颗「显示常用命令」下面一行「管理常用命令」：上面那颗管这一段露不露（关掉时这一行一起收起来），这一行管这一段有哪几条。
- 新增配置位 `global.common_commands`（非空列表，缺省即空）：`ConfigCodec.VERSION` 45 → 46，`tools/config-shape.txt` 同步刷新（fields 104 → 108）；不进广播（注入侧不认识它）。
- 棘轮按同一工作区的规模增长放宽了几条，逐条理由写在 `tools/ratchet.txt`。

### 抽屉里的「打开应用 / 结束应用」能用了

- 那两行原先点下去只把抽屉关掉：抽屉交给 `onOpenPicker` 的 `StepPickerPage.App` / `AppStop` 没人接（这一页没有挑应用的去路），用户的读法就是「打不开」。
- 新增落点 `PickTarget.CommonCommand`（`ui/state/AppPickerState`）：进「选择应用」页挑一条，挑中的应用 / 结束应用**追加成清单里新的一条**（`PageEntryWrite.addCommonCommand`，已经在清单里就不重复追），写成功自己退页、写失败留在原地。
- 清场纪律与另两趟（加一步 / 松手额外动作）对齐：`openForGesture` / `openForStep` / `openForRelease` / `openForBranch` / `clearTarget` 都把这个标记收掉 —— 漏一处就是「上一趟的『为谁挑』落到别人头上」。
- 「以小窗口打开 / 使用原版动画」在这一趟照常生效（`window:` 本来就是一个合法动作）。
- 顺带把 `writeToken` 里「写回哪一格」的三选一判据抽成 `pickTargetOf`：那一位是**落点表的分派器**，多一个落点必然多一个分支，判定摊在里面就顶 detekt 的 `CyclomaticComplexMethod`。

### 新建配置不再带上一份的自定义键

- `ConfigProfiles.createAs` 造的那份「空白配置」不再从当前配置复制 `customKeys`：收集来的那几颗键属于「这一套绑定」，换一份配置就从收集开始（全局设置与免责协议仍跟过来，那是「这台机器怎么用」）。

### 常用命令跟着切换配置走

- 那张清单住在 `GlobalConfig` 里（因为纯界面项、不进广播），但语义上属于**这一套绑定**：每一条都是一个动作引用，命中的目标在**这一份自己的绑定与命令库**里。切换配置时它随主配置整份对调，不需要额外的附加文件；「重置配置」按 `DEFAULT` 重建时它一起清空。
- 真正的漏洞在**新建**：`createAs` 原先整份照搬 `current.global`，于是新配置凭空继承了上一份的清单 —— 而它自己的命令库是空的，那几条 `cmd:common.*` 全成了没有正文的名字，点下去不执行。现在照搬全局设置时单独把这一位清空（`global = (current?.global ?: DEFAULT.global).copy(commonCommands = emptyList())`）。
- 条目的身份写进 KDoc：它与 `keys` / `combos` / 命令库同一档，不是「这台机器怎么用」—— 记在这里，免得以后再被当成纯显示项复制过去。

### 常用命令的增删与入口显隐都走卡片进出场

- 「常用命令」页里**加一条 / 移除一条**都有滑入滑出：添加时新行先按「不在场」组合一帧、下一帧展开；移除时先让那一行收起，退场播完才从清单里删（直接删的话是硬消失）。动画规格就是 `CardList` 那一套（`VISIBILITY_ENTER` / `VISIBILITY_EXIT`）。
- 两处例外：**清单本来是空的时候加第一条不播行进场**（那一下整块正从空态淡进清单，行再展开一遍就是同一件事播两遍 —— 用户口径「从空态到列表不要滑出来」）；**删的是最后一条时不等退场**（那一行跟着整块一起淡出成空态，与「条件执行」页删最后一块同一套）。
- 「按键设置」页那颗「管理常用命令」也改成 `CardRow.Item.visible`，拨「显示常用命令」时随开关滑进 / 滑出，与页里其它随开关显隐的行同一档。

### 常用命令一条都没有时是居中的空态

- 空清单不再摆成一行「尚未添加命令」的卡片 —— 那一行读起来像「有一条不能点的命令」，整页看着像坏了。现在按全项目那套整页空态：`Feedback`（字形 + 「尚未添加命令」+「使用右下角的添加按钮」）塞进 `VisibleAreaCentered`，高度由 `visibleAreaHeight`（视口 − 顶栏 − 页底留白）量出来，于是它落在**看得见的正中间**，且整块仍在滚动内容里（拖动照样跟着弹）。
- 空态 ↔ 清单之间走 `AnimatedContent` 交叉淡入淡出（`contentKey` 只看空 / 非空，增删某一条不重播），与「条件执行」页空态 ↔ 表格同一套：只做淡入淡出、不插值高度。原先 `if / else` 硬切，删掉最后一条时清单「啪」地消失。
- 空态那一支不画小标题（个数在顶栏副标题里照样看得到），小标题跟着清单一起进退。

### 移除一条常用命令会清掉按键对它的引用

- 移除不再只是从清单里摘一行：绑过它的按键、组合键（含两个松手槽与各自的场景块）一起清成「无操作」。只摘清单的话，那颗键会继续按 `cmd:common.*` 那一串执行，而界面上再也念不出名字。
- 收口在 `Config.withoutAction(token)`（`core/model/ActionRefs.kt`）：逐档映射，多击那张表里被清成「无操作」的那一格从表里删掉（与 `KeyConfig.withAction` 的写侧同一个口径）。
- 清单那一笔与引用那一笔落在**同一次落盘**里（移除那一段一次写出，分两次写会出现「清单没了、绑定还在」的中间态）；确认窗正文改成「绑定它的按键会恢复为无操作」。

### 按键绑定页没有常用命令时也留一段「去添加」

- 这一段原先「清单为空就整段不画」（怕留一张空卡片）：于是第一次用的人在这一页上完全看不出还有「常用命令」这回事，只能自己去别的页找。现在标题照画（`常用命令 (0)`），下面换成一行「添加命令」（`arrow`，点进「常用命令」页）—— 与下面「自定义命令」那一段的「去创建」同一个读法、同一张卡。
- 这一行**不画行首图标**：`CommandCode`（代码加号）是「这一段是什么」的标记，清单里那几条命令才带它；一行入口再画一遍，读起来像「已经有一条叫『添加命令』的命令」。
- 小字不采用「点右下角加号添加」：**本页右下角那颗加号形 FAB 进入的是「自定义命令」页**（`BindingFab`，两页共用、`contentDescription` 即「自定义命令」），与常用命令无关。照搬清单页那句话，指向的是本页不存在的入口，用户据此操作会进入另一处。现在两种情形各述其步骤：清单为空 →「在常用命令页添加」（`binding.common_commands_add_desc`）；有清单但均未勾选「在按键绑定页显示」→ 复用菜单项名「显示在按键绑定页」，读作「在那一页开启该开关」。
- 清单页空态那句同样改成书面表达（「点右下角加号添加」→「使用右下角的添加按钮」），两处风格一致。
- 这一行**不吃 `linkReady` 那道闸**（链路没就绪时绑不了，但「去添加一条」与链路无关），只跟整页那道闸走。

### 这一页的菜单与两个窗关掉时有退场动画了

- 三处原先都是「数据一清、整支不画」：行菜单 `?.let` 只画开着的那一支，改名窗与移除确认窗拿 `cmd == null` 直接 `return` —— 库那边的退场动画根本没机会播，看起来是「啪」地消失。
- 现在显隐与内容分两位：菜单给**空行表**表示关闭（`PageMenu` 的开关就是「行表空不空」，退场那一段的内容与锚点由 `MenuPopup` 自己保住）；两个窗把 `show` 与 `cmd` 分开传，正文照**最后画过的那一条**画（`LastCommand`，与 `ModeMenuPopups` 的 `LastPick` 同一个理由）—— 否则正文里那个名字会先空掉，退场那两百毫秒闪成「将「」移除」。
- 退场途中再点一下「确定 / 移除」不会落盘（那一帧 `cmd` 已经空了），与音量窗退场途中又点一次确定同一个口径。

### 「接口选择」改叫「接口与显示」

- 「按键设置」那张卡与「独立设置」页那张卡一起改名：它现在装的是接口那一条 + 「显示常用命令」，不再只是「走哪套系统接口」。
- 首页那颗入口的摘要跟着改（「接口选择、振动与组合按键」→「接口、振动与组合按键」），一处改名不留旧句子。

### 「独立设置」页的手势组有了小标题

- 三击 / 四击 / 单击后长按那一组上面补一个小标题（`key_settings.multi_click`，「多击手势」），与下面「总开关 / 接口与显示 / 按键行为」三个标题同构。
- 那张卡不再自己让顶边距（原先靠 `SECTION_TITLE_PAD_TOP` 顶替小标题的位置）—— 标题自带同一档上间距，两处都给就是双份空隙。

### 发布：前置条件不再静默跳过，tag 不补前导零

- `publish.yml` 的「检查模块仓库的前置条件」从**跳过改成失败**：令牌缺失、令牌读不到模块仓库（401 / 404）、仓库不存在，三种都直接红并原样打出 `gh` 的报错。跳过的话整条 run 绿着、模块仓库一条都没多 —— 看起来上过架、实际没有，事后只能靠翻那一次 run 的步骤结论才发现。
- tag 改回**不补前导零**（`16-1.4.2`）：模块仓库的机器人会按 APK 二进制清单里的 versionCode 重算 tag 名，写 `00016-1.4.2` 上去它会把 Release 挪到 `16-1.4.2`、把补零那个留成一条没有 Release 的孤儿 tag。跟它写法一致最省事。
- **「补零能修排序」这个判断是错的，别再走一遍**：管理器取的是 Release 列表第一条，而那条列表按**创建时间**排（实际是 tag 所指 commit 的提交时间）；`3-1.0.0` ~ `15-1.4.1` 这 12 个 tag 全指向模块仓库初始化时的同一个提交，时间并列，于是退化成按名字倒序 —— `9-1.3.1` 排最前、`14-1.4.0` 与 `15-1.4.1` 落到 `3-…` 后面。补零改的是名字，改不动 commit 时间，还会被机器人打回。真正让新版排第一的是机器人上架时给这一版推的那个独立提交。
- 于是「一次性把历史 tag 改成五位」那条路不采用（那个 `retag.yml` 已经删掉了）：它对排序没用，只换来一批失效的旧下载地址。
- `docs/process/release.md` 与 `tools/read-version.sh` 的注释按上面这些重写，并留了一条上架后要核的东西：`git/ref/tags/<tag>` 取 sha、再看 `git/commits/<sha>` 的 `committer.date` 是不是当天 —— 不是就说明机器人没推提交，排序会重新错乱。

### 菜单那一项改叫「捐赠列表」、行首换成表格，名单页那张表的上边距与「系统场景」条对齐

- 首页「其他」卡那一行仍叫「捐赠打赏」（仍是原来那颗爱心）；点开那层菜单里最后一项、以及它进去那一页的标题一起叫「捐赠列表」（共用 `donate.list_title`）。
- 那一项的行首换成 `table`（`PageIcons.DonateList`，名单页空态那一行同一颗）；「管理常用命令」那一行接走它原来的 `notes`（`PageIcons.CommonCommands`）。
- 名单页那张表格的顶部让位改成「顶栏 + 小标题那一档」，与「系统场景」条同一条账：有带子的页由带子自带那 8dp，没有带子的页（`BranchScreen` 那一页）也只让顶栏 + 16dp，不另加 `PAGE_TOP_PADDING`。

### 「命令详情」只接受「支持的命令格式」里那六种前缀

- 那一栏的格式闸从「解析器认的十八种前缀」收窄到卡片上列的六种：`shell:` / `keyevent:` / `intent:` / `notify:` / `fluid:` / `shortcut:`；`none`（无操作）照旧放行。
- 其余前缀（`app:` / `window:` / `oplus:` / `setting:` / `proc:` / `volume:` / `bright:` / `setvar:` / `panel:` / `ringer:` / `ringervolume:` / `appshortcut:`）以及 `flashlight` / `power` / `zoom:mini` 这几个裸 token，都是格子或菜单选出来的内置动作 —— 解析器仍认（绑定与已存配置要能跑），只是不再能手写进这一栏。
- 写错的提示改成「必须以支持的格式开头」（原来那句「写 shell: 这类前缀」会让人以为任何前缀都行），并从只淡入淡出改成滑动显隐 —— 那一栏高度跟着展开 / 收起，不再「字淡入、下面一栏当场被推开一截」。落点是 `animateContentSize` 而不是 `expandVertically`：后者首帧从 `(0, 0)` 拉起来、宽度也跟着动，看着是「从左往右擦出来」。
- 判据与那张卡现在是同一个集合，两边一起管：清单里冒出一个能手写的动作、或列表里列了一个过不了闸的前缀，单测（`ActionTokenTest`）直接红。
- 「测试命令」也走同一道闸：格式不支持时直接不派发、回一句「必须以支持的格式开头」。原来它只拦空命令，格式不对的照样派发，执行侧解析成 `none` 什么都不做 —— 读起来像「试过了、没反应」。
- 「支持的命令格式」六行各配了一颗行首图标（终端 / 键盘 / 界面 / 消息 / 横胶囊 / 链条），六颗互不相同 —— 原来是一列等宽的字，从上往下扫分不出哪行是哪行。
- 那六行改成**各自一块圆角**（8dp 正圆角 —— 行只有 32dp 高，且四周离卡片边还有余量，不必跟卡片同族曲线），左右各比文字外扩 8dp、父容器的内边距同步减掉同一档 —— 文字仍落在卡片那条 16dp 竖线上，按下去那一块则铺到离卡片边 8dp 处；分隔线跟着文字对齐，不跟着外扩。
- 单条命令的图标改成两层：**底图**说明它怎么写（`shell:` 终端 / `notify:` 消息 / `fluid:` 横胶囊 …，直接查「支持的命令格式」那张表），**右下角那颗井号**说明它以 root 执行。原先 root 会把整颗换成井号，于是「一条提权的 notify 命令」在列表里只看得见提权、看不出它干什么。拼接复用音量 / 亮度 / 铃声那几族的角标那一支（`badgedIcon` + 新增的 `Badge.Hash`）：底图右下角**裁掉一块方形缺角**、井号落进去 —— 圆缺口只适合手绘那种细笔画，裁在图标库的整颗字形上会留一段月牙弧。
