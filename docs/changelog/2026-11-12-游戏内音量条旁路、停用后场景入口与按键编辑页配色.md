# 2026-11-12 · 游戏内音量条旁路、停用后场景入口与按键编辑页配色

### 发版：1.4.2

- 版本号 1.4.1 → 1.4.2，`versionCode` 15 → 16。
- tag 的第一段补齐到五位（`00016-1.4.2`）：按名字排序时 `15-…` 会排到 `3-…` 后面，补齐之后顺序与版本一致；管理器 `split` 后按 `Long.parseLong` 解析，前导零不影响。`3-1.0.0` ~ `15-1.4.1` 那批旧名字保留不动。
- `ModuleInfo.BUILD_ID` 升到 `2026-11-12-0002`：这一版注入侧动了（游戏内音量条那一路的按键观察者、音量写入改由系统侧），不换这把尺子的话，换了包 `system_server` 里还是旧的，界面照样判「同一次构建」。
- 用户可感知的那一版写在 `docs/release-notes/1.4.2.md`。

这一批 42 个文件，八件事：**注入侧多拦一条旁路**（游戏里那颗音量条不再由游戏空间自己画）、**停用的键 / 组合连同场景入口一起收口**（原先留着的那个例外被推翻）、**按键编辑页两颗 FAB 的配色与删除行为**、**唤醒宿主不再顺带把模块页弹出来**、**双击无操作时那两下各算一次单击**、**音量写入改由注入侧执行**、**新增「以宿主身份发一条通知」**，以及**按键绑定页新增一段「常用命令」**。

### 新增动作：以宿主身份发一条通知（`notify:正文`）

- 新增 `notify:` 动作：以**宿主**（`com.oplus.gesture`）的名义往通知中心发一条通知 —— 标题是宿主应用名、正文是 token 里那一段，渠道 `opluskey_notice`（默认重要度）、小图标用宿主的启动图标。
- 落点：`Action.Notify`（取值 / 解析 / `isBarePrefix`）+ `host/action/NotifyAction`（执行器）+ `ActionRunner` 的一支；「支持的命令格式」卡里加了一行说明（这一档没有网格入口，与 `shell:` / `intent:` 一样手写）。
- 与「执行时提示」不是一回事：那条是注入侧弹的 toast，这条是用户要的通知。「why」写进 `docs/device/actions/feedback.md` §41。
- 发之前先查**宿主那一份** `POST_NOTIFICATIONS`（Android 13 起）与「它的通知被关了」两道闸，两道分开判、失败各说一句；Android Lint 那条 `NotificationPermission` 只看本模块清单，认不出「发通知的是宿主」，用一处带理由的抑制认下（在跑通运行时权限判据之后仍红，所以只能如此）。

### 音量写入改由注入侧执行

- 正常路径改成「注入侧（`system_server`）写」：宿主那次 `setStreamVolume` 被 ColorOS 整条丢掉，「写完读回」判不出「成功」与「被丢」—— 值变了那一档还能靠读回认出结果，值没变那一档恒真。
- 值不变的那一档（音量 0 时再「设为 0 / 再减一下」）只有 `adjustStreamVolume(ADJUST_SAME, FLAG_SHOW_UI)` 能叫出面板，`setStreamVolume` 同值不发面板（宿主与注入侧两边实测一致）。
- 宿主自己那几档写退成兜底（只在注入侧没接上时走），最后仍是注入音量键。「why」写进 `docs/device/actions/audio.md` §36 / §37；执行归属的例外在 AGENTS 五之二、6 登记了一行。

### 双击无操作时那两下各算一次单击

- 「忽视无操作多击手势」+「单击后长按」同时开着时，两下轻点原先被判成「双击」而双击是无操作 —— 结果什么都不执行。现在第 2 击抬手那一刻按两次单击派发（判据 `KeyConfig.doubleFallsBackToSingles`）。
- 判据要问的是「双击这一档到底有没有人要（含场景）」：广播里的最高绑定击数改成发**没抬过下限**的那个数，下限由两侧各自加一次，两边算出来逐字相同。
- 转发侧的 `sent_at` 改成严格递增，否则同一毫秒里的第二条同类手势会被宿主当补发吞掉（只执行一下）。

### 唤醒宿主不再顺带把模块页弹出来

- 宿主服务 `onStartCommand` 在锁屏 / 熄屏 / 游戏等条件下会打开侧键设置页（就是被模块替换成模块页的那一页），而模块的唤醒与保活都靠 `startService` 打这个服务 —— 宿主侧掐掉这段正文，启动 / 绑定本身照旧。
- 「why」写进 `docs/device/side-key.md` §40（含反编译依据与判据行）；`docs/device/side-key.md` §9.3 那句「两个服务都没有 `onStartCommand`」一并纠正。
- 已知限制里「开机约 15 秒内侧键不响应」那条改成：这一段仍不执行，但不再弹模块页。

### 游戏里不再弹游戏空间的音量条

- 新增注入侧 `KeyObserverHooks`，在 `KeyHooks` 的安装序列里与侧键那条**分开装**：挂不上只是「游戏里照旧弹条」，音量键本身不受影响。
- 拦的是系统那套按键观察者派发（`OplusKeyEventUtil`）：外层 `onKeyEvent` 与逐条观察者的 `OnKeyEventObserver#onKeyEvent` **两处都挂**，谁先命中谁吞；候选点全落空时各留一行 W，不硬猜别的名字。
- 判据三条同时成立才丢：音量加 / 减、物理事件、配置里这颗键归模块管（`deviceId < 0` 的注入键与停用的键照常放行，否则「音量 + / −」那个动作会把自己拦住）。
- 桌面与普通应用里看不出差别（系统音量面板本来就被吞）；露馅只在游戏里 —— 游戏空间的观察者把按键转给 `MultiVolumeManager` 画条，不走 `PhoneWindowManager`，也不经宿主那条链。

### 停用的键 / 组合不再留着场景入口

用户口径：按键 / 组合键禁用时，场景那条路一并不给用。原先「停用的键照样能先把场景配好、再回去启用」这条例外整个撤掉。

- 判据收成一份 `bindingTargetStopped`（`BindingPageSpec`）：这一份自己被停用就回那句原因，开着回 `null`；场景块恒回 `null`（那一页的闸门只看整页）。
- 四处一起跟它走：页面顶部那条「系统场景」入口行、⋮ 菜单里那一行（按键菜单与组合菜单各一处）、「自定义命令」小标题的跳转、右下角那颗「进自定义命令」的 FAB（整颗不出现，不只是压灰）。
- 停用原因**不另写一份**：与「独立设置」入口、两页顶栏那颗设置键同一个出口（`按键「X」已停用` / `组合键「X」已停用`），灰着点一下说的是同一句。
- 整页闸门（主开关 / 链路 / 只读）不受影响，仍走 `bindingTargetEnabled`：命令库与某颗键开没开无关，那一片该压灰的照旧压灰。
- 三处原先写着反过来的规矩的注释（`BindingTarget.pageBlockedReason`、`ScenarioEntryRow`、两处菜单）一并改口径，不再留一份自相矛盾的说明。

### 按键编辑页两颗 FAB 换色，删除不再空转

- 「停用 / 启用」那颗从 `secondaryContainer` 改 `primary`：原来那一档在暗色下是半透明白，合过 `surface` 之后就是一片灰，读不出「可以按」；图标改 `onPrimary`。
- 「删除」那颗改 `error` 底 + `onError` 图标：不可撤销的那一下与旁边那颗分开，两颗都是实心圆时颜色才是那道保险（`onError` 不写死白色，Monet 深色档的 `error` 是浅红）。
- 勾的**只有内置快捷键**时，点删除不再先弹确认窗再回一句「不能删除」：直接说原因（`keys.builtin_keep`，与列表页那一格同一句、同一条过滤判据）。
- 这一颗的外观**不跟着变**：不置灰 —— 灰掉之后既不像能按也不像真的禁用，反倒像坏了；做不到的原因交给点下去那一句。

### 按键绑定页新增一段「常用命令」

- 新增 `core/present/CommonCommands` 那张表：一条 = 一条**由模块维护**的命令（稳定 id + 名字 / 副标题的字典键 + 要跑的动作写法），现在只有「微信扫一扫」一条（`am start -a android.intent.action.VIEW -d weixin://dl/scan`，经 root 执行）。
- 三种绑定页（按键绑定 / 组合键编辑 / 场景动作）都摆这一段，排在「按键设置」下面、动作网格上面；点一条就把 `cmd:common.wechat_scan` 绑到当前这一档手势上，那一行行尾显示已绑定。
- 这几条**不进用户的命令库**：命令页里一条都不出现，也不写命令库文件。执行侧改成「先查命令库、查不到再退到这张表」（`CustomCommandRunner`），所以用户建的同名命令始终优先，模块带的那几条不会盖掉它。
- 名字按 **id 寻址**、不用落盘时的字面量：`cmd:` 引用的是 `common.wechat_scan`，界面（步骤行 / 计数摘要 / 执行时提示）按当前语言念成「微信扫一扫」，切语言之后那条绑定照旧认得出来。
- 「按键设置」页（`Screen.GENERAL`）的「按键行为」卡新增「显示常用命令」一开关，默认开；关掉只是那几行不画，已经绑上去的动作与命令库都不动。
- 新增配置位 `global.show_common_commands`（落盘键 `show_common_commands`）：`ConfigCodec.VERSION` 44 → 45，`tools/config-shape.txt` 基线同步刷新。注入侧不读它，不进广播。
- **现行隐藏**（`CommonCommands.SHOW` = false）：绑定页那一段与「按键设置」那颗开关都不出现。表、执行侧的兜底与配置位一律不动 —— 已经绑上去的 `cmd:` 照常执行，改回 `true` 两处入口一起回来。
