# 2026-11-13 · 组合键按住手势与按法、提示走流体云、各处上限

### 新增：组合的第二种触发方式 —— 先按住一个成员，再按另一个

- `comboHoldOn`（公共默认**关**）+ `ComboKey.holdOn`（每组可另设，`null` = 跟随公共）：与原来那条「窗口内先后按下」**并存**、谁也不取代谁。判据是**第一颗还按着**，不看隔了多久；上界是那颗键自己的长按 —— 判过长按就已经执行过自己的动作，再认组合就是一次按压两个动作。
- 「松手时触发」的键没有这条上界：那一档到点并不执行（动作押在抬手），正是「按住久一点再补一颗」要的形状。组合一旦凑成，那颗键的状态机被摘掉、押着的那次长按跟着没 —— B 按下之后 A 的长按就不出了，只有「按住 A 直接松手」那一下才出。
- 只对**两颗**的组合成立：三颗及以上没有「哪一颗先按住」这个唯一起点。独立设置里那一行也跟着只在两颗上出现。
- 新增「首键按住时长」（公共默认 100ms + 每组可另设，40~500 / 10ms 一档）：先按住的那颗要**按满这么久、且还没抬手**，第二颗落下才算。它把「一起按」与「真的按住一颗再补另一颗」分开 —— 两颗键几乎同时落下（实测相差 0~40ms、谁先上报看硬件）不叫按住，那种归窗口那条；没有这条下限时，一起按会按物理先后落进某一种顺序，而那个顺序用户未必加过（真机日志：53 次一起按，23 次落空）。
- 按住那两种顺序**要手动加**：没加过的那一种判定侧不认。加的时候只查**先按住的那一颗**是不是「松手时触发」，不是就先弹一句、确认后同一次落盘（改它的长按时机 + 把这一种顺序记进去）。
- 配置 53 / 54 / 55 / 57：这一位、两条触发方式的公共与每组覆盖、手动加过的顺序、首键按住时长。老文件缺它们 ⇒ 关 / 空 / 跟随公共，判定与这一位出现之前逐字一致。

### 新增：组合的三种按法，各有一套动作

- 动作槽按「这一下是怎么按出来的」分三套：窗口内等齐落 `single` / `long`，先按住第一颗落 `singleA` / `longA`，先按住第二颗落 `singleB` / `longB`。共用一套的话，改了一种按法另一种也跟着变。
- 动作页**仍然只有短按 / 长按两页**：按法不占页签，换成右下角一颗 FAB（hand-click 图标，叠在「新增命令」上面，间距 12dp、同一次进出场）+ 一个单选窗，三行就是三种按法。
- 窗里的键名是**名字框**而不是方括号：选择器多了一档 `PickerOption.chips`（文案留 `%s` 占位，名字画成 `NameChip`，装不下自动换行）。三行文案按成员键名拼全：`按下 [A] 或 [B] 后等另一颗` / `按住 [A] 后再按 [B]` / `按住 [B] 后再按 [A]`。
- 只列**能选的那几档**（`Config.comboPressModes`）：等窗口看「使用等待手势」，两种按住顺序看「使用按住手势」且成员正好两颗；不够两档时这颗 FAB 不露出来。没添加过的顺序照常占一行，点它就是「加这一种」（先走那一问）。
- 换一档报一句回执（与那一组其余项共用同一个回执位），并切到那一套动作表 —— 这一窗一关，页面上唯一的变化就是格子里那几行字，不说一声像「点了没反应」。
- 按住那两套**暂不走场景表**：场景块只有短按 / 长按两档，没有「按法」这一维。

### 改：组合的两条触发方式各成一个开关，都关着时那一页走空态

- 公共设置那张卡里是「使用等待手势」（默认开）与「使用按住手势」（默认关），两位也都进了某一组的「独立设置」（跟着那一组的总开关走）。
- 「按键之间的等待」与「无操作时执行按键命令」都归到窗口那条底下：窗口关掉时滑动收起，取值也不再算数 —— 成员键按下不再押着等一个窗口（立刻走自己的手势），那一格没绑动作时也没有「两颗键各干各的」这条路了（没绑动作照样吞掉 ROM 的判定）。
- 两条都关着 ⇒ 这一档永远不成立：动作页摆一页空态（「两种手势均未启用」）、页签带一起灰掉。空态仍在滚动内容里，能越界回弹、顶栏照常折叠。
- 三颗那一档不能靠「先按两颗、再补一颗」升级凑出来：升级那条也吃窗口那一位。
- 独立设置里「使用等待手势」一直在 —— 三颗及以上只走它这条判据，藏起来就没处可改了。

### 改：按住手势与「松手时触发」互为出入口

- 关掉某颗键的「松手时触发」时先看它是不是某些组合里**先按住的那一颗**：不是就直接关；是就弹窗说清是哪几组（正文一行一个组合名），确认后**同一次落盘**关掉这一位、并把这几种按住顺序一起移除 —— 留着它们在按法窗里只是一个永远不成立的选项。
- 组合编辑页 ⋮ 菜单多一行「修补当前按法」：把当前那一档按住顺序的起点键重新改回「松手时触发」。当前按法是等窗口、或那颗键本来就是松手时触发时，这一行灰着并说明「当前按法不需要修补」。
- 两处判据同源，都只看**加过的那几种顺序** —— 没加过的顺序判定侧本来就不认。

### 改：只参与组合的键按住能出原生长按

- 窗口到点时用户还按着，就只补发原生「按下」，不再一律补「按下 + 抬起」的一对 —— 原先长按在窗口到点那一刻被截成了短按：按住不放只得到一次音量 +1，电源键永远弹不出长按菜单。
- 按住期间的重复事件转发给系统，抬手时补一条抬起、真实那条吞掉。
- 补过按下之后，真实抬手 / 配置变更 / 兜底（10 秒）三个出口都会补一条抬起，那颗键不会卡在按住状态。
- 这颗键若参与的是**按住手势**那一档，按下一直压到抬手再补一对：那一档没有「窗口到点」这回事，窗口一漏就必然是「一次按压两个动作」。代价是它在这一档里**不再出原生长按**，要原生长按就把这一组从按住手势里撤掉。
- 等多久改成按这一颗键自己参与的窗口取，不再跟着全局最宽的那一档白等；补发的事件时间取投递那一刻，不回溯成真实按下的时刻。

### 新增：执行时提示可以走流体云

- 「执行时提示」多一档「用流体云提示」（配置 56：公共 + 每档「独立设置」各一格）：开着时同一句提示由宿主弹成状态栏胶囊，关着仍走注入侧的 Toast。
- 胶囊左边那颗图标取**这一次执行的动作**：界面层把配置里出现过的动作逐个画成 png 落进宿主共享目录，宿主执行时按同一个 token 找回来；还没画过的（刚导入配置、没进过设置页）退回模板自带那张通用图，已经不在配置里的旧图跟着清掉。
- 文案不跟着换：仍是「提示文案」那一句模板，`$key` / `$gesture` / `$action` 照旧。
- 失败不再回头弹一条 Toast（那是「提示失败的提示」，用户要的那一句照样没出现），日志里仍有一行说清断在哪。
- 命令改名 / 删命令要跟着改的动作清单补上按住手势那两套（先按第一颗的 `singleA` / `longA`、先按第二颗的 `singleB` / `longB`）。

### 改：切到已是目标档位也弹流体云

- 「切到响铃 / 振动 / 静音」这类命令，档位本来就在目标档时不再一声不响地早退：`使用 ColorOS 接口` 开着就照旧发一条流体云，让人看得出这条命令跑了。
- 流体云是 ColorOS 那边弹的，只有主动发这一条事件才出来；系统自身在「没变档」时不会弹。档位不重写、那条触觉也不补。

### 改：挑应用页多选的行尾换成序号

- 给条件挑应用时行尾那颗勾换成一枚序号（主题色实心圆 + 亮色数字），第几个选的看得出来；一条条件最多 25 个应用，到顶后再点只提示、不选中。
- 多选里没选中的、以及单选里没选中的行，行尾都不再画那枚空心圈（占位仍留着，行宽不变）。
- 进页与下拉刷新时把已选中的那几行排到最前，顺序按保存的先后；页里点选、取消期间不重排（否则点一下那一行就从手指底下挪走）。
- 顶栏那一行报「已选择 n / 25 个应用」。
- 「结束应用」那一趟挑了却没落盘，返回时才问一句「放弃选择」；点一下本来就是它的那一行不算挑过。

### 新增：命令、常用命令、变量都加上限

- 命令库单条与多条**各**最多 50 条，闸在写入那一道（导入配置也绕不过去）；常用命令 20 个；变量 50 个（闸落在 `VariableStore.add` 上，界面那颗「新建」提前拦一次）。
- 三处标题行尾都改成 `n/上限`：命令列表两段、常用命令、自定义变量列表。

### 改：提示条与弹窗文案

- 提示条支持名字框（`HintItem` / `HintQueue.push` / `HintCenter.hint` / `SettingsPage.hint` / `writeAndNotice` 一路带下去）：文案留 `%s` 占位，键名画成 `NameChip`。带名字框的那一条**不走跑马灯**（框跟着滚会读成「标签也在滚」），改成一列流式排布、装不下换行；纯文字那些条一个字节没变。
- 「一句话里夹着几枚名字框」收成一份 `ChipText`，选择器那一列与提示条共用：切分、去空格、模板与名字个数对不上时退回原文这三件事只有一处实现。
- 已换成名字框的回执：按键启用 / 停用、删除按键、换一档按法（对应的三条模板去掉方括号改成占位符）。
- 弹窗正文按句分行：单个换行 = 换行、空行 = 分段、行首 `- ` = 项目符号。重置模块、重置配置、覆盖配置、取消原版动画、从常用命令里移除、批量删除命令、按住手势那一问这几位改成两行写，「不可恢复 / 无法撤销」这类收尾一律单起一行。
- 兜底审计改按字面量解转义再比：正文里带换行的条目不再假红。
