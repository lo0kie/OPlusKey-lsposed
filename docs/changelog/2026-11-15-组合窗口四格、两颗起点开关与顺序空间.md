# 组合窗口四格、两颗起点开关与顺序空间

这一批三件结构改动：**组合的窗口从「一个数」拆成四格**、**两个「固定窗口起点」拆成两个变量**、
**按顺序触发的组合不再有长按**。另有两件判据改动：**「添加组合」改按顺序空间判重**、
**跨度按按法分档取**（这一条修掉了一个「调宽了却不生效」的缺陷）。
配置从 **v71 推到 v75**，字段 136 → 147。

## 一、窗口从一个数拆成四格

### 一个数在管四件事

原先的「等待窗口」压着四件互不相干的事：等待组合凑齐、等待组合相邻两颗的间隔、
按住组合的成员接收、按住组合的逐次等满。于是调宽「按住组合的成员接收」会把
「等待组合的收集」一起拖钝 —— 用户是为了手感调的，结果另一边变钝了还找不到原因。

更糟的是开关会换掉数的含义：同一个 80ms，「固定窗口起点」开着时表示**整串共用一个窗口**，
关着时表示**相邻两颗各一个**。一个旋钮两种语义，滑杆上那个数就没法读了。

所以拆成 `ComboWindows` 四格，各存一份：

- `wait` —— 等待组合、起点**开**：从首个成员按下起，整串共用一个窗口；
- `waitPair` —— 等待组合、起点**关**：相邻两颗之间（n 颗整串 = 它 × (n-1)）；
- `hold` —— 按住组合、起点**开**：后续成员要在首个成员按下后的这个窗口内落完；
- `holdFollower` —— 按住组合、起点**关**：后续成员每颗各自往前等多久。

### 四格存在哪、从哪读

- 公共四格在 `GlobalConfig`：`comboWaitWindowMs` / `comboWaitPairMs` / `comboHoldWindowMs` /
  `comboHoldFollowerMs`。前三格出厂 80；**第四格出厂 150** —— 它原先是
  `HOLD_FOLLOWER_WINDOW_MS` 这个写死的常量，现在成了可调的一项，出厂值与原来一致；
- 每组四格在 `ComboKey`：`waitWindowMs` / `waitPairMs` / `holdWindowMs` / `holdFollowerMs`，
  `0` = 跟随公共，受那一组的「使用独立设置」管；
- 取值只有两处出口：`Config.comboWindowsFor`（**实际生效**）与 `comboStoredWindowsFor`
  （这一组**自己存着**的那份）。界面滑杆要的是后者 —— 取生效值的话，拨一下总开关它就
  从公共值跳到这一组自己的值，看着像刚拖好的窗口被改了；
- 四格全走广播（`F_COMBO_WAIT_WINDOW_MS` 等四支）：判定在注入侧，那边读不到配置文件。
  注入侧的 `ConfigChannel.windowsFor` 在还没收到广播时按公共出厂值兜底（80 / 80 / 80 / 150）。

### 跨度按按法分档取

`comboSpanFor` 早先**不分档**：两种按法都读等待那两格与 `comboFixedWindowStartFor`。
于是把「按住组合的成员接收」调宽之后，扫描窗口仍按等待档算，第三颗落下时第一颗已经出了
扫描窗 —— 那一档**永远凑不齐**，而日志里只有一行「间隔超出窗口」，看起来像用户按得不对。

现在分档取，并且按住档取两格里的**宽者**（宁宽勿窄，它的首键本来就不吃窗口）：

- 等待档：起点开着 `wait`，关着 `waitPair × (n-1)`；
- 按住档：起点开着 `maxOf(hold, holdFollower)`，关着 `holdFollower × (n-1)`。

`comboScanWindowMs` 同步改成「四格公共值 + 各档跨度」取最大值，并且只算 `liveCombos()` ——
凑不齐的那一档按多宽的窗口扫也命中不了，让它参与取最大值只会白撑扫描时长。

### `collectMs` 改名 `spanMs`：跨度只展开一次

`ComboPlan.collectMs` 存的是「相邻两颗隔多久」，判定器与镜像 `ComboSequence` 各自再乘一次
成员数。而「开着固定窗口起点时整串只给一个窗口」这件事乘法表达不了 —— 一个数在两个地方
各自展开，口径迟早会分家。

现在改成 `spanMs`：由 `Config.comboSpanFor` **展开一次**，判定（`multiFor` / `pairFor`）、
镜像、扫候选、「等更宽的一档」（`awaitWider`）几处直接用这一个数，判定侧不再乘。
`ComboSequence` 里那段 `(plan.size - 1).coerceIn(1, MAX_JUDGE_KEYS - 1)` 随之删掉。
探针 `ProbeOps` 造的计划也改成 `300 × (n-1)`，与「起点关着」那一档同一算法，期望值好写成人能算的数。

### 迁移

- 老文件那**一个**数（v73 的 `window_ms`，更老的还有 `fixed_window_ms`）由 `clampOrFollow`
  铺到**前三格**，第四格用出厂 150ms；`0`（跟随公共）必须原样留着 —— `clamp` 会把它抬到下限 20，
  那就从「跟随」变成了一个具体的数；
- 写回永远是 0：`window_ms` / `fixed_window_ms` 在 DTO 里降级成只读的遗留字段。

## 二、两颗「固定窗口起点」是两个变量

等待组合那颗决定「整串算一个窗口，还是相邻两颗各一个」；按住组合那颗决定
「后续成员从首成员按下起共用一个窗口，还是每颗各自往前等」。这是两件不同的事。

共用一个变量时，在「按住组合」卡上拨一下，等待组合那根滑杆也会跟着换一格 —— 调一边连带改另一边。
所以拆成 `comboFixedWindowStart`（等待）与 `comboHoldFixedWindowStart`（按住），
档内对应 `fixedWindowStart` / `holdFixedWindowStart` 两个可空字段（`null` = 跟随公共）。

判定侧之前借的是等待组合那一位（`comboFixedWindowStartFor`），现在按住档改读
`comboHoldFixedWindowStartFor`，只有 `ComboDetector` 的 `fixedWindowStartFor` 一处。

新增的这一位**必须走广播**（`F_COMBO_HOLD_FIXED_WINDOW_START`）：注入侧读不到配置文件，
少了它，按住组合那颗开关拨了没反应，而等待组合那颗照常生效 —— 更难看出是哪一半没接上。

### 顺带：独立设置逐项复核，播种只补空格

把「按键独立设置」的每一项（共用的九项 + 组合独有的九项）从头过了一遍「读谁 / 写谁 /
总开关关着时看谁」，只剩一处真实耦合：

`withSeededComboFields` 早先**整份覆盖** —— 打开「使用独立设置」那一刻，用公共值把四格窗口 /
首键按住时长 / 场景时机 / 两颗起点一起写进去。这对「从没开过」的档是对的（开了就该与公共一样），
但碰上「`useOwnSettings` 早已开着、`ownSettingsSeeded` 还是 false」的老配置，拨一下别的项就会把
这一组早先调好的窗口**顶回公共值**，现象是「改了振动强度，窗口自己变了」。

改成**按位补空**（`null` / `0` 才算空）：只给确实没设过的那几位落笔，重复执行也幂等。

确认**不**耦合、保持原样的（各有明确判据）：

- 「无操作时振动」与「振动反馈」互不依赖（`GestureExec.haptic` 的 `force` 分支只读前者）；
- 「用流体云提示」跟着「使用 ColorOS 接口」走 —— 能力依赖而非状态耦合，界面置灰说明与执行侧
  `own.toastFluid && own.colorOsApi` 同一口径；
- 振动强度滑杆显示这一档自己那份（不跟总开关跳），可见性按生效值判；
- 独立设置页只摆这一组自己那一种触发方式的卡。

## 三、按顺序触发的组合没有长按

那一档要的是成员按先后落下，判据量的是**相邻两颗之间**，整组按满多久在它身上不是一个问题；
按住不放时也没有「连发 / 松手收尾」那一段能落在长按动作上。留一页写进去永远不会命中。

判据放在 core 一处：`ComboKey.hasLong`（`!(isWait && ordered)`），清单由
`GestureTrigger.comboSlots` 收口。三处界面都只读这一支 —— 各读一份就会演出
「带子只剩一档、分页器还是两页」：

- 编辑页手势带与分页器页数（`comboGestureSlots()` → `PagePagers`）；
- 「场景动作」页与系统场景里每块的动作行（`BranchOwner.bindingTargetsOf`）。

判定侧 `ComboDetector.scheduleLong` 同样早退：排了枪会到点判出「长按」并把 `longFired` 置上，
抬手那条路于是不再按「一起短按」派发 —— 而那一档在界面上根本配不出长按动作，
结果就是「按完什么都没发生」。

两处界面细节：

- 页数会变小：先在「不分顺序」那档停在长按页，退出去再进一档按顺序触发的组合，
  位置还留在第 2 页而页数只剩 1，分页器自己停在越界那一页时横向那一屏是空的 ——
  `PagePagers` 按 `pageCount` 收一次位置；
- 只剩一档时整条手势带不画，并且**显式报 0 高度**：那一页上一次可能画过两档的带子，
  高度按页缓存在 `BandHeight` 里，不报的话内容顶上会一直空着一条已经不存在的带子。

## 四、「添加组合」按顺序空间判

选键窗的「添加」原先按「这一类里还有没有一档没占」判。而等待组合加完「不分顺序」之后
还能加各种有序排列 —— 「有没有一档」不代表「没得加了」。

改成按**顺序空间**判：`n!` 个排列里还剩没剩（`orderSpaceSize` / `usedWaitOrders`），
按住组合仍按「每个成员各当一次首键」（`comboAllModesTaken`）。四种「加不进」分开说：

- 按住那几种首键都当过 ⇒「所有触发方式都已添加」；
- 已经加过某几种顺序、而「不分顺序」被它们挡住 ⇒ `combo.order_any_blocked`；
- 顺序一个不剩 ⇒ `combo.order_all_blocked`（新文案，说的是「顺序已满」而不是「这组加过了」）；
- 还没选够键 ⇒ 原来的那一句。

顺序选择器里两个方向也互为阻塞：已经加过**按顺序**的组合时，「不分顺序」那一行点不动
（它覆盖所有按法）；反过来已有不分顺序时，各排列也加不进。原先用「这组按键已经添加过了」
说「加过一档有序组合」，用户点的正是那一行，读起来像坏了。

## 五、界面：一张卡一根滑杆，按开关挑格

两张卡各只摆一根「等待窗口」，**按它自己那颗开关挑当前那一格**（开 = 整串，关 = 相邻两颗 /
每颗各自），显示值、双击回落值、写入落点三者一起跟着换。摆两根让人猜哪根算数，
与单击设置里「等满多击窗口」那一根同一条做法。

- 正反两格分别存，所以「关着起点调好的那个数」不会被「开着起点调的那一下」改写；
- 「按键之间的等待」整行删掉 —— 它问的是同一件事，现在就是「关」的那一格，随开关露面；
- 「固定窗口长度」改名「等待窗口」，与等待组合那张卡同名同一句；
- 写函数按格拆：公共四支 `setComboWaitWindow` / `setComboWaitPair` / `setComboHoldWindow` /
  `setComboHoldFollower`，档内四支 `setComboOwn*`，两颗起点开关各一支；
- 打开「使用独立设置」时四格 + 两颗开关**一起播种**（`withSeededComboFields`）。
  少播一格，那一格就还在跟随公共 —— 界面上看着像「独立设置开着、可这根滑杆拨了不改行为」；
  只播一颗开关，另一颗仍停在 `null`，改公共设置会连带改到这一档。

## 六、「显示更详细的按键设置」

「更多选项 → 配置」第一行加了一颗开关（`GlobalConfig.detailedKeySettings`，默认关），
与「界面振动反馈」同一档：只落盘、不进广播，判定与执行一个字都不读它。

**这一位现在还没有读取方** —— 先把配置键与回执跑通，按键页暂时不变。写在这里是为了让
下一个接手的人知道它不是坏了。
