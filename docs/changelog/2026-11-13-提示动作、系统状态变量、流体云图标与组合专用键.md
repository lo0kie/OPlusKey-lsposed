# 2026-11-13 · 提示动作、系统状态变量、流体云图标与组合专用键

### 新增：`toast:` —— 第三个「让用户看见一句话」的落点

- 三条按**留不留得下**分工：`notify:` 进通知中心能留着、`fluid:` 在状态栏挂几秒、`toast:` 说完就没了。正文同样展开变量。
- 走模块**唯一那条提示出口**（`requestSystemToast`）：宿主发广播，注入侧用系统身份（包名 `android`，持有 `UNLIMITED_TOASTS`）发话。之所以绕这一圈，是宿主自己的包受系统按包限流（3 条 / 20 秒），连按几下之后后面那些会被 `NotificationService` 静默丢掉 —— 真机表现就是「按了没提示」。
- **这一档没有图标，也做不到**：Android 11 起带自定义视图的 toast（`setView`）会被系统按「后台应用 + targetSdk ≥ 30」拦掉（`Blocking custom toast from package …`），而文字 toast 由 SystemUI 自己画、`getView()` 返回 `null`。要带图只能用自绘浮层（要悬浮窗权限），那是另一件事。结论写在 `Action.Toast` 的 KDoc 里，免得以后有人再试一遍。
- 已登进「支持的命令格式」卡（`Action.PREFIXES` 同步加一项，两边是同一个集合）；`isBarePrefix` 认「只有前缀」为坏配置。

### 新增：流体云可以带图标（`fluid:<图标 id>|正文`）

- 分隔符选 `|` 而不是 `:` —— 正文自己常带冒号（`fluid:现在是14:30`），用冒号切会把时间劈开。没有分隔符时整段都是正文、图标留空，旧配置照常读。
- 分隔符前那一段**只认小写字母 / 数字 / 连字符**；认不出（比如正文本身带一个 `|`）就把整段当正文 —— 宁可少切一刀，也不吃掉用户一截字。
- `fluid:` 那一栏多一档「图标」（只在正文是 `fluid:` 时滑入）：点开是一张 Tabler 字形网格，标题行尾带总数（`(48)`）；点中一颗即把它渲染成 36×36 透明底纯白 png，写进宿主的 `files/share_images/okey-fluid-<id>.png`，命令里只记 id。
- 宿主侧按同一个 id 找文件、组 `content://` 并授权给 SystemUI —— 不改包、不 hook。

### 改：没选图标就**不画**图标

- 以前有一条「默认图标 + 宿主兜底」的链路：界面层进设置页时预渲染一张 `okey-fluid.png`、宿主执行时缺文件就塞模块 assets 里那张 `card_icon.png`。于是「选过默认那颗」和「压根没选」长得一模一样，用户也没法让它干脆不带图。
- 现在 `icon` 为空时 `logo` 直接传空串，胶囊左边那格空着。传了图标但 png 还没渲染出来（刚导入配置）仍退回包里那张通用图 —— 用户是**选过**的，给张通用图比空着更接近他的意思。
- 随之拆掉的死代码：`ExportFluidCardArt`（预渲染默认图，已无读者）、`FluidAction.moduleAsset` / `ICON_ASSET`、以及 `assets/fluid/card_icon.png` 那个文件本身。

### 改：「以 root 执行」只在命令**用得上**时出现，且不落盘

- 新增 `Action.usesRoot`（全项目唯一判据，`this is Shell`）：那个开关管的是**执行身份**，只有「另起一个进程跑一段命令」那一档有身份可挑。`toast:` / `notify:` / `fluid:` / `keyevent:` 走的是模块自己的通道，开了没有任何差别 —— 给它们摆一个开关，只会让人以为「不开就跑不了」。
- 判定只在 `shell:` 时滑入显示（`AnimatedColumn`，与「图标」那一档同一套动效），小标题跟着卡片一起进退。
- **保存时也不写这一位**：不是 `shell:` 的命令直接落模型默认值。表单里会残着上一次的值（`reset()` 归 false、`load()` 灌的是上一个真实取值），照抄就会让一条 `toast:` 命令的配置里多出一个 `root: true`，读起来像「这条提示要以 root 执行」。`dirty` 比较同步收紧，避免在不存在的开关上动一下就判定「有未保存改动」。
- 图标角上那颗 root 井号同样只给 `shell:`，与开关是**同一份判据**：能看见开关的那一档，列表里才看得见井号。
- 两条**真会提权**但进不了自定义命令的（`proc:stop:` 硬编码 `su` + `kill -9`、`bright:` 自动亮度时写私有键）不在管辖范围：`PREFIXES` 那道闸把它们挡在手写之外，而且它们直接调 `ShellRunner.exec`、不读 `Command.root` —— 给了开关也是假的。完备性论证写在 `usesRoot` 与 `PREFIXES` 两处，互为指路。

### 新增：按键「只参与组合按键」

- 「独立设置」页手势卡最前面多一行（**不吃**「使用独立设置」总开关）：这颗键不判任何单键手势，按下 / 抬手原样放行给系统，模块只用它等组合的另一半；另一颗键在窗口内按下时组合照常成立，**那一下**照常吞掉。
- 抬手吞不吞按**自己那一次按下**走（放行过的抬手不能吞，否则系统只收到半截）；按住不放的重复事件既不喂组合也不吞。
- 行首图标用 `arrows-double-ne-sw`：双向，对应「两头都有去处」—— 单键归系统、组合里照样干活，不是坏了也不是只剩一半。
- 它**不是**已删掉的「交还系统」动作档：那一档要「同一次按压归系统」、必须先吞 DOWN，两者互斥。代价（组合成立时先按那颗的原生动作已经发生）写在 `docs/runtime/key-to-gesture.md` 四。

### 改：开了「只参与组合」之后，那几处一并不给配动作

- **独立设置页**：除了「只参与组合」这一行自己，多击那三档（三击 / 四击 / 单击后长按）与「接口 / 振动 / 提示」那张卡整体灰掉 —— 这颗键不判单键手势，配了也没处执行。留那一行是因为**关回来**得走它。
- **按键绑定页**：整页灰（原有行为），另外三处也禁用 —— 顶部「系统场景」入口、右下角那颗「进自定义命令」的 FAB、「自定义命令」小标题跳转。判据收进 `bindingTargetStopped` 一处，四个读者共用。
- **⋮ 菜单**：「系统场景」那一行禁用，但「独立设置」**必须留着** —— 那一页是唯一能把这一位关回来的地方，菜单里也拦上就再也点不进去了。
- **按键列表**行尾那一格改成三态（`keyStateLabel`）：停用 →「已停用」、只参与组合 →「只参与组合」、正常启用 → 什么都不写。两处列表（内置侧键 / 自定义键）共用一份判据；组合键恒传 `comboOnly = false`（那一位只属于单键）。
- 「只参与组合」不换行首图标：那颗键仍在干活，不该画成停用的样子。

### 新增：系统场景那几档状态可以当变量写进命令

- 新增一类**只读变量** `${sys.<条件 id>}`（`sys.ringer` / `sys.screen` / `sys.wifi` / `sys.charging` / `sys.time` …），取值与系统场景条件**同一套词表**（`normal` / `vibrate` / `silent`、`on` / `off` / `locked` …），判据也是同一份。
- 两种写法：不带后缀是**输出值**（`silent`），带 `.text` 是**文案**（「静音」）—— `${sys.ringer.text}`，文案跟着界面语言走。
- 名单只收「说得清此刻是什么」的那几种：前台应用两档（取值是一组包名）不进这张表；**时间区间进** —— 输出值是**时间戳**（毫秒），文案值是此刻的 `HH:mm`。
- 用户自建变量同名时**用户那一颗赢**（`sys.` 是约定、不是保留字）；判不出时按原文留着，与「认不出的变量名原样保留」同一条。

### 新增：「命令详情」下面一档「可用变量」

- 单条命令页在正文输入框与「命令设置」之间多了一档：小标题 + 一行入口（行尾是 **selector**），点开是一层菜单，一行一个状态（行首图标与系统场景菜单同一颗），小字就是这一档**此刻**的值（「静音」/「开」/「14:30」）。
- 菜单顶部那行小标题带条数（`可用变量 (8)`），卡里那行入口的标题仍是纯标题。
- 点一行先弹选择窗，问**要哪一种写法**：两行分别写着此刻这个值在两种形态下的样子（「输出值（on）」/「文案值（开）」），选完把对应的 `${sys.xxx}` / `${sys.xxx.text}` 接在正文末尾，并把页面滚回顶部。
- 名单、取值、文案全部来自场景条件那一份，界面上不另存一份；排序态里整张表跟着禁用。

### 改：`shell:` 的 `${变量}` 展开点沉到唯一出口

- `shell:` 有三条进来的路（内置动作、单条命令的正文、多条命令的步骤），原先只有内置那一支会展开 —— 自定义命令正文里写变量会**静默不展开**。现在三条路共用 `ActionRunner.runShell` 这一处。
- `Action.expandedWith` 因此不再展开 `shell:`，改为把通知 / 流体云 / 提示的正文纳入展开。
- 执行侧新增 `${sys.xxx}` 的唯一取值出口（`ConditionProbe.varValue`）：用户变量里查不到这个名字时才被问到。

### 改：命令详情不再自动聚焦

- 点「支持的命令格式」里一行，原先会「滚回顶部 → 等窗口拿到焦点 → 抢焦点 → 键盘弹出 → 光标挪到末尾」。现在只剩**滚回顶部**：点一行格式是「挑一个前缀」，不是「要在这儿打字」；抢了焦点键盘就顶上来，把刚点的那张格式卡盖掉。
- `CommandUiState.singleFocusRequest` 随之收窄成 `singleScrollRequest` —— 名字只管滚，注释也重写成「只管滚，不管焦点」。输入框不再挂 `FocusRequester`，也不再挂 `caretToEndOnFirstFocus`（用户自己点进来时，光标该落在点的地方）。
- 弹窗自己的聚焦（`FrostedDialog` / `NameDialog` / `FocusOnShow`）一行未动。

### 新增：键盘收走就失焦

- 收起键盘（返回键 / 键盘上那颗收起键 / 系统收走）之后，输入框**仍然持着焦点**：光标还闪、框还画着聚焦描边，可键盘没了 —— 这时去点别的输入框，第一个框看着还「在编辑」。
- 新增 `ImeFocusRelease`：键盘从**露着**变成**没了**的那一刻清焦点。判据有两条（IME inset 与 View 层），所以用轮询而不是 `snapshotFlow`（后者收不到 View 层的那个变化）。
- 弹窗里的那一档要等守卫窗口过去（`AppInputOptions.imeHoldMs`）—— 两个窗交替时，「关掉的窗顺手收键盘」不能被当成用户编辑完了。

### 新增：多击窗口可以「逐次等满」

- 按键设置卡新增一行「逐次等满多击窗口」：关（默认）= 数够要的那一档就立刻判；开 = 每一击之后都等满窗口、按实际击数判（超出最高档的击数夹回最高档）。
- 开着它时「忽视无操作双击」不生效（那是「抬手即判单击」的抢跑，与等满窗口正相反），单击最坏多等一个窗口。

### 改：顶栏副标题把键名画成圆角框

- 装**键名**的那几页（按键绑定 / 独立设置 / 场景动作 / 组合键编辑）副标题不再拼 `[侧键]×[电量 +]` 这种文字，改成每颗键一枚圆角框、中间一个 `×`，与列表行、场景条件同一套 tag；框**只占一行**，超宽裁掉，不把顶栏顶高。
- 框的字号就是副标题那一档，颜色跟着这一页的压暗值走 —— 整页停用时框与里面的字一起暗下去。
- 界面库的顶栏补了一个 `subtitleContent` 槽位（`patches/coui/0015-subtitle-content.patch`），与 `subtitle` 二选一；本地仓库那份 aar 同步重打，`verification-metadata.xml` 加了对应的 `also-trust`。
- 「单键叫什么、组合的成员是谁」收成一份（`comboKeyNames` / `settingsTargetNames` / `branchOwnerNames`）：需要逐个上样式的拿名单，只需要一句话的拿拼好的串。

### 改：「常用命令」页顶栏副标题把条数写进句子

- 由 `已添加的动作 (3)` 改成「已添加3个动作」，与「已保存3条命令」同一写法；英文档 `3 actions added`。
- 一条都没有时写「没有添加的动作」，不报数（与「已保存的命令」那一页同一个口径）。

### 改：条件取值那几句文案下沉到 core

- 「锁屏」「振动」「开」这一族翻译原先只在界面层，而执行侧展开 `${sys.xxx.text}` 时也要念同一段字 —— 实现挪到 `core/present/ConditionValueText`，界面层那份只留转发；条件菜单、条件行、变量菜单、执行侧共用一份。

### 配置格式：两个键级字段（version 47）

- `KeyDto` 新增 `combo_only` / `wait_multi_window`（`null` = 老文件按「关」读），两个都进 `ConfigFields` 的广播字段表 —— 注入侧判定要用（吞不吞、到档等不等）。
- `ConfigCodec.VERSION` 46 → 47，`tools/config-shape.txt` 同步刷新（108 → 110 字段）。

### 改：规模判据从「只许降的棘轮」改成三条绝对阈值

- 原先 `tools/audit-ratchet.py` 把「今天实测到的值」记成上限、声称只许降。查历史发现**8 次提交改过 8 次上限表，两个指标一次都没降过**（`Strings.kt` 1513 → 1513 → 1514 → 1542 → 1554 → 1587 → 1646；`settings_page_ext` 516 → 517 → 520 → 530 → 530 → 534 → 546 → 546）—— 原因是结构性的：`--tighten` 在超限时根本走不到，而功能开发期规模只会涨。
- 更要紧的是它数的是**物理行数、含注释**：本仓库注释占比 50–70%（`Action.kt` 1139 行里 436 行是代码），于是「把判据写清楚」这个动作会被记账，逼着人解释「为什么多这几行」，理由无一例外是「因为加了功能」。
- 现在只剩三条**绝对阈值**（`tools/ratchet.txt`）：detekt 基线必须为 **0**（一条豁免都不许有）、`SettingsPage` 状态字段 ≤ 45、页面扩展成员 ≤ 700。给的是**失控线，不是现状** —— 正常加功能碰不到，真要一口气挂几十个才红。
- 千行文件与逐文件行数不再管（它分不清「123 行图标声明」与「1600 行逻辑」）。「看一眼」的警告仍留在 `audit-coupling.py`（1500 行那条）。
- 脚本会校验阈值表的键与它度量的键一一对应：拼错一个键就等于那条判据没在跑，那种「全绿」是假的。

### 新增：系统状态变量的单测

- `SystemVarsTest` 覆盖名字解析（`sys.xxx` / `.text` / 认不出）、名单范围（前台应用不进、时间进），以及三条展开规则：用户表没命中才问兜底、同名时用户变量赢、通知与流体云正文展开而 `shell:` 留给它自己那个出口。
