# 以 Shizuku 执行、常用命令入口与命令格式收口

## 改

### 改：`shell:` 可以选「以 Shizuku 执行」

- 命令设置里多一行「以 Shizuku 执行」，与「以 root 执行」同一档：**每条命令自己的开关**，
  只在正文是 `shell:` 时出现；两行**互斥**（开一个就把另一个关掉，旧配置里两条都为真的读进来时
  归一成 Shizuku）；
- 两行都是「先有授权，才许打开」：没授权时点一下就是去申请，拿到才真的停在「开」上，拒绝 /
  关掉框就退回「关」；Shizuku 那一行的勾还跟着授权状态走（撤了授权自己灭），root 那档读不了，
  只在按下去那一刻探；
- 授权框由 Shizuku / Sui 自己弹，**关掉框不算失败**（一个字都不报）；只有「没有可用的 Shizuku」
  才弹那句失败提示；
- 执行先在本进程做（Sui 那一路：zygisk 把 binder 注进了每个 app 进程，`Sui.init` 就能拿到），
  拿不到才转交模块进程那一路（真 Shizuku）；两条路共用同一份执行实现；
- 没有可用 Shizuku（没装 / 没起 / 没授权）单独报一档，与「命令本身跑失败」分开；
- 清单里补上 Shizuku 的 binder ContentProvider 与执行 Service（后者按调用方 uid 拦一道，
  只认自己与宿主）；
- `Command.viaShizuku` 随命令落盘（配置里多一位，缺键即「不走」）。

### 改：「添加命令」这一行改叫「添加常用命令」，行首补一颗加号

- 按键绑定页「常用命令」那一段空着时露出的那一行：文案改成「添加常用命令」（英文
  `Add common command`），行首补一颗加号；行尾那颗箭头留着 —— 它说的是「后面还有一页」，
  加号说的是「往这张清单里加一条」，两件事各由一处说；
- 同一个字典键还被「加一条」那个抽屉当标题用，跟着一起变；
- 这颗加号与「添加按键」「给命令加一步」是同形不同义（对象分别是按键 / 步骤 / 常用命令清单），
  按本仓库的规矩各留一个名字。

### 改：格式提示并进「支持的命令格式」卡，红字回到输入框那一格

- 输入框底下那句「格式提示」整条撤掉（连同它那一族排版：居中注脚、固定间距、trim 掉行高留白
  的那版字）；红字交回库的 `errorMessage`，与输入框同一张卡、同一套左右边距；
- 那几句「后面该跟什么」并没有丢：并进「支持的命令格式」卡每一行的左列，写成
  `shell: <命令>` / `keyevent: <keycode>` / `notify: <文字>` / `shortcut: <id>` 这种形式
  （冒号后留一个空格），中英两份都改了；
- 卡片里相邻两行的分隔线左端缩进到文字列（起于图标 + 图标间距之后），右端仍按行的外扩让回来；
- 字典里那七条 `command.format_*_tip` 连同生成物里对应的七条常量一并删掉（提醒那句已并进卡片，
  再留着就是第二份文本）。

### 改：可用变量的选择窗改用「状态名」，并新增「前台应用」

- 选择窗标题从变量名（`${sys.x}`）改成**状态本身**（屏幕状态 / 系统时间 / 前台应用…），
  菜单副标题补一行「当前：」加这一刻的取值；
- 每个变量的两行调换顺序：**文案值在上、输出值在下**（写命令时先看到的是「显示什么」）；
- 「时间区间」这一档在两侧统一改叫「系统时间」（原来的变量名那一份删掉，同一件事只留一处说法）；
- 新增「前台应用」并排在菜单第一位：输出值是包名、文案值是应用名，`APP_NOT` 不参与；
- 单测里那三条「前台应用不当变量」的判据跟着改成「能」。

### 改：通用菜单自己画一条边框（颜色取 header 按钮那一档）

- 面板四角是超椭圆，正圆角的描边画上去会四角缺一截 —— 改用 superellipse 那段路径拼框；
- 描边与磨砂层拆成兄弟层：`clip` 会连带裁掉它右边的绘制，画在同一层里圆角处必然被削；
- 只往里让半个线宽，不再额外内缩（1dp 边线本来就该压在边沿上）。

### 改：几处图标换成更贴意思的那一颗

- QQ 群：换成 QQ 字标；「编辑列表」：换成 `sort-ascending-shapes`；「测试命令」：换成 `test-pipe`；
- 新用到的两颗字形补进图标选择器清单（`sortascendingshapes` / `testpipe`）。

## 修

### 修：刚写到 `keyevent:` 就报「必须以支持的格式开头」

- 判据拿「解析得出动作」当「格式合法」，于是只打了个支持前缀（`keyevent:` / `shell:`）也会被判成
  格式不对 —— 红字和下面那句格式提示同时指着同一个位置，一边说「这样写」，一边说「必须以支持的
  格式开头」；
- 现在「还只是个前缀」单独成一档：不算错、不报红字；保存按钮与「测试」那条路对它的说法也跟着改
  （报「还没写完」，不报格式错）；
- 判据只认**这一栏允许手写的那几种前缀**（格式提示认得的那一份），`bright:` 这类内置动作前缀
  照旧报格式错。
