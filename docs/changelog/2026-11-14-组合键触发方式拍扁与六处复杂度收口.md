# 2026-11-14 · 组合键触发方式拍扁与六处复杂度收口

### 改：一档组合只认一种触发方式，写在这一档的 `mode` 里

- 三种方式：等窗口 / 先按住第一颗 / 先按住第二颗。**它们共用 `single` / `long` 这一对动作槽** —— 换方式就是换这一档的判据，不是换一套动作表。
- 原先一档带两条开关（`windowOn` / `holdOn`）+ 一组「加过哪几种按住顺序」（`holdOrders`）+ 四套动作槽（`single` / `long` / `singleA` / `longA` / `singleB` / `longB`），32 种配置只对应 8 种行为，还得再定义「窗口与按住同时成立时谁优先」。拍扁之后同一档只有一条判据，两条不会同时成立。
- 按住那两种**只对两颗成立**：三颗及以上没有「哪一颗先按住」这个唯一起点，解析与界面两处都按 `ComboKey.modeFor` 夹回等窗口。
- 「两条都关着 ⇒ 这一档永远不成立」这个空档随之消失：组合动作页不再有那页空态，页签带也不再为它灰掉。

### 改：组合列表拆成「等待组合 / 按住组合」两列，类别在添加时定

- 两列各有自己的筛选（`ComboEditState.waitFilter` / `holdFilter`）与自己的上限（`MAX_COMBOS` 每列各算一次，标题上的计数只数本列），行首「第几组」也**按段内独立编号**从 1 数起 —— 原先按全局位次给号，按住那一列从「等待的条数 + 1」开始，看着像前面缺了几组。
- 每列末尾各有自己的添加入口：「添加等待组合」直接建；**「添加按住组合」选完键再问「先按住第一颗还是第二颗」**，问完才落盘。
- 方式是一档的身份，所以没有「在这一档上改方式」这条路 —— 想两种按法就在两列里各建一档。同一类里等待只有一档、按住两档（两种顺序各一档）：`comboRoomLeft` 判这一类还排不排得下；顺序选择器里**已经用过的那一种置灰**，「添加」按不动时说的就是这句。那个选择器是「二选一新建」，不是在改某个已选值，所以哪一行都不打勾（`selectedIndex = -1`）。
- 行内文案按类别分开：**等待组合**仍是「`[侧键]`×`[电量 +]`」一串框；**按住组合**写成一句「按住 `[侧键]` 后再按 `[电量 +]`」—— 那两档的判据就是「谁先按住」，只摆两枚框读不出顺序。句子里键名仍是 `NameChip`（模板按 `%s` 切成几段、段与框交替排，装不下换行），框宽跟着自己的字宽走，不套整列那个对齐用的宽。
- 组合动作页底角那颗「触发方式」FAB 与 ⋮ 菜单里那一行都撤掉：两列本身就是入口。

### 改：同一组键可以有几档，判定侧逐档试、按住优先

- `Config.comboFor` 拆出 `combosFor`（返回候选列表：成员多的在前，同数按配置顺序），`ComboDetector` 的 `bindingFor` 换成 `bindingsFor`。
- `pairFor` 对候选**逐档试它自己的判据**（等窗口看窗口，按住看起点键 + 下限），某档命中就取它；**按住那几档命中即停** —— 它要求起点键先按满下限，是比「第二颗在窗口内落下」更明确的表态。多成员路径（`multiFor`）与升级路径（`absorb`）只在候选里挑「够大且认窗口」的那档。

### 改：切触发方式与「松手时触发」一次落盘

- 加按住那两档之前先查**起点键**是不是「松手时触发」：不是就先问一句，确认后同一次落盘（改那颗键的长按时机 + 建这一档）。那一问挂在组合列表页（`ComboModeAskDialog`）—— 添加动作发生在那里。
- 关掉某颗键的「松手时触发」时，以它为起点的按住档**改回等窗口**：留着它们只是一个永远按不出来的档，动作还在，换回等窗口照样能用。

### 改：公共设置里那两颗「使用等待手势 / 使用按住手势」撤掉

- 它们只管「新加的组合默认认哪条」，而默认值现在就是 `MODE_WAIT`，没有可拨的东西。那张卡只剩三个参数：无操作时执行按键命令、按键之间的等待、首键按住时长。
- 独立设置里，「按键之间的等待」「无操作时执行按键命令」只在等窗口那一档出现，「首键按住时长」只在按住那两档出现。

### 改：配置格式升到 58，老配置推一次

- `ComboDto` 多了 `mode`；`GlobalDto` 的 `combo_window_on` / `combo_hold_on` 与 `ComboDto` 的 `windowOn` / `holdOn` / `holdOrders` / 四套 A·B 动作槽退场。
- 老文件由 `LegacyCombo.kt` 推成一种：认窗口就当等窗口，只认按住就看加过哪一种顺序（只有第二种 ⇒ 先按住第二颗，其余 ⇒ 先按住第一颗），再把**那一种方式原来用的那一对槽**搬进 `single` / `long`。两种都关着的老配置落回等窗口，配过的动作留在这一对槽里。
- 那七个字段留在 DTO 里只为「`ignoreUnknownKeys` 不把老文件那几位静默吞掉」，写回恒为 `null` / 空表；等确认没人从 v57 及以前升上来，就连推演一起删。

### 改：只参与组合的键，没理由压住的那一下就完全交给系统

- 那一组既不认窗口、这颗键也不是**起点键**时，按下**原样交给系统**：不压窗口、不补发、一次注入都不做。原先这种情况仍然先吞一个窗口再把事件补回去 —— 单按白慢一拍，补回去的还是我们注入的那一条，不是用户按的那一条。
- 四种情形按这个顺序分：凑成组合（吞）> 起点键（压到抬手）> 认窗口的成员（压一个窗口）> 都不沾（完全放行）。集合在配置到达时算好（`deriveCombos` 的 `holdStarters` / `windowMembers`），按键路径上只查表。

### 改：组合那六处「同一条规则写几遍」各自收成一处

- **触发方式的开关与参数**：「独立设置开着看自己、关着看公共」原先在 `Config` 里手写了五遍，现在收成 `effective` / `stored` 两个判据 —— 一处实现、其余都是单行。
- **配置到达时的三张派生表**：参与组合的键、每颗键要等的窗口、按住档的起点键，原先各扫一遍 `liveCombos()`，现在一次遍历产出同一个对象（`deriveCombos`）。
- **组合的老配置迁移**：推演搬进 `LegacyCombo.kt`，`ComboDto.toCombo` 只剩一句委托。
- **页面级的「一问一答」**：停用 / 启用键与组合那一问、切触发方式那一问、关掉「松手时触发」那一问，原先各是一个 `object` + 每条字段一个 `mutableStateOf`（中间那一帧会被读到半截，归零漏一位就挂住）。现在共用一个 `PendingAsk<T>`，载荷是一个对象。
- **每页一份的带子高度**：七个字段（其中一个已经没人读）改成按 `Screen` 索引的 `BandHeights`；「场景动作」页那三样（第几块 / 停在哪档 / 进来时长什么样）收成一个 `SceneBinding` —— 它们永远同进同出，分开三份时「放弃」会按上一块的基线还原。
- **动作图标**：清单里已经声明过的 token 不再在图标兜底表里抄一遍（删掉 14 支重复分支），剩下的分支只服务「清单里没有 `Spec` 可查」的写法；最后一道兜底从 `Dots` 改成「清单里有就按它的字形画」。

### 修：卡片首行藏起来之后，第二行顶上多出一根悬空细线

- `CardRow` 的分隔线原先按**物理位次** `index > 0` 判，行藏起来之后它就成了卡片第一行、却仍画一条线。真机上「按住组合 → 独立设置」里那根「首键按住时长」就是这样（它前面的「按键之间的等待」只对等窗口那一档出现）。
- 现在按**此刻还在场的那几行**（`shown`）判首行：首行不画线，退场播完的行也不画。这一处是公共组件，其它卡片里「首行隐藏、次行顶上多一条线」一并修好。

### 修：顺序选择器没去重、且带着不该有的选中样式

- 打开「先按住第一颗 / 第二颗」那一问时先取这组键**已经用过的顺序**，用过的那一行置灰 —— 否则能建出两档同顺序，后一档永远轮不到。
- 那个窗是「二选一新建一档」，不是在改某个已选中的值，所以不再给第一行打勾（`selectedIndex = -1`）。

### 改：chip 那一层多加一个「句子里夹名字框」的排法

- `ChipFlow` 的换行间距常量开成 `internal`（`CHIP_FLOW_GAP`），组合列表那句「按住 A 后再按 B」与场景条件共用同一份间距；句子里的框不套整列统一宽度（那是给「一串并列的键名」对齐用的）。
