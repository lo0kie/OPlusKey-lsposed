# 系统场景行尾、运行状态收口与抽屉几何

## 修

### 修：灵感语音在 ColorOS 16 上找不到落点

- 16 那代的 AI 记忆包（`com.oplus.aimemory` 16.10.1）没有采集服务，录音只在 App 内部；同一能力
  在「智慧数据感知」（`com.oplus.gleanerservice`）的 `flashnotes` 采集服务上，载荷与 17 那份同构，
  更早一代还挂在颜色直连服务里（取证见 `docs/device/actions/voice.md` 四十七、四十八）；
- 落点表 `RomProfile.BuiltIn` 多一位 `fallback`（可接成链）：开始 → AI 记忆 → 智慧数据感知 →
  打开「小布记忆」（`MainActivity`，宿主持有 `START_ANY_ACTIVITY`）；结束 → AI 记忆 →
  智慧数据感知 → 颜色直连服务的同一服务（事件号 2）；
- `AppLauncher` 起之前按 `PackageManager` 解析挑一档：带 action 的服务按 **action** 问（不看类名），
  判的是「在不在」而不是「有没有权限」；链上全都不在仍照主落点试，由原起法把「试过什么」写进日志；
- 主落点补 `longPressScreenOff=false`（ROM 自己那一发也带，缺了等于少说一句话）；
- 16 上那条旧服务在 `onStartCommand` 里有一道 SDK 版本闸，引导没走完只拉介绍页、不采集 ——
  所以「打开小布记忆」是那一代唯一能落到界面的路。

### 修：按顺序的组合落成两颗键各自单击

- `ComboKey.matchesOrdered` 从「按下序列**开头**几位」改成「**最后**几位」：当前这一下一定是
  这一组的最后一颗，扫描窗口里多出来的更早按键（比如这一组开始前先点了一下音量键）不该把
  有序组合判掉；
- 真机现象：音量减 → 音量加 → 快捷键 的顺序组合不生效，落成音量减与快捷键各自单击；
  日志里的「跨度 500ms」是**整串**的允许时长（逐次等 250ms × 2），不是某一格的设置值；
- 单测补两条：前面多一颗仍命中、成员之间夹一颗仍不命中。

### 修：图标选择器点格子没有振动

- 弹层网格的每一格点击时叫一声通用振动（`LocalTick`，与卡片行 / 菜单行同一通道）：
  原先只在点中之后异步导出 png，整条路径上没有触觉反馈。

## 改

### 改：系统场景的动作行与条件行

- 动作行的档位（单击 / 双击 / 长按）从标题前缀挪到行尾、后面仍跟右箭头；没配（「跟随默认」）时
  标题、档位与箭头一起压到禁用色，行本身仍可点；
- 「前台应用」「前台应用以外」多选之后，名字之间不再插「和」，只留空格；
- 进「多选应用」不再弹那句多选提示，两句文案与常量一并删掉，多选本身不变。

### 改：「运行状态」收成手风琴，并去掉小标题

- 平时只摆「整体状态」一行；点它把每一段都滑出来（正常段也列），再点收起，行尾箭头跟着转；
  新增通用手风琴组件 `AccordionCard` / `rememberAccordionState` / `AccordionChevron`，
  正文行仍走 `CardList` 的 `visible` 进出场；
- 整体状态与各段明细的结论改贴行尾（只读行，行尾只留文字）；「主开关已关闭」那一句不再带后半句；
- 三段异常换成「坏」的字形：`server` → `server-off`、`keyboard` → `keyboard-off`、
  `pointer` → `pointer-cancel`；这几颗与 `device-mobile-question` 一并补进图标选择器；
- 「使用验证」两态都用 `test-pipe`、**始终不标红**（新增 `LinkCheck.neverRed`），
  行尾「未生效」改成「未验证」（英文 `Not verified`）；
- 调试通道 `--es checks all` 仍可把每段都按异常画（使用验证只换说法、不标红）。

### 改：「关于」页与版本串

- 「运行状态」不再有小标题，第一张卡与顶栏之间补回标题自带的间距；
- 机型（含适配清单的结论）从「运行状态」卡挪到「关于」卡，排在版本与签名之间；
  字形换成手机：命中适配 `device-mobile`，等待适配 / 不在清单 `device-mobile-question`；
- 「更多选项」的版本行只写版本号（`1.5.0`）并挪到行尾，不再显示构建类型与时刻；
- 首页状态卡的版本串去掉 `version-` 前缀（`1.5.0-debug-260…` / `1.5.0-release`）；
  导出日志头与「更多选项」页不受影响。

### 改：折叠态顶栏「标题 + 副标题」整组上移

- 副标题槽加一条 6dp 底边距（`(52 - 40) / 2`，由栏高与圆键算出）：库按副标题高度把标题
  堆在它上面，两行的 3.5dp 间距不变、整组一起上移，副标题底边与右侧圆键底边同线；
- 展开态因此多 6dp 空白，折叠那条 52dp 栏不受影响。

### 改：底部抽屉的圆角与滚动条

- 抽屉上沿两角从库默认 20dp 加到 24dp，与弹窗同档；
- 内容那一半的横向内边距改成由页面自己给（补丁 `0017` 的 `contentInsideMargin`），
  滚动条于是贴到面板右边缘、拇指完整；顶部不滚的那一块自己补 `PAGE_MARGIN`；
- 内容**不再**为滚动条额外让出一条：条正好落在两侧边距之外那 `SCROLLBAR_WIDTH` 上。

### 改：常用命令里的自定义命令按类型画字形

- 没换过图标的 `cmd:` 条目不再一律画通用命令字形：去命令库里找到那一条，按它的类型取 ——
  单条按写法 / 执行身份（终端 / root / Shizuku / 通知…），多条按步骤数（`box-multiple-N`）；
- 换过图标的仍以换的为准；引用的命令已被删掉时退回通用字形；内置动作条目不变。

### 改：「显示更详细的按键设置」先临时隐藏

- 「配置」卡第一行先不摆（配置项与写回逻辑一个字没动）：`SHOW_DETAILED_KEY_SETTINGS_ROW` 置
  `false`，恢复时改回 `true`。

### 加：诊断日志 —— 系统侧键配置的每个场景列出关键列

- 宿主读一次侧键配置后，逐个场景打印「谁 / 单击动作 / 长按动作 / 二级菜单」这几列（d 级）：
  排查「系统原生某个动作到底调的谁」时，答案就在这张表里。

## 依赖与补丁

- 界面库换到 `coui-ui-android:1.1.0-title2r4`（`strictly` 一并改）：相对 `title2r3` 多补丁
  `0017`（抽屉内容内边距可单独指定），`patches/coui/build-patched.sh` 的 `VER_TO`、
  `gradle/verification-metadata.xml` 与 `app/gradle.lockfile` 同步；
- `patches/repo` 里那几份产物随之重打，校验和一致（`tools/verify-patches.py` 通过）。

### 加：补丁 `0017` —— 抽屉的内容内边距可以由调用点单独指定

- 库原先只有一个 `insideMargin`，同时套在把手 / 标题 / 内容上：内容想自己摆边距
  （比如让滚动条贴到面板边缘）就只能整张抽屉一起缩，标题跟着挪；
- 现在多一位 `contentInsideMargin`（`OverlayBottomSheet` 与内部布局链都有），默认就是
  `insideMargin` —— 不传的调用点行为不变；内容区因此可以拿到整幅面板宽；
- 把手与标题仍吃 `insideMargin`，两边的左边线不受影响。
