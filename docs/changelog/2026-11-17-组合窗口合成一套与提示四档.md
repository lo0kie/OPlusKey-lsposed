# 组合窗口合成一套与提示四档

## 改

### 改：组合窗口合成一套，有序无序共用

- 公共那八格（等待 / 按住 × 整串 / 逐颗 × 是否按顺序）减到四格，每组自己存的那八格同样减半，
  四颗「固定窗口起点」开关减到两颗 —— 档位要不要按配置的先后落（`ordered`）与
  「多久之内落完」是两件事，窗口不该因此分成两套数；
- 公共设置页与独立设置页的等待卡、按住卡各自回到**一对**窗口行（原来公共那一片摆两对）；
- 配置版本抬到 85：`GlobalDto` 与 `ComboDto` 各少 `combo_ordered_*` / `ordered_*` 六位，
  老文件里残留的这几位按未知键丢掉，取值回落到共用那四格与两颗开关。

### 改：窗口那两行的前缀按页分工

- 公共设置的**按住**卡那颗开关写「按键间隔和多击固定窗口起点」（一份默认值同时服务
  三颗以上的按住档与两键档的成员多击）；公共的**等待**卡写「按键间隔固定窗口起点」——
  普通与有序两种等待档量的都是两次按下之间的间隔，前缀只有这一个；
- 独立设置页**只写这一档自己的前缀**：等待组合两种档都是「按键间隔固定窗口起点」；
  按住组合里三颗及以上与有序档同样是「按键间隔固定窗口起点」，只有两键档写「多击固定窗口起点」；
- 「顺序固定窗口起点」这条字典键随之删掉：有序档与其余各档量的是同一件事，再留一个名字
  只会让人以为窗口也是两套；
- **下面那根滑杆一律叫「等待窗口」**，不带任何前缀 —— 前缀只标「这一档算哪一类」，
  滑杆本身只回答「等多久」；
- 拨那颗开关的回执跟标题同源（同一个判据算名字），不再出现卡片写一种、提示说另一种。

### 改：执行时提示收成四档，命令只管「念什么」

- 「执行时提示」从「一颗开关 + 用流体云提示」换成**四档菜单**（不提示 / 通知 / Toast / 流体云），
  公共设置页与独立设置卡是同一行、同一份菜单；
- 四档由配置里那三颗布尔**派生**（`NoticeMode.of` 是唯一出口），这一轮为此补了
  「走通知」那一位 `toastNotify`：配置版本 84，`GlobalDto` / `KeyDto` / `ComboDto` 各多一格；
- 命令级的「提示执行结果」四档**删掉**，换成一颗「提示文案使用命令输出结果」：
  开着的命令，执行提示里那句动作名换成它的标准输出，没有输出回落到命令名 ——
  **念不念、往哪念**归「执行时提示」（含独立设置），命令这一位只管念什么；
- 连带删掉：`CommandOutput` 四档枚举、`OutputSink`、命令级那颗流体云图标（图标仍按动作自己那颗取）；
- 输出要等命令跑完才有字：判定侧只把「模板 + 主语 + 落点 + 回退那句」算好交下去，
  宿主在回调里拼 —— 一次执行仍然只留一条提示，不会「命令名一条、输出一条」；
- 流体云图标的名字带上**执行身份**（空串 / `root` / `sui`，三档各一张）：预渲染、清理名单、
  执行侧取图读同一份后缀，改完执行方式不再沿用旧那张井号；
- 配置版本 83：`CommandDto` 少 `outputIcon`、`output` 那一格换成 `showOutput`
  （老值非 `none` 即折成 `true`）。

### 改：命令列表编辑态补上「全选」

- 进「命令列表」的编辑态后，顶栏「编辑 / 完成」左边多一颗「全选」：按一下把清单一次勾满，
  已经勾满时再按一下收回 —— 与「按键功能」「常用命令」那两颗同一个位置、同一颗字形、同一档强调色；
- 勾中的是命令名（与列表行、批量删除同一个键）；一条都没有或整页写不了时置灰并说清原因。

### 改：判定算术收进 `core/judge`，第一次有了能跑的判据

- 新包 `core/judge/JudgeMath.kt`，装的是判定里**只跟数字有关**的那几件：
  `poolWithinWindow`（多成员候选池）、`followersFresh`（按住档成员是否都在窗口内落完）、
  `spanFrom`（整串跨度取最早那颗）、`fireCount`（到点实际派发几击）、
  `pressOrder` / `orderMatch`（按真实按下序挑有序档）；
- 它们原先是 `ComboDetector` / `GestureDetector` 的私有成员，**不碰状态、不读时钟、不调 Android
  API**，却因为住在 `:app` 而不可能被测（`:app` 没有 test 源集）。搬进 `:core` 之后
  `ComboDetector.multiFor` 只保留「什么时候算」，算术全走这几支；`GestureDetector` 那三处
  `clicks.coerceAtLeast(1).coerceAtMost(judgeCap)` 换成 `fireCount`；
- 新增 `core/src/test/.../judge/JudgeMathTest.kt`（12 条）：窗口边界、按住档首键早出窗口、
  一颗成员都没有、连击数超封顶 / 为 0、候选池里自身只出现一次、有序档只留顺向那档。
  这批边界原先只能真机手按——**这也是把它们搬出来的唯一理由**；
- 参数一律传数据不传容器（`presses` / `held` 是判定器那两张表的只读视图），不复制、不改写，
  热路径不因重构多一次 map 拷贝（`audit-perf` 通过）。

## 修

### 修：切「多击手势」时「等待窗口」那根滑杆会跳值

- 那颗滑杆的显示值原先带了「有没有开多击」这一道（`noMulti = judgeCap <= 1`）：关掉最后那档
  多击手势（双击出厂是开的）会让 `judgeCap` 掉回 1，滑杆当场从「多击窗口」改读「单击延迟」，
  数字一跳；打开时再跳回来；
- 而且那一跳之后显示的是错的：判定侧用的是 `clickWindowMs`（`waitMultiWindow` 为真时优先
  `multiWaitMs`），与开没开多击无关；
- 现在显示值只看**判定时机**（`fixedWindowStart`），「有没有开多击」只决定这一行能不能拖
  （`enabled` 与「未开启多击手势」那句）；写入的落点判据同步去掉了 `!noMulti`。

### 修：按住组合的长按连续触发一直不生效

- 现象：按住组合（例：快捷键 + 按键 1）到长按阈值，动作执行一次，之后按住不放**不再重复**；
  单键那一档的连续触发是好的；
- 根因：这一档开了成员连击时，成员键的**长按**也走成员连击链，而两条定时枪同一毫秒到点。
  成员链那条先跑 ⇒ 派发一档 ⇒ 成员连击的回调收尾（`finishCombo`）把整组清掉 ⇒
  **组合自己那一枪连跑都没跑**，而「长按连续触发」那串定时链只长在组合那一枪里；
- 已有的「让位」判据只认 `ClickThenLong`（单击后长按），`LongPress`（成员键自己那一档长按）
  没在里头 —— 两者都是「按住到阈值」判出来的、与组合长按是同一个手势，都得让；
- 真机日志（同一毫秒内的顺序）：`按键 1：长按` → `组合键：plus + ck1 成员连击 长按（cmb1）`
  → `组合键：cmb1（plus + ck1）长按 → keyevent:187`，之后到抬手一行都没有。

### 修：按住组合配了 AB 与 ABC 两档时，ABC 凑不出来

- 现象：`{A,B}` 与 `{A,B,C}` 都配成「先按住」，按住 A 再按 B、再按 C —— 第三颗被 `{A,B}` 吞掉，
  `{A,B,C}` 永远凑不齐（用户口径「想触发 ABC 被 AB 抢了」）；
- 根因：升级路径（`ComboDetector.absorb`）只认**等窗口**那一档（判据里带了 `it.isWait`），
  按住档走不进去；而等窗口那档不会出这事，因为它在 `awaitWider` 里先不派发；
- 现在升级按每一档自己的触发方式各量一次（新 `upgradeTo`）：等窗口档仍是「整串跨度还没用完」，
  按住档改判「起点键还按着且过了下限、长按没判出来、后续成员都在各自窗口内落完」——
  与「凑成」那两条判据同源（`holdReady` + `followersFresh`）；
- 上界仍是这一档自己的长按：长按一执行，这次按压的结论就定了，再换一档就是一次按压两个动作。

### 修：有序组合在顶栏那行还是念成「A × B」

- 顶栏副标题装键名的那几页（组合编辑页、「独立设置」、条件执行页）成员之间的分隔符现在跟着
  这一档有没有顺序走：不分顺序「×」、按顺序「→」；
- 按住组合那一句「按住 A 后再按 …」里**后续成员之间**同样按这一位走（原先不看 `ordered`、
  恒用「×」，于是顺序按住档读成「按住 A 后再按 B × C」）；
- 判据与组合列表行标题同一份（都看 `ComboKey.ordered`），同一组不会在列表里念「先后」、
  在顶栏念「一起按下」。

### 修：按住组合选「成员顺序」那一窗，退场时整支塌掉

- 现象：点中一行之后的那两百毫秒里，窗上的键名先变空（`按住  后再按  `），随后整支被摘掉，
  退场动画根本来不及播；
- 「触发方式」「等待顺序」两窗早就各留了一份「比数据慢一格」的副本，唯独最后这一窗没有 ——
  现在三窗共用同一支（`LastHoldOrder`）：点中 / 取消时数据立刻回 `null`，窗照最后画过的那一份画完。

### 修：Sui 授权成功后本页会整个消失，却一直挂一句「正在检查授权…」

- 后端是 Sui 时，权限一变它就 `force-stop` 请求方（作用在宿主那两个进程上），正编辑着的页面
  连同草稿一起没掉，等不到任何回执 —— 屏幕上那句「正在检查授权…」永远不结束；
- 现在那一行按后端分两句：Sui 这一档提前说「授权成功后本页会重启，重进本页后再打开该开关」，
  真 Shizuku 仍是「正在检查授权…」（它按 uid 记，不重启进程）；
- 发起请求时先打一行 W 日志，说明这一次会以「本进程被 force-stop」收场，
  免得下次按「模块把页面弄没了」去查。

### 修：Shizuku 通道失败时只有一句 `exit=255`，看不出原因

- `ShizukuExec` 读 stderr 时原先传 `null`，只走 `d`（release 编译期消除）—— 走 Shizuku 的命令
  失败时日志里没有任何原因，`sh` 那条却有完整的输出尾；
- 现在收一个 12 行的环形尾部，**非 0 退出时以 `w` 回放**（与 `ShellRunner.logOutputTail` 同档）；
- 模块进程那条通道（`ShizukuShellClient`）仍只回 stdout：回执协议里没有 stderr 这一格，
  要补得先改 `ShizukuShellService` 的消息字段。
