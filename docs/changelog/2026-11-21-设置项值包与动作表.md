# 2026-11-21 · 设置项值包与动作表

### 加：设置项注册表 `Params` / `KeyParams` / `ComboParams` / `GlobalParams`

- `core/param/Params.kt`：六种 `Param` 形态（布尔 / 带区间的整数 / 动作 token / 文本 / 三态布尔 / 整数集合）
  加值包 `Params`（`Param.id` → 字符串）：写成出厂值的项自动从包里删掉，`normalized()` 读回时按注册表归一，
  认不出的键原样留着（可能是更新版本写的）；
- `core/param/ModelParams.kt`：单键 / 组合 / 公共三个作用域各一张表，每项声明落盘键、出厂值、区间，
  `ALL` 供全量序列化遍历；
- 加一项设置从此只是「表里加一行」——运行时那些同名属性只是读法。

### 改：单键与组合的存储从逐字段换成「动作表 + 值包」

- `KeyConfig` / `ComboKey` 不再是 data class：只剩 `actions`（档位 → 动作）、`params`（设置项）
  与结构位（`id` / `keys` / `enabled` / `scenes` / `useOwnSettings`）；
- 六十多个旧字段名全部保留为只读属性，`copy` 逐参数同名同义（没传的保持原值）——读与写的调用点都零改动；
- 新增 `with(spec, value)` / `withAction(trigger, action)` / `withActions` / `withParams` 四支写入口；
- 组合的 `mode` / `ordered`、四格窗口、成员后长按那几格一并进 `params`；构造点改成
  「结构位走构造 + 其余走 `copy`」（界面新建、调试入口、广播接收三处）；
- 场景表仍是结构、不进值包：`scene*` 派生位照旧由宿主算好随广播带过来。

### 改：动作按档位存，成员连击与单键共用一套编号

- `actions` 的键就是 `GestureTrigger`：组合自身的单击 / 长按 / 长按松手占 `Click(1)` / `LongPress` / `Release`，
  成员连击占 `Click(2)` 与 `Click(3..)`、`ClickThenLong(n)` 与其松手；
- 「成员第几击」与「单键第几击」从此是同一个编号，`count + 1` 那层换算在数据里不再存在；
- 加一档手势不需要动这两个类 —— `GestureTrigger` 本身就是键。

### 改：落盘格式换成「动作表 + 值包」，旧格式整份冻结成只读迁移

- `KeyDto` / `ComboDto` 只剩结构位加 `actions`（档位 id → 动作 token）与 `params`（`Param.id` → 值）两层，
  六十多格逐档字段与三十二格成员连击字段一起消失；
- `VERSION` 抬到 `99`：先读文件头部的 `version`，`v98` 及更早的文本整份按 `LegacyConfigDto`（冻结副本）解析，
  读出来之后不再参与写入；
- 写出时 `params` **全量写**（含出厂值），读回时按注册表归一 —— 「按当前 DTO 重编码算 md5」的口径不用改，
  也不会出现「同一份配置存一次长大一圈」；
- md5 之前的排序连 `params` / `actions` 一起排：只把两行参数或两档动作换个位置，不该让摘要失配；
- 新增 `LegacyMigrationTest`：一份 `v98` 文本读回来与新模型逐字段相同；新格式往返之后两段文本逐字相同；
- `tools/config-shape.txt` 跟着抬到 99（字段数 206 → 87）。

### 改：公共设置也走值包

- `GlobalConfig` 同样是 `params`（`GlobalParams`）+ 同名只读属性 + 逐参数 `copy`，`DEFAULT` 直接读注册表的默认值；
- 落盘 `GlobalDto` 保持逐字段：`@SerialName` 与「v73 四格窗口铺底」那种迁移语义都在它身上，
  改它换不到多少收益、风险却不小 —— 公共这一层加设置的频率本来就低。

### 改：广播每颗键改成两个 map

- 宿主发给注入侧那一份不再逐列（几十个 `F_*` extra），改成每颗键带 `params`（`Map<String, String>`）与
  `actions`（档位 id → 动作 token）两个 map，外加 `enabled` / `own` 两位；
- 发送侧仍负责把「生效值」与派生位算好塞进去：没开独立设置时的单击三项与后长按按住时长取公共那一份，
  `longIsSerial` / `clickThenLongIsSerial` / `scene*` / `judgeClicks` 照旧现算；
- 加一项设置、加一档手势，广播这一层都不用再动。

### 改：前台转小窗改用框架自己的切换入口

- 「前台转小窗时使用动画」打开时，先调 `FlexibleWindowManager#toggleFlexibleWindow`（计算器首页那颗按钮的同一条）：
  落点与切换动画都由服务端算，转换与动画一次完成；
- 它没受理（任务在过渡中 / 分屏内嵌 / 正在拖拽）才退「先原地收、再补播框架动画」那一档；
- 反射面（门面类名、切换方法名）进 `RomProfile`，与其它小窗名字同处；
- 加一道准入闸：判据用框架自己的 `isSupportZoomMode`（与「以小窗打开」同一把尺子），判「不支持」就提示并不做 ——
  这条入口本身不拦应用声明，不加闸会把不支持小窗的应用也强行收起来；收起档同样加这一道；
- 收起档（`zoom:mini:collapse`）也补上动画：先原地收成右上角那条，再用框架动画器演「全屏 → 收起落点」；
  收起落点（屏幕矩形与缩放）按机型进 `MiniWindowGeometry`，没量过的机器只收不播；
- 收起档的验收改成只记诊断：minimized 那一态报的窗口模式不是 `100`，拿它判成败会把「已经收起了」误报成「不支持小窗」；
- 补播动画前先判任务尺寸可调性：服务端「受理（返回 2）」不等于真转，不可调尺寸的任务会被受理却不转，
  那时补播就是「画面缩一下又弹回全屏」—— 两档都不再对它播动画；
- `docs/features/zoom-window/notes.md` 的总览表、配方与踩坑记录跟着更新。

### 改：以小窗打开时，目标应用已在前台也走动画档

- `window:包名` 的目标就在最前面时，「前台转小窗时使用动画」开着就走动画档：原生切换受理即完，
  没受理再「先真转换、再补播」，都不成立才落回 recents 正门；
- 这一段与 `zoom:mini` 共用 `animIntoMiniIfEnabled`（准入闸一起）：同一个开关在两条入口上不再表现不同；
- 收的仍是那一份前台任务，不新起实例；判「不支持小窗」时只提示、不动屏幕。

### 改：多条命令至少两步才能保存

- `Command.MIN_STEPS = 2`：保存前的判据、间隔卡的禁用、右下角那颗 FAB 三处共用它；
- 步骤不足两步时「保存」压暗（换底色与字形色，两段都跟着状态渐变），新写一条只有一步时那颗 FAB 干脆不画，
  改一条已存命令时照常出现；
- 「命令执行间隔」那张卡在步骤不足时整块禁用，提示语是同一句「至少两步才能保存」；
- 行标题「命令间隔时长」改成「命令执行间隔」，中英两份字典与相关注释同步。

### 改：首页「前台转小窗时使用动画」挪进「接口与显示」卡

- 这一行从「按键行为」卡移到「接口与显示」：它与「走哪套系统接口」同一类（决定命令怎么落地），
  与振动 / 提示那几项不是一件事；
- 行首图标换成 `transition-top`，隐藏它的常量 `SHOW_HOME_MINI_ANIM` 删掉 —— 首选换成框架切换之后，
  落点与横竖屏都不再由模块决定。

### 改：独立设置里删掉「使用 ColorOS 接口」

- 独立设置不再逐键分叉「走哪套系统接口」：那一张「接口与显示」小标题与 `OwnField.COLOR_OS` 一并删掉，
  这一项只在公共页调一次；
- 独立设置页只剩「总开关」与「按键行为」两张卡，卡标题与「按键设置」页仍读同一个字典键。
