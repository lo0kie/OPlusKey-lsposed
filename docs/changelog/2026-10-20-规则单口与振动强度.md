- 注入侧自检（`HomeLinkSelfCheck`）没跑完时，`injectStatus` 的 `null` 只是**初值**，

- 自检的两个出口（两端都答 / 问满所有轮）都置这一位，只置 true 不回 false（重进首页不收起已确认的结论）。

### 按键按状态执行不同命令（底层接口）

- `KeyConfig` 多了 `rules`（`StateRule` 列表）：一条 = 手势 + 状态条件 + 动作，按顺序匹配、
  **第一条成立的赢**；`KeyConfig.actionFor(gesture, state)` 是唯一入口，一条都不成立就退回原来那三档绑定；
- 状态维度先只做「前台应用」一档（`StateCondition.ForegroundApp`，写法 `app:包名`），
  其余维度以后按同一个接口加；
- 取不到环境时传 `KeyState.UNKNOWN`，于是所有分支都不成立 —— 与「状态不匹配」是同一个结果；
- 认不出的手势 / 条件整条丢掉，不兜成「永远成立」：那样一条写错的分支会静默接管这颗键的全部手势；
- 只做底层，判定侧与执行侧都还没接（`GestureExec` 仍只读原来那三档）。

### 工具：一条命令拿到作用域与重启状态（`tools/device-state.py`）

- 起因：排查「模块启动不起来」时，只看 `modules_config.db` 得出过相反结论 —— 库里的 `scope` 只代表
  **用户勾了什么**，不代表这一轮**真的注入了**。现在把结论拆成三层，缺一条就不下判断：
    - **时间线**：`settings get global boot_count`（单调计数，跨重启保留，两次采样不同即中间重启过）
        - `/proc/uptime`（`CLOCK_BOOTTIME`，含休眠）⇒ 开机时刻 = 设备当前 epoch − uptime；
          另有 `getprop sys.boot_completed` 表示起完了没有；
    - **意图**：`modules_config.db` 的 `modules` / `modules_state` / `scope` 三张表。设备上没有 `sqlite3`，
      只能拉回本地查；**db + `-wal` + `-shm` 用一次 `tar` 打包**（三条 `cat` 的窗口足够宽，读到的会是上一版）；
    - **事实**：`/data/adb/lspd/log/modules_<开机会话>.log` 里 `(进程名)[包名` 的行数。
      三个进程各有含义：`system` = 注入侧（侧键接管）、`com.oplus.gesture` = 宿主侧（手势劫持与执行）、
      `com.oplus.gesture.ui` = 设置页替换。**0 行就是整轮跳过**，这是唯一的实证。
- 交叉校验：lspd 日志文件名的时间戳就是「框架自己的开机会话」，与 uptime 推出的开机时刻应当相差
  +10~25 秒；负数说明这份日志不属于本轮，时间线对不上。
- 结论区把三种已知故障直接映射到 `docs/device-findings.md` 的条目：路径过期 ⇒ 六之三；
  路径对但 `system` 没注入 ⇒ 六之三之一（增量安装 / 装包时 daemon 没在跑）。
- 实测两轮：13:17 那轮 `system` 0 行（库里路径过期，整轮跳过）；13:23 那轮 50 / 38 / 83 行，三条全绿。

### 判据：一次说清「哪一侧还在跑旧包」

- 旧尺子是 `ModuleInfo.BUILD_ID`，要**人手改**：忘改一次就量不出差别（10-20 的两个包都还挂着
  `2026-10-18-0004`，换了包从模块侧看不出任何不同）。换成时间戳当主尺子、`BUILD_ID` 退成备用：
    - 新增 `core/ProcClock`：`startWall() = currentTimeMillis - (elapsedRealtime - getStartElapsedRealtime)`、
      `bootWall()` 取整到秒当「本轮开机」的指纹。三项都只读本进程状态，system_server 里也安全；
    - 注入侧回包带 `EXTRA_INJECT_PROC_START`、宿主报活带 `EXTRA_HOST_PROC_START`，
      设置页在**建页的 IO 线程上**问 `PackageManager` 要 `lastUpdateTime`（查 `ModuleInfo.PACKAGE`）；
    - 判据：**进程启动时刻 < 包更新时间** ⇒ 该侧加载的是上一版。比大小留 5 秒余量（换包到开机相差是分钟级，
      只有「装完立刻开页」才可能落在几秒内，那时不该冤枉成过期）；
    - 两侧处置不同：注入侧过期只能整机重启（一、11），宿主侧过期用「重启服务」即可（五之一、6）。
- 「没回话」拆成三档：`opluskey_ui.conf` 里记 `inject_ever_alive` / `inject_alive_boot`（只增不减，
  只在值真的变时落盘），配合开机指纹分「从没起来过 / 装好等重启 / 本轮掉线」——
  前两档对用户的动作不同：一档要先去 LSPosed 勾作用域再重启，一档只要重启。
- 仍然分不开的一档写明了：「作用域漏了 `system`」与「勾了但从没重启过」现象完全一样，
  作用域只存在框架的库里、宿主与 system_server 都读不到（六之六），所以那一档文案同时说两件事。
- 文案：新增 `status.host_stale`（宿主旧版 → 用「重启服务」，不必重启手机）与
  `status.system_stale`（系统侧旧版 → 只说「重启手机后生效」）；`BUILD_ID` 同步升到 `2026-10-20-0001`；
  `status.disabled` 补上「改完重启手机」并与兜底字样对齐（国际化校验从 1 处不一致回到 0）。
- `PageLoadSnapshot` 的参数表收到 6 个（detekt 上限）：界面偏好整包成 `UiPrefs`，
  「包更新时间 / 曾生效 / 那轮开机」三项打包成 `LinkBaseline`；顺带把两段三态读盘拆成
  `loadConfigOrReadOnly` / `loadCommandsOrReadOnly`，`readPageLoadSnapshot` 不再贴 `LongMethod` 的线。

### 修：撤掉「系统框架」后一直提示「重启后生效」

- 成因：**「撤了作用域」与「装了新版等重启」在模块眼里是同一组信号**（本轮系统侧没回话、上一轮回过），
  旧判据只认这两条，于是撤掉「系统框架」之后那句「重启手机后生效」会一直挂着，重启多少次都不变。
- 补的判据：拿**包的更新时间**与**本次开机时刻**比 —— 包在开机之前就装好了 ⇒ 本轮早该用上它，
  现在没回话只能是作用域里没有它（新档 `InjectPendingKind.SCOPE_GONE`，报「去勾系统框架」）；
  包在开机之后才装 ⇒ 确实在等重启。余量 60 秒（`REBOOT_EPSILON_MS`）：两者贴得很近时不判成等重启。
- 剩下那一档（刚装完、作用域也刚好被撤）仍是分不开的 —— 作用域只有框架自己知道（六之六）。
  于是「等重启」那条文案改写成**一句话覆盖两步**：先重启，重启后还见这句就去勾作用域
  （`status.pending_or_scope`）。
- 自检**还没问完**那一小段（原来什么都不显示）现在显示「正在检查模块…」（`status.checking`）：
  以前那几秒页面上没有任何解释，看着像「点了没反应」；它仍不算故障、不参与整页总闸。
