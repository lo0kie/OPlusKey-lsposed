# 2026-11-15 · 无操作时振动、多击判定回到开关、重启服务回执先于拉起

### 新增：无操作时振动

- 两颗开关，位置与「振动反馈」并列：**公共设置**一份、**每个独立设置**（按键 / 组合的「按键行为」）各一份，独立设置关着时跟随公共值并置灰。
- 语义与「振动反馈」分开：那一颗管「真的执行了动作」的那一下，这一颗管「按下去有反应、但这一档什么都没配」。没有它时，「这一档没绑」与「模块没生效」在手上完全一样。
- 力度沿用现有三档强度；连续触发的重复不补振（同一次按压只振一下）。
- 收起在 `OwnSettings` 契约里（`vibrateOnNone`），三份实现各存一格；字段表里两位都走**落盘那一列**，不进广播 —— 振的是宿主，注入侧不需要读。
- 行首字形单独一个 `VibrateOnNone`（`mood-empty`），不复用「振动反馈」那颗手机图标：两行说的是两件事，同形会读成同一个开关。
- 配置抬到 **v66**（`ConfigCodec.VERSION` 与 `tools/config-shape.txt` 一起改）：老文件缺这一项按「关」读入，不需要迁移分支。

### 改：多击判定回到「按开关算」

- `judgeCap` 恢复成按档位开关算（`doubleClickOn` / `extraClicksOn` / `clickThenLongOn` 取大），**不看那一档绑没绑动作**。真机口径：「多击开关开着就要等」，不想等就把它关掉。
- 上一版按「按绑了哪几档算」改过一次，默认配置（双击开着、双击没绑）下每一次单击都当场判、不等窗口；这次按真机反馈改回，并把字段 KDoc、`GestureDetector` 那一支、`GesturePlan` 的说明三处一起对齐，避免下次又被当成「语义不对」改反。
- `GesturePlan.clickWindowMs` 改取 `clickWindowMs`（原来写 `doubleClickMs`，把「每次松手重新起算」那一档漏掉了）；`slots` 里的双击档补上开关判断。

### 改：单击后长按认档看开关，多击档不再退回单击

- 「单击后长按」动作设为无操作时**仍然认档**：第 2 击按住就归它，什么都不执行，而不是落成 `Click(2)` 之后被逐级回退成单击命令。判据从「有动作」改成「开关开着」，三处（第 2 击按下、长按到点、抬手收尾）一起改。
- 删掉宿主 `resolveAction` 里 `Click(n)` 的**逐级回退**：双击 / 三击那一格空着就什么都不做（用户口径「双击、三击也会触发单击事件」）。空档返回 `null` 而不是 `Action.None` —— 后者会走一次 `run(None)`，把「什么都没做」记成一次成功执行。

### 修：重启服务之后页面拉不起来

- **回执必须先于 `startPage`**：页面收到回执才杀自己，`startPage`（`singleInstance`）才会拉起新进程。把回执挪到拉起之后，等于在旧实例还活着时 start，随后页面自杀、宿主又判「页面没起来」不重启 —— 页面直接消失。这条顺序写进注释当硬约束。
- 回执已经发出去、页面已经退出时，`startPage` 失败不再一次了事：900ms 起试、每 400ms 重试、最多 3 次，全失败才放弃并写清日志（本进程不自杀）。
- 页面加**迟回执守卫**：回执超过 600ms 才到，说明宿主还在老顺序上，这时不杀自己，并提示「宿主还是旧代码，已替你重载，请再点一次」。装模块包不会重启 `com.oplus.gesture` 的进程，宿主侧改动本来就得等它自己重来 —— 这一条把那一轮从「页面丢了」改成「点一下就好」。

### 改：「只参与组合」→「只参与非首键的按住组合」

- 新名字与代码一致：这一档不能当按住组合的起点，也不能加入等待组合。开关标题、摘要、阻断条、三处弹窗正文全部改写，英文同步 `Hold-combo member only (never the first key)`。
- 行尾角标单独用短名「非首键按住组合」：全称 11 个字会把行尾箭头挤出去。
- 布局兜底：行尾状态文字改 `weight(fill = false)` + 单行省略，编辑态的勾选框同样处理 —— 以后任何状态文案变长都压不掉行尾控件。

### 修：配置与链路口径（审计收口）

- `.prev` 快照判据改判「主文件本身读得懂」（不回落 `.prev`）：原来用 `readOf`，主文件坏掉时它会因为 `.prev` 读得懂而返回非 null，写一次就把唯一可救的备份换成坏内容。
- 切档成功后丢掉当前槽的 `.prev`（它属于另一份配置，留着会在主文件坏时把别人的配置恢复回来）；还原分支区分「没有要还原的东西」与「还原成功」。
- 坏文件告警从进程级布尔改成**按路径**记：第二个坏文件的第一条不再被降成 `d`。
- `nextCustomKeyId` 把组合成员引用到的 id 也算进已用；`withKeyName` 加重名拒绝。
- `parseTimer` 超上限不再静默夹到 24h（按「认不出」处理）；`hasSupportedFormat` 追加「正文解析得开」，`setvar:计数` 少 `=` 这类能存却不执行的写法被拦下；`Fluid.token` 图标 id 一律小写。
- `TimeRange` 的 `24:00` 不再被夹成 `23:00`，`minuteOf` 也能读回 1440；`KsuCompat` 的串命令检测补 `>` `<` 反引号 `$(` `${`。
- `SceneRule` 的 `hasRelease` / `hasChainRelease` / `longBound` / `chainBound` 都加 `isReady`（没配完的块不该让判定白等、也不该让界面那一格亮着）。

### 修：注入侧与宿主侧的静默失败

- 组合多成员跨度改取**最早成员**（原来取配置首键，跨度算小会误认组合并吞掉这几颗键的单击）；窗口已过期、那一枪还没跑到时，新按下前先补派发，不再丢前一次单击；被组合认领的那一下，真实抬手一并吞掉（不再放出一条没有 DOWN 的孤立抬手）。
- `injectNativeKey` 把注入结果透传出去（原先恒 `true`，回声账永远销不掉）；`ComboOnlyNative` 两条主 looper 定时枪整段包 `catch`。
- `ActionRunner` 的失败归属改按**派发线程**认（异步失败不再记到下一趟头上）；铃声音量三条路全落空时回失败提示；`timer:<秒>` 的广播发不出去时退回倒计时页；显式组件退路判 `startService` 的空返回；「结束应用」指向本模块时用新档 `SELF_TARGET`。
- 界面：松手格重挑补回 `chain` / `stop`；`editingAction` 按 ReleaseSlot 三支读；滑杆点轨道用稳定闭包；入口格菜单的焦点 token 先取出来再 dismiss；字数统计按**码点**；Activity 条数不含快捷方式；分页滑块浮点位置夹进范围；场景页整页闸门盖到「添加场景 / 添加条件 / 确认」四个写入口；命令库读不出与「没有命令」分开说；链路自检注册失败给提示；步骤行退场后摘除；常用命令删除的落盘不随页面取消；导出看门狗带轮次；回执统一走包了 try 的 `postHint`。
